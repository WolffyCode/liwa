## 0. 结论

1. **四层，依赖只朝下。** agent CLI → 公共调用层（Paseo daemon + 记忆库）→ 主对话控制层（liwa 内核）→ 人设层；入口是客户端和外部适配器。上面坏了下面照常：记忆库挂了，对话照常；内核没开，Paseo 原有的一对一照常。
2. **liwa 新代码只放在四个地方**：记忆库插件 `plugins/liwa-memory/`；liwa 核心模块 `packages/server/src/server/liwa/`（内核和成员数据）；协议 `packages/protocol/src/liwa/`；客户端界面 `packages/app/src/liwa/`。外部适配器各是一个插件。对 Paseo 原有代码只改公共契约，每条契约配契约测试（第 6 节）。
3. **每样数据只有一个归属**（第 3 节）：记忆归记忆库插件（`memory.db`）；工单、成员目录、空间、群消息、人归内核（`ledger.db`，因为它们要在同一个事务里读写）；人设版本、经历流、成长记录归成员数据（`members.db`）；会话和时间线仍归 Paseo。
4. **跨部件只走公开接口**：内核调 Paseo 只经它的门面；记忆库插件只经 Paseo 的插件钩子和工具接口；内核把"这个会话是谁、在场有谁"写进会话的元数据，记忆库插件读元数据决定带哪些记忆，两者不互相调用（第 4 节）。
5. **内核照旧双层设计的骨架**：账本只有一个写入口（命令入口，一条命令一个事务）；编排层只执行持久任务、结果再以命令写回；对人说话只有一个出口；启动时按固定顺序对账（第 2.3 节）。

## 1. 分层与代码落点

```text
入口层     客户端 packages/app（Paseo 原有界面 + liwa 新界面 packages/app/src/liwa/）
           外部适配器 plugins/liwa-adapter-<平台>/（第 5 期）
                │  WebSocket 协议（packages/protocol，liwa 部分在 packages/protocol/src/liwa/）
─────────────── daemon 进程 packages/server ───────────────────────────────────
④ 人设层   成员目录（内核账本里）+ 成员数据 packages/server/src/server/liwa/member-data/
③ 控制层   liwa 内核 packages/server/src/server/liwa/kernel/
           账本、命令入口、接单、派工、回报、对人出口、巡检、恢复、主对话、群、空间
② 公共层   Paseo 原有：AgentManager、提供方、工作区与 worktree、插件运行时、MCP 工具通道
           记忆库插件 plugins/liwa-memory/（daemon 进程内运行的内置插件）
① CLI 层   Claude Code · Codex · OpenCode · Pi · OMP · ACP 一类（各自的子进程）
```

- 内置插件在 daemon 进程内运行，启动早于会话恢复（`packages/server/src/server/plugins/runtime.ts:349-367`；`bootstrap.ts:1905-1910`〔一手〕）；只能引用 `@getpaseo/plugin/*`、`zod` 和 Node 内置模块（`docs/plugins.md:109-111`〔一手〕）。
- liwa 的数据都放在 `$PASEO_HOME/liwa/` 下；开发版是仓库内的 `.dev/paseo-home/liwa/`，不碰正式安装的 `~/.paseo`。
- 存储一律用 Node 内置的 `node:sqlite`：打包版跑在 Electron 44 自带的 Node 24.20，开发模式跑在 Node 22.20，两边实测都能用，含 FTS5 全文检索〔一手：实测〕。不加 npm 依赖。

## 2. 部件清单

每个部件只做一件事，只暴露表里的接口，其余都是私有的。

### 2.1 Paseo 原有（复用，不改或只改公共契约）

| 部件                  | 管什么                                                            | liwa 怎么用                                          |
| --------------------- | ----------------------------------------------------------------- | ---------------------------------------------------- |
| AgentManager 与提供方 | 建会话、起回合、插话、取消、关闭、归档、事件订阅；各家 CLI 的适配 | 内核经门面调用；记忆库经插件钩子挂上                 |
| 工作区与 worktree     | 项目、工作区、worktree 的创建和归档                               | 每张工单一个 worktree；群成员在群里各一个 worktree   |
| 插件运行时            | 内置和用户插件、钩子、插件工具、设置页                            | 记忆库插件、适配器插件                               |
| MCP 工具通道          | 给 agent 注入 Paseo 自己的工具，并告诉工具是谁在调                | 记忆工具挂在这里；主对话和执行器的领域工具也挂在这里 |
| 时间线与客户端协议    | 会话时间线、WebSocket 消息                                        | 主对话卡片、群消息投影、工单栏数据                   |

### 2.3 liwa 内核 `packages/server/src/server/liwa/kernel/`（第 2 期起）

照旧双层设计的骨架：依赖只能向下；账本的所有写入经命令入口；编排层各模块之间不互相调用，一个任务做完以命令写回账本，并在同一个事务里排下一个任务；领域规则是纯函数。

| 子部件          | 管什么                                                                                                 | 对外接口                                                     | 唯一归属的数据                             |
| --------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------ |
| `ledger/`       | 存储：仓储、事务、持久任务队列                                                                         | `atomic(fn)`（只给命令入口）、仓储接口、任务入队和认领       | `ledger.db` 和它的表结构                   |
| `commands/`     | 账本的唯一写入入口：一条命令一个事务，按调用 id 幂等                                                   | `execute(命令)`                                              | 命令类型表                                 |
| `domain/`       | 领域规则：工单阶段、名额口径、转发规则、出站依据、巡检规则                                             | 纯函数                                                       | 状态转换表                                 |
| `intake/`       | 接单：人的消息入账、合批、交给主对话研判                                                               | 执行接单任务                                                 | —                                          |
| `dispatch/`     | 派工：名额、排队、建执行器、worktree、交接包、投递输入、取消                                           | 执行派工、投递、取消任务；名额快照                           | 名额表（内存，从账本重建）；交接包格式     |
| `relay/`        | 把回报、结局、事故变成给主对话的卡片                                                                   | `renderCard`                                                 | 卡片格式                                   |
| `outbound/`     | 对人说话的唯一出口：出站依据校验、待发队列、渠道（客户端、群、适配器）                                 | 执行发送任务；`channels.register`                            | 待发队列的语义；各渠道长度上限             |
| `patrol/`       | 巡检：定时和事件驱动的确定性检查、提醒、升级                                                           | `start`、`stop`、`onAgentEvent`                              | 每次执行的巡检状态                         |
| `recovery/`     | 启动时按固定顺序对账；关机时隔离在途任务                                                               | `recoverOnStartup`、`prepareShutdown`                        | 恢复顺序表                                 |
| `router/`       | 主对话：提示词装配、工单表快照、换新                                                                   | `assemblePrompt`、`boardSnapshot`                            | 提示词模板                                 |
| `tools/`        | 主对话和执行器的领域工具：定义、入参校验、按凭据认身份                                                 | `routerTools(caller)`、`workerTools(caller)`                 | 工具名和入参定义                           |
| `members/`      | 成员目录：角色、数字生命的登记（名字、类型、默认大脑、能否被派活、最多几单、当前人设版本号）、可派名单 | 查询和命令                                                   | 账本里的成员表（第 3 期）                  |
| `rooms/`        | 群：成员名单、群消息、读游标、唤醒规则、成本闸                                                         | 群命令；唤醒判定（纯函数）                                   | 账本里的群表（第 3 期）                    |
| `spaces/`       | 空间和人：客户端私聊、群、外部会话；人与外部账号的绑定；适配器的桥                                     | 统一准入；桥的入站和回执                                     | 账本里的空间、人、账号绑定表（第 4、5 期） |
| `adapters/`     | Paseo 公共契约的 liwa 一侧实现：投递准入、角色工具策略、目标守卫、恢复排除                             | 见第 6 节                                                    | —                                          |
| `paseo-facade/` | 内核对 Paseo 的全部调用和事件订阅；提供方能力表                                                        | 建会话、加载、起回合、插话、取消、关闭、归档、worktree、事件 | 提供方能力表（哪家能当主对话）             |
| `config/`       | liwa 配置的唯一归属：读 daemon 配置的 `liwa` 段、校验、给默认值                                        | `snapshot`、`subscribe`                                      | 所有默认值和上限                           |
| `health/`       | 健康项：各部件报告状态，健康板读                                                                       | `report`、`snapshot`                                         | 健康项清单                                 |

内核的详细设计以之前审过五轮的双层设计稿为起点，第 2 期动工前按新产品模型改写成 `dual-layer.md`。

### 2.4 成员数据 `packages/server/src/server/liwa/member-data/`（第 4 期起）

| 管什么                         | 对外接口                                                                                                 | 唯一归属的数据        |
| ------------------------------ | -------------------------------------------------------------------------------------------------------- | --------------------- |
| 人设的各个版本、待确认的新版本 | `persona.current`、`persona.propose`、`persona.activate`、`persona.rollback`（生效和撤回只能由主人触发） | `members.db` 的人设表 |
| 经历流：只追加                 | `journal.append`（只由内核推）、按时间读                                                                 | 经历表                |
| 成长：夜间整理、提案           | `growth.run`（由定时触发）                                                                               | 成长记录表            |

- 成员数据不认识内核：内核把"工单结了、谁说了什么"作为经历推给它，并带好受众；成长要的原料都从经历流里读，不反过来查账本。
- 人物级记忆不在这里，在记忆库里，是记忆库的一种范围；成员数据只在成长时经记忆库插件的 RPC 整理它。

### 2.5 协议与客户端

- 协议：`packages/protocol/src/liwa/`，放内核的读接口、推送和处置命令的入参出参定义；只追加、可选，旧客户端照常解析。
- 客户端：`packages/app/src/liwa/` 放内置的新界面：工单栏、健康板、新建 agent 的类型选择、角色库、群对话和成员栏、她的页面、空间与人物。按"功能优先"，都用 Paseo 现有部件拼。
- 记忆页和适配器自己的界面走插件设置页，不在这里。

### 2.6 外部适配器（第 5 期）

- 插件接口 `packages/plugin/src/server/` 新加一个贡献点：声明适配器、报入站消息、实现发送并报回执。
- 每个平台一个插件 `plugins/liwa-adapter-<平台>/`；插件只能碰到内核 `spaces/` 的桥，碰不到账本。

## 3. 数据归属

问"XX 该去哪找"，答案只有一个；别的部件要用，只经归属方的接口。

| 数据                                             | 归谁               | 存在哪                              | 谁能写                       | 期   |
| ------------------------------------------------ | ------------------ | ----------------------------------- | ---------------------------- | ---- |
| agent 会话、时间线、提供方会话句柄               | Paseo AgentManager | `$PASEO_HOME` 下的 JSON（上游原样） | AgentManager                 | 原有 |
| 项目、工作区、worktree                           | Paseo              | 同上                                | Paseo                        | 原有 |
| 记忆（系统级、人物级）、读过外部内容的标记       | 记忆库插件         | `$PASEO_HOME/liwa/memory.db`        | 只有 `store`                 | 1、4 |
| 工单、执行、输入、回报、持久任务、待发消息、触发 | 内核               | `$PASEO_HOME/liwa/ledger.db`        | 只有 `commands/`             | 2    |
| 成员目录、可派名单                               | 内核 `members/`    | 同上                                | 只有 `commands/`             | 3    |
| 群、成员名单、群消息、读游标                     | 内核 `rooms/`      | 同上                                | 只有 `commands/`             | 3    |
| 空间、人、外部账号绑定                           | 内核 `spaces/`     | 同上                                | 只有 `commands/`             | 4、5 |
| 人设版本、经历流、成长记录                       | 成员数据           | `$PASEO_HOME/liwa/members.db`       | 只有成员数据                 | 4    |
| 外部平台的登录态、原始消息格式、限频             | 各适配器插件       | 插件自己的设置                      | 插件自己                     | 5    |
| 记忆库的配置（预算、上限）                       | 记忆库插件         | 插件设置                            | 主人在设置里改               | 1    |
| 内核的配置（名额、上限、预算、超时）             | 内核 `config/`     | daemon 配置的 `liwa` 段             | 主人改配置；代码里不写死数字 | 2    |

**为什么记忆库和内核分两个库**：记忆库第 1 期就要用，那时还没有内核；记忆库是插件，内核是核心模块，各管各的数据，坏一个不影响另一个。**为什么成员目录、群、空间和工单在一个库**：开单时要在同一个事务里查"指定的角色在不在可派名单、名额够不够"，群里派活要同时查"这个成员在不在群里"〔推理〕。

## 4. 部件之间怎么调用

```text
客户端 ──WebSocket──▶ daemon 会话层 ──▶ 内核 commands/（第 2 期起）
                                    └─▶ Paseo 原有（普通对话）

内核 ──paseo-facade/──▶ AgentManager（建会话时把成员 id、位置、在场的人写进会话元数据）
                         │
                         ▼ 插件钩子 agent.create.before / agent.open.before
                      记忆库插件（读元数据决定带哪些范围、按在场的人过滤）

内核 ──端口──▶ 成员数据（推经历、取人设）
成员数据 ──插件 RPC──▶ 记忆库插件（成长时整理人物级记忆）
适配器插件 ──桥──▶ 内核 spaces/ ──统一准入──▶ commands/
内核 outbound/ ──渠道──▶ 客户端 / 群 / 适配器插件
```

- **内核和记忆库插件不互相调用**：内核建会话时在元数据里写下成员 id、位置和在场的人；记忆库插件在钩子里读这份元数据。普通对话没有这些元数据，记忆库就只带系统级记忆。
- **人设由内核装进系统提示**：建会话时人设放在系统提示最前面，记忆库插件的记忆段跟在后面，主对话、执行器的说明放最后〔推理：Paseo 的钩子按顺序追加，内核在创建配置里先放人设〕。
- **调用方身份**：领域工具和记忆工具的调用方都取自 daemon 自己的记录（`packages/server/src/server/agent/agent-manager.ts:1024-1042`〔一手〕），模型伪造不了。已知的漏洞是 Paseo 给所有 agent 用同一个 MCP 口令（`bootstrap.ts:713`、`1707-1714`〔一手〕），能跑 shell 的 agent 在技术上能冒充别的 agent，第一版接受，见 [`product.md`](product.md) 第 11.3 节。

## 5. 关键流程

### 5.1 开任何一个会话（第 1 期起）

```text
客户端或内核要开会话
 → AgentManager 准备配置（内核开的：带上人设、成员 id、位置、在场的人）
 → 插件钩子 agent.create.before：记忆库按范围挑记忆，追加进系统提示，记下注入了哪几条
 → 提供方起 CLI 进程
 → 插件钩子 agent.open.before：挂上两个记忆工具；设 CLAUDE_CODE_DISABLE_AUTO_MEMORY=1
 → 会话开始；会话中途要更多记忆就调 memory_search
```

导入的外部会话不走 `agent.create.before`（`agent-manager.ts:1770-1782`〔一手〕），没有开局记忆快照，但打开时照样有工具。

### 5.2 双层派活（第 2 期起）

```text
人对主对话说"登录页 500 修一下"
 → 会话层把消息交给内核：统一准入 → commands/ 记一条触发 → 回执"已收到"
 → intake/ 把触发交给主对话研判
 → 主对话调 route：commands/ 在一个事务里开单、记执行配置（指定的角色或匿名）、入队派工任务
 → dispatch/：等名额 → 建 worktree → 经门面建执行器会话（收好工具、带交接包；角色执行时带人设）
 → 执行器干活，调 report 交回报（带分支、提交、测试命令和退出码）
 → commands/ 记回报 → relay/ 做成卡片投给主对话 → 主对话调 reply
 → outbound/ 校验出站依据，把话发回人所在的地方
 → 人说"可以了" → commands/ 结单 → 释放名额
```

### 5.3 群消息（第 3 期起）

```text
人在群里说"@小王 登录按钮错位了"
 → 统一准入 → commands/ 记一条群消息
 → rooms/ 唤醒判定（纯函数）：被 @ 的是小王；没 @ 任何人且群里有调度 → 交给调度
 → dispatch/ 给小王的群会话投递"他上次发言以来的群消息"（超出上限给指针）
 → 小王在自己的群 worktree 里干，调 room_say 发言 → commands/ 记群消息 → 推到客户端
 → 有调度的群里派活：走 5.2，空间是这个群，回报署成员的名字发到群里
```

### 5.4 数字生命被唤醒（第 4 期起）

```text
触发：人的消息 / 到点（liwa 自己的定时器） / 她派的活的回报
 → 内核找到她在这个空间的那段对话
 → 装配：人设（当前版本）＋ 人物级记忆（按在场的人过滤）＋ 系统级记忆
 → 她回话：经 outbound/ 发回触发所在的地方；闲聊是一种出站目的，不能夹带工单结果
 → 内核把这件事作为经历推给成员数据
 → 夜里 growth.run：读经历流 → 整理人物级记忆 → 出人设新版本（待确认）
 → 主人在她的页面确认 → 她的下一个新会话用新版本
```

### 5.5 外部适配器（第 5 期起）

```text
平台来消息 → 适配器插件报入站事实 → spaces/ 的桥校验 → 统一准入
 → 按"外部会话 → 空间 → 她的那段对话"找到实例；发送账号没绑到人的，按陌生账号处理
 → 回话经 outbound/ 的待发队列 → 该空间的渠道（这个插件）发出去 → 插件报回执
 → 回执不明的不盲目重发；客户端显示"未送达"
```

## 6. 对 Paseo 原有代码改哪里

改动按公共契约计。每条契约在原处改语义，不另加平行状态；每条配一个契约测试，保证普通 agent 的行为不变。

| 期  | 契约                   | 改什么                                                                                                     |
| --- | ---------------------- | ---------------------------------------------------------------------------------------------------------- |
| 1   | Codex 提供方配置       | `buildCodexInnerConfig` 固定关掉 Codex 的三项记忆配置                                                      |

| 2   | 控制入口               | 取消、关闭、归档、改模式等对主对话和执行器先过目标守卫                                                     |

## 7. 横向问题

| 问题       | 怎么做                                                                                                                                   |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 配置       | 内核读 daemon 配置的 `liwa` 段；记忆库读自己的插件设置；所有上限和默认值各有唯一归属，代码里不写死数字                                   |
| 健康       | 各部件向 `health/` 报告；健康板读它。第 1 期还没有内核，记忆库的状态先显示在记忆页上，第 2 期接进健康板                                  |
| 出错隔离   | 记忆库打不开：不注入、工具返回"不可用"，对话照常；内核关闭：Paseo 原有功能照常；适配器掉线：话留在待发队列                               |
| 恢复       | 内核启动时按固定顺序对账；结果不明的不自动重放，交给主人在工单栏处置                                                                     |
| 身份与安全 | 第一版不加锁、不给每个 agent 单独口令，健康板标出；私密记忆只按受众过滤                                                                  |
| 合上游     | 远端 `upstream` 只跟踪 Paseo 的 `main`；每期验收后合一次，普通合并；新代码集中在四个目录，冲突主要出在第 6 节那些契约上                  |
| 测试       | 单元（纯函数和存储）、契约（每条 Paseo 契约一个）、集成（用模拟提供方的插件和内核测试）、真实验收（开发版上用真的 Claude Code 和 Codex） |

## 9. 风险

| 风险                                                  | 影响                   | 应对                                                 |
| ----------------------------------------------------- | ---------------------- | ---------------------------------------------------- |
| 内置插件启动失败只记日志                              | 记忆库悄悄不工作       | 记忆页和健康板显示状态                               |
