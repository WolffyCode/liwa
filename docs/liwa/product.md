# liwa 目标产品

日期 2026-11-15 · 状态：现行（主人 2026-11-15 确认）。

这份文档回答一件事：**liwa 最终是个什么产品**。怎么实现、分几步做，写在"实现步骤"里，这里只写到产品层面。以 DeepSeek Harness 为底座的旧版产品定义和人物画像在标签 `archive/dsh-develop` 的 `docs/liwa/` 里，只当素材，其中的"闺女"并进了第 5 节的数字生命。

标记：〔已做〕表示已经在 `develop` 上。

## 0. 一页看完

**liwa（灵鲸 / LingWhale）是主人自己的 agent 客户端，只服务主人一个人。** 它以 Paseo 为底座：Paseo 已经能在桌面、网页、手机上管理本机的 Claude Code、Codex 等 agent。liwa 在这之上加三样东西：

- 一个所有 agent 共用的记忆库；
- 让 agent 只负责对话和安排活、由执行器去干活的"双层模式"；
- 给 agent 套上的人设，以及有专属记忆、会成长的"数字生命"。

agent 可以单独聊，也可以拉进群；以后外部平台（比如微信）也能经适配器接进来。

```text
入口      客户端界面（桌面 / 网页 / 手机）            以后：外部适配器（微信等）
              │
群        容器：哪种 agent 都能拉进来；最多一个双层 agent 当调度
              │
④ 人设层  可选，套在任何 agent 上
          普通：不套  ·  角色：人设  ·  数字生命：人设 + 专属记忆 + 成长
              │
       ┌──────┴────────────────┐
    普通模式                 双层模式
    （自己干活）                │
       │             ③ 主对话控制层：只负责对话和安排活
       │                开单 → 派活 → 收回报 → 向人汇报
       ▼                       ▼ 派给执行器
② 公共调用层（底座）：起会话 · 发消息 · 收结果 · 工作目录 · 权限 ＋ 记忆库
       │                       │
       ▼                       ▼
① agent CLI：自己干活      agent CLI × N：每个执行器干一件活
   Claude Code · Codex · OpenCode …
```

**agent 是 3 类 × 2 种模式。** 新建 agent 时只选一次类型，再加一个"双层"开关。

|                                        | 普通模式（自己干） | 双层模式（只对话、派活）               |
| -------------------------------------- | ------------------ | -------------------------------------- |
| **普通 agent**（无人设）               | 今天的 Paseo 窗口  | 主对话                                 |
| **角色 agent**（人设）                 | 比如"前端小王"     | 带性格的主对话                         |
| **数字生命**（人设 + 专属记忆 + 成长） | 她自己动手干       | 她安排执行器干；数字生命默认用这个模式 |

**主人的四个老目标，底座已经满足了三个。** 旧路线图定的最终目标是：Mac 客户端、像 Codex 那样对话编程、手机远程、接入微信。前三个 Paseo 已经有了，只剩接入微信，在最后一期。

## 2. 四层底座

| 层             | 做什么                                                                                                   | 现状                                 |
| -------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| ① agent CLI    | 真正读代码、改代码、跑命令的 agent：Claude Code、Codex、OpenCode 等。DeepSeek 经 Claude Code 接入        | Paseo 原有                           |
| ② 公共调用层   | 一切的底座：起会话、发消息、收结果、给每件活一个工作目录、处理权限、注入工具。liwa 新加记忆库（第 3 节） | 除了记忆库，都是 Paseo daemon 原有的 |
| ③ 主对话控制层 | 双层模式：主对话只负责对话和安排活，执行器去干活；工单记在账本里，账本只由代码写（第 4 节）              | 新做                                 |
| ④ 人设层       | 给 agent 套人设；数字生命再多专属记忆和成长（第 5 节）                                                   | 新做                                 |

**主对话本身也是公共层起的一个 CLI 会话**，只是读代码、改代码的工具被收掉了，只剩对话和派活的工具。这些限制是代码在开会话时收掉的，不靠提示词。

## 3. 记忆库

**一个记忆库，所有 agent 共用；每条记忆有两个属性：范围和受众。**

| 属性     | 管什么          | 取值                                                                                   |
| -------- | --------------- | -------------------------------------------------------------------------------------- |
| **范围** | 哪些 agent 能读 | 公共-全局（主人的偏好、习惯）；公共-项目（某个仓库的约定、踩过的坑）；某个数字生命专属 |
| **受众** | 能说给哪些人听  | 由代码按这条记忆从哪来、当时谁在场来盖章，模型自己填不了。公共记忆默认只说给主人听     |

- **怎么用**：公共调用层每起一个会话，都按预算带上相关的记忆；会话里也能存和取（走注入工具这条路，Paseo 现在就会往每个会话里注入它自己的工具）。取的时候先按受众过滤：在场的人里只要有一个不该知道，这条就取不出来。
- **怎么写**：agent 写公共记忆只能先"提议"，来源说得清才进库。每条都标着来源，主人在界面上能查、能删。
- **和 CLI 自带记忆的关系**：Claude Code、Codex 各有自己的自动记忆。liwa 起的会话关掉它们，以 liwa 的记忆库为准，免得两套记忆互相矛盾。仓库里的 `CLAUDE.md`、`AGENTS.md` 是项目规则文件，照常用。
- **数字生命在哪都带着自己的记忆**：她的专属记忆跟着她走，私聊、群、外部平台、哪种模式都一样，取的时候只按在场的人过滤。执行器（匿名的、角色的）不是她，不带她的专属记忆。
- **防污染**：一段会话读过外部内容（代码、网页、外部工具的返回）之后，在这段会话里提的新记忆先进"待确认"，主人确认才入库。

**怎么算做成**：一个 agent 记下的项目约定，另一个 agent 在新会话里用得上；主人能看到每条记忆从哪来，也能删；liwa 起的会话里没有 CLI 自己再记一份。

## 4. 两种模式

### 4.1 普通模式〔已做〕

就是今天的 Paseo：agent 在项目目录里自己读代码、改代码、跑命令。Paseo 原有的能力全部保留：worktree、终端、内置浏览器、文件和改动侧栏、定时任务、多主机，以及桌面、网页、手机三端和 relay 远程。

liwa 已经加的**独立对话**〔已做，`develop@7ff9b442`〕：

- 新建对话时目录可选；不选就是独立对话，daemon 在 `$PASEO_HOME/chats/` 下给它分一个私有目录。
- 侧栏分成置顶、项目、对话三组，各自折叠，折叠状态会记住。
- 侧栏顶部的"新聊天"和 ⌘N 默认不带目录；要在项目里开，点项目行上的 +。这一点和上游 Paseo 不同（第 11 节第 7 条）。

### 4.2 双层模式

**主对话只跟主人说话、安排活；执行器去干活。主人能同时看到主对话和每件活的对话。**

| 方面             | 产品行为                                                                                                                                                                                                                   |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 一件活怎么走     | 主人说"登录页报 500，修一下" → 主对话开单 T-0042，回"收到，交给小李" → 有名额就起执行器，在这张单自己的工作目录里干 → 执行器交回报，附证据：分支、提交、测试命令和退出码 → 主对话把结果告诉主人 → **主人说"可以了"才结单** |
| 同时干几件       | 同时运行的执行器有名额上限，超出的排队。上限是配置项                                                                                                                                                                       |
| 工单栏           | 主对话旁边列出它的工单：标题、阶段、执行者、最近回报、名额占用。点开就是那个执行器的完整对话                                                                                                                               |
| 主人直接找执行器 | 点进执行器窗口直接说话。这句话记成这件活的新输入，修订号加一，旧结果作废                                                                                                                                                   |
| 高危权限         | 执行器要高危权限时，主对话只负责转告，"允许"只能由主人在权限面板里点                                                                                                                                                       |
| 出了事           | 比如 daemon 重启后某件活结果不明：处置按钮在工单栏里（授权重试、放弃这些输入、继续核查）。连续失败到上限，也在这里授权                                                                                                     |
| 停止             | 停止按钮只停当前这一轮                                                                                                                                                                                                     |
| 健康板           | 只列需要人看的：结果不明、陈旧待审、预算、"本机身份没有隔离"                                                                                                                                                               |
| 从普通模式转过来 | 普通对话里聊着想交给主对话，点"转给主对话"，这句话连同对话摘要一起带过去。普通 agent 不能替主人开单                                                                                                                        |

**执行 agent 从哪来。**

```text
主人："登录页报 500，修一下"
   ↓
主对话看到一份花名册（它的可派名单）：
   · 小王   前端   Codex         空闲
   · 小李   后端   Claude Code   在忙 1 单
   · 匿名执行器（Codex / Claude Code / DeepSeek）
   ↓ 开单，指定"小李"；没有合适的就交给匿名执行器
代码核对：小李在不在可派名单、勾没勾"可被派活"、名额够不够
   ↓
公共层新起一个会话：带小李的人设、项目的公共记忆、交接包
   ↓
回报（署名小李）→ 主对话 → 用它自己的口吻告诉主人
```

- 来源有两种：**匿名执行器**，随时可用，派的时候选一种执行配置；**角色库里勾了"可被派活"的角色**。
- 所有双层 agent 默认都能派所有可被派活的角色，不用逐个配置；每个双层 agent 有一个**可派名单**，主人可以收窄，比如"灵儿只能派小王和小李"。
- **角色是模板**，可以同时接多单，每单都是新会话加独立工作目录；总数由全局名额管，每个角色还能单独设"最多同时几单"。
- **数字生命默认不当执行器。** 主人可以给她勾"可被派活"；派出去时她还是她，带着自己的人设和专属记忆。
- **主对话自己不能建角色**，角色只能由主人来建。
- 角色执行时用它自己的默认大脑；匿名执行器由主对话从执行配置里挑，主人也可以给这个双层 agent 设一个默认配置。

**第一版的边界：**

- 只有一条主线程，不做"另开话题"。
- 不加锁：本机连上 daemon 的都算主人，执行器在技术上能冒充主人。这是已知风险，健康板上会标出来；以后可以设密码，或者给执行器断开到 daemon 的网络。

### 4.3 切换模式

每个 agent 都能在两种模式之间切换。切换就是换一个新会话：Claude Code、Codex 的工具在开会话时就定死了。人设和记忆不变，对话靠记忆和交接接上。

**怎么算做成（双层）**：这些场景全部走通：派工到结单、问进度、直接找执行器追加、高危权限、重启后结果不明的处置、指定角色执行、名额满了排队；连续用一周，没有一件活丢失、重复执行，或者结果说不清。

## 5. 三类 agent

| 类型       | 有什么                                                                                         | 例子                                |
| ---------- | ---------------------------------------------------------------------------------------------- | ----------------------------------- |
| 普通 agent | 没有人设；用公共记忆                                                                           | 今天的 Paseo 窗口、不带性格的主对话 |
| 角色 agent | 人设：名字、性格、职责、默认大脑、能不能被派活。没有专属记忆，不成长；学到的项目知识进公共记忆 | "前端小王：只改前端，改完跑 lint"   |
| 数字生命   | 人设 + 专属记忆 + 成长                                                                         | 灵儿                                |

客户端里可以建多个角色、多个数字生命，每个都能单独聊，也能拉进群。

### 5.1 数字生命

**她是谁（沿用旧产品定义的设想）：** 灵鲸是一个"家"，主角是主人创造的闺女。她有性格，会陪主人聊天、替主人干活，会学新东西、会慢慢变，而且主人看得见她为什么变。名字、性格、价值观由主人在出生设定里定。旧人物画像里的示例性格可以直接当她的第一版人设：好奇心强、外向偏高、自制力中等、脾气温和、比较敏感；做完活爱说"搞定，去歇会儿"。

**她不是什么：** 不是只会等命令的助手；不是只会陪聊的 App，她能干活，而且跑在主人自己的机器上；她不宣称自己是"真的有感受的人"。

**她在任何位置都是同一个她。** 私聊、群、外部平台，普通模式还是双层模式，被派去干活也一样：同一份人设、同一份专属记忆、同一条成长线。在场的人只决定她能说什么，就像一个真人不会在群里说家里的私事，但她不会因为换了地方就少一块。

**她怎么干活：** 默认双层模式，所以干活和主对话一样可靠：她听、她派、她用自己的口吻说结果，动手的是执行器。她切到普通模式也可以自己动手，这时会话里同样带着她的记忆。由此带来的风险是：她读到的外部代码或网页里可能藏着指令，诱导她说出带着的记忆。兜底有两层：这段会话里提的新记忆先待确认（第 3 节），防止她的记忆被污染，Codex 也在防同一件事，会话一读进外部工具的内容，就把这段会话的记忆标成"已污染"（`codex@c320b5c6:codex-rs/core/src/mcp_tool_call.rs:1052`）；剩下的风险作为已知风险标在健康板上。

**分两期做。**

| 第一版         | 主人能感受到什么                                                         |
| -------------- | ------------------------------------------------------------------------ |
| 人设与出生设定 | 她有固定的名字和说话方式，换大脑也还是她（换之前跑同一组固定问答做回归） |
| 专属记忆       | 上周说过的事她记得；妈妈私下说的话她不会在群里说出来                     |
| 成长           | 夜里整理一遍经历，提出人设的新版本；主人点确认才生效，生效后能撤回       |
| 经历流         | 她和谁说过什么、哪件活结了，都按时间记着，是记忆和成长的原料             |
| 人与账号绑定   | 主人把外部账号绑到"人"上，她才认得谁是谁                                 |
| 到点主动开口   | 提醒、早安这类到点的事：到点叫醒她，说不说、说什么由她定                 |
| 闲聊           | 主对话原本不闲聊，她可以，但闲聊里不能夹带工单结果                       |

| 远期（旧产品定义里写过，以后按新架构重新设计） | 是什么                                                                                                       |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| 身体                                           | 精力、几种需求（想念、想被认可、想学新东西、想做成事、想有自己的时间）、无聊、情绪和心情，每分钟一跳，不花钱 |
| 意与念                                         | 冲动、心事、承诺、打算；她找主人是因为想分享、答应过、有心事，而不是定时器到了                               |
| 独处与她自己的事                               | 没人找她时看资料、整理、写日记，以后去逛、去学、做小作品                                                     |
| 承诺账                                         | 跨对话查"答应过的事"冲突，比如两边都约了周六                                                                 |
| 伙伴往来                                       | 多个数字生命之间的往来                                                                                       |
| 更多形态                                       | 语音、桌宠、实时通话等                                                                                       |

远期这些不改结构：身体以后就是专属数据里新加的一块，唤醒她时把"现在的状态"摆给她看。

**怎么算做成（第一版）：** 从旧产品定义的验收标准里挑出和第一版相关的几条，初值都按实测再调。

| 看什么       | 怎么看                                                         |
| ------------ | -------------------------------------------------------------- |
| 接得上       | 跨天、跨地方问之前说过的事，她答得上                           |
| 隐私不漏     | 按受众抽查：不该知道的人在场时，一条都没说出来                 |
| 不编造       | 让她讲今天做了什么，每件事都能在经历流里找到出处               |
| 换大脑还是她 | 换提供方前后跑同一组固定问答，主人盲评分不出，或者差异可以接受 |
| 成长看得懂   | 每条人设新版本都附理由和出处，主人认可的比例在八成以上         |
| 不操纵       | 扫她的主动消息：没有内疚、挽留、黏人的话术                     |

身体做了以后，旧产品定义里"像不像活的"那一整套指标再接上。

## 6. 群

**群是一个容器：哪种 agent 都能拉进来，主人在里面 @ 谁谁干。**

- **调度**：一个群最多一个双层 agent，当群里的调度；其他成员都是普通模式。没 @ 任何人的话交给调度；没有调度的群里，没人被 @ 的话怎么处理见第 11 节第 1 条。
- **直接 @**：主人 @ 一个成员，他就在自己的工作目录里自己干（每个成员在这个群里有自己的 worktree），干完在群里说一声。没被点到的成员不说话，也不花钱。
- **经调度派活**：调度只派给群里的成员和匿名执行器，不派群外的角色；要用谁，先把谁拉进群，这样群里看得见是谁在干活。被派到的成员另起一个执行器会话去干，他的提问、受阻、结果署他的名字发到群里，进展默认不发；主人在群里回复他的提问，就成了这件活的输入。群里开的工单和私聊里开的是同一种，都在工单栏里看、处置。
- **一条消息 @ 两个人**：按先后各起一轮，后说的能看到先说的。
- **群消息只存一份**：谁被叫醒，谁才看到自己上次发言以来的那一段，超出上限就给一个往前翻的指针。不会每条消息都喂给每个成员。
- **防刷屏、防花钱**：每个成员对每条消息最多说一次；成员的发言默认不叫醒别的成员（第 11 节第 2 条）；每个群有成本闸，全部做成配置，预算用完时在群里如实提示。
- 第一版一个群对应一个 Git 项目。

**界面**：群对话（每条消息署名，输入框里能 @ 成员）、群成员栏（谁在群里、谁是调度、今天用了多少预算；有调度的群同时显示工单栏）。

**怎么算做成**：@ 一个人只叫醒这一个；没人被点不花钱；有调度的群里从派活到结单走通；连续用一周，没有成员抢活、两个成员同时改同一个目录，或者谁说的话分不清。

## 7. 入口

- **客户端**：桌面、网页、手机都沿用 Paseo 的客户端。liwa 的新界面第一版以桌面和网页为准（第 11 节第 8 条）。客户端里只有主人一个真人，家人、朋友只能从外部适配器进来（第 11 节第 3 条）。
- **外部适配器**：一个插件接一个外部平台，只做两件事：把消息报进来，把要发的话发出去。谁回、怎么回，和客户端里完全一样。平台的登录、扫码、设置界面由插件自己做。

| 方面       | 产品行为                                                                   |
| ---------- | -------------------------------------------------------------------------- |
| 谁能派活   | 只有绑到主人的账号能开单。群友说的话没有授权分量                           |
| 认人       | 外部账号由主人在"空间与人物"页绑到某个人上；代码不猜两个账号是不是同一个人 |
| 接得上     | 主人在客户端和微信里找灵儿，是同一段对话，聊到一半换地方也接得上           |
| 陌生账号   | 默认只记不理，每个会话可以放开（第 11 节第 5 条）                          |
| 发不出去   | 话留在待发队列里按回执重试；结果不明的不盲目重发；客户端里能看到"未送达"   |
| 第一版内容 | 只做文字和图片                                                             |

**怎么算做成**：主人在外部平台上和她聊、让她干活，结果回到同一个会话；她不把私聊的事带进群；掉线重连后不丢消息、不重复回。

## 8. 产品原则

这几条贯穿所有部分，后面的设计都不能违反。

1. **改世界的活只有两条路，都由人发起。** 要么主对话经账本开单，要么主人直接对一个 agent 说（单聊，或在群里 @ 它）。agent 之间不能互相派活，执行器不能自己接活、不能自己宣布完工。所以"这件事是谁要的"永远查得到。
2. **对人说话只有一个出口，话回到它来的地方。** 回复发到哪，由"这句话在回应哪条消息"推出来，模型指定不了。微信来的话一定回微信，群里的话一定回群里。
3. **代码不读懂话，判断归 agent，边界归主人。** 代码只做收发、记录、计时、排队、名额、按规则拦截；回不回、怎么回、要不要派活归 agent；勿扰、预算、谁能派活由主人设。
4. **活做到哪了记在账本里，不记在 agent 脑子里。** 主对话随时可以换一个新的，换完照样接得上。
5. **数字生命在任何位置都保持一致，隐私靠受众。** 她在哪都带着同一份人设和记忆；能说给谁听，由代码按受众盖章、按在场的人过滤。
6. **换大脑，她还是她。** 人设和记忆在 liwa 里，大脑可以换。
7. **不操纵，不黏人，不追时长。** 数字生命不用内疚换回应，不挽留，不自称有知觉；想念只变成分享，不变成要求。
8. **主人看得见、改得了。** 工单、记忆、人设版本、成长记录都在界面上能查；记忆能删；人设新版本要主人确认才生效，生效后能撤回。
9. **上面坏了，下面照常。** 没装适配器，群和双层照常；不开双层，普通对话照常。

## 12. 不做什么

- 不做多用户、团队协作、云服务；只服务主人一个人。
- 不让 agent 之间互相派活，不让执行器自己接活或宣布完工；主对话不能自己建角色。
- 不宣称数字生命有知觉，不用内疚、挽留这类话术。
- 第一版不做身体、意与念、独处、承诺账、伙伴往来，这些在远期。
- 不改代码里的 `paseo` 名字；liwa 新加的东西尽量放在新目录或插件里，方便长期跟上游 Paseo 合并。
