## 0. 一页看完

**liwa（灵鲸 / LingWhale）是主人自己的 agent 客户端，只服务主人一个人。** 它以 Paseo 为底座：Paseo 已经能在桌面、网页、手机上管理本机的 Claude Code、Codex 等 agent。liwa 在这之上加三样东西：所有 agent 共用的记忆库；让 agent 只负责对话和安排活、由执行器干活的"双层模式"；给 agent 套上的人设，以及有人物级记忆、会成长的"数字生命"。agent 可以单独聊，也可以拉进群；以后外部平台（比如微信）也能经适配器接进来。

```text
入口      客户端界面（桌面 / 网页 / 手机）            以后：外部适配器（微信等）
              │
群        容器：哪种 agent 都能拉进来；最多一个双层 agent 当调度
              │
④ 人设层  可选，套在任何 agent 上
          普通：不套  ·  角色：人设  ·  数字生命：人设 + 人物级记忆 + 成长
              │
       ┌──────┴────────────────┐
    普通模式                 双层模式
    （自己干活）                │
       │             ③ 主对话控制层：只负责对话和安排活
       │                开单 → 派活 → 收回报 → 向人汇报
       ▼                       ▼ 派给执行器
② 公共调用层（底座）：起会话 · 发消息 · 收结果 · 工作目录 · 权限 ＋ 记忆库
       │                       │
       ▼                       ▼
① agent CLI：自己干活      agent CLI × N：每个执行器干一件活
   Claude Code · Codex · OpenCode …
```

**agent 是 3 类 × 2 种模式。** 新建 agent 时只选一次类型，再加一个"双层"开关。

|                                          | 普通模式（自己干） | 双层模式（只对话、派活）               |
| ---------------------------------------- | ------------------ | -------------------------------------- |
| **普通 agent**（无人设）                 | 今天的 Paseo 窗口  | 主对话                                 |
| **角色 agent**（人设）                   | 比如"前端小王"     | 带性格的主对话                         |
| **数字生命**（人设 + 人物级记忆 + 成长） | 她自己动手干       | 她安排执行器干；数字生命默认用这个模式 |

**主人的四个老目标，底座已经满足了三个。** 旧路线图定的最终目标是：Mac 客户端、像 Codex 那样对话编程、手机远程、接入微信。前三个 Paseo 已经有了，只剩接入微信，在第 5 期。

## 3. 模块 1：底座与对话

### 3.1 Paseo 原有能力（原样保留）

- **提供方**：Claude Code、Codex、OpenCode、Copilot、Pi 等；自定义提供方（如基于 Claude Code、走 DeepSeek 接口的 DeepSeek）。
- **项目与工作区**：打开本机目录作为项目；在项目里开 worktree；归档工作区。
- **一对一对话**：发消息、附图片和文件、权限审批、停止、分叉到新标签页或新工作区。
- **工具面板**：终端、内置浏览器、文件和改动侧栏。
- **定时任务**：按计划新建 agent 或往同一个对话里回灌。
- **多端与远程**：桌面、网页、手机三端；经 relay 远程连回家里的 daemon。

### 3.2 独立对话〔已做〕

- 新建对话时目录可选；不选就是独立对话，daemon 在 `$PASEO_HOME/chats/` 下给它分一个私有目录。
- 是不是独立对话只看工作区上的 `purpose: "chat"`，不看名字和路径。
- 独立对话背后的私有目录和"Chats"后台项目不出现在任何项目列表里。
- 对话行能重新打开、改名、置顶、归档；离开页面、关闭标签页不删除对话；归档会停掉它的 agent，之后能在"历史"里找到。

### 3.3 侧栏三组〔已做〕

- 侧栏分置顶、项目、对话三组，按这个顺序排；三组各自折叠，折叠状态按设备记住。
- 置顶的对话只出现在"置顶"，不重复出现。
- 顶部"新聊天"和 ⌘N 默认不带目录；项目行上的 + 会带上这个项目。

## 4. 模块 2：记忆库

**记忆是扁平的：liwa 的记忆库是唯一的记忆来源，不管是哪家 CLI，读的、写的都是这一个库。** CLI 自带的自动记忆一律关掉；仓库里的 `CLAUDE.md`、`AGENTS.md` 是项目规则文件，不算记忆，照常加载。

### 4.1 两级记忆

| 级         | 范围                                                               | 谁能读                                               | 谁能写                      | 期      |
| ---------- | ------------------------------------------------------------------ | ---------------------------------------------------- | --------------------------- | ------- |
| **系统级** | 全局：主人的偏好、习惯、通用约定                                   | 所有 agent                                           | 所有 agent 提议，规则见 4.4 | 第 1 期 |
|            | 项目：某个仓库的约定、踩过的坑；同一仓库的几个 worktree 算一个项目 | 在这个项目里工作的 agent                             | 同上                        | 第 1 期 |
| **人物级** | 某个数字生命专属：她和谁说过什么、她记得的事                       | 只有她自己的会话（私聊、群、外部平台、哪种模式都算） | 她自己提议                  | 第 4 期 |

- 每条记忆都带**来源**（哪个 agent、哪家 CLI、哪个项目、什么时候），由代码盖章，模型填不了。
- 每条记忆都带**受众**（能说给哪些人听）：系统级默认只说给主人听；人物级由代码按这条记忆从哪来、当时谁在场盖章。取记忆时按在场的人过滤，在场的人里只要有一个不该知道，这条就取不出来。
- 执行器（匿名的、角色的）只带系统级记忆，不带任何数字生命的人物级记忆。
- 角色没有人物级记忆，学到的项目知识进系统级（〔待定 3〕）。

### 4.2 怎么带进每家 CLI〔第 1 期〕

带入走公共调用层（Paseo daemon），所以每家 CLI 用的是同一条路：

| 时机               | 怎么带                                                                                                                                                  | 适用的 CLI                                              |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 开会话             | 按预算挑出相关的记忆（系统级的"全局 + 本项目"；数字生命再加她的人物级），整段写进系统提示                                                               | 能追加系统提示的：Claude Code、Codex、OpenCode、Pi、OMP |
| 开会话（ACP 一类） | Copilot、Cursor、Kimi、Kiro、Trae 等走 ACP 协议的 CLI，Paseo 没有追加系统提示的通道；第一版只靠工具，以后再看要不要把记忆附在第一条消息前（〔待定 1〕） | ACP 一类                                                |
| 会话中途           | 两个工具：`memory_search` 查记忆、`memory_propose` 提议记一条，经 Paseo 统一注入工具的通道挂上                                                          | 所有能挂 MCP 工具的 CLI                                 |

- 系统提示只在开会话时写一次，之后不变；会话中途要更多，靠 `memory_search`。
- 主人关掉了"给 agent 注入 Paseo 工具"时，记忆工具会一起失效，记忆页上会提示。

### 4.3 关掉 CLI 自带的记忆〔第 1 期〕

- **Claude Code**：每次打开会话都设环境变量 `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`。实测关掉后系统提示里没有它自己的记忆段，也不建记忆目录；`CLAUDE.md` 照常加载。
- **Codex**：在 liwa 的 Codex 提供方里固定关掉 `features.memories`、`memories.generate_memories`、`memories.use_memories`；`AGENTS.md` 照常加载（〔待定 4〕）。
- 其他家 CLI 用到时逐个核实有没有自带的自动记忆，有就照这个办法关掉。

### 4.4 查记忆和提议记忆〔第 1 期〕

- **查**：`memory_search(查询词)` 在调用者能读的范围里搜，只搜已确认的；查询词 3 个字以上走全文检索，短的按子串匹配；默认返回 10 条，最多 30 条。
- **提议**：`memory_propose(内容, 范围, 理由可选)`。
  - 内容不能为空，最多 500 字；范围只能选调用者能写的（不在项目里就不能选项目级）。
  - 同一范围里已有相同内容的，不重复存，返回已有那条。
  - 提议的会话没读过外部内容，直接进库；读过的，进"待确认"，主人确认才生效。
- **什么算读过外部内容**：上网取页面、联网搜索、内置浏览器、第三方 MCP 工具，以及子 agent 用过这些；读本地文件、跑 shell 不算。一个会话一旦算读过，之后提议的都进待确认。判断不了的时候按"读过"处理（〔待定 2〕）。

### 4.5 记忆页〔第 1 期〕

- 设置里一页"记忆"：一张表，列出内容、级别和范围、来源、状态；筛选"全部 / 待确认"。
- 每条能删除（真删）；待确认的能"确认"或"丢弃"。
- 顶部显示记忆库状态：共多少条、待确认多少条；库打不开或工具失效时显示原因。

### 4.6 导入 CLI 已有的记忆〔第 1 期〕

- 主人点一次"导入"，把 Claude Code 的记忆目录、Codex 的记忆文件里已有的内容读进来，全部进"待确认"。
- 按来源标明"从 Claude Code 导入""从 Codex 导入"，主人逐条确认后变成系统级记忆，丢弃的不再导入。
- 导入只读这些文件，不改不删。

### 4.7 人物级记忆〔第 4 期〕

- 数字生命在任何地方说的、听的，都可以提议进她的人物级记忆；受众由代码按来源和在场的人盖章。
- 她在哪都带着同一份人物级记忆，只按在场的人过滤能说什么。
- 她的人物级记忆只在"她的页面"里看、删。

**怎么算做成（第 1 期）**：一个 agent 记下的项目约定，另一家 CLI 的 agent 在新会话里用得上；主人能看到每条从哪来、能删；待确认的没确认前不会被带进会话；liwa 起的 Claude Code、Codex 会话不再自己写记忆；导入的旧记忆确认后能用。

## 5. 模块 3：agent 管理

### 5.1 新建 agent〔第 2–4 期逐步加〕

- 新建时先选类型：普通（第 0 期起就有）、角色（第 3 期）、数字生命（第 4 期）；再选一个"双层"开关（第 2 期起）。
- 选角色或数字生命时，从角色库、数字生命列表里挑一个，或者当场新建。
- 选完类型后照常选项目（可不选）、选提供方和模型。

### 5.2 切换模式〔第 2 期〕

- 任何 agent 都能在普通模式和双层模式之间切换。
- 切换就是换一个新会话：CLI 的工具在开会话时就定死了。人设和记忆不变，对话靠记忆和一份交接摘要接上。
- 群里的成员模式由群决定（见 8.4），在群里不能单独切。

### 5.3 agent 设置

- 默认大脑：用哪家提供方、哪个模型。
- 能不能被派活、最多同时接几单（角色、数字生命才有）。
- 可派名单（双层模式的 agent 才有，见 6.3）。

## 6. 模块 4：双层模式〔第 2 期〕

**主对话只跟主人说话、安排活；执行器去干活。主人能同时看到主对话和每件活的对话。**

### 6.1 主对话

- 主对话本身也是一个 CLI 会话，但读代码、改代码、跑命令的工具在开会话时就收掉了，只剩对话和调度用的工具。限制靠代码，不靠提示词。
- 能做的事：开单、查进度、给某张单补充说明、叫停、授权重试的转告、回话。
- 对人说话只有一个出口：话回到它回应的那条消息所在的地方。
- 活做到哪了记在账本里，不记在主对话脑子里，所以主对话随时可以换一个新的，换完照样接得上。
- 能当主对话的提供方要能在开会话时收掉工具，第一版以 Claude Code、Codex 为准，其他家逐个核实。

### 6.2 工单

- **开单**：只有主对话能开，而且必须对应主人说过的一句话；开单时记下标题、谁要的、派给谁。
- **排队**：同时运行的执行器有名额上限，满了就排队；上限是配置项。
- **执行**：每张单一个独立的工作目录（worktree）；每次尝试是一个新会话。
- **回报**：执行器交回报必须带证据：分支、提交、测试命令和退出码。
- **结单**：只有主人能结，主人说"可以了"才算完；执行器不能自己宣布完工。
- **追加**：主人直接对执行器说的话记成这张单的新输入，修订号加一，旧结果作废，主对话不重复转述。
- **停止**：停止按钮只停当前这一轮。
- **重试**：失败或结果不明时，由主人在工单栏授权重试，可以换一个执行配置。

### 6.3 执行者

- 来源两种：**匿名执行器**，随时可用，派的时候选一种执行配置（比如 Codex 高推理、Claude Code、DeepSeek）；**角色库里勾了"可被派活"的角色**（第 3 期起）。
- 所有双层 agent 默认都能派所有可被派活的角色；每个双层 agent 有一个可派名单，主人可以收窄。
- 开单时可以指定角色，没有合适的就派匿名执行器；代码核对指定的角色在不在名单里、名额够不够。
- 角色是模板，可以同时接多单；数字生命默认不当执行器，勾了"可被派活"后派出去时她还是她。
- 主对话自己不能建角色。
- 执行器只带系统级记忆和交接包；角色执行时另带角色的人设。

### 6.4 工单栏

- 主对话旁边的右侧面板：列出它的工单，每行显示标题、阶段、执行者、最近回报、名额占用。
- 点一行打开那个执行器的完整对话，能直接对它说话。
- 处置按钮直接放在行上：授权重试、放弃这些输入、继续核查。

### 6.5 高危权限

- 执行器要高危权限时，主对话只负责转告；"允许"只能由主人在权限面板里点。

### 6.6 出事处置

- daemon 重启后，账本和实际情况对一遍；对不上的工单标成"结果不明"，主对话告知主人，处置在工单栏。
- 连续失败到上限的，同样在工单栏由主人授权。
- 结果不明的不自动重放，避免同一件活做两遍。

### 6.7 转给主对话

- 普通对话里聊着想交给主对话，点"转给主对话"，这句话连同对话摘要一起带过去。
- 普通 agent 不能替主人开单。

### 6.8 健康板

- 设置里一页，只列需要人看的：结果不明的工单、陈旧待审、预算、"本机身份没有隔离"、记忆库状态。

**第一版的边界**：只有一条主线程，不做"另开话题"；不加锁，本机连上 daemon 的都算主人（见 11.3）。

**怎么算做成**：这些场景全部走通：派工到结单、问进度、直接找执行器追加、高危权限、重启后结果不明的处置、指定角色执行、名额满了排队、普通和双层来回切换；连续用一周，没有一件活丢失、重复执行，或者结果说不清。

## 7. 模块 5：角色〔第 3 期〕

### 7.1 角色库

- 设置里一页：列出所有角色，能新建、修改、删除。
- 角色的字段：名字、人设（性格、职责，如"前端小王：只改前端，改完跑 lint"）、默认大脑、能不能被派活、最多同时几单。
- 删除角色不影响已经结了的工单；进行中的工单照常干完。

### 7.2 人设注入

- 用这个角色开会话时，人设放在系统提示最前面，记忆跟在后面。
- 改了人设，在下一个新会话生效；正在跑的会话不变。

### 7.3 角色单聊

- 新建 agent 时选这个角色，就能单独和它聊，普通模式或双层模式都行。

### 7.4 角色当执行器

- 见 6.3。被派活时每单一个新会话，带角色的人设、系统级记忆和交接包；回报署角色的名字。

## 8. 模块 6：群〔第 3 期〕

**群是一个容器：哪种 agent 都能拉进来，主人在里面 @ 谁谁干。**

### 8.1 建群与成员

- 主人建群，起名字，选一个项目（第一版一个群对应一个 Git 项目）。
- 拉成员：从普通 agent、角色、数字生命里挑；移出成员不影响他已经在干的活。
- 客户端里的群只有主人一个真人；别的真人只能从外部适配器进来。

### 8.2 群消息

- 每条消息署名；能 @ 成员，能回复某条消息。第一版在输入框里直接打"@名字"，补全以后再做。
- 群消息只存一份；谁被叫醒，谁才看到自己上次发言以来的那一段，超出上限就给一个往前翻的指针。

### 8.3 唤醒规则

- 被 @、被回复的成员才说话；没被点到的不说话，也不花钱。
- 一条消息 @ 两个人，按先后各起一轮，后说的能看到先说的。
- 每个成员对每条消息最多说一次；成员的发言默认不叫醒别的成员，每个群可以打开，打开后最多传一跳。
- 没有调度的群里，没人被 @ 的话不回；群可以设一个默认成员来接。

### 8.4 群调度

- 一个群最多一个双层 agent，当群里的调度；其他成员都是普通模式。
- 没 @ 任何人的话交给调度。
- 调度只派给群里的成员和匿名执行器，不派群外的角色；要用谁，先拉进群。
- 被派到的成员另起一个执行器会话去干；他的提问、受阻、结果署他的名字发到群里，进展默认不发；主人在群里回复他的提问，就成了这件活的输入。
- 群里开的工单和私聊里开的是同一种，都在工单栏里看、处置。

### 8.5 工作目录

- 成员被 @ 直接干活时，在这个群里有自己的 worktree，几个成员不会同时改同一个目录。

### 8.6 成本闸

- 每个群有日预算等上限，全部是配置项；预算用完时，在群里如实提示，不再叫醒成员。

### 8.7 群界面

- 群对话复用对话时间线，每条消息前显示发言人。
- 右侧面板：成员列表（谁在群里、谁是调度、今天用了多少预算）；有调度的群同时显示工单栏。

**怎么算做成**：@ 一个人只叫醒这一个；没人被点不花钱；有调度的群里从派活到结单走通；连续用一周，没有成员抢活、两个成员同时改同一个目录，或者谁说的话分不清。

## 9. 模块 7：数字生命〔第 4 期〕

**数字生命就是有人设、有人物级记忆、会成长的 agent。** 她默认用双层模式，所以干活和主对话一样可靠。客户端里可以建多个，每个都能单独聊、能拉进群。

**她是谁（沿用旧产品定义的设想）**：灵鲸是一个"家"，主角是主人创造的闺女。她有性格，会陪主人聊天、替主人干活，会学新东西、会慢慢变，而且主人看得见她为什么变。她不是只会等命令的助手，也不是只会陪聊的 App；她不宣称自己是"真的有感受的人"。

### 9.1 她在任何位置都是同一个她

- 私聊、群、外部平台，普通模式还是双层模式，被派去干活也一样：同一份人设、同一份人物级记忆、同一条成长线。
- 在场的人只决定她能说什么，就像一个真人不会在群里说家里的私事。
- 她自己动手的会话也带着她的记忆。风险是外部内容可能诱导她说出带着的记忆：读过外部内容的会话里提的新记忆先待确认，剩下的风险标在健康板上。

### 9.2 出生设定与人设

- 主人在出生设定里定她的名字、性格、价值观、说话方式；旧人物画像里的示例性格可以直接当第一版人设（好奇心强、外向偏高、自制力中等、脾气温和、比较敏感；做完活爱说"搞定，去歇会儿"）。
- 人设有版本号；她自己改不了人设，只能经成长提出新版本。

### 9.3 人物级记忆

- 见 4.7。

### 9.4 成长

- 默认每天夜里整理一次：读她当天的经历流，整理人物级记忆，提出人设的新版本。
- 新版本附理由和出处，主人点确认才生效；生效后在她的下一个新会话里用上；生效后也能撤回。
- 成长不是她的会话，是一次单独的后台整理。

### 9.5 经历流

- 她和谁说过什么、哪件活结了，都按时间记一条，只追加不修改；它是人物级记忆和成长的原料。

### 9.6 主动开口

- 提醒、早安这类到点的事：到点叫醒她，说不说、说什么由她定。
- 定时由 liwa 自己往她的那段对话里记一条触发，不是新开一个 agent。

### 9.7 闲聊

- 主对话原本不闲聊，她可以；闲聊里不能夹带工单结果。

### 9.8 认人

- 主人能建"人"（主人、妈妈……），把外部平台的账号绑到人上，她才认得谁是谁；代码不猜两个账号是不是同一个人。

### 9.9 她的页面

- 数字生命自己的设置页，从她的对话进入：人设的各个版本和差异、待确认的新版本（带确认按钮）、人物级记忆（可删）、成长记录（可撤回）。

### 9.10 换大脑还是她

- 换提供方前后跑同一组固定问答，主人盲评分不出，或者差异可以接受。

**远期（不在第 4 期）**：身体（精力、几种需求、情绪和心情，每分钟一跳）、意与念、独处与她自己的事、承诺账、伙伴往来、语音和桌宠。它们不改结构：以后是她的专属数据里新加的一块。

**怎么算做成**：接得上（跨天、跨地方问之前说过的事，她答得上）、隐私不漏（不该知道的人在场时一条都没说）、不编造（她讲的每件事都能在经历流里找到出处）、换大脑还是她、成长看得懂（新版本主人认可的比例在八成以上）、不操纵（她的主动消息里没有内疚、挽留、黏人的话术）。

## 10. 模块 8：外部适配器〔第 5 期〕

**适配器是空间的另一种来法。** 插件只做两件事：把外部平台的消息报进来，把要发的话发出去。谁回、怎么回，和客户端里完全一样。

### 10.1 适配器接口

- 插件接口新加一个"接入外部会话"的能力：报入站消息（会话、发送账号、有没有 @ 她、回复哪条、内容）、按给定目标发消息并报回执。
- 插件只能碰到 daemon 这边的一座桥，碰不到账本；桥对入站消息做完整校验。
- 平台的登录、扫码、设置界面由插件自己做。

### 10.2 第一个平台

- 倾向微信；微信没有官方的个人号接口，先调研接法和封号风险，再定先接哪个（备选是有官方机器人接口的平台）。
- 第一版只做文字和图片。

### 10.3 空间与人物

- 设置里一张绑定表：外部账号绑到人；外部会话绑到她的哪段对话。主人在客户端和微信里找灵儿，是同一段对话。

### 10.4 谁能派活、陌生账号

- 只有绑到主人的账号能开单；群友说的话没有授权分量。
- 没绑定的陌生账号默认只记不理；每个会话可以改成"可以聊，不能派活"。

### 10.5 回执与重发

- 话留在待发队列里，按回执重试；结果不明的不盲目重发；客户端里能看到"未送达"。

**怎么算做成**：主人在外部平台上和她聊、让她干活，结果回到同一个会话；她不把私聊的事带进群；掉线重连后不丢消息、不重复回。

## 11. 模块 9：安全与运维（贯穿）

### 11.1 健康板汇总

- 见 6.8；每期新加的需要人看的状态都汇总到这里（记忆库、工单、群预算、适配器掉线）。

### 11.2 预算与成本

- 名额、群预算、注入预算、搜索条数等上限全部是配置项，代码里不写死数字。

### 11.3 本机身份不隔离（已知风险）

- 第一版不加锁：本机连上 daemon 的都算主人；agent 之间共用一个工具口令，能跑 shell 的 agent 在技术上能冒充主人或别的 agent。
- 健康板上标出这条；以后可以设密码、给执行器断开到 daemon 的网络、给每个 agent 发单独口令。

### 11.4 一切可查

- 工单、记忆、人设版本、成长记录都在界面上查得到来源；"这件事是谁要的、这条记忆是谁记的"永远查得到。

## 12. 产品原则

这几条贯穿所有模块，设计都不能违反。

1. **改世界的活只有两条路，都由人发起。** 要么主对话经账本开单，要么主人直接对一个 agent 说（单聊，或在群里 @ 它）。agent 之间不能互相派活，执行器不能自己接活、不能自己宣布完工。
2. **对人说话只有一个出口，话回到它来的地方。** 回复发到哪由"这句话在回应哪条消息"推出来，模型指定不了。
3. **代码不读懂话，判断归 agent，边界归主人。** 代码只做收发、记录、计时、排队、名额、按规则拦截；回不回、怎么回、要不要派活归 agent；勿扰、预算、谁能派活由主人设。
4. **活做到哪了记在账本里，不记在 agent 脑子里。**
5. **记忆是扁平的。** 只有 liwa 一个记忆库，每家 CLI 读写同一个库；CLI 自带的记忆关掉。
6. **数字生命在任何位置都保持一致，隐私靠受众。**
7. **换大脑，她还是她。** 人设和记忆在 liwa 里，大脑可以换。
8. **不操纵，不黏人，不追时长。**
9. **主人看得见、改得了。** 记忆能删；人设新版本要主人确认才生效，生效后能撤回。
10. **上面坏了，下面照常。** 没装适配器，群和双层照常；不开双层，普通对话照常；记忆库挂了，对话照常，只是没有记忆。

## 15. 不做什么

- 不做多用户、团队协作、云服务；只服务主人一个人。
- 不让 agent 之间互相派活，不让执行器自己接活或宣布完工；主对话不能自己建角色。
- 不宣称数字生命有知觉，不用内疚、挽留这类话术。
- 第一版不做身体、意与念、独处、承诺账、伙伴往来，这些在远期。
- 不改代码里的 `paseo` 名字；liwa 新加的东西尽量放在新目录或插件里，方便长期跟上游 Paseo 合并。
