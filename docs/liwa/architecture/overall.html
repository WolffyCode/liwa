总图

A1

总图：四层，一个她，多个实例

本体是她的身体和神经系统，不是脑子；思考全部经第四层开会话：第二层的实例会话和第三层的四种活。代码不读懂话的意思，也不替她做选择。

  • 所有事件进同一条经历流；所有动作走同一条管线（准入 → 记将要做 → 执行 → 记结果）。
  • 身每分钟一跳几毫秒，是共用层里唯一一直在跑的东西；只有一个身体。
  • 实例之间不直连，只经共用账本；第二层和第三层之间只走事件；第二层和第三层都用第四层。
A2

进程：一个本体加一群子进程

崩溃隔离在子进程里；写只在主线程。

A3

分层与依赖方向

两种切法：四层按「谁在做什么」分，代码依赖按「谁能调谁」分。调用只能向下；同层只调公开 API；守护横切。

四层模块
第一层 对外适配层gateway（主控台、终端、网页）、formhost 与形态适配器【V2】、世界源、senses 入站归一、outbox 出站投递
第二层 成员层共用层：self、body、memory、people、skills、roster、will、attention（含路由）、scheduler；实例：minds 的实例部分（登记、代次、待投递队列与投递器）、context、toolport
第三层 干活层tasks、workspace、minds 的活会话部分
第四层 agent CLI 集成层brains（底座自带 agent、Claude Code、Codex、通用 ACP）、procs
横向guard、actions、abilities、journal、plugins

循环

B1

身的每分钟一跳

确定性：只依赖注入的时钟、带种子的随机和按成员算的情境快照，所以能回放。只有一个身体，所有实例共用。

B2

进哪个实例

代码按结构查路由表，送进对应的实例，由她在那里判断；确定性的事代码直接办；其余只记或进每轮前缀。代码不读内容。

B3

经历流与投影

事件信封不改，正文是可删的载荷；一切状态都是投影，能删掉重算。权威是经历流加本体的待投递队列，提供方自己记的对话只是缓存。

链路

C1

链路一：主人在微信问"在干嘛"（第一版是主控台，微信是第二版）

没有想事活出场；心事由代码按结构注入；妈妈的实例没动；她自己的事的活没停，放不放下由她定。

C2

链路二：她自己冒出念头（第四版的活动，机制第一版就有）

代码只摆事实不排序，她在独处实例里选；连续的小选择由她，硬币只定隔几个问她一次；腻和冲突作为事实摆给她。

C3

链路三：想找主人（判断归她，边界归你）

代码不发消息、不按阈值放行；它只让想念涨落、在她选择后让冲动按算术消退、拼事实包、查家规。说不说由她。

C4

链路四：夜里整理

一件整理活，十件事按顺序交提案，账本校验后写入。
