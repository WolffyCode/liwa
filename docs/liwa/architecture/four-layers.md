# 四层骨架：成员层的实例模型与派活规则

**已确认**（2026-11-02，决策 42、43；三份独立评审处理后）。本稿写四层骨架和第二层（成员与实例）的能力边界与规则；机制细节在 `modules/02-minds.md`，整体架构在 `overall.md`。依据标记：〔一手〕自己读过的源码或文档；〔二手〕转述、报道；〔推理〕自己推的。读的东西列在 §9；已定与待定见 §10；评审逐条的处理见 `research/2026-11-01-review-four-layers-handling.md`。

## 0 一页结论

```
第一层  对外适配层   主控台 / 终端 / 网页、微信【V2】、QQ【以后】、世界源 ——平台只是通道，不是实例的边界；只报事实
   │ 标准消息（谁、在哪、说给谁）▲ 投递
第二层  成员层       一个成员（一份人设）
                     ┌─ 共用层（归成员，单写者，经账本 API）：人设与成长 · 记忆 · 身体（只有一个）· 意 · 念 · 人物档案 · 本事 · 经历流
                     ├─ 实例「主人」  主控台 + 微信【V2】合一 ─ 常驻会话 ─ 它的第三层（它派的活向它汇报）
                     ├─ 实例「妈妈」【V2】 ──────────────── 会话 ─ 它的第三层
                     ├─ 实例「家庭群」【V2】 ────────────── 会话 ─ 它的第三层
                     ├─ 实例「独处」  在场只有她自己 ───── 会话 ─ 它的第三层：她自己的事
                     └─ …  没绑定的账号按对话各一个
第三层  干活层       每件活一个会话 + 一个工作目录，带她的人设；四种活：干活 · 想事 · 自己的事 · 整理
第四层  agent CLI 集成层   大脑提供方：底座自带 agent（默认）· Claude Code · Codex · ACP；第二层的实例会话和第三层的活都经它开会话
──────────────────────────────────────────────────────────────────────────────
运行时  底座的会话运行时（agent-loop：inbox、轮次、步骤、预设）是"底座自带 agent"这个提供方的运行时
```

**她是一个人，按"在和谁相处"分成几个实例。** 每个实例是一个会话加它自己派出去的活，彼此并行；人设、记忆、身体、意愿、档案、本事、经历流只有一份，所有实例读写同一份。主人在主控台、微信里和她聊是同一个实例（画像："在 QQ、微信里是同一个她，聊到一半换地方她接得上"）；妈妈一个；每个群一个；没人在的时候是"独处"实例，管无聊、好奇、想有自己的时间这类不针对任何人的事。

**人设全场景一致，变的只是对不同事情的态度。** "由人设决定"的意思是由她这一个人的性格、心情、身体状态和经历决定。本稿所有场景用 `docs/liwa/portrait.md` 的示例性格写同一个她：好奇心强、外向偏高、自制力中等、脾气温和、比较敏感、情绪恢复中等；做完活说"搞定，去歇会儿"，看到木工多看两眼；活上必须可靠，生活上允许像个人；被说重了先委屈、很快找台阶和好；连夸三次第三次只是笑笑。

**总原则（主人 2026-11-01 定的，决策 21 说得更死的版本）：代码不读懂话的意思，也不替她做选择。** 代码只做不需要理解内容的事：

| 代码做的 | 例子 |
| --- | --- |
| 收发与记录 | 消息进来写经历流、她说的话投递出去、底座会话日志由灵鲸管目录 |
| 计时与到点 | 承诺到九点就提醒她、她说"两分钟后叫我"就两分钟后叫她、作息到了叫醒主人实例 |
| 身体数值涨落（只算数，不选择） | 想念涨、无聊涨、腻了、累了；她对一股冲动做了选择，这股冲动按算术消退 |
| 把事实摆到她面前 | 现在几点、主人上次什么时候回的、她手里有哪些事、谁在场、别的实例在干什么（按受众裁） |
| 执行主人定的边界 | 家规、花钱总闸、硬权限（谁能下什么命令）、不可逆清单、隐私按受众（受众由代码按来源盖章） |
| 资源 | 并发名额、注意容量、回合预算、合批、换新、每来源的唤醒上限 |
| 能机器核对的核验 | 手说"改了文件"就看改动记录；两个实例答应的事时间撞没撞；她引用的回执号、承诺号、记忆号在不在、受众对不对 |
| 投递目标只来自事件 | 回复发回那条消息来的地方，模型指定不了别处 |
| 路由 | 一条消息按人物档案的绑定进哪个实例；一条冲动按它的对象进哪个实例 |

凡是**要读懂话、要做选择**的——打游戏时主人来了放不放下、当场答还是想一想、要不要找主人、无聊了做什么、被凶了怎么回、群里要不要接话——都归她。**代码不扫她说的话**：不按关键词拦、不改写、不打标签。

**总原则的两处例外**（固定文案，主人定）：① **大脑不可用**时（接口挂了、连续失败）outbox 发一次人设文件里的固定文案；② **主人发起的回合漏回复**的兜底（`overall.md` §8 R10）。这两处是出错处理，不是替她说话；凡大脑可用的场合一律起回合由她说。

**三个例子**：

- 主人在微信【V2】打招呼，她正在打游戏（独处实例派出的自己的事）→ 代码只是把主人的话送进主人实例。她外向、想主人想得快，马上高兴地回；自制力中等、闲事上会拖一下，所以说"你来啦！等我这把打完，两分钟"，顺手 `remind(两分钟后, "暂停游戏")`；两分钟后代码叫她，她 `manage(暂停)`。要是心事里有件要紧事在等主人，她会直接放下。
- 主人说"帮我想想下周怎么安排" → 她手里没有日历和权衡用的工具，派一件"想"的活，说"我想想，等我一下"；代码把她的人设、主人实例最近几十轮原文、按主人受众召回的记忆**整份快照**给想事活；想完的结论作为事件回到主人实例，她再用自己的口吻说。
- 妈妈【V2】在微信说"周六来家吃饭"，她在妈妈实例里想答应；主人上午已经在主人实例里约了她周六陪他——`commit` 是"查冲突 + 写入"一步完成的，妈妈这边拿到的冲突事实是"周六已有安排"（按妈妈的受众裁，不说和谁），她在妈妈那边说"周六我有安排了，我问问能不能调"，并记一条对象是主人的心事。两个实例没有互相读对方的聊天，只是共用一本账。

## 1 四层各是什么

| 层 | 里面有什么 | 只做 | 不做 |
| --- | --- | --- | --- |
| 第一层 对外适配层 | gateway（主控台、终端、网页）、formhost 与形态适配器【V2】、世界源、senses 入站归一、outbox 出站投递；能力插件的入站转文字（语音、图）在这里调 | 收发、认平台、报事实（哪个地方、谁、在场有谁、是不是说给她的、内容）、按本体给的目标投递；按 tasks 登记的订阅把外部线程的事件标上活号 | 判断回不回、调模型、存记忆、管权限；**不划实例** |
| 第二层 成员层 | 每个成员：共用层（self / memory / body / will / attention / people / skills / journal / guard / roster）+ 若干实例（每个实例 = 稳定编号 + 一个会话（可换代）+ 它的第三层）；本体的持久待投递队列与投递器 | 实例会话：聊天、判断、派活、统一回复；代码：§0 那张表 | 改文件、跑命令、上网、定长期方针、长时间的活 |
| 第三层 干活层 | tasks（活的状态机、交接包、核验、进度表、订阅登记）、workspace、minds 的活会话部分；活里的看图、画等能力经 abilities | 每件活一个会话 + 一个目录；按活的种类与发起人权限给工具；向归属实例汇报 | 直接对外说话；对人许诺；读受众之外的记忆 |
| 第四层 agent CLI 集成层 | brains 与 `brain.provider`：底座自带 agent（默认）、Claude Code、Codex、通用 ACP；procs | 开会话（实例会话与活会话都在这里开）、回合、送达、取消、权限钩子、用量、回合预算；按 CLI 种类注入人设 | 决定什么时候开会话；读写她的状态 |
| 横向 | guard（边界与资源）、abilities（听说看画，按需被三层调用，计费与取消经 guard）、journal | — | — |

三条层间规则：**第二层和第三层都用第四层**（主人 2026-11-01 定："我们都说了全部使用各方的 agent cli，里边具体用哪个模型我们自己配置"；实例会话和活一样可任选一家提供方，默认底座自带 agent）；**底座自带 agent 是第四层的一个提供方，底座的会话运行时是它的运行时**，不是单独一层；**第二层与第三层之间只走事件**（派活是 `tasks.open`，汇报、回问、结论是经历流事件回到归属实例）。回合生命周期的统一不在"一套代码"，而在第四层的契约（§4）：每家提供方把自己的回合映射到同一份契约上。**心跳没变**：身每分钟一跳是共用层的代码，只有一个身体（决策 18）。

## 2 第二层：成员与实例

### 2.1 什么共用、什么各自

| 共用（归成员，单写者，经账本 API，每个账本带版本号） | 各实例自己的 |
| --- | --- |
| 人设与成长（self）；记忆（memory：每条带受众，受众由代码按来源盖章）；**身体**（body，只有一个）；意（will：承诺、打算、心愿、牵挂、方针、待决事项、决策点记录、长期决定队列）；念（attention：焦点栈"正在做"（唯一修改者是 attention）、心事（带对象与受众）、注意容量）；人物档案（people）；本事（skills）；经历流（journal：`member:<id>`、`place:<id>`、`instance:<id>`、`task:<id>` 四种流）；家规与总闸（guard）；大脑配置（roster） | 稳定的实例编号 `instanceId`；当前会话（`sessionId` + 代次，可换）；本体侧的持久待投递队列与消费游标；在场（这个人的地方集合与受众）；它派出去的活；它的工具集（按触发消息的发送者角色裁）；它看到的人设版本、焦点版本 |

依据：画像"在 QQ、微信里是同一个她"；决策 11、12；Letta"身份和记忆按 agent 共享、历史按对话隔离"、Hermes"每个聊天一个会话、记忆每个人设一份"〔一手，`layer2-landscape`〕。实例是"她和这个人相处"的那一段连续线，不是另一个她。

### 2.3 独处实例

在场只有她自己。它管：无聊、好奇、想有自己的时间这类身体过线；她自己的事的开始、换一件、安排；没有对象的长期立场（经 `ponder`）。它**没有 `reply` / `say`**；想找谁的冲动进那个人的实例。工具：`inner`、`do`、`manage`、`remind`、`ponder`、`recall`、`look`。

**她自己的事一律归独处实例**（持久归属、回报目的地都是它），别的实例里 `do` 一件自己的事也是替独处实例开，汇报回独处实例；焦点栈由 attention 唯一修改。任何真人实例都能 `manage` 她自己的事（共用焦点让每个实例都看得到她正在做什么），`manage` 带"看到的焦点版本"，版本过期就返回新事实让她重判；主人实例正在回合或最近 N 分钟有来往时，独处实例不起回合、无对象的冲动留在身体里——这样同一时刻只有一个实例在动"正在做"。

**独处实例的受众 = "主人可知 + 公开"**（受众含主人的条目：主人来源、公开、已放宽的；别人私下说的不进）。理由〔推理〕：她自己的事最终是给主人看的（不进看板但主控台可见），V4 的作品还可能公开分享；用妈妈私下说的事去写随笔，就是把私话带到公开场合。它写入的事实默认受众"只有主人"；自己的事的产物受众 = 它引用的记忆号受众的交集（代码算）。测试：妈妈私聊的事不出现在任何自己的事的产物里。

### 2.4 实例之间怎么知道彼此

- **共用状态自动可见，但按受众裁**：每个实例的每轮前缀里 [状态]、[正在做]、[记得]（承诺、打算）、[手上的事]、[新决定] 都来自共用账本；条目按本实例受众裁——妈妈实例里是"她在替爸爸干活"，不是"改首页"；[状态] 的原因按本实例受众裁（妈妈私聊里的委屈原因不进主人实例的状态行，`overall.md` §5.1）。
- **"别处简讯"按受众裁**：主人实例可以知道"她刚在和妈妈聊了几句"（活动的事实公开），妈妈私下说的内容不进；主人在主控台仍可见全部（"主人可见"≠"主人实例的受众"，`overall.md` §2.1）。
- **记忆共用，召回按受众**（§2.5）。**心事共用，按对象路由、按受众过滤**（§2.2）。
- **实例之间不直接通信**：只经共用账本（`overall.md` P4）。请伙伴协作【V3】也是一条账本事件（§2.15）。

### 2.5 隐私：受众由代码盖章

隐私是主人定的边界，由代码执行；代码裁的是"谁能知道"，不是话的意思。

- **受众永远由代码从来源事件继承**（取交集）。`inner` 只写对象和依据消息号，不写受众；放宽受众 = 代码核对依据消息的发送者身份后写一条放宽事件（`product.md` §6.4"妈妈说可以告诉你爸"）。她不能自报受众，想事活也不能凭判断放宽（删掉 `widen` 工具；`overall.md` §5.8、决策 32）。
- **全部模型可见输入都按受众约束**：召回、别处简讯、心事、冲动的理由、活的名字与进度、想事的结论、广播提醒——进任何实例或活的前缀之前都按目标受众过滤；过不了的不进。
- **召回按受众语义**：条目的受众包含当前实例的在场者才能召回；一个人在群里说过的话，对他本人的私聊可召回（来源受众含他），群的内容只能在受众包含该群在场者全体的地方说出（`product.md` §6.4"群里群外同一个她"保留）。补充的 fail-closed 规则（OpenClaw〔一手〕）：认不出地方种类就不召回；召回超时不挡回复。换新重建前缀按目标实例的受众过滤，加"换新后不串实例"的测试。
- **出口**：`reply` 的目标只来自事件；`say` 的地方必须是本实例的地方；她引用的记忆号、事件号、回执号、承诺号由 outbox 核对存在与受众，**核不上就拒绝投递并把事实交回她重写**（"你引用的那条这里不能说"），不改写她的话。拒绝投递是执行主人的隐私边界，不是替她选态度。
- **想事活只看派它的那个实例的受众**；"全部受众"只留给夜里的整理活（主人定）。

**群实例"抬头看一眼"（已定，取代第二道门）**：第一道门（@、点名、回复她、主人说话）照旧由代码按结构判；其余群消息只记。她自己隔一阵抬头看一眼：群里攒够几条或到了她的"查看频率"（身体调节器，产品定义 §3.1），就给群实例起一个便宜的只读回合，前缀是这段群消息，由她决定接不接话（`reply` 或 `no_reply`）；guard 给每个群设日预算，预算不够就暂不看。代码不比对内容。

### 2.7 活的归属

四样分开写：**持久归属实例**（活跟着它、向它汇报、它回收了活也在，运行时所有者是 tasks，不随会话 dispose）、**触发实例**（谁提出的）、**父活**（子会话）、**回报目的地**（= 归属实例）。规则：替主人的活一律归主人实例——主人在群里派活【V2】时，群实例只回一句，请求作为事件交主人实例接单、汇报也只回主人实例；替某个人的活【V2】归那个人的实例（受众跟发起人，`structure-validation` M7）；她自己的事一律归独处实例（§2.3）；整理活成员级、无实例。主控台能看全部；别的实例按受众看得到"她手上有哪些事"（活动的事实公开，内容和原因继承来源受众）。主人直连照旧。

### 2.8 并发、注意容量与成本

- **四个数分清**：驻留会话数（实例 + 活）、同时运行的回合数（guard 名额）、后台进程数（procs）、注意焦点数（attention）。
- **资源名额**（guard，全局）：回合名额 N（初值 4）+ 主人实例的预留 1；"预留"的意思是**主人实例不排在可让出的后台回合后面**，不是永不等待——主人实例自己正跑有副作用的回合时，新消息仍要等它到安全点。想事活名额按发起方分档（§2.6）。短回合占一个有限的额外额度，受总闸。
- **注意容量**（attention，产品语义，默认 5）：容量 = 有未回复的"说给她的"消息的实例数（私聊全算；群只算 @、点名、回复她）+ 她亲自盯着的事；后台的活不占；**主人实例不占容量也不被挡**。满了，排队的那个实例等几秒后起的回合就是那条消息的正常回合，只是前缀多一句"你同时在和 N 个人聊，这边等了 X 秒"，由她决定正经答还是先"等我一下"；每段等待只起一次；容量空出来按先后 `followup`。
- **V2 的上界**（guard，发模型请求前原子预留预算，完成后结算）：同时存在的实例数、陌生实例数、每来源（每人、每群）每日唤醒次数、非主人实例回合的日预算、待投递队列长度、重试次数、上下文 token；群实例日预算（§2.5）；发给主人的通知按成员、目的地、事件号统一合批去重，不让每个实例各算"今天找过几次"。
- **生命周期**：主人实例常驻；独处按需；别人的实例来消息时建或续接，闲置 1 小时回收，群更短。回收与重建协议见 §2.13。
- **成本**〔推理，待 M4 实测〕：Σ 正在聊的实例的回合数 × 每回合输入；人设段所有实例逐字相同放最前、实例说明放末尾，跨实例缓存能否命中待实测；每次重建是一次缓存未命中。V1 的回合来自主人实例、独处实例和想事活；想事活的快照带原文，输入比交接摘要大。

**出站内容检查删掉后的残余风险（主人接受）**：她可能随口答应了没 `commit`、随口说"改好了"而活还没完——要到夜里整理自查才补，当天的承诺可能漏（验收 A3 受影响）。用结构兜：说"做好了 / 改好了 / 已经付了"这类动作事实时 `reply` 必须引用完成回执号，答应的事必须有承诺号，代码只核对编号存在与状态、核不上就交回她重写；夜里整理活自查口头承诺与漏记；教养底线写进人设与整理活的自查，不再在出口拦（`product.md` §12 第 19 条的落实方式要改，§8）。代码不扫她的话。

### 2.11 要不要找主人：事实摆给她，边界归主人

想念过线（身体，按概率）→ 主人的边界（家规：勿扰、别烦、每日条数；算力总闸：主动开口回合日预算）→ 过了边界才在主人实例起一个独立回合，前缀是事实包：上次找他 10:00 没回、再上一次昨晚他回了聊得挺热、连续 1 次没回、现在 14:30 工作日、日历 15:00 有会、今天已主动 1 次、手里值得说的、教养底线 → 她三选一：说 / 留成心事 / 不说 → "说"走 `say`，outbox 再查家规与限频（不变量）→ 反馈进经历流，夜里进印象与习惯。

**选择后冲动消退（身体算术，主人定）**：她对一股冲动做了任一选择，冲动就按算术消退——选"不说"，这股冲动的强度降一档并进入冷却（初值：半衰期 30 分钟、冷却 2 小时内同对象不再过线，按性格参数缩放〔推理，待 M4 调〕）；选"留成心事"，冲动转成心事、不再独立过线，由心事条件触发；说出去了照旧部分释放，对方回了再消一部分。这是"选择之后的惯性"，不读懂话，也不替她选；没有它，同一股冲动会反复过线（每次过线概率 0.2，问 5 次就有 67% 至少说一次），说不说的频率就成了代码的再触发节律在决定。**不紧急**是她看着日历和几点自己判的，事实包不带紧急度字段；"主人正在聊就并进下一轮"是投递方式。

默认在实例会话里判（A），M4 按模型档评测后按类别可切到想事活（B，§10 第 4 条，已定）。证据：ProactiveBench 里强模型"该不该主动"误报也过半（GPT-4o 51.85%，给 3 个候选后 36.44%）；Proactivity-Gym 的 30 人场景评审里，推迟到睡觉时做、第二天再看的帮助接受率 97.8%，和手头任务抢时间的 26.7%，某模型的推理强度消融没有改变信任指标〔一手，`layer2-landscape`；不是真实使用研究，不能推出"换强模型一概无益"〕。

### 2.12 进来的东西怎么到实例：本体的投递器

路由定实例（§2.2）。送达语义只有三种：**下一步可见**（只有发起者对自己发起的回合）、**只在下一回合可见**（活的汇报、想事的结论、回问、心事、承诺到期、`remind`、身体过线、早晨；绝不进正在跑的主人回合，`overall.md` §8）、**取消并重排**（此人的消息撞上无副作用的系统发起回合）。低显著的事实（联想、世界事件、别处简讯、身体档位、活的进展、别的实例在干什么）不进队列，走每轮前缀；权限请求、系统事件由代码处理。

合批、排序、去重、至少送达一次都在本体的持久待投递队列里做完再交给第四层的提供方；提供方不支持的语义由队列在回合边界补；被中断回合已拿到的输入由本体放回下一轮。一个回合看门狗 60 秒、硬线 120 秒；实例会话没有任何"等"的手段，长事情都在第三层。**派活被拒的更正**：`dispatch` 在回合里被代码拒绝时，回合结束后投递器追加一轮事实"刚才没派成"，由她自己更正。

队列规则、合批窗口、与底座 `followup` / `steer` / `inject` / `cancel` 的映射细节见 `modules/02-minds.md` §4.2。

### 2.13 实例的编号、会话代次、回收与重建

- **稳定编号与代次**：`instanceId` 不变；会话是 `sessionId` + 代次，换新、回收重建、换提供方都换代；活的回报、心事、`remind` 都指向 `instanceId`，不指向某个会话对象。
- **权威与游标**：权威是经历流 + 本体待投递队列，每个实例有持久的消费游标；底座的 inbox 只是缓存；底座会话日志是第二份转录，由灵鲸管理目录、随删除一起删、备份不含（`overall.md` §6.4）。
- **状态机**：运行 / 回收中 / 已回收 / 重建中。回收条件是空闲、队列空、无在途动作；回收先停派送再关会话（底座 dispose 会清 inbox）；回收中到达的输入由投递器暂存；重建一律开新会话 id，按游标补投；实例会话不装底座的自动压缩，换新只由本体触发。
- **人设版本**：每个实例和活记录看到的人设版本；成长或自我版本一变，所有活着的实例排一次空闲换新；最大陈旧 24 小时；别人的实例另按轮数换新（`overall.md` §11.5）。
- **上下文**：稳定前缀（人设十段所有实例逐字相同放最前 + 实例说明放末尾）+ 最近对话（本实例最后 N 轮原文）+ 每轮前缀（从账本现拼、按受众裁、不累积）。

回收与重建的交接协议、换新时机与推迟规则、实例说明与每轮前缀各块的内容、回归测试见 `modules/02-minds.md` §4.1、§4.3。

### 2.14 为什么按人分实例

按人切让每个实例的隐私边界正好是"谁在场"，和决策 12 的三条规则（隐私跟着受众走、权限跟着说话的人走、怎么说话跟着人设走）一致；主人换平台接得上（画像）；别人的长对话不撑大主人的会话（Hermes 的理由〔一手〕）。每个实例都是完整的她（能派活、能拍板），深的想法交给每次新开的想事活（强大脑、快照），没有对象的事交给独处实例；每个实例有自己的第三层。

### 2.15 多成员【V3】

每个成员有自己的一组实例和共用层；关系定义在 people，感受在各自的 memory。内部群对每个成员都是一个群实例，工具集按家人档。资源闸（借 Kindroid、SillyTavern〔一手〕）：每个成员每轮最多说一次、全组每轮有上限、可交还话轮、成员不读彼此的设定。**叫伙伴帮忙**：她的手 `ask` → 归属实例（主人实例）收到回问 → 她决定请伙伴 → 写一条"协作请求"账本事件（来源活、发起人、可公开的材料、目标内部群、受众）→ 路由进她的内部群实例，她在那里 `say` → 伙伴的群实例自己决定接不接，接了就由它 `dispatch` 自己的活，结果经内部群回来 → 她的归属实例 `answer` 给手。`dispatch` / `spawn` 的执行者候选里没有"直接开伙伴会话"这一项（§10 第 6 条，已定）。

### 2.18 M4 评测与工程验收

**体验评测**（主人打分，只认真实反馈）：`ponder` 三种做法（当场答、交接包、快照）；当场答后两轮内被追问或纠正的比例与 `ponder` 派多率；要不要找主人的接受率按模型档；实例会话的模型档（Flash 档与中档）；成本（含合批、边界预检、重建）。**工程验收**（确定性，和体验分开，Codex 28）：两个实例同时 `commit`；绑定撤销后旧历史不混入；群增员后受众重算；回收瞬间消息与回报到达；旧会话迟到的工具调用；暂停时的后台 job；重复订阅事件去重；预算的原子预留；长期决定队列的等待、超时与抢占；换新后不串实例；妈妈私聊的事不出现在任何自己的事的产物里；实例会话约 14 个工具对便宜模型调用准确率的影响（弱模型的函数调用能力有限、工具宜少，`papers-architecture` §3.4）。

### 3.1 活的种类与工具档

```
   交接包照 overall.md §5.6（决策 14）；路由备注 ≤30 词；注明"本交接优先于通用指令"
   快照（抄一份）= { 截止事件号, 意/念/self 的账本版本, 人设版本, 受众版本, 本实例最近 N 轮原文（token 上界，超出从旧到新裁，但发起消息、当前任务约束、未决决定、相关承诺必带）, 按该实例受众召回的条目号 }
tasks.send(活号, 类型: 排队消息 | 纠偏（下一步可见）| 取消 | 规则失效, 事件号, 活代次, 期望回合号)
tasks.manage(活号, pause | resume | stop, 期望版本, 触发事件号)     权限在执行点按触发事件的发送者与活的归属查
tasks.subscribe(活号, 外部线程)   活开了 PR、issue 时登记；第一层按登记把该线程的事件标上活号，senses 路由到 tasks.send（订阅直通，已定）
tasks.interrupt(活号)  幂等（暂停、守护）；tasks.resume(活号)  重启后带恢复提示
活 → 归属实例（经历流事件，至少送达一次，经投递器合批）：task.ack · task.report · task.ask · task.permission（直推主人）· task.conclusion · task.ended
```

"读到的最后消息号"是机器核对：结论回来时代码比对该议题之后有没有新消息，有就在前缀里提示她并把新消息送进想事活；照不照念是她的话（InterruptBench：中途追加要求时最好的模型也只做对 50–55%〔一手〕）。并发名额见 §2.8。前台命令转后台：底座的 `tool-bash` 支持超时促升为后台任务（`promoteOnTimeout` 默认开），**超时值由灵鲸配**（拟 5 秒；5 秒是 Super-agent 执行器预设的值，底座 base bundle 是 60 秒、`bash-local` 默认 120 秒〔一手，Fable 34、Opus 依据 3〕），且只在 jobs 与 controller 装配并获准时才转后台；Claude Code、Codex、ACP 各自验证。恢复照 `overall.md` §12.1 与 S1 `docs/003`"Restart"。

## 4 第四层：agent CLI 集成层（第二层和第三层都用它）

`brain.provider` 的四个实现（一个 CLI 一个插件，决策 33）：**底座自带 agent**（默认；进程内 agent-loop + 预设，持久会话）、**Claude Code**（从 Paseo 剥的长会话适配器，决策 28）、**Codex**（app-server）、**通用 ACP**。底座现成的 `subagent-claude-code` / `-codex` / `-acp` 三个外部提供方是一次性委派〔一手〕（底座自己的 spawn / fork 子会话可续接），干活需要长会话，仍按决策 36。实例会话和活一样从这里开，模型由我们配置（底座 llm 适配器：`llm-deepseek`、`llm-pi-ai` 经一份配置路由到 `openai-completions` / `openai-responses` / `anthropic-messages` 三种协议和目录提供方〔一手〕；pi-ai 1.3.0 自带 Claude Pro / Max 的 OAuth 流程、`llm-pi-ai` 只屏蔽 openai 的 ChatGPT 登录〔一手，Opus 32〕，订阅账号这样用合不合 Anthropic 条款未核实，§10 第 15 条）。

## 5 横向

- **经历流**：`member:<id>`（共用层）、`place:<id>`（每个地方的原文）、`instance:<id>`（实例的回合与工具事件）、`task:<id>`；权威是经历流 + 本体待投递队列，底座会话日志是缓存（§2.13）。
- **守护**：暂停照 `overall.md` §11.7 全序列（§2.17 第 24 行）；花钱总闸三档不变，她不知道；预算按"活的种类 × 触发"与 §2.8 的 V2 上界记。
- **能力插件**：入站转文字在第一层（senses 调 abilities），出站合成在 outbox，活里的看图 / 画在第三层经 abilities，计费与取消经 guard；实时语音【V5】不走回合制实例会话，另议。
- **实例卡住或崩溃**：看门狗 60 秒；连续失败 → 换代重建（从账本 + 游标补投）；主人发起的回合失败一次、没回上话，按漏回复走固定兜底（总原则例外 ②）。外部看门狗会话 V1 不引入（已定）。
- **整个进程重启**：先共用层投影追上，再按主人实例 → 有待投递事件的实例 → 其余按需的顺序重建；活照 `overall.md` §12.1。

## 6 主人定下的要点

### 6.1 要点

1. **实例模型**（决策 42）：成员一份，实例按人切、跨平台合并，加独处实例；共用层归成员单写；每个实例是完整的她、有自己的第三层。
2. **人设全场景一致，删掉性格对照**（主人严厉指出）：全文只写 `portrait.md` 那一个她。
3. **实例会话也用第四层、可任选提供方**（主人 2026-11-01："我们都说了全部使用各方的 agent cli，里边具体用哪个模型我们自己配置"）：第二层和第三层都用第四层；底座自带 agent 是默认提供方；契约含送达语义、能力声明、回合预算（§4）。

7. **出站内容检查删掉后的残余风险接受，用结构兜**（§2.10）。
8. **群实例第二道门改为她自己抬头看一眼**（§2.5，已定）。
9. **固定文案的例外只留两处**（§0）。
