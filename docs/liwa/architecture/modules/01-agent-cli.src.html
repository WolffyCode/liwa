1 四层总览：第四层在哪

本页与 01-agent-cli.md 对齐到 2026-11-05：第 1、2 步已实现，其余图示为目标机制；G1–G4 均待补，不能把“看门狗”标注当已实现。依据与待定以 Markdown 正文为准。

她按"在和谁相处"分成几个实例（第二层），每件活一个会话加一个目录（第三层），两层都不直接碰任何 agent 程序：开会话、送达、取消、权限、用量全经第四层。第四层对外只有一个 ctx.brains 服务和一份 brain.provider 契约；四个提供方都是独立进程的 CLI，每个会话一个进程。自建默认 agent 的提供方叫 deepseek（它是底座自带 agent 下沉成的 CLI），和 claude、codex、acp 并列。

2 第四层内部结构

本体进程里：minds 决定什么时候开会话，brains 负责开和管，提供方插件是各家 CLI 的客户端，toolport 把内核工具做成一个带会话令牌的 MCP 端点，guard 管准入与预算，subprocess 管进程。进程外：三种 CLI。内核工具不管走哪家 CLI，最后都回到 toolport.invoke(令牌, 工具, 参数)。

3 三个提供方各自的接法

三家在形态上完全一致：每会话一个独立进程、本体只有客户端、同一份契约、同一枚令牌、同一个成员配置目录。差别只在协议、人设注入字段和各家能力。
