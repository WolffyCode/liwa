1 四层总览：第四层在哪

她按"在和谁相处"分成几个实例（第二层），每件活一个会话加一个目录（第三层），两层都不直接碰任何 agent 程序：开会话、送达、取消、权限、用量全经第四层。第四层对外只有一个 ctx.brains 服务和一份 brain.provider 契约；四个提供方都是独立进程的 CLI，每个会话一个进程。自建默认 agent 的提供方叫 deepseek（它是底座自带 agent 下沉成的 CLI），和 claude、codex、acp 并列。

图 1　四层骨架。蓝色是第四层（本体进程里的客户端），橙色是它拉起的独立进程。第二层和第三层都只用 ctx.brains，谁都不直接碰 agent 程序。

三条层间规则（four-layers.md §1）：第二层和第三层都用第四层；回合生命周期的统一不在"一套代码"，而在契约——每家提供方把自己的回合映射到同一份契约；第二层与第三层之间只走事件。

2 第四层内部结构

本体进程里：minds 决定什么时候开会话，brains 负责开和管，提供方插件是各家 CLI 的客户端，toolport 把内核工具做成一个带会话令牌的 MCP 端点，guard 管准入与预算，subprocess 管进程。进程外：三种 CLI。内核工具不管走哪家 CLI，最后都回到 toolport.invoke(令牌, 工具, 参数)。

图 2　第四层的内部结构。实线是控制与会话流，虚线是内核工具的回程（MCP）。brains 不读账本、不读懂内容，只开会话、管进程、报事实与用量。

3 三个提供方各自的接法

三家在形态上完全一致：每会话一个独立进程、本体只有客户端、同一份契约、同一枚令牌、同一个成员配置目录。差别只在协议、人设注入字段和各家能力。

3.1 自建默认 agent：提供方 deepseek，进程 liwa --profile deepseek

图 3　自建默认 agent 的接法。每个会话一个进程（主人定），协议是 ACP v1 加三个 _liwa/* 扩展方法；人设十段作为该进程的 personaPrefix 注入一次，进程里的子会话自动继承；会话说明、每轮前缀按会话给。名字跟提供方走：bundle deepseek-app、profile deepseek，和模型适配器 llm-deepseek 是两层东西。

契约动作ACP 落点（都是我们自己的两端）
createSessionbrains 生成会话目录与 patch → ctx.subprocess.spawn → initialize（30 秒）→ session/new{ cwd, mcpServers:[toolport HTTP 端点 + 令牌], _meta.liwa{ mindKind, owner, notes, version, limits, concludeOn, model, childPolicy } } → 服务端 setup 选预设、注册会话说明段、挂 agent/pre-step、包 concludesTurn
startTurn / deliver(next_turn)session/prompt（一会话一次一个，阻塞到回合结束，返回里带 _meta.liwa.usage）；流式经 session/update
deliver(next_step)扩展方法 _liwa/steer{ sessionId, prompt } → 底座 agent.steer；没有在途提示词时回 unavailable，本体退化为下一回合
cancelsession/cancel（_meta.liwa.keepQueue 为 true 时服务端用 agent.cancel(cause, { keepInbox: true })），连带子会话
权限 / 续接 / 换模型 / 关闭标准 session/request_permission（子会话的带 _meta.liwa.childId）/ 回收 = 关进程保留目录，续接 = 同一目录重拉进程 + session/resume / session/set_config_option(model) / session/close（释放后代）→ 进程退出

图 4　Claude Code 的接法。Paseo 原值 settingSources: ['user','project','local'] 必须改；"user" 层就是灵鲸生成的配置目录，主人的 ~/.claude 不读。原生子 agent 在干活的活里放开：灵鲸只从 SDK 的任务协议观察，用量记在父活上，取消时逐个 stopTask。

3.3 Codex：app-server

图 5　Codex 的接法。V1 只给干活与查资料的活：read-only 沙箱仍能读文件、跑只读命令，实例会话收不干净原生工具。干活与查资料按默认读仓库 AGENTS.md，其余会话 project_doc_max_bytes = 0。

3.4 配置隔离：CLI 只读灵鲸管理的那一份

图 6　配置隔离。三个 CLI 的 home 变量都指进成员目录；子进程环境先由 @liwa/subprocess 剥掉凭据与 LIWA_*，再显式注入该 CLI 需要的变量名。

4 关键时序

九条链路。参与者统一：minds（02）、brains（01）、提供方插件、CLI 子进程、toolport、guard、gateway / 主人。

4.1 开会话

图 7　开会话。三家同一条链：先登记进程再拉起，握手有时限；配置目录每次开会话前覆盖生成；每个会话一个进程。

4.2 一个回合：送达、流式事件、工具经 MCP、收尾

图 8　一个回合。回复是工具调用（R1），收尾靠契约的 concludeOn；每家的落点不同但 minds 看到的是同一个 turn.completed。

4.3 中途插话：steer（下一步可见）

图 9　steer。只有发起者对自己发起的回合能"下一步可见"；提供方不支持的由本体队列在回合边界补上。

4.4 取消与看门狗

图 10　取消。原则来自 Paseo：中断幂等、停不干净就失败即关闭；"撤回未读走的 steer"是适配器自己的义务。

4.5 权限请求：一路到主人再返回

图 11　权限。第一版主人可见的选项是 allow_once / allow_session / deny_once / cancel；子 agent 的请求同样直推主人。

4.6 子 agent 路 ①：提供方自己的子 agent（默认；只在干活与查资料的活里）

图 12　路①。CLI 自己开、自己调度、自己回报，灵鲸不干预，只观察（三家都翻成 child.started / ended）、记录（brain_child、task:<id> 流）、计入父活预算；权限一律直推主人；子 agent 不登记成第三层的活。

图 13　跨 CLI 子活。这是 Paseo create_agent + notifyOnFinish 的形状，但把"agent 管 agent"换成"活管子活"：有归属实例、受众、交接包与核验。

4.8 崩溃后续接与换代

图 14　崩溃与续接。权威是经历流 + 本体队列，提供方转录只是缓存；续接省缓存，重建保正确。

4.9 实例从 deepseek 换到 claude

图 15　换提供方。人设、工具、队列都在本体，换代只换 impl；改回来走同一条路。

5 第二层的实例与第三层的活怎么经第四层开会话

两边走同一条链：minds 从 roster 取绑定 → toolport 发令牌 → brains 开会话。差别在 SessionConfig 的取值。

图 16　两层共用一条链。活的汇报不经第四层：它们是 toolport 的工具调用，变成 task:<id> 流的事件再投回归属实例。

7 包划分与进程模型

图 18　包与进程。四种子进程都是每会话一个，全部经 ctx.subprocess.spawn：进程组一起杀、环境剥凭据、宽限期内先礼后兵；拉起前写 brain_process，握手 30 秒；孤儿只清"已登记、父进程已不在、指纹对得上"的。

8 第一版范围与验收

m0

@liwa/brain + brain-acp（SDK 1.4）+ brain-deepseek + deepseek-app；实例预设与 reply / no_reply / inner；_liwa/steer；契约测试与回环编解码；liwa brain list|probe。

V1.0

brain-claude 全验证（实例、想事、整理、干活）；brain-codex 干活与查资料；五个预设；子 agent 路①（三家的观察）与路②；配置目录生成；备用提供方切换；Paseo 代码与 NOTICE 进仓。

V1.1

Codex 当实例会话；dynamicTools；Claude 订阅额度窗口；预热空闲 deepseek 进程；离线预审；别家 ACP CLI 验证；主控台的子 agent 面板。
#怎么算接通（真实 CLI，密钥从钥匙串读）
A1brain-deepseek：本体为主人实例拉起真 liwa --profile deepseek（LIWA_HOME 在该会话目录、~/.liwa 无新文件）→ liwa chat 一句话 → session/new 带 _meta.liwa → 事件 brain.session.opened → turn.started → tool.called(reply, inner 同批) → turn.completed{concludedBy: reply, usage 非空, inferences = 1}；第 4 步被 agent/pre-step 拒；主人追加一句经 _liwa/steer 在下一步可见；杀本体重启 → 清孤儿 → 同一目录重拉 → session/resume 成功、身份探针答对。
A2brain-claude：真 claude（≥ 2.1.292）开一件想事活（自定义 systemPrompt、settingSources ['user']、CLAUDE_CONFIG_DIR 在成员目录、tools []），conclude 经 MCP 到 toolport；maxTurns=3 第 4 次推理不发生；~/.claude/projects 无新文件；kill -9 本体后 claude 进程被下次启动清掉；steer 在下一步可见。
A3brain-codex：真 codex app-server 开一件干活活（developerInstructions、CODEX_HOME 在成员目录、workspace-write 限 worktree、读到仓库 AGENTS.md）；report 经 MCP 到 toolport；写 worktree 外触发 requestApproval → permission.request → 拒绝后回合继续；turn/steer 次步可见；tokenUsage 进 brain_usage。
A4子 agent：deepseek 上的干活活调 subagent 开子会话、子结束结果回到父的下一步、brain_child 与用量归父；Claude 上的干活活用 Agent 工具开一个子 agent → child.started / ended 出现在 task:<id> 流、用量记在父活、cancel(owner) 时子 agent 被 stopTask；同一活调 spawn(codex, 交接包) 开子活、子活 report 回到父活、父活结束级联停掉子活；子 agent 的一次权限请求直推主人而不是父。
A5切换：roster 把主人实例从 deepseek 改成 claude → 空闲换代 → 上下文从账本重建 → 身份探针通过 → 再改回。
A6契约：四个提供方过同一套契约测试（假 CLI 回放）与回环编解码；Meta 声明为 false 的语义恒回 unsupported。
先派一个探针任务实测（已定；文档 §10 的十一项）：_liwa/steer 的透传与延迟；session/prompt 阻塞期间 session/cancel 的时序；SDK PostToolBatch 能否收尾；Claude 自动压缩的开关；Codex project_doc_max_bytes、dynamicTools、自动压缩；turn/interrupt 作收尾时 Codex 的状态；agent/pre-step 拒步后 turn/end 是否正常落；每会话一个 deepseek 进程的内存、启动时间与想事活的延迟；子会话权限是否经父会话上报；Claude 原生子 agent 的用量口径；Codex 子线程的用量通知是否经同一连接到达。

9 已定的点与新待定

#点定了什么（主人 2026-11-02 两次答复）
1自建默认 agent 的形态第一版就是独立进程的 CLI，liwa --profile deepseek，和 Claude Code、Codex 同形
2进程粒度每个会话一个进程
3提供方名自建默认 agent 叫 deepseek（包 brain-deepseek、bundle deepseek-app、profile deepseek）；claude、codex 不变；通用 ACP 叫 acp
4ACP 扩展三个 _liwa/* 方法（steer、usage、children）+ _meta.liwa 字段
5子任务走 Paseo 的方式：默认用提供方自己的子 agent 机制，需要时经 spawn 子活调别家 CLI；不开放 CLI 路
6Claude / Codex 的原生子 agent干活与查资料的活里放开；灵鲸只观察、记录、计入父活预算；不带她的人设
7底座 subagent 系列留 seam + 进程内 spawn / fork + 两个工具；删四个外部委派与 OAR
8外部 CLI 的配置全局一律不读；每成员一份灵鲸生成、CLI 只读的目录
9被干活仓库的 CLAUDE.md / AGENTS.md干活与查资料的活读，灵鲸规矩优先；其余会话不读
10Codex 二进制PATH 上的 codex；底座随包的 0.153.4 随 subagent-codex 删
11Paseo 代码的改法原地改 + 每包 NOTICE 改动清单
12brain-acpV1 做，迁时升到 SDK 1.4
13内核工具到 CLIV1 toolport HTTP MCP，三家一个端点
14待实测项先派一个探针任务跑完十一项，结果决定 Meta 的真值
新冒出来的待定点（主人过目即可，设计里先按建议写）：① profile 名随提供方叫 deepseek，和模型适配器 llm-deepseek 同名异物，觉得会混就改回 brain；② 想事·立场类的活要不要也放开子 agent（本稿只给干活与查资料的活）；③ 原生子 agent 不带她的人设，是决策 5"执行者只能是她"的一个边界例外，建议记进 handoff 的决策表；④ 每会话一个 deepseek 进程给想事活带来的启动延迟，探针测出数字后再定要不要 V1.1 的预热。
