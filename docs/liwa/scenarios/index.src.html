名词

名词是什么
她一个成员，只有一份人设、记忆和身体。所有地方、所有活里都是同一个她
四层门（第一层，对外适配层）· 她（第二层，成员层）· 手（第三层，干活层）· 脑（第四层，大脑提供方）。见结构图
实例她和某个人相处的那段连续线，不是另一个她。按人分，不按平台分：你在主控台、终端、网页、微信【V2】跟她聊，都是同一个实例。每个实例 = 一个实例会话 + 它派出去的活
实例会话实例里常驻的那个会话：聊天、判断、派活、统一回复。手里没有改文件、跑命令、上网的工具，这些只能派活
主人实例你的那个实例。常驻、不回收；你在哪个平台都是完整权限；不占注意容量，也不排队
独处实例只有她自己的时候。按需起、闲置回收；管无聊、好奇、想有自己的时间，她自己的事都归它。它不对人说话：想找谁，就进那个人的实例
某人实例【V2】一个你绑定过的真人一个（如妈妈），他在哪个平台找她都进这一个
群实例【V2】一个群一个（如家庭群）
陌生实例【V2】没绑定的账号，按对话各一个；你确认绑定后，只改之后进哪个实例，以前的聊天不搬
共用层所有实例读写同一份：人设与成长、记忆、身体、意（承诺、打算、心愿、方针）、念（正在做、心事、注意容量）、人物档案、本事、经历流。实例之间不直接说话，只经这一本账
四种活（第三层）每件活一个会话 + 一个工作目录，带她的人设，向派它的实例汇报。干活：替某个人干一件事，查资料也是一件只读的活；想事：定长期的事（立场类）或替人出主意（出主意类），强大脑、每次新开，开活时抄一份派它的实例的快照；她自己的事：看资料、写东西、逛、玩，一律归独处实例；整理：空闲和夜里整理记忆、写日记、提成长、自查
第四层大脑提供方：底座自带 agent（默认）、Claude Code、Codex、ACP。实例会话和活都经它开会话，里面用哪个模型我们自己配
本体不思考的那部分代码：保管共用层，按人物档案和对象把东西送进实例，计时，让身体涨落，把事实摆给她，执行你定的边界（家规、权限、受众、总闸），核对编号。它不读懂话的意思，也不替她做选择
本体的投递器每个实例一条持久的待投递队列：合批、排序、去重，再按三种送达交给实例会话（规则四）
适配层（第一层）每种平台一个：主控台和网页、微信【V2】、QQ【以后】。处理平台细节，交给本体标准消息；只报事实，不划实例、不做判断
伙伴【V3】另一个成员（如批图专家），有自己的一组实例和共用层；她经内部群请伙伴，伙伴自己决定接不接

角色一览

谁什么时候动能做不能做默认大脑
主人实例你在任何地方说话；对象是你的冲动、心事、承诺到期；她给自己定的时到点；你派的活汇报；早晨聊天、记感受和心事、记承诺、派活、想事、开始或管她自己的事、给自己定时、回答活的回问、想起记忆、查看活改文件、跑命令、上网（只能派活）；定方针、改关系、花钱（只能派想事）；自己定谁能知道快而便宜，配备用
独处实例没有对象的身体过线（无聊、好奇、想有自己的时间）；作息边界；她自己的事做完记感受和心事、开始或管她自己的事、给自己定时、想事、派查资料、想起记忆、查看回复、对人说话（想找谁就进那个人的实例）快而便宜
别人的实例【V2】那个人说话；群里叫到她或她抬头看一眼；对象是那个人的冲动、心事、承诺按对方的角色给：聊天、记心事；家人能让她记承诺；群里有人约她可以想事；报告可疑的人替你干活（交给主人实例接单）；用别人私下说的事快而便宜
干活实例派活CLI 原生工具（限本工作目录）、开工回执、汇报、回问、开子会话、记录对外说话、对人许诺、问你（只能回问派它的实例）Claude Code / Codex 等
想事实例派：长期的事（立场类）、替人出主意（出主意类）立场类：定方针、推进心愿、关系与花钱类、派活、交结论；出主意类：只读、交结论记承诺（只写「建议承诺」）、放宽受众、对人说话强
她自己的事实例开始（一律归独处实例）只读、写草稿、记录、汇报（可带「下一件」）跑命令、对外说话便宜
整理白天空闲、夜里只交提案：记忆、关系、成长、日记、打算、自查任何对外动作便宜，夜里可换强

每件活都是她：带她的人设，读写同一份共用层。本体一直在，但不思考，见规则开头的总原则。

调度规则

总原则：代码不读懂话的意思，也不替她做选择

代码做的（不用读懂话）例子
收发与记录消息进来先写经历流；她说的话投递出去
计时与到点承诺到九点就叫她；她说「两分钟后叫我」就两分钟后叫她；作息到了叫醒主人实例
身体涨落（只算数）想念涨、无聊涨、腻了、累了；她对一股冲动做了选择，这股冲动按算术消退
把事实摆到她面前几点了、你上次什么时候回的、她手里有哪些事、别的实例在干什么（按受众裁）；只摆，不排序
执行你定的边界家规、花钱总闸、谁能让她做什么、隐私按受众（谁能知道由代码按来源盖章）
资源同时跑几个回合、注意容量、每回合的预算
能机器核对的她说「改好了」要引用完成回执号；两个实例答应的时间撞没撞
路由消息按人物档案进哪个实例；冲动按对象进哪个实例

要读懂话、要做选择的都归她：你来了放不放下手里的事、当场答还是想一想、要不要找你、无聊了做什么、群里接不接话。代码不扫她说的话。只有两处例外由代码替她说一句固定的话：大脑不可用时；你发的话她漏了回复时。

规则一：适配层和本体怎么分工

flowchart TD
  P["任何平台：主控台、网页、微信 V2、以后的 QQ……"] --> A["这个平台的适配层"]
  A --> A1["处理平台细节：收发、私聊还是群、有没有 @ 她或叫她名字、群里有谁、平台限制"]
  A1 --> STD["交给本体一条标准消息：哪个地方 · 谁发的（账号）· 在场有谁 · 是不是说给她的 · 内容"]
  STD --> K["本体：不认平台，只认人、地方、受众；查人物档案定进哪个实例"]
  K --> OUT["要发出去时：本体告诉适配层「在这个地方说这些」"]
  OUT --> A2["适配层换成平台格式发出去，回报发没发出去"]
适配层负责（只报事实）本体负责（不读懂话）
连上平台、收发消息这条消息进哪个实例
认出私聊还是群、有没有 @ 她、回复了她、叫了她的名字，统一成「是不是说给她的」这个账号是谁（只认你绑定的）
告诉本体地方里有哪些账号在场的人能知道什么（受众）
把她的话换成平台格式：表情、语音条、图片这个人能让她做什么（权限）
声明平台限制，比如每天最多主动发几条什么时候送进实例（三种送达）

适配层不划实例、不判断回不回、不调模型、不存记忆、不管权限。
