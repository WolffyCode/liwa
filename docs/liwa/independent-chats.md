# 独立对话

打开 **新聊天**，选模型，发出第一条消息即可开始对话。工作区目录可选：选了目录，就是在这个项目里开的对话（原来的新建工作区）；不选目录，就是独立对话，不属于任何项目。

## 入口与侧边栏

- 侧边栏顶部的 **新聊天**、⌘N（Ctrl+N）、命令中心的同名命令、「项目」和「对话」两个分组标题上的按钮，打开的都是同一个表单，每次都是一份新草稿，不带目录，也不沿用上次打开的工作区。项目行上的 **+** 仍然会带上这个项目。
- 表单里的目录选择器第一项是「不关联工作区」。选了目录后再清空，草稿保留；在选择器里添加新目录，添加完回到原表单，草稿保留，新目录直接选中。
- 侧边栏分「置顶」「项目」「对话」三组，按这个顺序排列。三组各自折叠，折叠状态按设备记住；折叠只收起行和空状态，分组标题上的按钮照常可用。项目筛选只作用于项目，不会藏起对话。
- 「对话」列出独立对话，按最后一次发消息的时间排序。置顶的对话只出现在「置顶」，不会重复出现在「对话」。
- 对话行支持重新打开、重命名、置顶、归档。离开页面、关闭 agent 标签页都不会删除对话；归档会停止它的 agent，把它从活跃列表移走，之后可以在「历史」里找到。归档当前打开的对话后，回到不带目录的新聊天表单。

## 运行时归属

agent 需要工作目录，所以 daemon 给每个独立对话在所选主机的 `$PASEO_HOME/chats/<workspaceId>` 下分配一个私有目录（权限 0700），以 `directory` 类型的工作区登记；所有独立对话共用一个名为 Chats 的后台项目。这个目录和后台项目只是运行时的承载：

- 是不是独立对话只看持久化的 `purpose: "chat"`（工作区和项目记录上都有），不看名字、路径或项目 key。
- 后台项目不出现在任何项目选择器、侧边栏项目分组、设置里的项目列表，`paseo project ls` 也不列它。
- 对话行不显示目录和 Git 信息。
- Git 对账不会把独立对话的目录当成 checkout，即使 `$PASEO_HOME` 恰好在某个 Git 仓库里。
- 普通的「打开目录 / 新建工作区」不能借用后台项目；同一路径的项目和对话互相冲突时返回 `project_purpose_conflict`。

## 创建与恢复

创建走已有的可恢复创建流程（`workspace_create_request` 加幂等 key）：

- 目录分配失败（`chat_directory_unavailable`）发生在登记之前，同一次操作可以直接重试；客户端遇到这类「工作区之前就被拒绝」的失败，会换一个新的操作 ID，所以改了消息再发也不会冲突。
- 工作区一旦就绪，客户端就跳进这个对话；agent 启动失败时，在对话里的草稿标签上重试，与项目工作区一致。结果不确定的操作保持原 ID，不会自动重放。
- agent 的 `cwd` 以对话目录为基准解析，客户端传 `"."`；解析到目录之外会被拒绝。

## 版本边界

- 协议新增 `source: { kind: "chat" }`、工作区和项目描述里的可选字段 `purpose`、`server_info.features.independentChats`，都只追加、可选，旧客户端照常解析。
- 不选目录时，客户端先看 `features.independentChats`，主机不支持就提示更新主机；SDK 也会在发请求前拒绝。选了目录，走的是原来的工作区创建契约。
- 兼容开关标了 `COMPAT(independentChats)`，2027-05-15 之后可以删除。

## 和 Helm 实现的差别

需求来自 Helm（Paseo 0.11 分支）的同名功能，这里按 0.16 的结构重做，没有搬代码。

- 0.16 在 `workspace_ready` 时就跳进工作区，agent 失败在工作区里重试，所以去掉了 Helm 里「agent 启动失败就归档半成品」的做法。
- 「历史」入口保持上游默认显示。
- 后台项目在 `workspace-structure` 这一个边界排除，所有项目消费者（选择器、侧边栏、设置、命令中心、定时任务）自动生效，不在各处分别过滤。
- 暂不支持从 CLI 或 MCP 创建独立对话。
