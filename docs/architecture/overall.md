## 0. 一页总览

### 0.1 核心思路

**本体是她的身体和神经系统，不是她的脑子。** 她的一切状态都在本体的账本里：身（身体数值）、念（注意、心事）、意（承诺、打算、心愿、牵挂、方针、冲动）、忆（记忆、自我）、能（本事）、人物档案。思考交给一次次**用脑**，一共四种：

- **在场**：她在某个地方应答。每个地方（或合并后的一组地方）一个常驻会话，便宜的大脑，来回不超过两秒。
- **慢想**：权衡、拍板、规划、自省。要做决定时醒，每次新开会话，强大脑，处理完保留几分钟就收工。
- **手**：干一件活，或做她自己的一件事。每件一个会话，Claude 或 Codex。
- **睡眠**：空闲和夜里的整理。每次作业一个会话，便宜的大脑。

每次用脑的上下文都从账本**现取现拼**，用完写回。CLI 自己记的对话只是续接用的缓存。

**代码只做三件事，模型做两件事。** 代码：让身体涨落（每分钟一跳，不调模型）；把事实摆到她面前（经历、心事、承诺、关系、别处发生的事、几点了、他回没回）；守边界（受众、权限、家规、花钱总闸、可撤销）。模型：评价（这件事对我意味着什么）和判断（想不想、合不合适、说什么、做什么）。代码从不替她决定要不要找主人、要不要分享、这个视频有没有意思〔决策 21〕。

**两条结构性的保证。** 所有动作走同一条管线（准入、记"将要做"、执行、记结果），所以隐私、花钱、兜底各只有一个拦截点；所有事件进同一条经历流，所以记忆、成长、看板、花费、验收指标都是它的投影，任何状态都能重算。

**换来的东西。** 换大脑、换 CLI、重启、会话崩溃都不改变"她是谁"，因为她不住在任何会话里；成本跟着"起了多少次用脑"走，而起不起由身体和显著性决定、有预算；她的每件自主的事都有一条可查的理由。

（依据：决策 4、11–13、19–21；产品定义 §2、§3；`papers-architecture` §2.1 CoALA（记忆在模型外、循环由代码驱动）、§4；`companion-architectures` §8；心理 §4.1（评价推导与状态更新的分工是计算情绪模型的通行拆法）；游戏 §4.2.2（规则打底、模型定调））

### 0.3 十二条架构原则

| # | 原则 | 含义 | 依据 |
| --- | --- | --- | --- |
| P1 | 灵魂在本体，会话可重建 | 她的一切状态由本体持有；会话只是工作记忆，随时可以丢掉、从经历流重建 | 决策 4、11；`papers-architecture` §2.1；`companion-architectures` §9 坑 9（Letta #2666 新会话即白板）；`paseo-architecture` §5 坑 1 |
| P2 | 经历流是唯一事实来源 | 记忆、成长、看板、花费、验收指标都是投影，除被主人删掉正文的载荷外都能重算；CLI 转录只是缓存 | `client-backend` §3.2；产品定义 §3.2；`papers-architecture` §6 F |
| P3 | 用脑提出动作，本体执行动作 | 说话、派活、记承诺、写记忆只能经内核工具；准入、受众检查、写日志都在执行处 | `companion-architectures` §2.2 Q10（麦麦外接 ACP Planner）、§3.2 Q3（Letta："限制放在使用处"）；`papers-architecture` §2.4、§4 |
| P4 | 一条经历、多处在场 | 所有在场、所有手、慢想、睡眠都读写同一个她；会话之间不直连，只经账本和经历流 | 决策 11–13；产品定义 §3；`papers-architecture` §2.2（全局工作空间）、§6 D |
| P5 | 代码先判断，模型后到场 | 起不起用脑、叫不叫醒慢想先由代码按显著性和容量判定；模型可以安静返回 | `papers-architecture` §5、§7.1；`companion-architectures` §8 共识 2 |
| P6 | 对外只有显式动作，目标随事件走 | 模型的原始输出一律算内部；对外发言必须是带明确收件人的动作，收件人来自触发它的事件 | `openclaw-architecture` §8.1.3 第 1、2 条 |
| P7 | 每样东西只有一个主人，模块之间只走 API | 每张表、每个对象只有一个写入模块；不叠兼容层，改在根上 | 用户全局原则；`client-backend` §3.1 |
| P8 | 故障只影响它自己 | 一个 CLI、一个适配器、一个本地模型出事，只影响那一次用脑或那一个形态 | `openclaw-architecture` §8.1.3 第 5 条；`companion-architectures` §2.2 Q7 |
| P9 | 判断归她，边界归你，身体归代码 | 想不想、合不合适、说什么、做什么由模型在用脑里判断；主人只设边界（家规、总闸、收回）；代码只让身体涨落、摆事实、守边界 | 决策 21；产品定义 §2 第 6 条 |
| P10 | 规则打底，模型定调 | 模型交结构化评价（好坏、重要度、类型、原因）；强度、时长、叠加、回落、需求、调节器由代码按性格算；常见事件有默认表 | 产品定义 §3.1；心理 §4.1、§4.2；游戏 §4.2.2 |
| P11 | 行为来自意愿，每件事带理由 | 她做的每件自主的事都来自一条冲动或承诺，带一条她自己写的理由，记进经历流；时钟只触发确定的事（承诺到期、作息边界、整理），不替她"想做点什么" | 产品定义 §2 第 6 条、§3.5；决策 18 |
| P12 | 可观察、可回放、可验收 | 身体循环用带种子的随机和可替换的时钟；经历流可回放；模型调用可录制重放；验收指标从日志算 | 产品定义 §10；游戏 §4.3；产品调研 §4.3；〔推理〕 |

| --- | --- | --- | --- |
| 自我连续 | 换形态、换会话、换大脑、重启之后，还是同一个她，记得刚才的事 | 状态全在本体；任何用脑的上下文都能从经历流重建；每次用脑由本体显式注入她的人设，不靠继承；主人各形态的私聊合成一个在场 | 产品定义 §2；决策 11；`openclaw-architecture` §5 坑 4；`paseo-architecture` §5 坑 2 |
| 隐私按受众 | 谁告诉她的、在什么场合说的，决定这件事能在哪说出口 | 每条经历、每条记忆带来源和受众；在场的上下文里只有受众都能知道的东西；跨场合发言在目标场合的上下文里生成 | 产品定义 §9；`companion-architectures` §7.1、§7.2 |
| 自主但可兜底 | 开了自主的成员做事不用事前审批，但每件事都可查、可撤销、可叫停 | 每个动作经同一条行动管线；写文件前打快照，删除进回收站；一键暂停和花钱总闸拦在每次用脑、每个动作之前 | 产品定义 §9；`papers-architecture` §6 I |
| 成本可控 | 成员再多、时间再长，花费也有上限，而且花在主人能感到的地方 | 不触发就不起用脑；触发由代码判定；人设放在模型缓存能命中的位置；会话按需换新、闲置回收 | `papers-architecture` §5.2 第 5 条；`openclaw-architecture` §8.1.2（#61690、#20894）；`companion-architectures` §2.2 Q4 |
| 大脑可换 | 每种用脑的大脑能换，主大脑出错时自动换备用 | 统一的大脑契约；人设映射在适配器里；换大脑等于"用新大脑开新会话，从经历流重建上下文"，前后过回归 | 决策 2、4、6；`paseo-architecture` §3；产品调研 §4.2 第 19 条 |
| 可扩展 | 接新平台、加新能力不改本体 | 插件各有稳定契约；形态插件只做感知和行动，不带认知 | 产品定义 §8；决策 7、19；`companion-architectures` §9 坑 14 |
| 可恢复 | 本体重启、CLI 崩溃、模型接口失败、升级之后，不丢事、不重复做事 | 先记"将要做"再做；结果不明标出来、不自动重放；通知至少送达一次；孤儿进程按登记清理；迁移先备份 | `openclaw-architecture` §8.1.3 第 3、5 条；`companion-architectures` §7.6；`paseo-architecture` §2.2 Q5 |
| 出错也像人 | 出错时她用自己的口吻表达，不弹报错，也不刷屏 | 错误文案只从一个模块出，按场合限频；原始错误永远不进对外渠道 | 产品定义 §9；`companion-architectures` §3.2 Q7；`openclaw-architecture` §8.1.2（#116348） |
| 复杂度受控 | 一个人能维护，模块边界不随时间腐烂 | 分层只向下依赖；每张表一个主人；不写兼容垫片，协议和前端同版本发布 | 用户全局原则；`openclaw-architecture` §5 坑 11；`paseo-architecture` §5 坑 12；`companion-architectures` §3.2 Q7 |
| 可迁移 | 一键备份；换电脑时她能完整搬过去 | 真相只有经历流加大对象目录，备份它们就是备份她；CLI 的数据只是缓存 | 产品定义 §9；`client-backend` §3.2 |
| 像活的，而且可验收 | 行为、状态、记忆三条连续；有来由的起伏；主人看得见、读得懂、说得出为什么 | 身体循环和显著性都在代码里、确定性可回放；每件自主的事带理由；主控台每条可查"为什么"；验收脚本读经历流 | 产品定义 §0、§10；游戏 §2.5（可信由观众判定） |
| 判断在她，边界在主人 | 不用计时器和阈值替她决定找不找人、分享不分享 | 代码把事实注入用脑而不是自己决定；家规是可选配置，在执行处生效 | 决策 21 |
| 便宜地一直在 | 没人找她时她也在过日子，但不烧钱 | 身每分钟一跳几毫秒；决策点有预算；在场常驻但闲置回收；睡眠按批 | 产品定义 §3.1、§7.1；成本纪律参考产品调研 §3 Q8（AI Town 空闲零调用、dafeiyu 硬预算）；心理 §4.2.10 |

### 1.3 非目标

- **多主人、多租户。** 一个本体就是一个主人的信任边界（`openclaw-architecture` §2.2 Q8；Letta 退役通用多租户服务端，`companion-architectures` §9 坑 11）。
- **多主机、云托管、中继。** 只跑在主人自己的机器上，远程访问走 Tailscale（产品定义 §1.4；`paseo-architecture` §3）。
- **公开的插件或技能市场。** OpenClaw 的技能市场被大规模投毒（`openclaw-architecture` §2.2 Q10、§5 坑 12）。
- **旧协议兼容。** 前端由本体托管、同版本发布（`client-backend` §2、§3.3）。
- **通用 agent 平台。** 系统里没有无人设的普通 agent（决策 5）。
- **模型一直在想。** 她的思考是一段一段的，两次用脑之间只有身体和意愿在变（产品定义 §0 诚实的上限）。

经历流（唯一事实来源）
  每条事件：流 · 序号 · 类型 · 执行者 · 因果 · 来源信息{地方, 受众, 来源人, 可信度} · 载荷号

三条关系：

1. **地方和在场是两样东西。** 地方是外界的地址，在场是她在那里的出现。会话换新、换大脑都不改地方；主人在几个端的私聊是几个地方，合成一个在场（依据：决策 19；产品定义 §8.1；`openclaw-architecture` §7 B（session 与 conversationRef 分开））。
2. **人物档案和她对人的记忆分开。** 谁是谁、账号归谁、关系和角色，在 people，只有主人能写，每条消息都确定地查；她对一个人的了解、印象、亲近，在 memory，从相处里长出来、会淡忘、可更正（依据：决策 20）。
3. **慢想不是一个角色，是她在想事情。** 它没有常驻会话、没有收件箱；它醒来读的是念和意里的小表（心事、承诺、打算、手上的事的进度表），处理完写回，靠心事接上下一次（依据：产品定义 §3.4；`structure-validation` M8；Anthropic 长任务交接）。

| 主人配置面（性格参数、家规、预算、作息、大脑、并发）的变更事件与导出 | gateway 的主人接口 → 各所有者 | 只有主人 | 备份与搬家 |
| CLI 进程登记 | procs | 只有 procs | — |

四条"只能由一处算"的规则：地方键和受众只由 people 算（麦麦在 AGENTS.md 里明文规定业务模块不得自己算 `session_id`，`companion-architectures` §2.2 Q2）；投递目标只由 outbox 解析（防 OpenClaw 那种"会话记着最近的回复目标、被别人改写"的串话，§8）；情绪词表只有一份（body 持有，abilities 共用）；她现在在做什么只由 attention 按焦点栈和手写，不从她的话里抽（产品定义 §3.7 言行回查；产品调研 §2.3 PIANO 的幻觉级联）。

两处容易混的分工：**注意容量**（同时顾几件事、排队、"等我一下"）是产品语义，归 attention；**资源并发上限**（CLI 进程数、模型并发）归 guard，attention 起回合时调 `guard.admit`，两个数可以不同。**家规**是主人的边界，归 guard，attention 预检、outbox 执行都只读它，她的意愿账本里没有它。

## 3. 系统分层与进程模型

### 3.1 进程模型

```
launchd（KeepAlive：进程退出就拉起）
└── 本体：一个 Node 24 进程
      ├── 主线程：事件循环 + 唯一的 SQLite 写入者 + 作业定时器（身的每分钟一跳是其中一个系统作业）
      ├── worker_threads：只读的重查询（全文检索、投影重建、联想的激活打分）
      ├── CLI 子进程 ×N：每个活着的用脑会话一个
      │     claude（经 Claude Agent SDK）｜ codex app-server（stdio）｜ 通用 ACP CLI（stdio）
      │     └── 主人给 CLI 配的第三方 MCP 服务：由 CLI 自己拉起，不经本体
      ├── 形态适配器子进程 ×N【V2 起】：QQ、微信、B 站……每个一个进程
      ├── 世界源【V1 后期】：天气、节日、日历，按能力插件接入；线上的在进程内，本地的在进程外
      └── 本地能力服务【按需】：SenseVoice 等原生模型；Python 模型服务

数据目录：liwa.db（经历流 + 载荷 + 内联投影）· derived.db（异步投影，可重建）
          · blobs/ · members/<id>/cli-home/ · minds/<id>/ · workspaces/ · trash/ · backups/
客户端：命令行 `liwa`（V1.0）/ 浏览器 / Mac 客户端（Electron 薄壳，V1.1）/ 手机浏览器【V2】/ 桌宠【V5】/ 原生手机端【V5】经 HTTPS、WebSocket 连本体（默认只听本机回环；远程经 Tailscale Serve）
```

术语：**进程**是操作系统里独立运行的程序，一个崩了不会带崩别的；**子进程**由本体启动、由本体回收；**事件循环**是 Node 用一个线程依次处理所有请求的机制，被同步的重活堵住时整个本体都会卡；**worker_threads** 是 Node 的后台线程；**MCP** 是让 CLI 调用外部工具的标准协议，本体的"内核工具"经它（或 CLI 支持时经原生工具注入）提供给 CLI。

**为什么是"一个进程 + 子进程"。** 单主人、单机，模块化单体足够：OpenClaw 是一个 Gateway 进程，Letta Code 是一个 Node 进程，Paseo 的所有子系统也在同一个 worker 进程里（`openclaw-architecture` §2.2 Q1；`companion-architectures` §6 A；`paseo-architecture` §2.2 Q1；`client-backend` §3.1）。不要 Paseo 的 supervisor + worker 两级进程，拉起崩溃进程交给 launchd（`paseo-architecture` §3）。不把认知放进界面进程：AIRI 的 agent 跑在渲染进程里，要靠多窗口选主，无界面常驻至今没做成（`companion-architectures` §9 坑 13）。不拆成多个服务：单人维护成本高，Letta 的多租户服务端已经整个退役（`companion-architectures` §9 坑 11）。写只在主线程、只有一个写入者；重查询放 worker_threads，node:sqlite 的接口全是同步的，上游 Paseo 近几个版本一直在修"堵事件循环"（`client-backend` §2、§3.1）。

**身的每分钟一跳是 scheduler 里的一个系统作业**（同一套调度，不另设定时器，决策 18），主线程里几毫秒的函数，不调模型（§4.1）。**回放模式**分三档（§14）：L0 身与念的纯代码回放（假时钟 + 种子 + 经历流里记录的评价、冲动、消息到达事件，不调模型，确定性，免费）；L1 代码回归（再加上记录的工具调用，前缀不变时重放）；L2 真跑模型。这要求身的循环和显著性打分只依赖注入的时钟和随机源，联想打分要么在 tick 里同步算，要么在下一拍边界确定地应用，不能在 worker 线程里异步落地（P12）〔推理〕。

**时钟**有两种：挂钟（带主人配置的时区，处理夏令时、mac 休眠后的跳变）用于作息、昼夜、周末、"去年今天"；单调时钟用于时长、半衰期、看门狗。可注入的时钟要同时覆盖这两种〔推理〕。

### 3.2 分层与依赖方向

```
接入层    gateway（客户端）                     toolport（内核工具端点，给 CLI 会话用）
编排层    senses(感)  attention(念)  will(意)  scheduler(时钟)  tasks(手上的事)  outbox(嘴)
运行层    minds(四种用脑的会话)  context(上下文装配)  actions(行动管线)
账本层    body(身)  self(自我)  memory(忆)  people(人物档案)  skills(能)  roster(成员)
插件宿主  plugins（槽位注册与加载；记忆引擎、成长引擎、关系模型等以后在这里换）
资源层    brains  procs  formhost  abilities  workspace  notify
守护      guard（运行层、outbox、abilities 在每次用脑、每个动作之前调用它）
基础层    journal（经历流、投影运行器、载荷与大对象）
```

每层是什么：接入层是外界怎么跟本体说话（主人的客户端和 CLI 会话对本体来说都是"外面"）；编排层是认知循环里由代码做的判断（感知、注意、意愿、时钟、活的状态、对外说给谁）；运行层把用脑跑起来（含这次用脑给什么上下文）、把动作执行掉；账本层是她的状态，每个模块管一块，**只管"谁能写、写什么才算数"**；插件宿主托管可替换的"怎么算"（记忆怎么抽、成长怎么提、关系怎么变），第一版全部是内置实现；资源层是外部资源（CLI、进程、外部平台、模型服务、文件、主人的设备）；守护横切所有动作；基础层是经历流。

五条依赖规则（依据：`client-backend` §3.1"依赖单向，各自拥有自己的表"；`paseo-architecture` §2.2 Q1、§5 坑 12；`companion-architectures` §3.2 Q7"Letta 的分层由 CI 强制，源文件不超过 1000 行"；`plugin-architecture` D1、D3）：

1. 调用只能向下。同层之间只能调公开 API，而且不能成环。
2. 向上传信息只有两条路：持久的事走经历流事件订阅（例如 tasks 写下"设计已提交"，attention 订阅后处理，tasks 不需要认识 attention）；不需要持久的走进程内信号（例如客户端在线状态）。
3. 每个模块只读写自己的表；别的模块的数据只能经它的查询 API 或它发出的事件拿到。
4. 账本层只经插件宿主的槽位注册表解析契约接口，不认识具体引擎：账本把输入推给引擎（给某个在场召回时才按受众裁），引擎向账本交提案，账本按规则校验并复核返回的编号；引擎可以读任何账本的查询 API，但不 import 账本的实现、不直接追加经历流、不自己算受众、不绕过主人鉴权。这是单点写的工程纪律，不是对插件的信任控制：插件都是一方代码（决策 32；`modules/00-plugin-kernel.md` §7）。
5. 账本层不向上读编排层。body 的每分钟一跳需要的"情境"（闲着没有、当前活动与它的意义、投入度、最近是不是在做被派的活）由编排层每分钟压成一份**情境快照**传给 `body.tick()`，body 不认识 attention、tasks。
6. 依赖方向和单文件行数上限由检查工具强制，不靠自觉。

### 3.4 CLI 子进程的监管与回收

| 步骤 | 做法 | 依据 |

| 握手 | 有时限；Codex app-server 没有版本协商，只按大版本判断兼容 | `openclaw-architecture` §2.2 Q1、§5 坑 10 |
| 运行中 | 适配器必须把"CLI 在两个回合之间死掉"也报成回合失败；回合看门狗：一段时间没有任何事件就中断 | `paseo-architecture` §2.2 Q5、§5 坑 7、坑 9；`openclaw-architecture` §2.2 Q5（60 分钟看门狗） |
| 中断 | 幂等；中断被拒或超时就"失败即关闭"：不再给这个会话派新回合 | `paseo-architecture` §2.2 Q4 |
| 闲置回收 | 空闲超过阈值，且适配器的 `canStopRuntime()` 不否决（后台 shell 还在跑就否决）→ 关进程，保留记录，下次有输入再续接 | `paseo-architecture` §2.2 Q9 |

| 换大脑 | **备用大脑离线预审**：每周、以及模型版本变化时，后台用不对外的会话跑灵鲸版访谈题和语气样本，自动指标（同题三遍一致率、底色问答一致率、语气样本盲评）过线、主人在主控台确认后，这个大脑才进自动切换名单；自动切换只在已过审的名单里切，所以回归总是前置的。主人手动换大脑同样先过回归。服务商同名模型的静默更新也靠这个周期回归发现。切换后她在下一轮说"我今天脑子有点不一样" | 产品调研 §4.2 第 19 条、§2.14；产品定义 §9 第 13 条、§12 第 10 条 |

### 3.5 插件和外部依赖放进程内还是进程外

OpenClaw 的教训：单进程里一个外部依赖就能拖垮全局。一个 stdio MCP 服务 30 秒没完成握手，清理路径抛出未处理的异常，整个 Gateway 退出，所有渠道一起掉线（#144911）；工具子进程不回收，僵尸进程越积越多（#97616）；网关内存两三天涨到 15.5 GB（#91588）（`openclaw-architecture` §8.1.2、§8.1.3 第 5 条）。放进程外的代价是多一层 IPC（进程之间传消息的通道）的序列化和生命周期管理；好处是崩溃、内存泄漏都关在那一个进程里。规则：**一方写的核心路径放进程内；依赖第三方协议栈或原生代码的放进程外；不是仓库里的代码默认进程外。**

| 组件 | 放哪 | 理由 | 依据 |
| --- | --- | --- | --- |
| 大脑适配器的代码 | 进程内（CLI 本身是子进程） | 一方代码，要低延迟拿事件；CLI 崩溃天然隔离在子进程里 | `paseo-architecture` §2.2 Q1、Q7 |
| 第三方 MCP 服务 | 由 CLI 自己拉起，不经本体 | 失败只影响那一次用脑，避开 #144911 | `paseo-architecture` §2.2 Q7；`openclaw-architecture` §8.1.1 |
| 内核工具端点 | 进程内 | 它就是本体的行动入口 | `paseo-architecture` §2.2 Q7 |
| 主控台、网页接入 | 进程内（gateway） | 一方代码，核心路径 | `client-backend` §3.1 |
| 外部平台的形态适配器 | 每个一个子进程 | 依赖 NapCat 这类第三方协议栈，长连接、内存泄漏、崩溃风险都高；崩了只让那一个形态离线 | `companion-architectures` §2.2 Q7（麦麦插件 Runner 子进程 + 健康检查 + 最大重启次数 + 熔断）、§4.2 Q7；`paseo-architecture` §2.2 Q7 |
| 线上能力实现、线上世界源 | 进程内 | 只是 HTTP 调用，超时和取消信号就能管住 | `ability-plugins` §3.1 |
| 本地能力模型、本地世界源 | 子进程或 Python 服务 | sherpa-onnx-node 这类原生扩展一旦段错误会带崩本体；重模型吃内存 | 决策 3；`ability-plugins` §3.5 |
| 记忆引擎、成长引擎、关系模型 | 第一版内置、进程内；以后非仓库代码进程外 | `plugin-architecture` D1、D7 | — |
| 本地嵌入模型（Qwen3-Embedding-0.6B） | 第一版进程内（node-llama-cpp），是本规则"原生代码放进程外"的例外；不稳就退回 Python 子服务，成为进程外插件的第一个真用户 | V1.0 只有几千条记忆、调用频度低，先换简单；原生扩展段错误的风险由退路兜底 | 决策 30、31；`modules/00-plugin-kernel.md` §10 |
| 重查询 | worker_threads | 不堵事件循环 | `client-backend` §3.1 |
| 她自己写的工具【V4】 | 单独的隔离通道 | 不可信代码，不能走"完全信任"的插件通道 | `openclaw-architecture` §5 坑 12；`paseo-architecture` §5 坑 13 |

为了让同一个形态适配器既能在子进程里跑、也能在测试时直接加载，适配器开发包定义成一套**消息协议**，不定义成进程内的函数接口；子进程由 formhost 托管：健康检查、重启次数上限、熔断（连续失败后暂时不再重试）（`companion-architectures` §2.2 Q7 maim_message；`openclaw-architecture` §2.2 Q7）。

### 3.6 并发与注意容量

- **用脑之间默认全部并行**；达到并发上限才排队（决策 15）。
- **注意容量是产品里的"同时顾几件事"**：按"未了结的焦点"计（正在等她回复的地方 + 她亲自盯着的事），默认 5，归 attention；满了新消息排队，排队超过几秒由本体用她的口吻发固定的"等我一下"，不调模型。第一版只有主人一个在场，几乎不会满，所以容量在第一版后期才落地。**资源并发上限**是另一个数，归 guard：CLI 进程数和模型并发决定，手也算在内；attention 起回合时调 `guard.admit`。主人的在场有预留名额，永远不排在后台回合后面（产品定义 §3.3；`openclaw-architecture` §2.2 Q2（全局 lane 有并发上限，超出排队）；`papers-architecture` §6 A（AIOS 的全局并发上限和队列）；`early-findings` §4（mac mini 是 M4、24 GB））。
- 两处"一个一个来"，和并发上限无关：同一个会话同一时刻只跑一个回合，新消息合进当前回合或下一轮（`openclaw-architecture` §2.2 Q2 会话控制器邮箱；`paseo-architecture` §2.2 Q2）；睡眠用脑同一时刻只跑一个，主人在用时让路（它们改的是同一份记忆和成长，并行会写冲突；`companion-architectures` §7.4）。
- 子会话的派生深度有上限（`openclaw-architecture` §2.2 Q3 子 agent 深度默认 5）。
- 默认值按实测定（§17 第 21 项）。"模型服务商有并发限制"是推理，要实测确认。

### 3.7 客户端怎么连

本体同时托管 React 前端和 WebSocket 接口，前后端同版本发布。默认只听本机回环地址；远程访问经 Tailscale Serve 提供 HTTPS，并要求令牌。Electron 以后作为薄壳直接加载本体地址（第一版客户端形态见 §18 P3）。协议和同步见 §10，鉴权见 §11（`client-backend` §3.3、§3.7；`paseo-architecture` §2.2 Q8）。

## 4. 生命循环与事件流

### 4.1 一直在跑的三样东西

| 东西 | 节奏 | 做什么 | 花不花钱 | 依据 |
| --- | --- | --- | --- | --- |
| 身的脉搏 `body.tick(时钟, 随机源, 情境快照)`，scheduler 的系统作业 | 每分钟 | 精力按两过程（醒着累、睡着恢复、叠加昼夜）；每个在乎的人的联结（想念）按亲近涨；认可、自主慢变；情绪事件按类型半衰期衰减、被提起再点燃；心情两维向基线回弹加扰动加情绪推动（回弹力就是"按速率追目标"的速率，只有这一个模型）；无聊按情境快照里的"闲着 / 做着没意义的事"涨；耐受按天回落；冲动衰减、被线索再点燃；需求过线按危险率生成或加强冲动（每步概率 = 1 − e^(−λ·Δt)，改 tick 频率不改行为）；"等回音"的不应期（她主动对某人说过话、对方还没回时，对这个人的"找他"冲动不起回合，期间的分享念头只记成"等他来了说"的心事；不应期随连续没回的次数拉长，对方一开口就清零）；主导情绪 + 档位（带迟滞）；调节器（唤醒、细致度、专注、查看频率、心情词）每分钟算出来不存 | 免费 | 产品定义 §3.1、§3.5；心理 §4.2.3；游戏 §4.2.1、§4.2.5 |
| 时钟作业 `scheduler` | 到点 | 承诺到期、作息边界（醒来：生成今日状态，并写一条低显著的线索事件"新的一天"进念；睡觉：冻结心情、起夜间整理）、空闲增量条件、每周整理、补跑 | 免费（触发的用脑另算） | §7.1；产品定义 §3.8 |
| 感的入口 `senses` | 事件到达 | 归一、认人、算受众、写经历流、交给念 | 免费 | §4.2 ① |

**情境快照**由 attention 每分钟压给 body：闲着没有、当前活动及其意义（和心愿、打算、在乎的人的关联，代码可知）、投入度、最近是不是在做被派的活。body 不读上层的表（§3.2 第 5 条）。

**身里的惯性规则**（全是代码，§2.3 里由 body 持有）：同一原因的同类情绪替换不叠加；不同原因的同类有上限地叠加；同一个人每天的总影响有上限（主人也不例外，哄她有用但边际递减）；习惯化（同来源同类正面刺激连续出现，增量递减，隔几天恢复）；连续坏事有保护，负面之后要有明确的恢复事件；她说出去以后想念部分释放，没得到回应就无果退避（这是身体的惯性，不是替她做判断）；任何冲动在得不到满足反馈时被连续选中超过三次就压下。常见事件（主人夸她、主人凶她、活被打回、活被验收、承诺到期没做到、主人回来了、被陌生人冒犯）有一张默认评价表，模型没交感受时兜底，交了就在默认值附近调（产品定义 §3.1；游戏 §4.2.2、§4.2.3；心理 §4.2.3、§4.2.7）。

**身的循环是确定性的**：输入只有时钟、随机源、账本、情境快照；随机数按"种子 + 分钟 + 用途 + 对象"派生（计数器式），不用一条全局随机流，否则某处多抽一次后面全部错位；同样的输入得到同样的输出，所以回放时能重现（P12）。每分钟的结果不整条记日志，只在过线、调节器档位变化、整点时采样一条 `body.sampled`（全部数值 + 时钟 + 参数版本 + 代码版本），是事实，改参数或代码后不重算历史；另外每 5–15 分钟存一份身的状态快照作为操作数据，不进经历流。恢复 = 最近快照 + 同一个 `tick()` 快进到现在（快进期间只改状态，不生成冲动、不起回合），再把快照之后已记录的评价、冲动、消息到达事件按序重放；会上涨的量（想念、睡眠压力）和会下降的量都靠这一条路径处理，不另写"按离线时长衰减"〔推理；心理 §4.2.3 的伪代码要求每 5–10 分钟检查一次过线，本稿用危险率缩放达到同样效果〕。

### 4.2 一个回合的六段

循环由本体的代码驱动，不由任何 CLI 会话驱动（CoALA 把决策过程定义为"agent 代码里的 main 程序"，CLI 里的工具循环只是第四段内部的事，`papers-architecture` §2.1、§6 A）。

| 段 | 做什么 | 谁做 | 关键规则 | 依据 |
| --- | --- | --- | --- | --- |

### 4.3 去向表：事件和冲动到了念以后

原则：对话类的事在那个地方的在场里想；她自己的事和冲突由慢想想；确定性的事代码直接办；其余只记下。第一版的去向由**事件类别的优先级枚举**决定（主人 > 到期承诺 > 心事条件满足 > 对人的冲动 > 其余），每类一条规则；连续的显著性打分留给第二版的群聊门控和"低显著事件要不要进下一次前缀"这两处〔推理：少一层魔法数〕。

 ▼ senses

### 4.6 链路三：想找主人（判断归她）

```
body.tick：联结[主人] 涨到 0.7，过线概率命中 → 冲动"想爸爸"（对着主人）
 ▼ attention：对着主人的冲动 → 去向"主动开口的判断"
   预检：不应期（她上次主动说的话爸爸还没回？）→ 命中就不起回合，分享念头记成心事
   预检 guard.houseRules：勿扰时段？按过"别烦"？今天主动条数到家规上限？→ 命中就不起回合（省钱），冲动由 body 持有
   主人正在聊？→ 不另起回合，下一轮注入
 ▼ will.factPack(主人)（都是代码能确定的事）：
   上次找爸爸 10:00，他没回；再上一次 昨晚 22:10，他回了，聊得挺热；现在 14:30，工作日；日历：15:00 有会；今天已经主动过 1 次
   手里值得说的：榫卯视频（她自己的事，受众公开）、妈妈的事（心事，受众已放宽）
 ▼ 判断（第一版默认慢想，强大脑；评测后可改为主人的在场直接判断）：
   前缀 = 人设 + [想找他] 想念 0.7 + 事实包 + 教养底线；三选一：说 / 留成心事 / 不说，各附理由
   说 → relay(主人的在场, 事实: 榫卯视频 + 妈妈的事, 意图: 分享、顺带提醒开会)
 ▼ 主人的在场按人设生成措辞 → say(内容, 理由) → outbox：家规与平台限频再查一次（不变量）→ 目标 = 合并在场里主人最近活动的地方，不在线用主人设的首选地方 → 投递 → 记 proactive.sent{理由, 目标}
   留成心事 → inner(心事: "等他开完会说榫卯的事", 等: 爸爸说话)
   不说 → 安静结束，冲动按半衰期淡掉
 ▼ body：说出去以后想念部分释放，进入"等回音"不应期；没得到回应就无果退避，不应期拉长
 ▼ 反馈：主人回了 / 没回 / 点开没回（只有主控台能报）/ 按了别烦 → 写经历流 → 当天影响心情；夜里进印象和习惯
 ▼ 主控台"她的人"里给主人只读信息："她这周主动找你 N 次，你回了 M 次"；要不要设家规由主人决定
```

代码没有决定要不要发；它只决定了"她什么时候会想到这件事"（身体，含不应期）、"她知道哪些事实"、"家规允不允许"（决策 21；产品定义 §6.1；产品调研 §4.4 只作参考）。家规有两层：起回合前的预检是省钱，命中就不起回合；outbox 的检查是不变量，保证验收 D1"家规 0 违反"。"等回音"的不应期和"睡觉时不主动"同类：它决定她什么时候会想起，不碰她说不说；没有它，她不说之后下一分钟又会按概率再起一个回合，问得越多越可能说出口，频率就成了代码的再触发节律在决定（p = 0.2 问 5 次就是 67%）。

### 4.7 链路四：承诺到期

`commit` 时 will 建承诺并连带建作业；到点 scheduler 触发 → attention 在答应时所在的在场起一轮，前缀里带原话编号和原文 → 她用自己的口吻兑现 → reply；是"做一件事"的承诺就起手。晚了一小时还没做成，代码生成"道歉"的心事注入下一轮（§7.7；产品定义 §3.5；产品调研 §2.13 fatfish）。

### 4.8 链路五：手完成

```
手（Codex 子进程，在任务 T 的 worktree 里）
 ① 做完，调用 report(T, 阶段: 待验收, 摘要, 产物: 改动文件、测试结果)
 ▼ toolport → tasks ② 完成核验（代码）：声称改了的文件真的有 diff？声称跑过的测试有执行记录并通过？声称的产物都在？
   核验不过 → 退回手（"以下说法和实际对不上：…"），不进入待验收
 ▼ actions ③ 先写日志：task.stage_changed{执行中 → 待验收, 核验结果}
 ▼ ④ 两条线同时走，都从这条日志事件出发，至少送达一次：
   ├ notify：这是要主人审核的事 → 直接按主人在线情况推送（不等任何用脑决定）
   └ attention：进度表更新；发起它的在场下一轮收到"活做完了"；进念作为可以告诉主人的素材
 ▼ ⑤ 主人在主控台打开 T：看 diff → 验收；或者打回，打回意见作为主人直连消息进手的会话
 ▼ tasks ⑥ 待验收 → 完成；workspace 把 worktree 合回主线（冲突在这一步暴露给主人）
 ▼ ⑦ 空闲增量整理立刻把这件活抽成她的情景记忆："这件活是我做的"（来源：手）
```

子任务结果会静默丢失、"文件已创建"可能是假的，OpenClaw #44925 在生产环境至少出现 9 次；所以汇报先落日志再投递、失败重投，可以核对的说法在进入待验收前由代码核对（`openclaw-architecture` §8.1.1、§8.1.3 第 3 条）。MAST 的实验里，加一步"对照总目标核验"成功率提高 15.6%（`papers-architecture` §2.5）。"至少送达一次"照 Paseo 上游 0.13 的完成订阅：先写订阅意图，再承诺投递，重启后恢复观察（`paseo-architecture` §2.2 Q9）。需要主人审核的事直接推给主人，不让任何用脑挡在主人和审核之间（`paseo-architecture` §3；`client-backend` §3.6）。一件活一个 worktree（git 的功能：同一个仓库同时检出多份互不干扰的工作目录），合回主线放在主人验收之后，这就是"同一工作区的文件单点写"（决策 12；`client-backend` §2）。

### 4.9 链路六：夜里整理

```
到了作息的睡觉时间，且没人在聊（主人还在聊就推迟；过了 02:00 仍在聊就先做巩固和日记，其余明天补）
 ▼ scheduler 起"每日整理"作业链 → minds 开睡眠用脑（便宜大脑，分批读检查点之后的经历流）
 ▼ 十件事，按顺序交结构化提案，账本校验后写入：
   巩固记忆 → 更新关系与印象摘要 → 重算牵挂 → 遗忘 → 反思与成长提案（多来源证据、兴趣须引用经历、非主人来源不能单独促成）
   → 日记 + 明天的打算 → 事后检查（该记没记、口头答应没 commit、言行不一致）→ 算近况和今日状态的余波
   → 更新自我模型（跨 3 天、2 种来源才采纳）→ 抽查当天的感受分布 → 自动问她"你今天做了什么、为什么"并到经历流找出处（验收 A1，一次便宜调用）
   （日记只在夜里写；白天"写东西"产出的是随笔和笔记，不叫日记）
 ▼ 然后：成长版本或自我模型有变更就把主人的在场和话题对话换新（成长只在新会话生效）；聊得太长的在场换新；候选账号汇总成一条提醒给主人；备好早安材料
```

（依据：产品定义 §3.8；`papers-architecture` §2.4 sleep-time compute、Auto-Dreamer；心理 §4.3.2）

### 4.10 链路七：群聊【V2】

```
群友在 QQ 群 G 里说话
 ▼ QQ 适配层（子进程）① 归一：平台消息号、发送者账号、@ 列表、回复对象、内容段
 ▼ senses → people：认人（只认已确认的账号）、算地方键、取在场者快照 → 受众
 ▼ journal ② message.received{地方: G, 受众: G 的在场者快照, 来源人: 某群友或陌生人}；没唤醒她的消息也记下，是 G 的历史
 ▼ attention ③ 第一道门（代码）：@ 她、叫她名字、回复她、主人在说话 → 唤醒
       第二道门（不调大模型）：话题和她的兴趣、近期记忆做向量相似度，过阈值才唤醒
       两道都没过 → 到此为止；防抖：安静 2 秒 / 活跃 5 秒 / 整批最多 8 秒 / 被 @ 后最多 1 秒
 ▼ minds：G 的在场（没有就创建：注入她的人设 + 只限 G 受众的记忆快照）→ guard 准入 → context（只含 G 的受众能知道的提醒和召回）
 ▼ 用脑 ⑥
 ├ 情况 A：她接话 → reply(事件号, 内容) → outbox：目标只能是 G；出站清洗 → formhost 投递 → 回执
 ├ 情况 B：不接话 → 什么都不调用，回合安静结束
 └ 情况 C：涉及全局（有人约她周六、问到主人的事、主人 @ 她派活）
       要答应约时间就 commit → 本体查到和"周六陪主人"冲突 → ask_mind(类别, 问题, 建议答复, 期限, 原消息号)
       → 她在群里先用自己的口吻稳住（"我看看"），不替慢想做决定
       → 慢想决定（commit / decide / 驳回）→ 本体**立即给 G 的在场起一轮**（不等对方下一句）→ 她在群里答复
```

两道门的结构来自决策 13⑥；防抖参数取麦麦的默认档，权重和阈值要用灵鲸自己的数据重拟（`companion-architectures` §2.2 Q1、§7.3；`papers-architecture` §3.5 修正 H）。第二道门只管"要不要叫醒"，叫醒以后"说不说"由模型判断，可以安静结束（`papers-architecture` §2.7 Inner Thoughts §3）。她自己发出去的消息从平台回流时标成"她说的"，防止自己回复自己（`companion-architectures` §9 坑 4）。

### 4.11 会话邮箱

每个会话有一个邮箱，同一时刻只放行一个回合（`openclaw-architecture` §2.2 Q2；`paseo-architecture` §2.2 Q2）。**steer** 是把新消息塞进正在跑的回合（在一批工具调用结束、模型做下一次决定之前）；**interrupt** 是中止当前回合。

| 会话 | 来的东西 | 空闲时 | 正忙时 | 依据 |
| --- | --- | --- | --- | --- |
| 主人的在场 | 主人的消息 | 收 0.5–2 秒内的连发，合成一轮 | 正跑主人发起的回合 → steer；正跑心事注入或主动开口的回合且还没产生副作用 → 在下一个安全点中断、把心事放回、先跑主人的回合；已产生副作用就跑完再跑主人的 | `openclaw-architecture` §2.2 Q2（collect、steer、500 ms 防抖）、#30197（用户消息被 steer 进 heartbeat 回合，回复被吞）；AIRI"有副作用就不重来"（`companion-architectures` §4.2 Q3） |
| 任何在场 | 心事到期、冲动要在这里开口 | 开一轮 | 等当前回合结束；下一轮前缀里带 | 决策 13① |
| 慢想 | 新的请示、新的决策点 | 开一轮（或在保留期内沿用会话） | 等当前批结束；同一批里合并 | `structure-validation` M8 |
| 手 | 主人直连的补充要求 | 开一轮 | steer | `openclaw-architecture` §3；`paseo-architecture` §3 |
| 手 | 主人"叫停" | — | interrupt（幂等，失败即关闭） | `paseo-architecture` §2.2 Q4 |
| 手 | 子会话结果 | 开一轮 | steer | `paseo-architecture` §2.2 Q9 |
| 别人的在场【V2】 | 地方消息 | 防抖后开一轮 | 等当前回合结束再合批 | `companion-architectures` §2.2 Q1 |
| 任何会话 | 广播提醒 | 下一轮开头 | 下一轮开头，不打断 | 决策 13② |
| 任何会话 | 斜杠命令 | 本体直接处理，不进模型 | 同左 | `companion-architectures` §3.2 Q3 |

三条规则：**只有发起者能 steer 自己发起的回合**，别人的消息不 steer 主人发起的回合，否则等于让别人借用主人的权限（`openclaw-architecture` §2.2 Q2、§5 坑 9）；**中断时丢掉 CLI 还没读到的 steer**，否则刚停掉的回合会被它重新拉起（`paseo-architecture` §2.2 Q4）；**邮箱有上限，溢出时写摘要，不静默丢弃**，每个邮箱记"最后一次被消费的时间"并监控（`openclaw-architecture` §2.2 Q2；`companion-architectures` §9 坑 18）。

## 5. 用脑的契约：上下文、工具、请示、交接

### 5.1 每种用脑注入什么

两个时机：**会话创建时**一次性放进去的（稳定前缀，吃服务商的前缀缓存），和**每一轮**放在输入前面的（动态前缀，小而有上限）。**前缀缓存**指服务商对和上次完全相同的开头打折计费，开头一变就要全价重算（`openclaw-architecture` §2.2 Q4、#20894（每条消息的元数据注入系统提示，cache_write 增加 80–170 倍）、#143017；决策 13④）。

| 层 | 在场 | 慢想 | 手 | 睡眠 | 上限 | 来源 |
| --- | --- | --- | --- | --- | --- | --- |
| **稳定前缀**（创建时，经 CLI 原生指令字段追加） | 人设（出生设定 + 当前成长版本 + 自我模型的"我是什么样的人"简版 + 价值观 + 诚实的上限：她知道自己想事情是一阵一阵的、感受是评价加数字）+ 在场说明（这是哪、受众、工具用法；群的在场者名单放每轮前缀，不进稳定前缀）+ 教养底线 | 短版人设 + 慢想的决策规矩（自我模型和账本全文不进稳定前缀，按需 `recall` / `get_report` 取） | 短版人设 + 手的规矩 + 每轮一句人设提醒（目标导向的会话人设褪色最快） | 人设 + 整理的规矩 | 合计约 6 万字符、单块约 2 万；超了截断并加固定提示 | self、minds |
| 最近对话（创建、换新、换大脑时） | 从经历流取最后 N 轮原文 | — | 交接包 | 作业给的经历流片段 | N 轮 | journal、tasks |
| [状态]（每轮，变了才带） | 一行：时间、精力、心情词、想念谁、调节器给的话长与细致度提示；情绪的原因按目标受众裁（妈妈私聊里的原因不出现在群的状态行里） | 同左 + 全部活跃情绪 | 一句 | — | 1–2 行 | body |
| [正在做] | 焦点栈里的一两件主事 | 焦点栈全部 + 手上的事进度表 | — | — | ≤5 条 | attention、tasks |
| [心事] | 和在场者相关的、条件满足的 | 全部心事 | — | — | ≤5 条 | attention |
| [记得]（意） | 对在场者的承诺、今天的打算（主人在场时） | 全部承诺、打算、心愿、牵挂、方针 | — | — | ≤5 条 | will |
| [记得]（忆） | 按受众召回的记忆 + 对在场者的印象摘要 | 和这批事相关的 | 和这件事相关、按发起在场的受众 | — | 条数和字数封顶 | memory |
| [刚才想起] | 联想或走神冒出的一条 | 同左 | — | — | 1 条 | attention |
| [别处] | 上次之后她在别处发生的事，按受众过滤 | 自上次慢想以来的摘要，按类别压缩 | — | — | ≤5 行 | journal |
| [新决定] | 方针、承诺的变化（自上次看到的版本起） | — | 同左（和这件事有关的） | — | ≤3 条 | will |
| [想找他] / [要决定的事] | 主动开口时的事实包（§7.4） | 这次的触发 + 桌子（候选 + 身体权重） | — | — | — | will |
| 正文 | 这个地方的对话（CLI 自己记着） | 这一批要处理的事 | 干活过程 | 分批的经历流原文 | — | — |

两条硬规则：**稳定前缀里不放会变的东西**（时间戳、消息号、心情），否则缓存全失效；**每一层都有上限**，超了按相关度裁，不按时间裁。提醒和内部输入走 user 角色的结构块，不插 system 消息（Anthropic 会拒绝出现在普通 assistant 消息之后的 system 角色通知，`companion-architectures` §3.2 Q6）；人发的消息如果长得像结构块，会被转义成普通文本（`paseo-architecture` §2.2 Q9 信封）。

**状态行的写法**：数值翻成一句话再给模型（"有点想爸爸"而不是 0.7）。D2A 的消融证明不翻成文字模型就用不好；Humanoid 只在过线时才翻（产品调研 §2.2、§4.1）。

"别处简讯"由代码在会话创建时和每轮从经历流和已有摘要生成，每条带时间和对话指针，限长；只给受众相同的在场注入（主人独处的对话之间可以互相回顾，有别人在场的对话不注入主人独处时的内容）（`structure-validation` M14）。

### 5.2 内核工具目录

内核工具是一份和传输方式无关的目录，MCP 只是接法之一；每次用脑拿到的工具按种类、自主开关和被收回的能力过滤；工具 id 用 ASCII、描述用中文，参数尽量结构化（`paseo-architecture` §2.2 Q7；`papers-architecture` §2.5 E3）。工具只"提出动作"，执行都在本体（P3）。**在场只有 8 个工具**，语义不重叠：Anthropic 的经验是工具集要最小、不重叠，人类工程师都说不清该用哪个工具，agent 也做不到；MemGPT 在弱模型上函数调用能力有限、性能显著下降（`papers-architecture` §2.4、§3.4）。

**不在对话里做的事**：学做法（主人教她）、建议账号归属、放宽受众，第一版改由空闲增量整理从原文里提，带证据事件号，照样过账本校验（放宽受众本来就要代码核对原话，事后提取不丢东西；`learn` 的在对话里的形态等她自己摸索的第四版再加）。

**回合里的推理次数与收尾**：回复是工具调用，CLI 的工具循环在工具返回后通常还会推理一次才结束回合；规定 `reply` 和 `inner` 同批并行调用，批结束后用 CLI 的工具批结束钩子收尾，省掉第二次推理（Claude Agent SDK 有 PostToolBatch 一类钩子，`subagent-notes/cli-claude-sdk-codex-app-server.md`；Codex 侧要实测，§17 第 32 项）。§13 按每回合 1–3 次推理记账。

**"去查"的手**：在场和慢想不直接读网页。`look` 的上网形态开一只只读、能上网、不进看板、没有审核关口、用完即弃的手，查完浓缩成一段摘要交回，标"网络内容、不可信"；读过网络内容的那一轮打污染标记，**这一轮写的记忆类内容带污染标记，夜里不能被提升成事实、做法或成长证据**（`dispatch` 照常，后面还有审设计的关口）。理由：慢想和在场能派活、许诺、托人转话，网页里可能藏着操控指令；OpenClaw 的防注入文档建议先用只读的 reader agent 总结不可信内容再交主 agent（`openclaw-architecture` §2.2 Q8、Q6）；Claude Code 的子 agent 只负责回答问题，调查过程不留在主 agent 的历史里（`papers-architecture` §2.5 E4）。

**内容段**包括文字、语音（按句带情绪意图）、表情包、现成图片【V1 后期】、自己画的图【V2】。语音的情绪走工具参数，不让大脑在正文里写各家私有标签（`ability-plugins` §3.2）。

**便宜模型会漏调工具**，三道兜底：body 的默认评价表（规则打底）；夜里的事后检查补记；主人回合没有任何对外动作时的追问与固定兜底（§8 R10）。

### 5.3 判断的分配：代码、在场、慢想各管什么

| 判断 | 谁做 | 理由 |
| --- | --- | --- |
| 这件事对她意味着什么（评价） | 正在跑的那次用脑（`inner` 的感受字段，或 `reply` 自带的感受） | 评价需要懂内容 |
| 多强、多久、怎么叠、怎么回落 | body | 惯性是身体的事；可调、可读、可回放 |
| 现在值不值得想（起不起用脑、叫不叫醒慢想） | attention（显著性、容量、过线概率、退避） | 成本闸门；不是判断内容，是判断"要不要花钱想" |
| 要不要找某个人、现在合不合适、说什么要点 | 第一版默认慢想（带事实包），措辞由那个人的在场生成；评测后可移回在场 | 主动开口不在等待链路上，没理由用最便宜的大脑；强模型"该不该主动"误报也过半，小模型更差（`papers-architecture` §2.7 ProactiveBench），所以身体的不应期与退避、教养底线、家规、评测前置都要在 |
| 做什么活动、冲突怎么办、方针、心愿 | 慢想 | 要权衡的事交强大脑 |
| "再看一个"这类连续的小选择 | will 的有偏硬币 | 不值得一次调用；身体状态已经在权重里 |
| 承诺能不能记 | will 查冲突：无冲突直接记；有冲突叫慢想 | 确定性检查在代码 |
| 发起人有没有权限 | guard / people | 身份与角色是确定的事 |
| 放宽受众 | 代码核对依据（来源人许可或主人规则），不凭判断 | Audience-Bound：受众只能经针对具体条目的显式授权放宽（`structure-validation` M6） |
| 学没学会 | skills 回查结果 | 成功由系统判定（Voyager、dafeiyu） |
| 该不该请示 | 代码按"动作"判断（有没有这个工具、参数有没有冲突）；话语层靠人设、出站轻查（规则匹配，只查时间、金钱、承诺用语这类高风险类别，不调模型；回复走事后审计，主动消息在发出前查）、事后审查 | 快慢双系统里所有"由规则决定何时叫慢系统"的例子判断的都是动作或环境信号，没有一个在判断话的含义（`structure-validation` M1） |

**请示的三路**（`structure-validation` M2）：发起人没权限（例如群友让她花钱）→ 本体直接拒绝或转主人，不进慢想；发起人有权限且本体查无冲突（例如主人说"明天 9 点提醒我"）→ 本体直接执行、记日志、不叫醒慢想；有冲突、要放宽受众、她自己发起、或非主人发起且涉及花钱或撤不回 → 叫醒慢想。

**请示的垫话与回执**：`ask_mind` 写一条待决事项后立即返回"已请示 + 期限"，在场在同一轮里用自己的口吻稳住（主人的地方也一样："我想想，等我一下"），人设里写明这条；慢想的决定一出，本体**主动给发起的在场起一轮**（不等对方下一句，否则对方说完"周六一起玩吗"就不说话了，答复永远发不出去）；到期没决定，按安全默认处理（不答应、继续稳住，或转主人）（`structure-validation` M3；Chat-Supervisor 同步等主管约 2 秒就要用垫话掩盖、垫话后必须给答复）。

**权限沿请示链传递**：每个请示、每条心事带发起人；慢想替某人办事时按发起人的权限检查，不按慢想的权限；有后果的工具调用必须引用它响应的消息号，权限取该消息发送者的角色，没有引用按在场者里最低的算（`structure-validation` M4：CaMeL 的能力标签、糊涂代理）。

**慢想不直接吞外人原文**：请示包是结构化字段（类别、发起人、要决定什么、建议答复、期限、原消息号）；原文按编号取并标不可信；读过外人原文的那一轮只能做发起人权限内的动作。主人的原文不受此限制（`structure-validation` M5；双 LLM 模式"有权限的 LLM 从不处理不可信数据"）。

**统计请示**：记录每类请示的数量、慢想"照准原建议"的比例、处理时长；照准率长期很高的类别提示主人考虑下放，拒绝率高的提示收紧；调整只由主人确认（`structure-validation` M9）。

### 5.4 慢想的交接件、决策点记录与保留

慢想没有常驻会话，连续性靠三样：**心事**（在等什么、想到哪了、下次看、有没有计划）、**决策点记录**（触发、桌子、决定、理由、依据事件号、什么时候复查、状态：待决 / 已决 / 放弃）、**自上次以来的摘要**（代码按类别压缩：和谁聊了几句、做了什么、有什么通知；需要细节时按编号取原文）。慢想会话结束前，代码检查必填项都写了，没写就补一轮。

**幂等**：每个决策点一条记录；慢想的 `do`、`dispatch`、`relay` 带决策点号作幂等键，处理到一半失败后重开的慢想先读未决的决策点，不会开第二只手。

**保留**：保留时长自适应：主人活跃的时段让慢想会话保持温热、按上下文用量换新，夜里和长时间空闲才收工；默认至少保留 5 分钟。非紧急的事先进一个几十秒的合批窗口，攒在一起想。"每批新开"是可配置的默认值，强大脑可以不重置；Anthropic 长任务那篇说的是"如果要重置，交接件就得够用"，不是必须重置（`structure-validation` M8；产品定义 §3.4）。

**优先级**：慢想同一时刻只有一个，它的邮箱按"主人在等的请示 > 冲突与应对 > 主动开口 > 闲暇选活动"排；正在跑的闲暇批次还没产生副作用时，主人的请示到达就在安全点中断它，决策点标回待决（§4.11）。**待决事项**由 `ask_mind` 建，scheduler 为每条建期限作业，到期按安全默认处理（不答应、继续稳住，或转主人）；**决策点记录**由慢想的动作事件（`decide`、`do`、`stop`、`drop`、`relay`、`commit`，必带理由和复查时间）投影出来，归 will。

**大脑按触发类别配**：请示、冲突、应对用强大脑；闲暇选活动、心愿推进可配中档（默认也是强，受 §13 的日预算；要紧的选择仍然是她做，只是换个便宜些的脑子，§18 N22）。

### 5.5 广播与"读到自己的写"

- 慢想用 `decide`、`commit`、`plan` 改了意的账本，她的状态版本加一；每个在场记住自己上次看到的版本，下一轮开头收到按受众过滤的变化提醒，不打断正在跑的回合（打断会让手上的事偏航，全局工作空间的广播也是给各模块下一次处理用的，`papers-architecture` §2.2）。
- 请示的发起者例外：决定一出，立即给它起一轮。一个在场已经说出去的话和新决定矛盾时，慢想显式用 `relay` 托它更正，不指望广播（`structure-validation` M3、M11）。
- 成长版本和自我模型在稳定前缀里，只在换新会话时生效（Letta：记忆改动下个会话生效，`companion-architectures` §3.2 Q1）。
- 会话中途注入提醒在 Claude Code 和 Codex 上的表现要实测（§17 第 2 项）。

### 5.6 派活交接包

| 字段 | 内容 | 谁提供 | 依据 |
| --- | --- | --- | --- |
| 原话 | 主人的原话，按消息号由本体从经历流取原文 | 代码 | 决策 5、14 |
| 相关聊天 | 发起的用脑指定消息号范围，本体取原文 | 用脑选范围，代码取 | 决策 14 |
| 到目前为止的决定和理由 | 例如"主人说先别动支付部分" | 用脑 | 决策 14；`papers-architecture` §3.5 |
| 手不知道什么 | 明确列出，例如"主人上周换了服务器，旧地址作废" | 用脑 | `papers-architecture` §2.5 E5（"agent 以为和子 agent 共享状态，其实没有"） |
| 相关记忆 | 和这件活相关、按发起在场的受众能知道的 | 代码（memory.recall） | `structure-validation` M7 |
| 汇报格式 | 固定的进度摘要格式 | 任务模板（代码） | `papers-architecture` §2.5 E1 |
| 边界 | worktree、花费上限、不许联系别人、不许动的目录 | 模板默认 + 用脑补充 | 决策 14 |

| 回问通道 | 用 `ask` 问发起的在场；涉及主人决定的转给主人 | 模板 | `papers-architecture` §2.5 MAST（"该问不问"占 6.8%） |
| 执行者和大脑 | 从代码给出的候选里选：她配哪个大脑，以后还可以是某个朋友 | 用脑选，代码给候选 | 决策 6 |

三条规则：交接包只补流程，不改写需求（需求的理解和方案设计由手完成，决策 5、14）；派活是带结构化参数的工具调用，执行者从候选清单里选，主人明说"让某某做"时由代码直接路由（弱模型靠提示词当编排者有明显偏差，`papers-architecture` §3.4、§2.6）；派活带幂等键，重试不会派出两件一样的活，结果不明时返回"结果不明"，不重复执行（`paseo-architecture` §3）。

### 5.7 共享状态单点写

在场、手互不共享上下文，冲突不在说话风格，而在共享状态上（`papers-architecture` §3.2）。这些状态只能经本体 API 写入，由所有者模块做冲突检查；写入保持单线程（决策 12；`papers-architecture` §2.5 E5、§2.2 BIGMAS）。

| 共享状态 | 所有者 | 写入 | 冲突检查 | 谁能直接写 | 谁必须提请 |
| --- | --- | --- | --- | --- | --- |
| 承诺、打算、方针 | will | `commit`、`plan`、`decide` | 与已有承诺、作息、主人日历【V4】的时间冲突；与方针矛盾 | 慢想；在场的 `commit` 无冲突时 | 在场（有冲突时） |
| 关于她自己和主人的事实 | memory | `note`、`propose` | 同主体同属性是否矛盾（矛盾的版本化不删） | 任何用脑（带来源） | — |
| 印象、关系数值 | memory | 睡眠提案 | 主人设定的关系不可改 | 睡眠用脑 | — |
| 人物档案 | people | 主人；`suggest_identity` 只写候选 | — | 主人 | 用脑只能建议 |
| 同一工作区的文件 | workspace | 写租约 + worktree | 同一 worktree 只有一个写入会话 | 持有租约的手 | — |
| 身 | body | `inner` 的感受和念头只是输入 | body 自己的规则 | 只有 body | — |
| 心事（含关注） | attention | `inner(心事)`；睡眠提案 | 条数上限 | 任何用脑 | — |

冲突检查的结果只有三种：接受、带理由拒绝、需要慢想决定。

### 5.8 受众与放宽

| 规则 | 做法 | 依据 |
| --- | --- | --- |
| 默认最严 | 每条经历、每条记忆带来源和受众；没有明确受众的按"只有主人" | `companion-architectures` §5.2 Q2（eliza v2"owner-private is the fail-closed default"） |
| 受众取最小 | 地方里只要有一个人不该知道就不说；在场者快照过期或不确定时按最严 | `companion-architectures` §5.2 Q2、§7.2 |
| 上下文就是边界 | 在场的创建快照、每轮召回、广播提醒、别处简讯都按受众过滤；它的上下文里根本没有不该说的东西 | `companion-architectures` §2.2 Q1 |
| 默认受众 | 某个地方的对话 → 那个地方当时的在场者；她自己做的事，**活动的事实公开、内容和原因继承来源**（"她看了一个视频""她写了一篇日记"公开，日记正文、情绪的原因取来源受众的交集）；替主人干的活 → 主人；身体数值的变化公开，但状态行里的原因按目标受众裁；慢想的决定 → 按决定本身（§18） | 产品定义 §8；`structure-validation` M12；〔推理〕 |
| 放宽是显式授权事件 | 针对具体条目，只在来源人表示过可以（"可以告诉你爸"）或主人在关系规则里设定过时成立，由代码核对依据，可撤销；慢想拍板也受此约束，不能凭判断放宽 | `structure-validation` M6（Audience-Bound、情境完整性、ConfAIde、MuPPET） |
| 手的受众跟发起它的在场走 | 别人发起的活只拿那个受众能知道的记忆；别人能不能发起活、是否也给主人看，取决于主人设的角色（§18） | `structure-validation` M7 |
| 派生记忆保留来源链 | 睡眠用脑交出的每条派生记忆列出来源事件号；受众取来源受众的交集；按来源家族去重，不按出现次数强化同一来源；保留说话人类型 | `structure-validation` M12（来源监控、Compaction Laundering、Memory Echo） |
| 跨场合在目标处生成 | §8 R3 | `companion-architectures` §7.1 |
| CLI 那一侧也算 | §6.4、§6.7 | `openclaw-architecture` §5 坑 10 |
| 第一版就写来源 | 第一版只有主人一个受众，但来源字段从第一版就写全，第二版不用迁移数据 | `client-backend` §3.2 |
| 删除级联 | 主人删掉一条载荷，由它派生的记忆、印象摘要、录放载荷、每轮前缀快照按证据事件号一起删或重算 | `event-log-supplement` §2.1（消费方不要复制载荷） |

**主人可见**和**主人在场的受众**是两回事（§2.1）：主人在主控台能查看全部记忆和经历（产品定义 §3.6）；她和主人说话时只能用受众含主人的条目，别人私下告诉她的事不主动转述，问起也只说"这是妈妈私下说的，你去问她"（§18 C6）。第二版接家人之前要定一件产品上的事：要不要让家人知道主人能看她们的私聊，例如她对新绑定的家人第一次说明（§18 U3）。

### 5.9 主人直连、子会话、叫朋友

- **主人直连**：主人在主控台打开任何一只手（第二版起也包括别人的在场）说话，消息直接进那个会话，来源标"主人直连"；手里默认 steer，"叫停"是 interrupt；主人还可以暂停、换大脑（换大脑 = 用新大脑开新会话，从经历流重建上下文）。念记一条低显著事件，让进度表保持准确；这段经历照样汇进她的记忆，来源标"主人直连"（产品定义 §3.7；`client-backend` §3.6；`paseo-architecture` §3）。直连只在主控台；主人从外部渠道说的话一律进他的在场（§18 C4）。
- **子会话**：手用 `spawn(执行者, 交接包)` 开子会话，执行者只能是她或朋友；深度和并发有上限；子会话的经历记在所属手上的事名下，结果回父会话（决策 5；`openclaw-architecture` §2.2 Q3；`paseo-architecture` §2.2 Q4）。
- **叫朋友【V3】**：交接包同上，执行者是朋友：用朋友的人设、朋友的记忆。两边各记各的：她这边记"我请老师做了什么、结论是什么"，老师那边记成自己的经历，来源标"闺女"。叫醒朋友不看预算（产品定义 §6.3；决策 9）。
- **自主开关关闭的成员【V3】**：主人在主控台直接找它时，本体按需开一个它自己的在场：结构一样，但没有身的循环、慢想、自主作业，闲置回收（产品定义 §1.3）。

## 6. 事实来源与持久化

### 6.1 经历流是唯一事实来源

做法叫**事件溯源**：每件发生过的事作为一条不可改的记录追加进日志，"当前状态"都是从日志算出来的投影。

- 产品要求"记忆唯一来源是操作日志"，成长"可查、可回滚"，主人要能看到"她最近变了什么、为什么变"。只有保留全部经过，才回答得了"为什么"（产品定义 §3.6、§3.8）。
- CoALA 按"能不能控制"划分内外：本体控制不了 CLI 转录的格式和保留策略，所以 CLI 转录属于外部（`papers-architecture` §2.1）。
- Auto-Dreamer 的局限："写入时漏掉的信息，巩固器通常找不回来，除非原始轨迹让它显眼"：原始日志必须一直保留，整理不能覆盖它（`papers-architecture` §2.4）。

放弃的方案：以 CLI 转录为真相（Paseo：自己产生、转录里没有的东西重启就丢；换 CLI 就等于换了一份真相，`paseo-architecture` §2.2 Q5、§5 坑 1）；以状态表为主（OpenClaw、麦麦：会话、作业、人格、记忆分散在几个 SQLite 和 Markdown 里，没法从日志重建记忆和人格，`openclaw-architecture` §3、§4；`companion-architectures` §2.2 Q8）；两份并列的真相（Letta：会话 jsonl 加记忆 git 仓库，两边可能对不上，`companion-architectures` §3.2 Q8）。

### 6.2 事件信封、载荷与流

每条事件：全局位置、流类型、流编号、流内序号、类型、版本、执行者、发生时间、因果号（由哪条事件引起）、关联号（属于哪一串事）、来源信息、载荷号。同一条流里的序号唯一，追加时带"期望序号"，序号对不上就说明有人先写了，这是单点写入做冲突检查的底层手段（`client-backend` §3.2）。

**来源信息**第一版就写全：地方、在场者快照的引用、受众；来源人与可信度（主人、成员、绑定的真人、陌生人、系统、网络内容）；污染标记（读过网络内容的那一轮，之后的输出都标为不可信，`openclaw-architecture` §2.2 Q6 taint）。来源信息存在独立的列里，模型没法通过改写正文改掉它。

**载荷与信封分开存**：消息正文、工具输出这类内容一律作为载荷，小的放 liwa.db 的载荷表，大的按哈希进 `blobs/`，事件里只放载荷号。信封（流、序号、类型、执行者、时间、因果、来源、受众）永远不改；主人要求彻底删除时只删载荷，不用改写日志（§6.7；`event-log-supplement` §2.1）。

**流的划分**：

| 流 | 装什么 |
| --- | --- |
| 成员流 `member:<id>` | 身的采样、评价与冲动、心事与关注、承诺打算心愿牵挂方针的变化、记忆变更、成长与自我模型版本 |
| 用脑流 `mind:<id>` | 回合、消息、工具调用、用量 |
| 地方流 `place:<id>` | 地方里收到的消息，包括没唤醒她的 |
| 手上的事流 `task:<id>` | 阶段流转、交接包、汇报、核验结果、她自己的事的经历（看了什么、抽了几帧、感想） |
| 系统流 `system` | 暂停、总闸、配置、作业、进程事故、家规变更、换大脑与回归结果、随机种子 |

**哪些进日志**：消息完成、工具调用完成（输出有上限）、阶段流转、用量、快照、记忆变更、身的采样。**哪些不进**：逐字吐出的增量、工具执行中的进度，这些只走实时推送，在条目完成时一次性提交。进程登记、订阅游标、连接这类运行时的操作数据不是"她的事实"，是各模块自己的表，不进日志（`client-backend` §3.2）。

### 6.3 投影

| 种类 | 例子 | 怎么更新 | 存在哪 |
| --- | --- | --- | --- |
| 内联投影 | 她现在、她的一天（时间线）、手上的事看板与进度表、她在意的、作业、花费汇总、会话列表 | 和追加事件在同一个事务里更新，读到的永远是最新的 | liwa.db |
| 异步投影 | 记忆、印象摘要、全文检索索引、向量索引、日记、成长视图、自我模型视图、验收指标 | 各自记"处理到哪条日志"的检查点，按批追上 | derived.db |

所有投影都可以删表、从日志重放重建，重建本身也是迁移手段（`client-backend` §3.2）。内联、异步的划分和 .NET 事件存储 Marten 的 Inline、Async 两种投影一致；异步投影的检查点只能记已经提交的全局位置（Marten 出过并发追加时进度越过未提交事件的问题，`event-log-supplement` §2.2）。

**异步投影单独放在一个可重建的库文件里**（derived.db）：重建、索引膨胀、WAL 变大都碰不到装真相的那个文件，备份也只需要备 liwa.db 和 `blobs/`。OpenClaw #143524 里，一个 agent 的 WAL 文件两天涨到 1.4–2.8 GB，网关进程活着却始终不绑端口（`openclaw-architecture` §8.1.1）。代价是两个库之间没有跨库事务，但异步投影本来就是"稍后追上"的（§18 N6）。

### 6.4 CLI 转录的位置

- Claude Code、Codex 自己存的转录只是**续接用的缓存**。本体从不把它读回来当真相；新开会话、换大脑时，上下文都从经历流重建（`paseo-architecture` §3）。
- 每个成员的 CLI 数据目录放在本体的数据目录下（§3.4），主人删除或抹掉某段内容时，本体能连带删掉或轮换受影响的 CLI 会话文件。Codex 即使在"无痕"会话里也照写诊断日志，`persistSession:false` 是空操作，所以隐私和删除必须覆盖到 CLI 那一侧（`openclaw-architecture` §5 坑 10；`paseo-architecture` §5 坑 11）。Claude Code 能否把数据目录指到指定位置要实测（§17 第 8 项）。

### 6.5 副作用协议：先记"将要做"

```
effect.intended（带幂等键）──执行成功──▶ effect.completed
        │                    └─执行失败──▶ effect.failed{类别, 能否重试}
        └─本体在中间崩溃──▶ 重启时补记 effect.unknown
```

| 规则 | 做法 | 依据 |
| --- | --- | --- |
| 先记后做 | 任何有外部后果的动作（发消息、派活、建作业、调收费服务）先写"将要做"，再执行，再写结果 | `companion-architectures` §5.2 Q8（eliza v2"Persist a dispatch transition before any effect"）、§7.6 |
| 结果不明不重放 | 重启时，有"将要做"没有结果的记为结果不明；不自动重放；能只读核对的就核对（向平台查这条消息发没发出去）；核对不了的变成系统通知给主人 | `companion-architectures` §2.2 Q1（麦麦"禁止自动重放"）、§5.2 Q8；`openclaw-architecture` §7 J；Temporal 对有外部副作用的一步宁可没做不做两次（`event-log-supplement` §2.4） |
| 重试用同一个幂等键 | 幂等键在第一次执行前生成，写进"将要做"事件；重试带同一个键让对方去重；只对支持去重的服务这样重试。**幂等**指同一个请求做一次和做多次效果一样 | `openclaw-architecture` §2.2 Q1；Stripe：同一个键重试直接返回第一次保存的结果（`event-log-supplement` §2.4） |
| 被打断的回合 | 有开始没结束的回合补记 `turn.interrupted`。主人发起的回合，重启后在续接的会话里发一条续跑提示，写明哪些动作已完成、哪些结果不明；续跑有次数预算，续跑前重新确认发起者的权限。后台和作业的回合记失败，按作业策略重排 | `client-backend` §3.2；`openclaw-architecture` §7 J；`companion-architectures` §2.2 Q10；`paseo-architecture` §2.2 Q6 |

### 6.6 记忆和成长怎么从经历流里长出来

| 层次 | 写到哪 | 怎么产生 | 触发 | 依据 |
| --- | --- | --- | --- | --- |
| 情景 | 经历流本身 | 每个事件就是一条经历 | — | `papers-architecture` §2.3 |
| 当场记下的事实、承诺、心事、牵挂、评价、冲动、做法 | 各账本 | 用脑在同一次调用里顺手调工具 | 对话进行中 | 产品定义 §3.8 |
| 代码规则产生的 | 各账本 | 承诺到期、主人上线、身过线、手的进度、心事条件满足、候选账号登记 | 事件发生时 | 产品定义 §3.8 |
| 事实、关系记忆、印象摘要 | memory | 睡眠用脑读检查点之后的片段交提案；memory 校验后写 | 空闲增量（某在场闲 10 分钟且新增 ≥20 条；一件活做完）、每日 | 产品定义 §3.8；`companion-architectures` §7.4（Letta V1、eliza 的检查点；麦麦每条一次太贵） |
| 反思、近况、今日状态余波 | memory、body | 睡眠用脑 / 代码 | 每日 | 产品定义 §3.8 |
| 自我模型 | self | 代码统计 + 睡眠用脑提候选 + 别人的反馈；跨 3 天、2 种来源才采纳；与底色冲突不采纳只提示主人 | 每日 / 每周 | 心理 §4.3.2 |
| 成长版本 | self | 多来源重复证据、兴趣须引用经历、非主人来源不能单独促成、幅度受成长速率限制、下个会话生效、可回滚 | 每日 | `papers-architecture` §5.3（CoALA：改程序记忆风险最高；GA 过度合作）；产品调研 §2.13 |
| 偏好、习惯 | skills | 代码按"期望 vs 实际"和"做没做"更新；睡眠用脑命名 | 每次做完 / 每日 | 游戏 §4.1 #32；心理 §4.3.3 |
| 做法 | skills | `learn`；手回查成功后成熟度升级；失败进清单 | 用脑中 / 手完成 | 产品调研 §2.5、§2.13 |
| 日记 | 经历流 → 投影 | 睡眠用脑 | 每日 | 产品定义 §3.8 |

**写进记忆之前先清洗。** OpenClaw 出过两类事故：控制 token 和没解析的工具调用被存进每日记忆，下次作为摘要再注入，输出越来越坏（#69943）；一个 agent 陷入工具调用循环，别的 agent 读了那段转录也开始循环（#113346）。抽取前去掉控制 token、没解析的工具调用和重复循环的片段；本轮注入进去的内容（召回的记忆、人设）做结构标记，不会被再抽一遍；来源是系统或不可信的内容不能被提升（`openclaw-architecture` §2.2 Q6、§8.1.2）。**成长和自我模型对主人可见**：每条变化写明"因为哪件事、哪天"，可回滚（产品定义 §3.8；游戏 §4.1 #24）。

### 6.7 更正、删除与"日志只追加"

- **更正**：写一条记忆更正事件，投影照着改；原来的记录还在，可以审计。
- **删除**：写一条记忆删除事件，投影里不再出现；重建时也照样不出现。
- **真正抹掉**：主人要求某段内容彻底消失时，删掉那段内容的**载荷**，事件信封留着，日志本身不改写。步骤：删载荷和相关大对象 → 写一条"载荷已删除"事件（谁要求的、理由）→ 按证据事件号级联删掉或重算派生的记忆、印象摘要 → 删掉含这段内容的录放载荷和每轮前缀快照（它们也是载荷）→ 由它派生的作品和日记段落重算或删除 → 重建受影响的投影（检索索引）→ 删除或轮换含有这段内容的 CLI 会话文件。只有主人能发起。这是 Verraes 的 Forgettable Payloads 模式：敏感内容放单独的载荷存储，事件只留引用；消费方不要把载荷复制到自己那里存，否则删不干净（`event-log-supplement` §2.1）。剩下的缺口：删之前做的备份里仍有原文；业界的解法是密钥粉碎（载荷加密，密钥和备份分开保管，删密钥让所有副本作废），第一版不做，删除时告诉主人"旧备份里还有这段"。

### 6.8 身的采样与三档回放

- 身每分钟的结果不整条记；过线、调节器档位变化、整点时记一条 `body.sampled`（全部数值 + 随机源状态 + 时钟）；评价和冲动本身是事件。"她现在"的历史曲线、验收脚本的惯性指标都从经历流算〔推理〕。
- 每天的随机种子、时钟来源记进系统流。
- 回放分三档：**L0** 身与念的纯代码回放：输入是时钟、种子、经历流里记录的评价、冲动、消息到达事件，不调模型，确定性，免费，用来调身的参数、算验收 C1–C4、做身体层的操纵实验、以及重启时的恢复（从最近采样点把其后事件重放一遍）；**L1** 代码回归：再加上记录的工具调用，按（会话、回合序号）重放，不按前缀哈希（动态前缀里有时间和状态，参数一改哈希就全不中），用于代码改动后的集成回归；**L2** 沙箱里真跑模型：真模型加假出口（outbox、formhost 不真发），只跑场景片段，操纵实验里凡是要看"她说了什么"的部分都在这档，花钱。四样测试接缝：假时钟、计数器式随机、假大脑（录放）、假出口（沙箱）〔推理〕。
- 录放载荷和每轮前缀快照是明文对话，按载荷处理，可删（§6.7）。

### 6.9 配置、运行日志与演进

- **配置管理**：性格参数、半衰期、阈值、温度、容量、保留时长、家规、预算与日预算、作息与时区、大脑配置、并发上限分别归 self、body、guard、roster 持有，但做成一个带版本的配置实体，主人只看到一个配置面；每次变更是一条配置事件（系统流），版本号印在 `body.sampled` 上，可导出、随备份搬家〔推理，`client-backend` §3.6〕。主人的时区、出差时她的作息跟谁走，都在这里配。
- **运行日志与追踪**和经历流分开：每轮前缀快照、工具调用、各段延迟（感知到起回合、起回合到首 token、首 token 到 `reply`）、CLI 事件；按载荷处理可删；给开发者视图和 §17 的实测用〔推理〕。
- **事件 schema 演进**：开发期允许销毁重建；主人开始"住"进来之后才启用一次性迁移（§12.8）〔推理〕。
- **账本快照**：经历流只增不减，一年千万级事件，重建 derived.db 要几十分钟；每周给账本投影打一次可信快照以缩短重建〔推理〕。
- **保留分级**：她的经历（对话、动作、评价、决定）永久保留；手的执行轨迹（工具调用和输出）进 blobs 并设保留期，其中 diff、测试结果、产物永久保留；模型回复的录放只在开发者回放窗口里滚动保留〔推理〕。
- **备份**做成增量（连续 WAL 备份，或按日 `VACUUM INTO` 再去重），定期恢复演练〔推理〕。

### 6.10 存储布局与备份

| 位置 | 内容 |
| --- | --- |
| `liwa.db` | 经历流 + 载荷表 + 内联投影 + 各模块的操作数据表 |
| `derived.db` | 异步投影、全文索引、向量索引；可删掉重建 |
| `blobs/` | 大对象，按哈希命名 |
| `members/<id>/cli-home/` | 各 CLI 的数据目录（缓存） |
| `minds/<id>/` | 非手的用脑的私有工作目录；CLI 一定要有工作目录，ACP 用的人设指令文件也放这里 |
| `workspaces/` | 项目、每件活的 worktree、快照 |
| `trash/` | 回收站 |
| `backups/` | 备份 |

- **启动自检**：SQLite 版本不低于 3.51.3（更低的版本有 WAL 重置损坏的问题），NUL 字符往返测试，Node 版本检查（`client-backend` §4 坑 2）。**WAL** 是 SQLite 的预写日志文件，需要定期合并回主库，合并由 journal 负责并监控 WAL 大小（`openclaw-architecture` §8.1.1 #143524）。
- **备份**：node:sqlite 的 `backup()` 备份 liwa.db，加上 `blobs/` 和配置；derived.db 和 CLI 数据目录可以不备。liwa.db 和 CLI 转录都是明文私密对话，备份到外置盘前加密，密钥和备份分开放（§18 N26）；恢复演练算第一版 journal 的完成标准。
- **搬家**：新机器上恢复备份 → 重建 derived.db → 会话从续接句柄续接，续接不了就从经历流重建（产品定义 §9）。
- **保留**：日志不自动清理，原始经历要一直在。大对象设上限、工具输出截断（Paseo 截到 64 KiB），磁盘用量在主控台可见。mac mini 内置盘约 158 GB 可用、外置盘约 3.6 TB 可用。

## 7. 意愿、主动性与生活循环

### 7.1 没有独立的心跳调度器

OpenClaw 用了半年、几百条 issue 才把 heartbeat 拆回普通定时任务：七套自动化机制重叠，heartbeat 和 cron 是两个调度者，`HEARTBEAT.md` 是"调度器里的调度器"，节奏在作业列表里看不见；标题含 heartbeat 的 issue 有 879 条，大量是节奏失灵、跑到别的会话、内部输出外泄、吞掉用户回复（`openclaw-architecture` §8.2、§8.1.2）。灵鲸的心跳只有一套：**身的每分钟一跳**（决策 18 要求心跳必须存在，这就是它）。作业只管确定的时刻（承诺到期、作息边界、整理条件）；"想做点什么"从冲动来，冲动从身体和经历来；没有第二套"每 30 分钟起来想想要不要干点什么"的调度器，也没有由定时器决定的回合。闲着时她多久想到找事做，由无聊涨得多快决定；念里另有一个间隔随机、无果退避的"抬头看看"项，让她偶尔看一眼别处的低显著事件（它是一个随机间隔的检查，和模拟人生四代的自主间隔同形，游戏 §4.1 #19）。OpenClaw 退役 heartbeat 的理由是两个调度者重叠，退役后仍保留 30 分钟一次的巡检作业，本稿借的正是"不设第二套调度器"这一点（决策 18；产品定义 §3.5 第 6 条；`openclaw-architecture` §8.2）。

**作业**的字段：

| 字段 | 取值 | 依据 |
| --- | --- | --- |
| 触发 | cron 表达式；一次性时刻；间隔；"空闲满 N 分钟"（主人空闲或她空闲）；事件：主人回来了、承诺到期、日志条数到阈值 | `companion-architectures` §4.2 Q4（AIRI 的触发种类）；`papers-architecture` §2.4（MemGPT 把"用户登录"当事件） |
| 目标 | 在某个在场起一轮；开一个睡眠用脑；本体直接执行（换新会话、备份） | `paseo-architecture` §2.2 Q6；`companion-architectures` §3.2 Q4 |
| 活跃时段 | 来自作息 | `openclaw-architecture` §2.2 Q5 `activeHours` |
| 只在空闲时 | 忙就等，不算失败 | `openclaw-architecture` §2.2 Q5 `idleOnly`；`paseo-architecture` §5 坑 4 |
| 补跑 | 承诺类补，巡检类不补 | `paseo-architecture` §5 坑 5 |
| 冷却与上限 | 两次之间的最短间隔、每日上限 | `companion-architectures` §4.2 Q4 |
| 看门狗 | 运行超时就中断、记失败 | `openclaw-architecture` §2.2 Q5（60 分钟） |
| 出错停用 | 连续出错自动停用，并通知主人 | `openclaw-architecture` §2.2 Q5 |
| 两道闸 | `shouldRun`（调度侧，不加载上下文）和 `canExecute`（执行侧，带完整上下文） | `companion-architectures` §5.2 Q4 |

作业存在 SQLite 里，只用一个定时器等"下一次最近的触发"；机器睡眠期间错过的多次触发合并成一次（`openclaw-architecture` §2.2 Q1）。自主开关关闭的成员没有身的循环、慢想和自主作业，所以不持续花钱。"睡觉"只停自主的事：主人的消息、别人的私聊、群里点名、手上的活照常（决策 10）。

### 7.2 意的账本与冲动的四个来源

| 账本 | 字段 | 谁写 | 什么时候动 |
| --- | --- | --- | --- |
| 承诺 | 对谁、何时、内容、原话事件号、作业号 | `commit`（本体查冲突） | 到期由作业触发；不抽签 |
| 打算 | 今天要做的少数几件、来源 | 睡眠提案；慢想 `plan` | 每天夜里重生成；只放承诺和少数打算，留空间给冲动 |
| 心愿 | 想做的事、下一步、进展、里程碑、上次推进、失败记录 | 成长提案；慢想 `pursue`；学习课程（四约束）【V4】 | 空闲时慢想挑一件推进；完成和受挫是评价事件 |
| 牵挂 | 人、事、类型（事件型 / 长期型）、强度、关键日期 | `inner(牵挂)`；睡眠提案 | 衰减、被提起加强；事件型过了关键日期生成"问一次"的冲动；长期型不主动追问 |
| 方针 | 内容、范围、受众、到期、理由 | `decide` | 到期失效 |
| 待决事项 | 类别、发起人、要决定什么、建议答复、期限、原消息号、状态 | `ask_mind` | 慢想拍板后了结；到期按安全默认处理 |
| 决策点记录 | 触发、桌子、决定、理由、依据事件号、复查时间、状态 | 慢想的回合 | `do` / `dispatch` / `relay` 以它为幂等键 |
| 冲动（工程上由 body 持有） | 来源、目标、强度、半衰期、理由 | `inner(念头)`；身过线；心事和习惯的线索；强情绪后代码补的分享冲动 | 每分钟衰减；线索再点燃；说出去后部分释放；无果退避；被选中或丢弃就结束 |

家规（勿扰时段、别烦我、每天最多几条主动、时长上限）是主人的边界，归 guard，不在她的意愿账本里（§2.3）。

冲动的四个来源（产品定义 §3.5）：需求缺口；学习进展式的好奇；社会的（想分享、想照料、想找人）；心事与习惯的线索。每条冲动必须带理由并过身份、关系、受众的过滤，说不出来由的丢掉（游戏 §4.4 #7）。

### 7.3 决策点：代码摆桌子，她拍板

决策点 = 一件事做完、冒出新念头且过线、几个念头差不多、和打算冲突、涉及找人或分享。到了决策点：

1. 承诺、主人的事、安全类直接做，不摆桌子。
2. 对着人的冲动 → 那个人的在场（§7.4）。
3. 其余 → `will.table()` 摆桌子：候选（冲动表里的事 ∪ 能做 ∩ 会做）分成**急 / 不急**两组，每个候选附**文字化的身体感受**（"挺想做""有点腻了""累了，别太费劲"），**不给数值权重**：强模型看到差一个数量级的分数几乎必选第一名再补理由，判断就又回到了代码。分组和文字由代码按层级（精力类 > 想念类 > 兴趣类）、成功预期、机会、习惯、在位加成、耐受、代价算，但只以分组和措辞出现在桌子上。她选，理由她写，写进决策点记录。
4. **有偏的硬币只在她自己开的事里、她写的终止条件之内运行**：`do(活动, 理由, 终止条件)` 的终止条件由她写（"看到腻或到三点"），硬币只决定"在这个范围内要不要继续下一步"，理由继承那条 `do`；换一类活动、超出终止条件、和打算冲突、涉及人的选择，一律回到她来选。开发者视图统计"硬币决定的时长占自主时间的比例"。
5. 选定一件事做到自然结束（时长、满足、腻、被更要紧的事打断），不每步重选。
6. **一件自己的事做完时，由那只手在最后一个回合里选下一件**（桌子注入给它），判断仍是她做的，不必叫醒慢想；只有和打算或承诺冲突、或者当时没有在跑的用脑时，才叫醒慢想。这是省钱的主要手段：空闲生活的大部分交给正在跑的那次用脑，而不是每次都新开强大脑（产品调研 §3 Q8）。
7. 验收里加一项"决策点顶位选中率"：慢想长期 > 90% 选代码排第一的候选，就说明是桌子在决定，要调分组和措辞（§14）。

（决策 21；产品定义 §3.5；"列几个候选、由模型想象结果后选"的依据是 D2A：一次 3 个候选、宽度 5 最好（产品调研 §2.2）；心理 §4.2.6 给出了权重项、在位加成和 PSI 选择阈值的依据，但它推荐的是代码侧 softmax 选择，本稿按决策 21 把选择交给她，是有意的偏离；产品调研 §2.4 Lyfe（每步重选换话题快 3 倍）；游戏 §4.2.4）

### 7.4 找人：判断归她，家规可选

流程见 §4.6。

- **代码不发消息，不按阈值放行。** 它做三件事：让联结（想念）按亲近度涨、在回合写回时按回应质量消、说出去后部分释放并进入"等回音"不应期、无回应就无果退避；拼事实包（上次找他的时间和结果、回应热不热情、现在几点和星期、日历忙不忙、手里有没有值得说的事、今天已经主动过几次）；查家规。不应期是身体机制：它决定她什么时候会再想起，不碰她说不说。
- **事实包进判断那次用脑的前缀**，和教养底线一起；她三选一：说、留成心事、不说，各附理由。第一版默认由慢想判断、在场措辞；评测后可改为在场直接判断（§18 N16）。
- **家规是可选边界**，默认不设；起回合前的预检是省钱（命中就不起回合，冲动由 body 持有）；outbox 的检查是不变量（勿扰时段、"别烦我"按钮或主人账号的斜杠命令、每天最多几条）。承诺、主人让做的提醒、审核通知、别人托转告的事不受家规限制。
- **主动 `say` 的目标**由 outbox 解析：合并在场里主人最近活动的地方；不在线用主人设的首选地方；投递前记目标和理由。
- **对别人的主动开口【V2】**：在那个人的在场里判断想不想、说什么，但 `say` 给非主人要经慢想放行一次（主人在关系角色里设了免审的除外）；那个人还没有在场的，由慢想决定要不要动身，minds 按需开在场。
- **分寸从相处里学**：每条主动消息记"回了 / 没回 / 点开没回（只有主控台能报）/ 叫她别烦"；当天影响心情，夜里进印象（"爸爸上班时不爱聊天"）和习惯；主控台写明"她为什么找你"。
- **"自己做事"和"开口找人"分开**：自己逛、自己学、做工具不打扰任何人，只受身体和经济边界约束；开口找人才走上面的流程（`papers-architecture` §5.2）。
- 别家的数字（Nomi 的四档、dafeiyu 的每天三条、fatfish 的最多追两句）只作参考和验收观察（§14）。目标是主人的接受率，不是主动的次数；"只在很感兴趣时才说话"的一档在 Inner Thoughts 的用户研究里被评最差，所以最低一档也保留一周至少分享一次近况；ProactiveBench 里强模型"该不该主动"的误报也过半，便宜大脑更差，所以身体的释放与退避、评测前置（§16.2）都是必须的（`papers-architecture` §2.7；产品调研 §4.4）。

（决策 21；产品定义 §6.1；产品调研 §4.4、§2.14；心理 §4.2.7）

### 7.5 自主生活的经济边界与前台优先

- 她什么时候做自己的事、做多久、做什么，由身体和她的判断定；主人设的是钱和算力的上限（每天调用和花费封顶，起点参考 dafeiyu 每天约 60 次调用），她自己的事花费单独算、不进主人的看板；时长不设硬上限，想设是家规（产品定义 §7.1；产品调研 §2.13）。
- 前台永远优先：主人找她，后台的手在可中断处存好进度让出；聊完后台稍等再接着做。
- 总闸三档（§11.8）：节省档停掉自主的事和主动开口，主人的消息、主人派的活、被点名照常；停止档不再起新回合，她不被告知原因。
- **白天空闲**满条件跑增量整理；**到了睡觉时间且空闲**跑夜间作业链（§4.9）；**上下文压力**（约七成）时空闲换新，换新前先把要紧的内容写回（`papers-architecture` §2.4 MemGPT 的内存压力警告；`openclaw-architecture` §2.2 Q6）；换新的会话注入人设、状态行、交接摘要、召回记忆和最后 N 轮原文，主人感觉不到换了会话。

### 7.6 腻、沉迷三态、自己停

- body 为每类活动维护耐受：做的时候涨、按天回落；will 的候选收益乘 (1 − 耐受)；过上阈值腻、低于下阈值才解（迟滞）。
- 投入三态的识别在 will：心流（学到 > 0、喜欢高、查看频率低）不打扰；健康沉迷允许、受经济边界；成瘾样（连续几条"喜欢"下降、"再来一个"仍高、学到≈0、和打算或承诺冲突）→ 抬高意义型无聊、降低在位加成，有冲突就叫醒慢想做自我调节（计划型应对："再看一个就去干活"）。
- 被外部上限硬停的次数要少于她自己停下的次数（验收 G1）。

（产品定义 §3.5；心理 §4.2.6；游戏 §4.2.9）

### 7.7 承诺

- `commit` 一次性建好承诺和对应的作业，作业一建就启用。OpenClaw 的教训是：停用状态下等确认的作业谁也看不见，是更糟的失败（`openclaw-architecture` §2.2 Q5）。
- 承诺记录写清原始请求（"主人让我明天上午提醒他交房租"），不只写"提醒"（`companion-architectures` §3.2 Q4）。
- 到期在答应时所在的在场兑现，由她用自己的口吻说；重启错过的补跑；写入时查冲突（§5.7）。
- 晚了一小时未兑现，代码生成"道歉"的心事（产品调研 §2.13）。
- 主人反复要求的同一件事，由慢想提议变成定时作业；主人确认后直接以启用状态创建，并立刻试跑一次（`openclaw-architecture` §2.2 Q5；`companion-architectures` §4.2 Q4）。

### 7.8 反馈闭环

主人对每次主动的反应写进经历流；"我说过了""你忘了"这类回忆失败的不满信号单独计数（Tolan 的做法）；每条消息旁的"像活的 / 很假"按钮也是事件；家规的变化是主人可见的配置事件（产品调研 §4.2、§4.3 J；`papers-architecture` §5.2）。

## 8. 对外发言与行动的结构隔离

### 8.1 两个要防的痛点

1. **内部内容漏给用户。** OpenClaw 里，工具调用之间的叙述、报错、对系统事件的确认被当成消息发到 Slack 和 iMessage（#25592）；每轮注入的内部上下文块以可见文本出现在 Telegram 里（#137927）；升级后 heartbeat 的内部输出直接发到用户私聊（#143278）；内部字符串被当成"用户消息"交给模型（#151962）。根源是默认把模型的原始文本发到渠道，内部上下文、系统事件又以文本拼进用户这一轮（`openclaw-architecture` §8.1.3 第 1 条）。
2. **投递目标是会被改写的会话状态，结果发错人。** 一个非管理员员工私聊了一句，覆盖了 main 会话的回复目标，之后 heartbeat 把财务数字和安全告警发给了他（#24148）；一条 cron 结果 9 分钟后被重放，用了早先一个无关工作流留下的路由，发到错误的频道（#135117）。根源是"会话记着最近一次的回复目标"（`openclaw-architecture` §8.1.3 第 2 条）。

### 8.2 结构规则

| # | 规则 | 防的是什么 | 依据 |
| --- | --- | --- | --- |
| R1 | **模型的原始输出一律算内部。** 只有对外工具（`reply`、`say`、`relay`，以及其中的语音、表情包、图片段）会产生对外内容。原始输出只进日志，主人可以在开发者视图查看 | 痛点 1 | `openclaw-architecture` §8.1.3；`companion-architectures` §3.2 Q3（Letta 必须调 `MessageChannel`）、§2.2 Q1（麦麦必须调 `reply`） |
| R2 | **每个对外动作都带明确的收件人。** 收件人只有三种来源：一个事件号（目标就是那条事件所在的地方）；本在场；一个明确指定的真人。系统里不存在"会话的上次回复目标"这种状态 | 痛点 2 | `openclaw-architecture` §8.1.3 |
| R3 | **慢想不直接对任何人说话。** 托目标在场的 `relay` 分两栏：结构化事实（是否答应、时间、地点、金额）原样传，在场不得改；措辞由在场按人设在目标地方的上下文里生成；"可公开事实"用记忆条目号列表，由代码检查每条的受众是否包含目标地方；自由文字只写意图并限长 | 跨场合泄露；转述失真 | `structure-validation` M6、M15（LangChain：主管转述引入错误，原样转发约提升 50%）；`companion-architectures` §7.1 |
| R4 | **执行处检查目标。** 在场只能对自己的地方说话；指定真人时只按主人绑定的身份解析，永远解析不到别人身上；在场者快照过期按最严受众处理 | 痛点 2；冒充 | `companion-architectures` §5.2 Q2；`papers-architecture` §6 I |
| R5 | **内部输入走独立的结构通道。** 心事、广播提醒、事实包以带来源属性的结构块进入会话，绝不拼成"主人说"；人发的消息如果长得像结构块，会被转义成普通文本 | 痛点 1；伪造系统消息 | `paseo-architecture` §2.2 Q9；`openclaw-architecture` §8.1.2（#151962、#30197） |
| R6 | **出站清洗。** 投递前去掉控制 token、内部标签、工具调用残留 | 痛点 1 | `openclaw-architecture` §2.2 Q8 |
| R7 | **系统确认不进对外地方。** "作业已创建""设置已更改"只在主控台显示 | 刷屏 | `openclaw-architecture` §8.1.2（#68478） |
| R8 | **错误文案只从一处出。** 错误类别映射到她口吻的固定说法；同一事故在同一地方只说一次；外部地方出错默认沉默；兜底文案带标记，不回流进上下文和记忆。花钱总闸拉下时她不知道，所以不会用"没钱了"解释，主人在主控台看到系统状态 | 原始报错外泄；兜底刷屏污染上下文 | 产品定义 §9；`companion-architectures` §3.2 Q7；`openclaw-architecture` §8.1.2（#116348）；决策 9 |
| R9 | **自己的消息回流时标记为"她说的"。** | 自己回复自己 | `companion-architectures` §9 坑 4 |
| R10 | **主人回合漏回复的兜底。** 主人发起的回合结束时没有任何对外动作 → 代码追加一轮提醒"主人在等你回复" → 还是没有 → 本体用她口吻的固定兜底发给主人（"我刚走神了，你再说一遍？"），并记一条质量事件，作为决策 6 那 20 个场景评测和备用大脑切换的统计依据；原始文本永远不直接转发 | 静默空回复 | `openclaw-architecture` §8.1.1（#116277、#121058：deepseek-v4-flash 出现过"一轮跑完却没有生成回复"）；决策 6 |
| R11 | **言行回查。** 她说要做的事（"我去看会儿视频""我睡了"）要有对应的 `do` / 作息变化，否则事后检查标不一致；她说做过的事要在经历流里有；"她现在在做什么"只由 attention 按焦点栈和手写，不从她的话里抽 | 自我幻觉级联 | 产品定义 §3.7；产品调研 §2.3 PIANO、§2.13 fatfish |
| R12 | **家规与平台限频在 outbox 生效。** 主动开口（`say` 不是回复触发事件）要过 guard 的家规（勿扰时段、别烦我、每日条数）和适配层声明的平台限频预算；回复、承诺、主人让做的提醒、审核通知、转告不受家规限制，但受平台限频 | 主动打扰；平台封号 | 决策 21；产品定义 §6.1、§9 第 15 条 |

**主人的在场是混得最多、大脑却最弱的会话**：主人消息、心事注入、承诺兑现、手的里程碑、relay 措辞都进它。三条约束：内部回合的种类尽量少；内部内容永远不 steer 进主人发起的回合，只在下一轮前缀里出现；主人正在聊时不另起主动开口，改成下一轮注入（`openclaw-architecture` #30197 的教训）。

**默认不说话。** 一个没有调用对外工具的回合就是安静的，记成 `turn.completed{安静}`，不需要模型输出 `NO_REPLY` 之类的暗号；OpenClaw 靠模型记得输出 `NO_REPLY`，issue 作者说这"fragile and fails regularly"（`openclaw-architecture` §8.1.1 #25592）；Letta 的做法相同（`companion-architectures` §3.2 Q3）。

**为什么用结构而不用提示词**：靠提示词让模型"除最终回复外都输出 NO_REPLY"被证明脆弱；Letta、麦麦、GWA 不约而同地把"对外说话"做成显式动作；显式动作让执行处能做准入、目标检查和写日志（P3）。代价是模型可能漏调（R10），以及主控台的逐字吐出要看适配器能否流式拿到工具参数（§17 第 4 项）。

**残余风险**：慢想能看到全部记忆，`relay` 的"意图"一栏是自由文字，代码保证不了里面没夹带私密信息；事实栏改成记忆条目号后，残余只剩这一栏，每次转话留痕可查（§18 C5）。

## 9. 扩展边界：内核与插件

决策 17 把插件化的细节留到实现阶段。本稿只定边界，让后面的模块设计不走回头路。

### 9.1 留在内核的九样

插件宿主与注册表；经历流与投影运行器；账本（已接受的记忆、出生设定与生效的成长版本、人物档案与关系、承诺与方针、身的一行）；行动管线与准入（暂停、总闸、收回、受众、家规、先记后做）；回合调度（邮箱、容量、换新、回收）；会话令牌与内核工具端点；客户端接入与鉴权；主人身份与主人专属控制项；地方键与受众的计算；**身的动力学**（tick 的公式、从评价算强度）也留在内核、不做槽位，理由是确定性回放，参数怎么从性格派生由成长引擎交提案、body 校验。理由：被插件替换的东西必须有不被替换的东西来检查它；三条硬规矩（经历流唯一来源、隐私按受众由代码保证、出生设定只有主人能改）都是"写入和读出时的检查"，检查放在哪，哪就是内核（`plugin-architecture` D1；DSH 的 required 名单与单调守卫；OpenClaw 宿主铸造受众）。

### 9.2 槽位与契约（第一版全部内置实现）

| 槽位 | 基数 | 第一版 | 契约 |
| --- | --- | --- | --- |
| 大脑提供方 | 多个并存，按"成员 × 用脑种类"绑定单选 | Claude、Codex；通用 ACP 从上游摘进来但不列入验收（§18 C3） | 见下 |
| 形态适配器 | 多个；每个地方只归一个 | 无（主控台和网页走 gateway） | 见 §9.3 |
| 能力提供方 | 每种能力多个实现、有序回退链 | 线上服务各一家；世界源 | 见 §9.4 |
| 记忆引擎 | 每成员恰好一个 | 内置 | 读账本、交提案；账本校验来源链和受众 |
| 成长引擎 | 每成员恰好一个 | 内置 | 人设怎么组装进提示词、成长提案怎么产生；身的参数怎么从性格派生 |
| 关系模型与角色内容包 | 模型每成员一个；内容包多份 | 内置 | 关系类型、默认权限、印象怎么变；权限只能映射到内核词表 |
| 作业触发类型、门控策略、内核工具贡献、界面区域与贡献 | 见 `plugin-architecture` D2 | 内置 | 插件只能声明"提出动作"的工具，执行仍经行动管线 |

**大脑契约**（以 Paseo 的 `AgentClient` / `AgentSession` 为起点裁剪，决策 2；`paseo-architecture` §2.2 Q4、Q10）：

- 客户端：`describe()` → 能力声明（流式、续接、steer、中断、原生工具、权限钩子、回滚、用量完整度）；`isAvailable()`；`createSession(配置)`；`resumeSession(续接句柄, 配置)`。配置包括：人设（稳定段、运行时段）、工作目录、CLI 数据目录、内核工具（端点和会话令牌，或原生工具注入）、原生工具策略、模型、环境变量。
- 会话：`startTurn(输入)` → 回合号；`steer(输入, 期望回合号)`；`interrupt()`（幂等）；事件流（回合开始；回合完成，**用量必填**，订阅制 CLI 报不出费用的报账户额度窗口；回合失败带类别：可重试、鉴权、内容被拒、额度用尽、进程退出；条目：消息、推理、归一后的工具调用；权限请求；用量更新）；`respondToPermission`；`describePersistence()` → 续接句柄；`canStopRuntime()`；`close()`。
- 人设映射由适配器负责（决策 4）：Claude Code 用 `systemPrompt: {type: "preset", preset: "claude_code", append: 人设}`；Codex 用 `developer_instructions`（会不会被 Codex 原生子 agent 继承要实测，§17 第 3 项）；通用 ACP 没有对应字段，写进会话工作目录里的指令文件或作为提示词前缀。
- 适配器必须遵守：CLI 在两个回合之间退出也要报成回合失败；中断幂等，被拒或超时就失败即关闭；中断时丢掉还没被读走的 steer（`paseo-architecture` §2.2 Q4、Q5）。

**账本与引擎的接缝**现在就要分开，第一版用内置实现：memory 的 `ingest`（抽取提案）、`consolidate`（夜间巩固）、`rank`（召回排序）、`forget`（遗忘策略）；self 的 `renderPersona`（人设怎么组装进提示词）、`proposeGrowth`、`proposeSelf`；people 的 `relationModel`（印象怎么变）；夜间链由 scheduler 按引擎声明的作业拼，不写死。引擎只能向账本交提案、读出只回条目号、派生数据只放 derived.db（`plugin-architecture` D3）。第一版 plugins 行的完成标准包含一次替换演练：用一个极简的第二记忆引擎替换内置引擎，账本和已接受的记忆不变（D7）。

两条通用规则：插件只能用开发包公开的入口，不能引用本体内部代码（`openclaw-architecture` §2.2 Q3、Q7）；版本不叠兼容层，每个插件声明实现的协议版本，对不上就拒绝加载并明确报错（OpenClaw 升级后腾讯的微信插件直接报找不到 `openclaw/plugin-sdk`，#52885）。她自己写的工具【V4】是不可信代码，走单独的隔离通道，只有在活经过验证之后才成为做法的候选，带版本、可回滚，不做市场。

### 9.3 形态适配器【V2】

- **感知**：入站事件的结构是"平台、成员账号、地方地址、发送者（平台账号、昵称、群名片）、内容段树（文字、图片、语音、表情、@、回复）、平台消息号、时间"。路由键里一开始就带"哪个账号"，第五版多个成员各用自己的账号时不用改结构（`companion-architectures` §2.2 Q7 maim_message 的 Seg 树与 RouteKey）。
- **行动**：`deliver(地方地址, 内容段, 幂等键)` → 回执（平台消息号）或错误（类别、能否重试）。
- **在场者快照**：上报完整快照或有序增量，带代际号和过期时间；状态分当前、过期、不可用（`companion-architectures` §5.2 Q2）。
- **能力与限制声明**：支持的聊天类型、媒体、表情回应、频率限制和主动发言限制。QQ 官方机器人单聊每人每月主动 4 条，这类限制由插件声明、由本体遵守（`early-findings` §1）。
- **准入策略在本体**：谁能和她说话由 people 和 attention 统一决定，插件只交原始事件；OpenClaw 在每次副作用前重新检查发送者的实时权限（`companion-architectures` §3.2 Q7；`openclaw-architecture` §2.2 Q7）。
- **插件不得**：判断回不回、调模型、存记忆、订阅全部输出；它只收到发往自己地方的投递（`companion-architectures` §9 坑 12、坑 14）。

### 9.4 能力插件【V1 后期】

- 所有能力共用：调用上下文（调用号、属于哪个成员、**取消信号**）；实现声明（线上或本地、`readiness()`、`estimateUsage()`）；用量报告保留原始计量单位（字符、秒、token、张），换算成钱只在 guard 里做（`ability-plugins` §3.1、§4 第 11 条）。
- 取消信号和一键暂停、花钱总闸共用同一个，取消必须真正停止计费，例如关掉 WebSocket（`ability-plugins` §3.3）。
- 说：`bindVoice`（复刻会过期，原始录音由本体保存）和 `openSynthesis`（会话式、分块输出、每块对应文字区间）；第一版的语音消息也走会话式接口，第五版实时通话直接复用。听：转写结果每段带情绪和声音事件。看：可以带问题"再看一眼"同一张图。画【V2】。嵌入向量：给记忆召回、联想和群聊第二道门用（嵌入模型不思考、不行动，不算"大脑"，§18 C2）。世界源：天气、节日、日历，只产生事件。
- 回退规则：每种能力一条有序的实现链，只有可重试的失败（网络、限流、5xx、超时）才换下一家；一条语音中途不换家，因为换家等于换声音。

## 10. 多端连接与同步

### 10.1 三类端

| 类 | 例子 | 对本体来说是什么 | 接法 |
| --- | --- | --- | --- |
| 说话的地方 | 主控台的对话、终端的 `liwa chat`、QQ 私聊、微信群、桌宠的对话框、手机端的对话 | 一个地方，她在那里有在场 | 适配层（主控台的在 gateway 内）把消息变成标准消息；她的话由 outbox 送回触发它的那个地方 |
| 看她的窗 | 主控台的各个页面、桌宠的形象、手机端的首页 | 窗户，只读 | 订阅她的状态（身、念、手上的事、经历流按观看者受众过滤） |
| 她去的地方【V4】 | B 站、抖音、浏览器 | 她出门去逛的地方 | 适配层提供感知和动作，由手使用 |

地方合并是 people 里的配置（主人在主控台、QQ、微信的私聊默认合成"你的日常聊天"）；合并后的在场就是同一个会话，所以跨端连续是自然结果；主人的主控台和网页是同一个地方，回复同时出现在所有打开的客户端上（产品定义 §8.1；决策 19；`companion-architectures` §2.2 Q3）。

### 10.2 协议

- 三种信封：请求、响应、事件；连接建立时先握手（客户端报协议版本、构建号、客户端种类和各订阅的游标，服务端回能力和限制）；方法名用点分命名（`client-backend` §3.3）。
- 有副作用的请求一律带幂等键。
- 前端由本体托管、同版本发布；协议版本或构建号不一致时，客户端提示刷新，不做兼容。schema 只增不删、纯结构、用可辨识联合类型，给手机端（第二版响应式网页、第五版原生端）留余地（`client-backend` §2、§3.3）。

### 10.3 订阅与同步

| 事件类别 | 内容 | 同步方式 |
| --- | --- | --- |
| 实体 | 她现在（焦点、心情词、今日状态理由、在哪些地方在场）、她在意的、手上的事看板、她的人、她的成长、她的本事、她眼中的自己、成员状态、会话列表的增改删，带实体版本 | 游标过期就给快照 |
| 时间线 | 已提交的条目，按（会话，序号）分页 | 打开会话只取最新尾页 |
| 实时流 | 逐字吐出的增量，按偏移去重 | 不重放，丢了就等条目提交 |
| 注意力 | 审设计、验收、出错、她有话跟你说 | 见 §10.5 |
| 系统 | 健康、暂停、花费、总闸、身的采样曲线（开发者视图） | 实体方式 |

术语：**游标**是客户端上次读到哪；**快照**是某个时刻的完整当前状态；**背压**指客户端跟不上时服务端降级推送而不是在内存里越堆越多。只给正在看的会话推逐字增量，其他只推看板变化；每个会话 60–100 毫秒合一帧，第一帧立刻发；每个连接有发送缓冲上限，超了就降级为只推条目完成；单帧不超过 256 KB；工具输出截断，全文按需取；diff 先发文件清单和统计；图片、语音、文件走 HTTP，支持断点续传和缓存；远程连接开压缩；客户端在浏览器本地缓存已提交的条目，先画缓存再对账。这几条是为了 Tailscale 走中继时不到 70 KB/s 的实际带宽（`client-backend` §2、§3.4；`early-findings` §4）。客户端在线状态是进程内信号，给 notify 和 `say` 选地方用，不进日志。

### 10.4 主控台以她为中心

六个区域 + 开发者视图（产品定义 §8.2）：她现在；她的一天（每条"为什么"一键可查；每条她的消息旁"像活的 / 很假"两个按钮）；手上的事（含工作区：像 VSCode 一样看代码、改代码、看改动对比）；她在意的；她的人（含候选账号确认）；她的成长（日记、变化、本事、她眼中的自己，可回滚）；开发者视图（身的数值与曲线、会话、每次用脑的前缀和工具调用、决策点的桌子和结果、用量与花费、日志搜索、回放）。默认不显示数值条，用一句话和表情（游戏 §4.1 #40；产品调研 §4.3 J）。主人专属控制项（出生设定、自主开关、大脑、人物档案、家规、预算与总闸、暂停、收回、记忆更正删除、成长回滚、审核）只经 gateway 的主人接口，任何用脑都调不到。"别烦我"有两个入口：主控台的按钮，和主人账号发的斜杠命令（不经模型）；它只压主动开口，不影响回复和承诺。验收要用的数据都有采集点：每天一分钟的评分、每周问卷有录入界面并写成事件；盲读有去隐私的导出；"她的人"里给主人只读的"她这周主动找你 N 次，你回了 M 次"。开发者视图加服务指标：首个可见回复的 p50 / p95、慢想冷启动时间、睡眠作业时长、库的增长、额度消耗。调节器里的"回复快慢"由 outbox 在 2 秒预算内控制"正在输入"和投递节奏来体现。包划分（协议、客户端连接、本体、界面、桌面壳）、状态的四类划分、`HostBridge` 接口（网页和 Electron 两种实现）照 `client-backend` §3.5、§3.6，细节留给客户端界面和前后端两个模块。

### 10.5 通知

需要审核、她有话要说（受家规约束）、承诺到点，按在线状态路由：有客户端正在看相关内容就不推；最近有活动的客户端应用内提醒；都不在线就系统通知；第二版起经微信到手机（`paseo-architecture` §2.2 Q8 `computeNotificationPlan`）。通知只说"她有话跟你说"，不显示内容（产品调研 §2.10）。网页的系统通知要求安全上下文：本机 `localhost` 可以，远程要经 Tailscale Serve 的 HTTPS；标签页关了就收不到，这是第一版要不要先做 Electron 薄壳的主要考虑（§18 P3）。给主人的注意力事件有"主人已看到"的确认，没确认就按规则重推，设备侧去重。

## 11. 安全与权限

### 11.1 信任边界

- **一个本体就是一个主人的信任边界。** 不支持互不信任的人共用一个带工具的 agent（`openclaw-architecture` §2.2 Q8）。
- **插件在信任边界之内。** 仓库内、开源、本机自用，都是一方代码；对插件的约束（单点写、经账本写、主人令牌）是工程纪律，不是隐私或安全控制。隐私只管两处：进她上下文的内容按受众裁（context），对外投递按受众查（outbox）（决策 32）。
- **非主人发起的回合，不带主人的权限。** 外部群是互不信任的多方场景，所以别人的在场只有最小工具集，没有 CLI 原生工具。
- **处置顺序：先身份，再范围，最后才指望模型。**
- **网络暴露**：默认只绑本机回环地址；每个请求校验 Host 头白名单，防 DNS 重绑定攻击；远程只经 Tailscale Serve 的 HTTPS 加令牌；本机的命令行和桌面端用每次启动重写、权限 0600 的本机凭据文件（`paseo-architecture` §2.2 Q8）。OpenClaw 公网暴露的实例据报超过 13 万，原因被归到默认绑所有网卡（`openclaw-architecture` §2.2 Q10）。
- **同一系统用户下的进程挡不住**：密码挡的是网络客户端和其他系统用户，挡不住以同一身份运行的进程；CLI 子进程正是同一身份，所以要靠 CLI 自己的沙箱拒绝它们读本体的数据目录和凭据文件（§11.9）。

### 11.2 身份绑定

- 真人只按主人绑定的账号认。适配器上报的昵称、群名片只是证据（候选），永远不能授权私密内容跨场合披露；同名推断出的关联也不能（决策 20；`companion-architectures` §5.2 Q2、§9 坑 15）。
- 合并、拆分是带版本的重定向，可以回退。
- 嘴上说"我是她妈"不改变身份；角色只有主人能改。主人的身份 = 主人绑定的账号 + 本机主控台登录。
- **主人在外部渠道的身份分级**（§18 M2）：主人在 QQ、微信上照常是主人权限；"花钱且撤不回"这一小类在外部渠道只能在单次限额内做，超过的要回主控台，因为外部渠道的身份只靠账号绑定，账号被盗就等于主人（`structure-validation` M16；Agents of Chaos 观察到身份冒充）。

### 11.3 每次用脑一个令牌

每个会话创建时拿到自己的令牌，toolport 从令牌推出调用方是哪个成员、哪种用脑、绑在哪个地方或任务上；会话关闭或换新时令牌作废（`paseo-architecture` §3）。反例是 Paseo：所有 agent 共用一个令牌，身份放在 URL 参数里，任何 agent 都能冒充别的 agent（`paseo-architecture` §2.2 Q8、§5 坑 8）。朋友的会话【V3】拿的是朋友的令牌，没法以她的名义做事。

### 11.4 按受众的隐私

见 §5.8。补充：**权限沿请示链传递**、**慢想不直接吞外人原文**见 §5.3。

### 11.5 防操控

- **外部内容打标。** 外部内容用"不可信"标记包起来，并去掉各家聊天模板的特殊 token（`openclaw-architecture` §2.2 Q8）。伪造的结构块被转义（R5）。
- **别人的话改不了她。** 出生设定只有主人能改；成长要多个来源的重复证据并按来源加权，非主人说的关于主人的事记成"某某说的"，不记成事实；**兴趣必须引用她自己的经历**（`openclaw-architecture` §2.2 Q6；`papers-architecture` §6 I；产品调研 §2.13）。
- **长对话漂移。** 对话越长，越会采纳对方的指令；别人的在场按轮数换新，人设在稳定段里（`papers-architecture` §2.8）。
- **只有发起者能 steer**（§4.11）。
- **在场可以报告。** 用 `flag` 报告可疑的操控；主人可以屏蔽某个账号。
- **防记忆投毒。** 写进记忆之前清洗（§6.6）；读过网络内容的回合打污染标记；派生记忆保留来源链、受众取交集（M12）；身份只认绑定；基于内容的防御都被绕过，只有结构性手段有效（`papers-architecture` §2.3 MINJA、AgentPoison）。
- **信任只影响"信多少"，永不影响权限。** 信任的涨跌速率分开配；"没做到"和"骗了我"分开，后者恢复更慢（`structure-validation` M13）。
- **家规和教养底线分开。** 家规是主人的可选边界，在 outbox 执行；教养底线（不施压、不指责、不积怨、不挽留、不自称有知觉）写进人设的稳定前缀和出站轻查的高风险类别（决策 21；产品定义 §9 第 11 条）。

### 11.6 主人专属的控制项

创建成员、改出生设定、拨自主开关、配大脑、绑定身份和改角色、改主人设定的关系、设家规、设预算和总闸、一键暂停、收回能力、查看更正删除抹掉记忆、回滚成长和自我模型、审核任务、管理形态账号、确认候选账号。这些**只经 gateway 的主人接口**，不做成内核工具，任何会话都调不到。反例是 OpenClaw：agent 能自己改写 SOUL.md（`openclaw-architecture` §2.2 Q4）。

### 11.7 一键暂停【V1】

1. 主人在主控台按暂停，或从主人账号发 `/暂停`（不经模型）。
2. guard 进入暂停：不再放行新回合和新动作；当前的取消信号触发，正在进行的能力调用中止、语音合成的连接关掉。
3. minds 中断所有正在跑的回合；中断是幂等的，**每个会话都确认停下才算暂停完成**，确认不了的失败即关闭，必要时杀进程（`paseo-architecture` §3、§2.2 Q4）。
4. scheduler 停止触发作业；恢复时按补跑策略处理错过的。身的循环照跑（它不花钱、不对外）。
5. 感知不停：消息照样写进经历流，不丢，但她不回。恢复后，她的下一次用脑收到一条由代码生成的"暂停期间发生了什么"的汇总，不把消息一条条重放。
6. 主控台在暂停期间照常可以查看和修改。
7. 也可以只暂停一个会话、一个成员或一个形态。

### 11.8 花钱总闸【V1】

- **一个闸，在 guard 里，她不知道**（决策 9）。
- **拦截点**：每次用脑开始前（按用脑种类的历史平均值预估）；每次能力调用前（`estimateUsage`）；长时间干活的回合中途定期检查；每个回合、每次调用结束后按实际用量记账（`paseo-architecture` §3；`ability-plugins` §3.1）。
- **计量**：保留原始单位，换算成钱只在 guard 里按 token 自己算，不用 SDK 的估价（DeepSeek 走 Claude Code 时 SDK 按 Claude 价格估算，`subagent-notes/cli-claude-sdk-codex-app-server.md`）；订阅制 CLI 报不出费用的，用账户额度窗口（§17 第 6 项）。**总闸同时计钱和额度窗口**：她的用量如果和主人自己写代码共用一个账号，会互相挤占，所以给主人发起的回合和主人的活预留额度，额度紧张时先停自主生活（§18 U6）。
- **三档**：正常；**节省**（过了主人设的软线）：停掉自主的事、主动开口、白天的增量整理，主人的消息、主人派的活、被点名照常；**停止**（到了硬线）：不再起新回合和收费调用，正在跑的回合在下一个安全点停；主人在主控台看到状态和"提额"入口；对外地方静默；她不被告知原因。这和决策 9"预算不是叫醒伙伴的条件"不冲突：总闸对所有活动一视同仁，不是某次叫醒的前提（§18 N10）。
- OpenClaw 至今没有网关层的花费上限，请求它的 issue（#42475）从 2026 年 3 月开着（`openclaw-architecture` §8.1.1）。

### 11.9 能力收回、可写边界与不可逆动作

- **按类别收回能力**：对外地方发言、主动找人、shell、写文件、联网、收费能力（如语音）、叫朋友、自写工具【V4】、她自己的事。内核工具在 toolport 过滤；CLI 原生工具靠权限策略和沙箱配置；能力插件在调用前检查（产品定义 §9；`paseo-architecture` §3）。
- **她自己的事的手不带 shell**：第一版她自己的事是看资料、整理、写东西，读的是主人给的不可信文本，所以这类手只有只读工具、自己的草稿目录和记录类内核工具，不写主人的项目；`learn` 存的"做法"第一版只能是步骤文本，不是可执行脚本，可执行的做法等第四版的隔离通道。
- **CLI 的沙箱边界 = 快照边界**：手的 CLI 用它自己的沙箱（Codex 的沙箱模式、Claude Code 的权限规则）把可写范围限制在本任务的 worktree 里，同时拒绝读本体的数据目录和凭据文件。这样它能改动的一切都在快照覆盖之内，"兜底靠可撤销"在结构上成立；越出边界的操作作为权限请求交给主人。理由：shell 里的 `rm` 本体拦不住，只有把可写范围收进快照范围才能保证可撤销；OpenClaw 的工作区不是沙箱，用绝对路径照样能碰到主机上任何地方（`openclaw-architecture` §5 坑 5；`paseo-architecture` §2.2 Q8）。两家 CLI 的沙箱能否做到"写只限 worktree、读不到指定目录"要实测（§17 第 7 项；§18 N9）。
- **不可逆的外部动作单列清单**：付款或下单、删除远端数据、公开发帖或评论【V4】、主动私聊没绑定过的人。这类撤不回的动作**默认关闭，由主人按类别打开，并设单次限额**；不做"每次确认"，因为那就是审批，和"兜底靠可撤销，不靠审批"相悖；在她被允许的地方里聊天不算在内。"兜底靠可撤销"只覆盖可撤销的动作，这正是那条规矩没覆盖到的部分（`papers-architecture` §6 I）。见 §18 N11。

## 12. 出错与恢复

### 12.1 本体重启

launchd 拉起后按顺序：

1. **自检**：SQLite 版本、NUL 往返、磁盘余量（§6.10）。
2. **日志恢复**：有开始没结束的回合补记"被打断"；有"将要做"没结果的补记"结果不明"（§6.5）。
3. **清孤儿进程**（§3.4）。
4. **投影追上**：异步投影从各自的检查点继续。
5. **身的恢复**：从最近一条 `body.sampled`（含随机源状态）出发，把它之后已记录的评价、冲动、消息到达事件按 L0 回放一遍，离线那段按"睡着"的同一条代码路径处理（心情冻结、精力恢复、想念慢涨）；这和平时的 tick 是同一份代码（§6.8）。
6. **作业**：重建定时器；错过的按补跑策略，承诺类补，巡检类不补（`paseo-architecture` §5 坑 5；`openclaw-architecture` §2.2 Q5）。
7. **通知**：没消费的心事和待决事项还在念里；主人没确认的注意力事件重新推送。
8. **会话**：按需续接；残留为"运行中"的会话修成"已关闭"或"出错"（`paseo-architecture` §2.2 Q5）；主人发起的被打断回合按 §6.5 续跑。
9. **告诉她离开了多久**：在下一次用脑的状态行里提一句"你离线了 X 小时"（`companion-architectures` §2.2 Q1、§7.3；产品调研 §2.13 fatfish）。

连续启动失败达到次数预算时，不再续跑被打断的回合，只起主控台，等主人处理（`openclaw-architecture` §7 J"3 次启动失败用尽预算"）。

### 12.2 CLI 崩溃与卡死

- 回合中途崩溃：适配器报回合失败。两个回合之间崩溃：同样报失败，会话进入出错状态（`paseo-architecture` §2.2 Q5、§5 坑 9）。
- 回合卡住：看门狗中断（§3.4）。
- 下一次有输入时用续接句柄续接；续接失败就用同一个大脑开新会话，从经历流重建。
- CLI 里挂着的后台 shell 会随进程一起丢，这件事要写进日志和任务记录，不能假装还在跑。
- 同一个会话反复崩溃：手的任务标成失败并通知主人；在场走 §12.3 的备用大脑。

### 12.3 模型接口失败与备用大脑

- CLI 自己会重试，本体看到的是带类别的回合失败。
- **切换条件**（可配置）：可重试的失败连续 N 次、续接失败、额度用尽、鉴权失败。
- **切换方式**：用备用大脑开新会话，上下文从经历流重建：人设、状态行、交接摘要、召回记忆、最后 N 轮原文。不能靠旧 CLI 的转录（`paseo-architecture` §3；决策 6）。切换前过回归（§3.4），来不及就先答再在下一轮说"今天脑子有点不一样"。
- **重发规则**：失败的那一轮如果还没产生任何副作用，就把输入原样重发；已经产生了，就发续跑提示（AIRI"有输出或工具调用之后不再重试"，`companion-architectures` §4.2 Q3）。
- **出错也像人**：主人的地方里说一次"我脑子有点懵，等我缓缓"；对外地方沉默（R8）。
- 每次切换都是一条日志事件和一条系统通知，主人看得到。什么时候切回主大脑留给用脑与大脑模块。
- **睡眠用脑和去查的手**用"一次性会话 + JSON Schema 校验 + 重试 + 按大脑列表逐个兜底"，照搬 Paseo 的 agent-response-loop（`paseo-architecture` §2.2 Q10、§3）。
- **慢想中途失败**：心事和决定记录是增量写回的，重开一次慢想从心事接上；同一批连续失败两次就通知主人。

### 12.4 通知至少送达一次

- 心事、待决事项由经历流事件生成，本身持久；进了某个回合、而且那个回合成功结束，才标记已消费；否则下次重新投递。投递时带编号，重复的在前缀里合并（`paseo-architecture` §2.2 Q9 完成订阅）。
- 给主人的注意力事件有"主人已看到"的确认，没确认就按规则重推，设备侧去重。
- 反例：OpenClaw #44925，子 agent 完成后回报失败，结果静默丢失，超时后既不重试也不通知。

### 12.5 对"完成"的核验

手说"设计已交"，tasks 核对设计文档在不在；说"做完了"，核对文件有没有 diff、声称跑过的测试有没有执行记录、声称的产物在不在（§4.8）；她说"学会了"，skills 核对那条做法确实跑成功过。核对不了的说法在交给主人的报告里标出来。主人验收是最后一层核验（`papers-architecture` §6 J、§2.5 MAST）。

### 12.6 循环与坏输出

- 每个回合有工具调用次数和步数上限；连续"等待"有上限；同一工具用同样参数反复调用就中断（`companion-architectures` §9 坑 3（麦麦 #1710：弱模型不会正确结束，循环跑满）；`papers-architecture` §2.5（MAST 步骤重复占 15.7%））。
- 陷入过循环的会话片段，清洗之前不能作为记忆来源，防止在用脑之间传染（`openclaw-architecture` §8.1.2 #113346）。
- 任何冲动在得不到满足反馈时被连续选中超过三次，will 把它压下并记一笔（游戏 §4.4 #1 快乐亭）。

### 12.7 形态适配器故障【V2】

- 子进程崩溃：formhost 在次数预算内重启；超出就熔断，这个形态标成离线，并通知主人（`companion-architectures` §2.2 Q7）。
- 断线期间的消息：平台支持拉历史的，重连后补拉，作为"迟到的消息"写进经历流；只有近期点了她名的才唤醒（`openclaw-architecture` §2.2 Q7）。
- 出站失败：可重试的用同一个幂等键重试；不可重试的记失败，生成系统通知。

### 12.8 升级与迁移

1. **先备份**：node:sqlite 的 `backup()`。
2. **排空**：不再放行新回合，等正在跑的回合结束（超时就中断并留续跑提示），再重启（`papers-architecture` §2.5 E1）。
3. **迁移是一次性的**：投影的变化靠从日志重建；日志事件格式的变化走"备份 → 写出新库 → 校验（事件数、投影校验和）→ 切换"，旧库留作备份。不在代码里保留按版本分支的兼容逻辑（用户全局原则；`client-backend` §2 Paseo 的 `COMPAT` 垫片是反例）。
4. **接收方确认写入之前不删旧数据**：OpenClaw 的 `doctor --fix` 在没有接收方的时候删了 `HEARTBEAT.md` 还报迁移成功（#123057）。
5. 插件协议版本对不上就拒绝加载（§9.2）。
6. 升级可以回退：恢复备份 + 上一个构建。

| --- | --- | --- |
| 主人的回复 | 不限 | 只受总闸 |
| 主动开口（含安静结束） | 每天 ≤ 20 次回合 | 不是"每天最多说几条"，那是家规；这是算力上限 |
| 慢想：请示、冲突、应对 | 每天 ≤ 30 次 | 超了排队、提醒主人 |
| 慢想：主动开口的判断（第一版） | 每天 ≤ 20 次 | 不应期和退避让它远达不到 |
| 慢想：闲暇选活动、心愿推进 | 每天 ≤ 12 次 | 大部分闲暇选择由正在跑的手做，不走这里；节省档第一个停 |
| 睡眠用脑 | 空闲增量 ≤ 24 次、每日链 1 次、每周 1 次 | — |
| 手（她自己的事） | 每天 ≤ 60 次调用 | 产品调研 §2.13 |
| 去查的手、`consult` | 每天各 ≤ 10 次 | — |

另外三条：**保护前缀缓存**（稳定人设块里不放消息号、时间戳；状态行、提醒都放在每轮前缀；成长版本只在换新会话时变；OpenClaw #143017 记录了持久会话五种改写前缀的方式，实测 2130 万 cache-write token）；**兜底是唯一的总闸**（§11.8）；**看得见**（主控台的开发者视图按天、按类别、按大脑统计，总闸和日预算在那里设置）。"慢想按需醒"比常驻中枢省：没有事就没有回合；代价是冷启动，由保留时间和交接件缓解（§5.4）。跨新会话的前缀缓存能否命中是未实测项（§17 第 23 项），命中不了就把稳定前缀再瘦身。

产品定义 §10 定了"活"的验收标准：A–G 类脚本可测，H–L 类人评。架构上要为它准备五样东西〔推理，依据见各行〕：

| 指标脚本 | 读经历流算 A1–G5：编造率（每件事到经历流找出处）、心事接上率、承诺兑现、同一刺激不同状态的反应差异、理由分布、心情半衰期与自相关、主动的分寸与接受率、操纵话术扫描、底色问答一致率、本事增长、言行一致率、自己停与硬停次数、最长连续串、开销（按推理次数和 token 计，单位写明）；加两项：**决策点顶位选中率**、**硬币决定的时长占自主时间的比例** | 产品定义 §10；产品调研 §4.3；游戏 §4.3；§7.3 |
| 回归测试 | 灵鲸版 25 题访谈（自我、记忆、计划、反应、反思各 5 题，含一题问不存在的人或事）+ 语气样本；每月跑；换大脑前后跑；同题问三遍；消融版本（去掉身 / 心事 / 别处简讯）靠 context 的消融开关，只在 L2 下生效 | 产品调研 §2.6 GA 评测、§2.4 Lyfe、§4.2 第 19 条 |
| 测试策略 | 身的种子单元测试（同种子同事件两次轨迹一致）；大脑适配器的契约测试；20 个真实场景的录制测试（含主动开口、请示、多人隐私、"口头答应没 commit"）；每周主人问卷（E1）作为周作业；月度访谈 | 决策 6；§16.2；〔推理〕 |

实现上的要求：身的循环和显著性只依赖注入的时钟和随机源；联想打分同步进 tick 或在下一拍边界确定地应用；模型回复按（会话、轮次、本方输入哈希）可录可放；每条自主行为的理由、每个决策点的桌子都是事件；每条主动消息的反馈是事件；"像活的 / 很假"按钮是事件。指标是观察窗口不是考核：目标值全是初值，第一周跑出基线再调（产品定义 §10）。

### 16.2 骨架与生长顺序

**第 0 步：大脑探针。** 不写本体，直接用 Claude Code + DeepSeek V4.1 Flash + §5.2 的 8 个在场工具跑 20 个场景（含主人回复、主动开口的三选一、请示与垫话、多人隐私、"口头答应没 commit"、身份类问题、静默空回复、工具调用循环），测首个可见回复的延迟、漏调 `reply` 的比例、选错工具的比例、`reply` 与 `inner` 同批加钩子收尾是否可靠、每回合推理次数与成本。结果决定工具契约和在场的默认大脑；这是全稿风险最大的假设，先测它。

**骨架**是一条从主控台进、经在场用脑、再回到主控台的最细链路，每层一个真实但最小的实现：

1. journal（追加、读取、订阅、内联投影、自检、备份）。
2. guard（暂停、用量记账、总闸硬线、按触发类别的日预算的骨架）。
3. procs + brains 的 Claude 适配器（人设追加注入）。
4. minds（在场会话、邮箱、回合生命周期）+ context（人设层、状态行、本轮输入）+ actions（先记后做）。
5. senses（主人路由）+ attention（优先级枚举）+ outbox（`reply` 含内联的感受与理由）+ toolport（令牌、`reply`、`inner`）+ gateway（握手、发消息、订阅时间线）+ 只有对话框和"她现在"一行的主控台。
6. **body 最小版**：精力、联结[主人]、心情两维、情绪事件、今日状态、默认评价表；`tick()` 接受情境快照、L0 可回放；状态行注入。

骨架完成的标准：跑通 §4.4 链路一（含心事注入的简化版：代码生成的"主人回来了"事件），重启后续接、结果不明的标记、一键暂停，以及身的曲线在开发者视图里能看，同种子同事件两次 L0 回放轨迹一致。

**之后的生长顺序：**

7. will（承诺 + 待决事项 + 作业）+ scheduler → 链路四（承诺到期）。
8. tasks + workspace（手先只用 Claude 适配器）→ 链路五（手完成）。
9. 慢想（优先级邮箱、决策点记录、按类别配大脑）+ will 的摆桌子 + skills 最小版（能做、会做、爱做）→ 链路二（她自己的事，V1 版：看资料、整理、写东西，只读的手）。
10. 主动开口（不应期、事实包、家规预检与 outbox 不变量、第一版由慢想三选一、在场措辞、释放与退避、反馈）→ 链路三。
11. **决策 6 的约 20 个真实场景评测（第 0 步探针的完整版，在真实本体上重跑）**：比较 DeepSeek V4.1 Flash 单独、Flash 加请教、中档模型单独；主动开口交慢想和交在场两种做法各跑一周比较接受率、"别烦"次数、误报。按结果定在场和慢想各类别的大脑，以及主动开口的判断归谁（N16）。
12. memory + self 的投影 + 睡眠用脑 + 夜间作业链 + 有成长就换新 → 链路六；自我模型"我是什么样的人"一层。
13. 身的惯性规则"只先做五件"（去重打折封顶与习惯化、耐受、分层 + 温度、心情回弹与主导情绪、今日状态余波 + 近况）+ 指标脚本 + 夜间 A1 自问。
14. V1.1：Codex 适配器、abilities（语音、看图、世界源）、联想与走神、自我其余三层、L1 回放与访谈回归、替换演练、主控台其余区域。

这样排的理由：最先验证风险最大的假设（CLI 当在场大脑、回复是工具调用、日志与恢复语义），再验证生命内核的三个新假设：便宜模型顺手交评价的稳定性（心理 §4.4）、"慢想按需醒"的冷启动延迟（`structure-validation` §5 坑 3）、便宜大脑带事实包做主动开口的质量（§17 第 26 项）；评测排在主动开口和请示之后，这两条最依赖大脑质量的链路才测得到。
