## 整体结论速览

- **产品**：灵鲸（LingWhale / Liwa）是一个"家"，住着主人创造的数字生命。主角是主人的闺女：有性格、有记忆、会成长、有自己的生活，陪主人聊天、替主人干活，出现在主控台、网页，以后还有 QQ、微信等地方。完整定义见 `docs/product.md`（新增了出生设定里的"成长速率"）。

## 待定事项

### 需要用户拍板（调研提出的）

1. **听语音时用本地 SenseVoice 补笑、哭等声音事件**：线上服务都不返回声音事件，SenseVoice 可经 sherpa-onnx-node 在 Node 里直接跑。这是对"第一版全部线上"的例外。
2. **语音合成失败时**：整条消息换到备选服务（前提是备选服务已用同一段录音复刻过），还是用她的口吻退回文字。
3. **第一版客户端**：调研建议网页优先，Electron 以后作为约 300 行的薄壳加入，理由见 `client-backend.md` 第 3.7 节。而 product.md 写的是"第一版：本体、主控台、网页端"，需要用户确认第一版是否先不做 Electron。
4. **实时通话的"大脑快通道"**：调研认为通话每轮可能等不起 CLI 外壳，要直接流式调模型接口。这与决策 4"全部走 CLI"冲突，留到第五版再议。
5. **转写小凌的讲解视频**：需要安装 ffmpeg 和中文语音识别（如 mlx-whisper），待用户同意；不做也不影响整体架构。

### 阶段一：整体架构（进行中）

- A. 本体的进程模型与分层：几个进程，哪些是子进程，怎么监管。

- C. 事件流：外部消息、时钟、内部事件怎么进入、路由、排队。
- D. "唯一主意识 + 多个并行对话"怎么组织：中心调度，还是多个 agent 平级协作。
- E. 主动性与生活循环怎么调度。
- F. 事实来源与持久化：事件日志溯源，还是状态表。
- G. 扩展边界：插件和适配器怎么划。
- H. 多端连接与同步。
- I. 安全与权限边界。
- J. 出错与恢复。

## 环境与工具注意事项

- **GitHub**：WebFetch 访问 github.com 会被代理拒绝。Bash 里已配 `HTTPS_PROXY`，curl 可用：
  - 优先用 raw 地址，不占 API 配额：`curl -sS -m 30 -o <file> https://raw.githubusercontent.com/OWNER/REPO/HEAD/<path>`。
  - API：README 用 `-H 'Accept: application/vnd.github.raw' https://api.github.com/repos/OWNER/REPO/readme`；目录用 `.../contents/<path>`。未认证每小时约 60 次、搜索每分钟 10 次，并行调研时很快就用完。
  - 完整目录树（`git/trees?recursive=1`）对大仓库会超时。
- 论文：`curl -sS 'https://export.arxiv.org/api/query?search_query=all:<terms>&max_results=5'`。
- macOS 没有 `timeout` 命令。zsh 里不要用小写 `path` 当变量名。
- mac mini：`ssh macmini`，用 `zsh -l -c '…'` 加载 PATH，命令末尾加 `< /dev/null`。
- 仓库提交身份：仓库级 `user.name=WolffyCode`，邮箱沿用全局 noreply。
