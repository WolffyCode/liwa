名词

名词是什么
在场她在一个地方（或合并后的一组地方）的出现；每个在场一个常驻会话，替她面对这个对话里的人。如「你·日常聊天的在场」「妈妈私聊的在场」「家庭群的在场」
慢想她要做决定时醒来的一次用脑：拍板、定方针、派活、托在场说话；每次新开，处理完保留几分钟就收工；不跟任何人直接聊天
手她做一件事的用脑：替你干活，或做她自己的事；「去查的手」是只读、能上网的轻量形态
睡眠用脑后台整理记忆、写日记、提成长、事后检查
伙伴的会话伙伴（另一个数字生命）被叫来时的会话，用伙伴自己的人设和记忆
本体不思考：保管她的身、念、意、忆、能、人物档案和经历流，负责显著性、检查（权限、受众、冲突、家规、花钱总闸）、调度。不认平台，只认地方、人、受众
适配层（主控台适配层、QQ 适配层、微信适配层……）每种形态一个，处理平台细节：收发、私聊还是群、有没有 @ 她、群里有谁、平台格式和限制。交给本体的是标准消息；只报事实，不做判断

调度规则

规则一：适配层和本体怎么分工

适配层负责（只报事实）本体负责（做判断）
连上平台、收发消息这个对话交给哪个在场
认出私聊还是群、有没有 @ 她、回复了她、叫了她的名字，统一成「是不是说给她的」这个账号是谁（只认你绑定的）
告诉本体对话里有哪些账号在场的人能知道什么（受众）
把她的话换成平台格式：表情、语音条、图片这个人能让她做什么（权限）
声明平台限制，比如每天最多主动发几条要不要叫醒在场

适配层不判断回不回、不调模型、不存记忆、不管权限。

规则二：消息交给谁

「你的日常聊天」默认合并主控台默认对话、你的 QQ 私聊、你的微信私聊。合并只看对话，不看平台。

规则三：作业到点、活有进展时交给谁

规则四：在场要做一件事时

规则五：身的脉搏

规则六：慢想醒来以后

人物怎么记

人物档案（他是谁）她对他的记忆（她了解他什么）
放在哪本体（像通讯录），不归记忆系统记忆系统，挂在档案编号下，不挂在账号上
内容名字、和你的关系、角色、他的各个账号了解到的事、相处经过、信任和亲近程度
谁来写只有你；她只能提建议从相处里自动长出来，夜里整理、会淡忘、可更正
用在哪认人、权限、隐私，每条消息都要确定地查聊天时想起来
为什么分开记忆会被自动整理、改写、淡忘，也最容易被投毒；身份决定权限和隐私，必须由你说了算、不能变模糊。账号合并后，挂在档案编号下的记忆自然合在一起

场景

S01

闲聊

V1

你在主控台跟她随便聊几句。

  • 连着发的几条合成一轮处理。
  • 日常聊天分身一直在，聊太长了会换新会话，你感觉不到。
S02

另开话题对话

V1

你在主控台新开一个对话，专门聊装修。

  • 每个话题对话是一个独立的在场，互不打扰。
  • 记下来的事进她的记忆，所有能看到这件事的分身都想得起来。
S03

让她干活

V1

你说「帮我把网站首页改成蓝色」，走完设计 → 审设计 → 执行 → 验收。

  • 你的原话原样交给手，不经过转述。
  • 要你审核的事直接推给你，不等谁转告。
  • 「做完了」由本体核对，不只听手说。
S04

直接找手

V1

你在主控台打开 T-12，直接提修改、叫停或换大脑。

S05

问活的进度

V1

你问「网站那件活怎么样了」。

  • 你一提到某件活，本体就把它的最新进度塞给在场，不靠它自己去查。
S06

让她提醒

V1★

你说「明天 9 点提醒我交房租」。

  • ★ 你亲口让她做、又没有冲突的事，本体直接执行。
  • ★ 提醒到点直接交给答应时所在的在场。
  • 本体重启错过了提醒，开机后补上。
