# four-layers.md 评审（Codex）

**四层骨架能立住，但这份草稿还不能直接作为实现契约。** 没发现必须推翻“成员一份、实例按人、活归实例、第二层直跑底座”的证据；底座也确实具备同进程运行多个独立 Agent 的基础。最大的三个风险是：**① 隐私边界没有闭合——想事活、独处实例能读全部记忆，回流结论却缺少同等强度的受众约束，出口查出不符还只记质量事件；② 会话回收被写成无损操作，但底座正常 dispose 会清空未消费 inbox，任务归属、旧回合和新会话之间缺少交接协议；③ 共用账本的“单写者”被当成了一致性保证，却没有明确读、检查、写入、定时作业和对外承诺的原子边界，也没有真正落实成员级长期决定串行。** 这三项分别会导致泄露、丢事或重复做事、相互矛盾的决定。证据见问题 01–03。

本次评审针对工作区内的实际草稿，包含尚未提交的内容：`liwa/main` 的 HEAD 为 `323f569e481e3019fe6ec162cc14d758f1efafd9`，`liwa-dsh/dsh-base` 的 HEAD 为 `f4a3d12a9f3280a0a0d0ebffba8ccf8ff5655cc0`。全程未修改文件、未提交 git、未开子 agent；未执行会写入缓存或产物的测试，以下底座结论属于静态源码核查，性能与取消时限没有实测背书。

以下源码路径以 `DSH/` 代表 `liwa-dsh/`（dsh-base 的 worktree）；其他路径相对 `liwa` 仓库。〔一手〕表示本次直接读到的本地文档或源码；外部资料只核对到本地调研转录的，另行标明，不把前一轮调研者的“一手”自动算成本次的一手。

## 八个方面逐条结论

1. **内部一致性。** 查了正文、工具表、场景表、协议与 §10；发现任务归属、`manage` 权限、并发口径、群召回、换新、早晨触发和已定状态均有不一致，见问题 05、08–10、14、17、20、24–26。

2. **与已确认文档的冲突。** 对照了 product、portrait、overall 的指定章节与决策 5、14、18、19、20、21、32、42。四层和实例方向按决策 42 成立；新增冲突主要落在受众硬边界、群记忆、直连范围、持久化和换新约束，不能全部归为 §8 已列的措辞迁移。

3. **底座可行性。** 查了 Agent 注册与创建/恢复/销毁、inbox、bash/jobs、压缩、预设、pi-ai、agent-team 和 subagent。**多 Agent 同进程可行，共用服务可行；成员账本一致性、无损回收、完整暂停、业务预算与长期决定串行需要灵鲸自己补，底座没有现成替它保证。**

4. **实例模型失败模式。** 核查了错绑、冒用、跨平台同时来消息、群里有主人、回收在途任务、缓存与重建、并发 commit、决定队列、跨实例泄露、刷屏、`manage` 争用、注意计数及 V2 成本。最缺的是稳定身份与会话代次的区分、执行时权限复查、原子提交、消费游标和明确资源上限。

5. **“代码不读懂话”。** 工具权限、资源和投递按结构执行可行；方针冲突、议题归并、来源人的文字许可等仍混入了语义判断。另一方面，自由文本说错承诺无法仅靠工具隔离杜绝，必须把确定性保障和模型残余风险分别写清。

6. **依据核查。** 对照本地 landscape 与四份 notes，抽查了下表 12 项，发现适用范围扩大、指标混用和推理升级为一手的情况。尝试回原文核验 MIRROR、HiL-Bench、OpenClaw 召回文档，但联网工具未给可读正文，直接访问也返回 `Operation not permitted`；因此没有把这些外部数字标成本次已独立证实。

7. **遗漏。** 对话编程主流程仍能从 overall 找到，未发现四层方向使它无法实现；但新稿没有明确保留能力插件、直连其他实例、空闲增量整理、成长全会话生效、备份和多路语音输出的接缝。语音、桌宠、多成员社交属于后续版本，不要求现在展开实现，但需保留归属与冲突规则。

8. **第三、第四层接口。** 原话交接、任务回报、提供方抽象的方向可用；现有示意契约不足以承担抄快照、订阅直通、跨实例 manage、回收后汇报、主人直连和伙伴协作。缺的是来源授权、事件幂等、任务代次、状态版本、回问答复与提供方能力差异，而不是再增加一层包装。

## 对已定前提的保留意见

**没有发现需要推翻四层、按人分实例、共用人设与身体、第三层带人设的严重证据。** “共同身份与状态、分开的对话上下文”与底座结构不冲突；真正未解决的是这些上下文如何获得有序、受众正确的共享状态。

有两项必须把保障上限说清，均不要求改掉主人已定方向：

1. **“代码不读话”与“任意文字都可靠兑现、绝不泄露”不能同时成为确定性承诺。** 代码能保证真实付款必须经过付款工具、已知私密条目不送入无权受众，但不能证明一段模型自由文本没有错误承诺，也不能仅凭模型自报记忆号证明文字没泄露。建议保留原则，硬边界以结构化动作和数据来源执行，自由文本残余风险由评测、审计和她的纠正承担。证据：`four-layers.md:119`、`:178`、`:203`；`overall.md:1090` 已承认旧 relay 自由文字的同类风险。

2. **“整份抄给想事活”应解释为可追溯的有限快照，不能解释为完整无损继承。** 主人已定的是人设、最近 N 轮原文、召回都给；这能避免便宜模型写交接摘要时漏信息，但它仍然会截断窗口外内容，并增加读取不可信原文、token 溢出和来源混合风险。应保留抄原文，补截止版本、必带未决事项、预算和受众契约。证据：`four-layers.md:178`、`:285`；`papers-fast-slow.md:156` 所录 fork 论述也明确指出额外成本和无关上下文风险。

## 要主人定的点

不需要把决策 42 已确认的项目再问一遍；原子提交、回收不丢消息、权限继承和暂停确认属于落实既定承诺的工程工作。真正还需选择的主要是以下几项：

| 点 | 推荐 | 理由 |
| --- | --- | --- |
| **实例会话要不要套 CLI 外壳** | V1 默认直接用底座 Agent；外壳保留为有实际需求后再接的备选。 | 已核实多实例、inbox、预设和模型路由均有基础；为尚未证实的订阅账号需求提前增加第二种生命周期，会扩大取消、恢复和上下文差异。草稿“只有外壳能用订阅制 Claude”先删去定论。 |
| **群实例第二道门** | 若坚持代码不按语义选择，采用按条数/时间合批、受预算约束的只读观察回合，由她决定是否接话；显式 @ 走既定优先路径。 | 向量相似度本质上仍是内容相关性判断，不能仅改名“资源闸”消除张力。代价是观察回合费用，须计入群预算；预算不够时允许暂不观察。 |
| **V2 家人、群、陌生人的默认动作权限** | 家人可在角色许可范围内记承诺；派工作活默认关闭；群和陌生人默认无工作任务控制权。她自己的事的跨实例 `manage` 也应明确是否包含这些实例。 | 当前正文“任何实例”与工具表冲突。这个选择影响外人能否反复打断她的活动、耗尽资源，不能由实现者悄悄选一个版本。 |
| **账号合并是否追溯历史** | 默认只改变确认后的路由与身份解析；旧历史保留原来源和当时受众，按可见范围重建，不整体搬进新实例。 | 这样误绑后仍能追溯和撤销映射，不会把原本不相关的历史永久混成一段关系。已经披露的信息无法靠撤销恢复，应在确认界面准确表达。 |
| **若坚持全局想事可读全部私密记忆，是否接受自由文本回流的残余泄露风险** | 推荐不新增这种例外：全局决定保留，窄受众回流必须受来源约束；无法证明可公开的结论留在成员内部。 | “不改她的话”不等于“查出越界也必须发”。拒绝投递是执行主人既定隐私边界，不是在替她选择态度。若要允许凭模型自觉回流，需要主人明确接受这项例外，不能藏在“只记质量事件”里。 |

**可进入下一轮设计的条件**是先在原文改正问题 01–04，并把稳定实例身份、持久消费进度、原子提交和受众回流契约写出来。四层不需要重画；当前最缺的，是各层在并发、换新、失败和跨受众时到底承担什么保证。
