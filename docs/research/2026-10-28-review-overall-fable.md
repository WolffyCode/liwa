## ① 一页结论

总体判断：**骨架是对的，可以在它上面做；但稿子现在还不能直接当实现 spec。** "她在账本不在会话、经历流唯一事实来源、动作走同一条管线、受众和权限由代码算、身在代码里每分钟一跳、评价归模型"这几根柱子都有依据、彼此咬合，不要动。问题集中在三类：几处所有权和依赖方向自相矛盾（实现时检查工具一开就红）；几项"看起来省钱"的设计没有算账（慢想、工具回合）；第一版范围对一个人不现实。按严重程度：

1. **身与意的所有权分裂，身的循环向上依赖**（M1）。§2.3 说冲动归 will，§4.1 却让 body.tick 生成、衰减、再点燃冲动；body 算无聊和调节器需要"闲着没有、当前活动有没有意义、投入度"，这些在上层的 attention / will / tasks 里，违反 §3.2"调用只能向下"。这是全稿最核心的一张表（§2.3）上的洞，必须先补。
2. **回复链里藏着多次模型调用**（M2）。回复本身是工具调用，一个回合至少两步模型推理；再顺手交 `feel`、`want`、`note`、`keep_in_mind`，便宜模型多半一步一个工具，就是四五步。§2.4 写"回复链里不再串第二次模型调用"，和自己的工具设计矛盾；延迟、成本、漏调都受它牵连。最便宜的修法是把感受和理由做成 `reply` / `say` 的可选字段。
3. **慢想没有算账，也没有优先级**（M4）。强大脑 + 每次新开 + 全量人设和四层自我 + 桌子，一次醒来就是几万 token；"闲时每小时零到几次"乘一天，就是每天几美元到十几美元量级（推理估算，见 M4），远超 §7.5 引用的"每天约 60 次调用"起点；跨会话前缀缓存能否命中是未实测项。同时慢想"同一时刻 0 或 1"，但主人的请示和她的闲暇选择谁先谁后没写。
4. **回放模式名实不符**（M3）。"模型回复按前缀哈希录放"只在前缀一字不变时命中；调参会改状态行、操纵实验会改前缀，两件 §14 列为回放目的的事都命中不了。要把回放拆成三档说清楚，否则 N17 进骨架就是白做一半。
5. **去向表在"对着人的冲动"上自相矛盾，主动 `say` 的投递目标没有规则**（M5）。§4.3 一行说对着人的冲动直接进那个人的在场，另一行说"她自己要主动找别人"要请示慢想；P6 要求收件人来自事件，但主动开口没有触发事件，合并后的"你的日常聊天"该发到主控台还是 QQ 没写（v3 §4.5 有、v4 丢了）；家规在起回合前查还是在 outbox 查两处写法不一致。
6. **第一版范围对一个人不现实，骨架缺两项关键验证**（M6）。§16.1 把概念稿 V1 全部项都排进去（自我模型四层、习惯命名、沉迷三态、联想走神、向量检索、30 多个工具、三档回放……）。建议明确砍到后面的清单，并把"感受内联到 reply""主动开口与请示纳入 20 场景评测""按触发类别的日预算"提前。
7. **账本与引擎的边界只在文字里，没落到模块清单**（S1）。§3.2 说第一版内置、以后在插件宿主里换；§3.3 的 memory / self / people 仍然同时装着账本和"怎么算"。插件调研 D7 要求的"一次替换演练"不在 §16。不改，以后换引擎就是重写。
8. **依据有几处过度引申**（E）：用 OpenClaw heartbeat 退役证明"不能有定时器来由"（一手资料说的恰恰是别的）；用心理 §4.2.6 支持"她拍板"（原文推荐的是代码 softmax 选）；用 AI Town"空闲零调用"支持"没人找她也在过日子"。都不致命，但会误导后面的模块设计。

## ② 问题清单

### 必须改

**M1 身与意的所有权、依赖方向**
- 位置：§2.1（身的一行含"冲动"）、§2.2（冲动画在 will 下）、§2.3（冲动所有者 will；"body 过线"也写）、§3.3（body `impulse()` 作为输入；`tick(时钟, 随机)`）、§4.1（body.tick 衰减、再点燃、过线生成冲动）、§3.2（账本层在编排层之下，调用只能向下）。
- 问题：冲动被两个模块写；body 要读"闲着 / 当前活动 / 意义 / 投入度 / 在不在做被派的活"，这些在 attention、will、tasks 里，账本层反向依赖编排层。P7"每样东西只有一个主人"和"依赖方向由检查工具强制"（§3.2）会在第一天就被自己的代码违反。context（运行层）读 attention / will / tasks（编排层）同样向上。
- 依据：稿内矛盾〔一手〕；心理 §4.2.3 伪代码里无聊、调节器、冲动本来就在同一个 tick 里〔一手〕。
- 建议：二选一并写进 §2.3。推荐：冲动和耐受一样算"身的动态状态"，归 body（它每分钟都要碰），will 只持"意愿账本"（承诺、打算、心愿、牵挂、方针）并经 body API 读冲动、`drop`；或者冲动归 will，body 每分钟调用 `will.decayImpulses()`、`will.raise()`。签名改成 `body.tick(时钟, 随机, 情境快照{闲着?, 当前活动与意义, 投入度, 最近是否被派活})`，快照由编排层每分钟压下去，body 不认识上层。context 要么划进编排层，要么在 §3.2 明写例外。
- 影响：§2.1–2.3、§3.2–3.3、§4.1、§7.2、§16.2 第 6 步。

**M2 回复链里的隐藏模型调用与工具漏调**
- 位置：§2.4（在场"来回 ≤2 秒；回复链里不串第二次调用"）、§4.4（模型调 `reply` 顺手 `feel`、`keep_in_mind`）、§5.2 工具目录、§13。
- 问题：`reply` 是工具，CLI 的工具循环在工具返回后还会再推理一次才结束回合，至少两步；每个"顺手"工具若不能和 `reply` 同一步并发，就各加一步。延迟上主人在 `reply` 执行时已看到回复，但成本翻倍到数倍；便宜模型为省事会少调工具，这正是 §5.2 承认的漏调。
- 依据：agent CLI 工具循环的通用行为〔推理，需实测；v3 §16 第 4 条已列"不调 reply 时回合怎么结束"但没列"一步多工具"〕；产品 §2.11 Tolan 加一道反思中位延迟升到 2.5 秒指标全掉〔一手·转写〕。
- 建议：① `reply(事件号, 内容段, 感受?{效价, 重要度, 类型, 原因}, 理由?)`、`say(内容段, 理由, 感受?)`：最常走的路径不再需要第二个工具，P11"每件事带理由"也顺手落地；② 其余记录类工具允许同一步并发，实测两家 CLI 和第三方模型是否支持并行 tool_use；③ §13 的在场一行按"每回合 2–5 次推理"记账；④ 常见事件的默认评价表（规则打底）要有所有者（建议 body 按事件类型兜底，见 S5）。
- 影响：§2.4、§4.4、§5.2、§13、§16.2 第 5 步、§17。

**M3 回放模式的三档与确定性条件**
- 位置：§3.1 回放模式、§4.1、§6.2、§12（身的恢复）、§14、§17 #29、§18 N17。
- 问题：① "模型回复录放按前缀哈希命中"只在前缀逐字相同时成立；调参会改状态行文字，操纵实验会把无聊、想念设到极端，前缀必变，录放全部失效，§14 列的两个回放目的都达不到。② 我们只能观察自己发给 CLI 的每轮前缀，CLI 持有的历史不在我们手里，所以录放的实际形态是"按（会话, 轮次, 本方输入哈希）重放记录的工具调用"，只适合代码改动后的回归。③ 确定性条件没写全：种子"每天换"但中途恢复需要 RNG 状态；§3.1 把"联想的激活打分"放 worker_threads，带噪声的打分若在线程里异步完成，结果进入主线程的时机就不确定；§12"从最近一条 `body.sampled` 恢复并按离线时长衰减"漏掉了采样点之后已记录的 feel / want 事件，等于放弃了确定性带来的免费恢复。
- 依据：稿内推导〔推理〕；心理 §4.4 #1 调参要靠真实日志回放〔一手〕。
- 建议：写成三档。L0 身与念的纯代码回放：输入是时钟、种子、经历流里记录的 feel / want / 消息到达事件，不调模型，确定性，免费，用于调身的参数、算 C1–C4、做身体层的操纵实验；L1 代码回归：加上记录的工具调用重放，要求前缀不变；L2 真跑模型：操纵实验里凡是要看"她说了什么"的部分都在这档，花钱。每条 `body.sampled` 带 RNG 状态；联想打分同步进 tick 或在下一拍边界确定地应用；恢复 = 从最近采样点把其后事件重放一遍。
- 影响：§3.1、§4.1、§6.2、§12、§14、§17、§18 N17。

**M4 慢想的成本账与优先级**
- 位置：§2.4（慢想：强大脑、每次新开、保留 5 分钟）、§5.1（慢想稳定前缀 = 人设 + 全部四层自我，上限约 6 万字符）、§5.4、§7.3、§13（慢想一行无数字）、§7.5（每天约 60 次调用的起点）。
- 问题：一次醒来的输入 = 全量人设 + 四层自我 + 全部心事承诺打算 + 桌子 + 摘要，数万 token；按强模型价位每次未命中缓存约 0.1–0.9 美元〔推理估算：3–6 万 token × 3–15 美元/百万〕；"闲时每小时零到几次"一天 10–30 次就是 1–27 美元/天。跨新会话的前缀缓存是否命中是 `structure-validation` §5.2 第 6 项未实测。另外慢想同一时刻只有一个：主人的请示到达时如果慢想正在替她选闲暇活动，谁让谁没写；N5 的抢占只覆盖在场。
- 依据：产品 §2.13 dafeiyu 每天 60 次调用〔一手〕；`structure-validation` 坑 3 冷启动落在主人等回复的链路上〔一手〕；稿内 §13 无数字〔一手〕。
- 建议：① 慢想的大脑按触发类别配：请示 / 冲突 / 应对用强大脑；闲暇选活动、心愿推进用中档或在场同级；② 慢想邮箱带优先级和抢占（请示 > 冲突 > 闲暇；闲暇批次无副作用时可中断）；③ guard 把慢想醒来次数计入经济边界（节省档先停闲暇类）；④ §13 写出每类触发的预计次数和 token；⑤ 慢想的稳定前缀瘦身：四层自我里"我的故事"只给当前章。这不动决策 21（要紧的选择仍是她做），只是换个便宜些的脑子做。
- 影响：§2.4、§3.6、§5.1、§5.4、§7.3、§13、§18 N15。

**M5 去向表的三处矛盾与主动投递规则**
- 位置：§4.3 第 7 行与第 11 行；§4.6 与 §7.4、§8 R12；§5.2 `say`；P6；§10.1。
- 问题：① 对着人的冲动 → 直接在那个人的在场起主动开口回合；"她自己要主动找别人" → 叫醒慢想（M2 第三路）。V1 只有主人不出事，V2 妈妈上线时两条都成立。② 主动 `say` 在合并在场"你的日常聊天"里有三个地方（主控台、QQ、微信），P6 要求收件人来自触发事件，主动没有事件；v3 §4.5"主控台在线发主控台，否则用主人设的首选形态"在 v4 丢了。③ 家规：§4.6 先查命中就不起回合，又写 outbox 再查一次并"把 `say` 挡下留成心事"（§7.4）；不起回合就没有 `say` 可挡。④ "动身"列在四种动作里（§0.2），但没有任何工具或机制能为一个还没有对话的地方开在场。
- 依据：稿内矛盾〔一手〕；`openclaw-architecture` §8.1.3 第 2 条投递目标不能是会被改写的会话状态〔一手〕。
- 建议：① 明写：对主人，冲动直接进主人的在场；对非主人（V2），冲动先进那个人的在场判断"想不想、说什么"，但 `say` 给非主人要经慢想放行一次（或按主人设的关系角色免审），把 M2 的"她自己发起"限定为"对非主人的主动开口"。② outbox 规则：主动 `say` 的目标 = 合并在场里主人最近活动的地方，不在线按主人设的首选地方，投递前记目标和理由。③ 家规分两层：起回合前查是省钱的预检（命中就持有冲动，不起回合）；outbox 的检查是不变量。删掉"挡下留成心事"的说法，心事是她的，代码只持有冲动。④ 给"动身"一个机制（minds 按需为某人开在场，受众按那个地方算），或把它从四种动作里删掉，V2 再加。
- 影响：§0.2、§4.3、§4.6、§5.2、§5.3、§7.4、§8 R12、§10.1、§16.1 outbox。

**M6 第一版范围与骨架顺序**
- 位置：§16.1、§16.2、§17、§18。
- 问题：§16.1 几乎把概念 §11 第一版一列全排进来，再加三档回放、指标脚本、访谈回归、插件宿主、六区域主控台。一个人加 AI 协作，这是半年到一年的量，最大的风险是在验证"像不像活"之前耗尽耐心。骨架六步验证了"CLI 当在场大脑、回复是工具调用、日志与恢复"，但决策 6 的 20 场景评测排在第 7 步之后，而主动开口和请示（最依赖大脑质量的两条链）要到第 9、11 步才有，评测时测不到。
- 依据：概念 §11"只先做五件"〔一手〕；`plugin-architecture` D7"形状要有，生态不要有"〔一手〕；DSH 靠 370 个包和 CI 门禁才撑住万物插件〔一手〕。
- 建议：砍到第一版后期或 V2：自我模型只做"我是什么样的人"一层（概念说的"初版"）；习惯只记"情境 → 动作"计数、不命名不提案（它本来就要两个月才可见）；沉迷三态和成瘾样识别推到 V4（V1 没有逛，只保留耐受）；关注项并进心事（S3）；联想与走神放第 10 步之后；向量检索推到 V2 群聊门控（V1 只有主人，FTS 够用）；`consult`、`look_up`、`read_workspace` 后期；调节器先只留"心情词 + 话长提示"；开发者视图先只有身的曲线和每回合前缀。提前：`feel` / 理由内联到 `reply`（第 5 步）；20 场景评测里加主动开口、请示、多人隐私、"口头答应没 commit"四类题，评测推到第 9 步后或用一个代码桩慢想；guard 按触发类别的日预算先于开自主（第 9 步前）；夜里有成长或自我变更就换新主人在场（S7）；D7 的替换演练进 §16.1 plugins 行。
- 影响：§16、§17、§18 N14、N17、N20。

### 应该改

**S1 账本与引擎的边界没落到模块清单**（§3.2、§3.3、§9、§16）
- 问题：§3.3 memory 同时含"召回、联想候选、更正删除"；self 含"成长校验"和"性格参数"；people 含"受众计算"和"候选建议"。哪一半是账本、哪一半是引擎没分；§4.9 夜里十件事是一条写死的链，不是引擎声明的作业。
- 依据：`plugin-architecture` D3 三条线（写入提案、读出只回编号、派生数据只放 derived.db）与 D7 第 5、6 条〔一手〕。
- 建议：§3.3 每个账本模块加"引擎接口"一列（`ingest / consolidate / rank / forget / renderPersona`），第一版内置实现；夜间链由 scheduler 按引擎声明的作业拼；§16.1 plugins 行加"极简第二记忆引擎的替换演练"。

**S2 注意容量的双重所有权**（§2.3 guard"注意容量与并发上限"、§3.3 attention"容量"、§3.6、landing §2.7）
- 问题：两个模块都"管容量"；引用的 landing §2.7 又说容量就是并发上限的产品化说法。
- 建议：attention 持产品语义（同时顾几件事、排队、"等我一下"），调用 guard.admit；guard 只持资源并发上限（CLI 进程数、模型并发）。写清两者数值可以不同。

**S3 四套"在等"的结构**（§2.1 心事 / 关注项 / 牵挂、§2.6"待决事项"、§5.3 请示期限）

- 建议：关注项并进心事（心事的"在等什么"就是匹配条件）；牵挂保留为关系层对象，关键日期到了生成的是一条心事；新增"待决事项"账本（所有者 will，字段：类别、发起人、期限、建议答复、状态），决定记录归 will。§2.3 补齐。

**S4 家规的归属**（§2.3、§3.3 will `houseRules`、§7.2 把家规列进"意的账本"）
- 问题：家规是主人的边界（P9"边界归你"），放进 will（她的意愿）在概念上就混了，实现里容易被当成她的偏好去"学"。
- 建议：家规归 guard（守边界）或单独的 rules 账本，outbox 和 attention 只读；"别烦我"的入口（主控台按钮、主人账号的斜杠命令）写进 §10.3、§4.3。

**S5 身的几项机制没人做、两种心情模型并存**（§4.1、§4.3、§7.6、§16.2 第 11 步）
- 问题：① 概念 §3.5 负面与恢复的第 ② 条路"应对由慢想按可控性选"在去向表里没有触发行；② "连续坏事有保护""同一个人每天的影响有上限"（防刷）不在 §4.1 的 body 清单；③ "主导情绪 + 档位（迟滞）"只在第 11 步一笔带过，没有定义为 body 的输出，而 §2.3 又说各通道共用一份情绪词表；④ §4.1 写 OU 过程"向基线回弹 + 情绪推动"，第 11 步写"心情目标与速率"（RimWorld 式追目标），是两个不同的模型；⑤ 常见事件默认评价表（规则打底）无所有者。
- 依据：心理 §4.2.8、§4.2.3〔一手〕；游戏 §4.1 #4、#6、#7、#9〔一手/二手〕。
- 建议：去向表加一行"负面情绪事件过阈值且可控性可判 → 叫醒慢想做应对（计入慢想预算）"；body 清单补三条惯性规则和"主导情绪 + 档位"输出；心情模型二选一（建议 OU + 情绪推动，RimWorld 的"按速率追"用 θ 表达，不另写一套）；默认评价表归 body，按事件类型在模型未交 `feel` 时兜底。

**S6 早安与作息边界没有触发源**（§4.1、§4.3、§7.1、§16.1）
- 问题：product.md 第一版承诺"主动关心（早安、提醒）"。v4 取消定时自主后，早安只能靠清晨想念过线碰巧命中（概念 §5 07:00 那一行就是这么写的），第一周主人多半感受不到。承诺所在的话题对话被关闭后，"在答应时所在的在场起一轮"没有回退。
- 建议：作息"醒来"边界生成一条低显著线索事件（"新的一天、昨夜余波"）进念，判断仍归她；出生设定里允许种一两条初始习惯（情境 → 动作），由她的身体和判断决定做不做；承诺的在场不存在时回退到主人日常聊天。

**S7 成长与自我只在换新会话时生效**（§4.9"聊得太长的在场换新"、§5.5、§6.3）
- 问题：主人的在场是常驻会话，不长就不换新，成长版本可能几天不进她的稳定前缀；v3 §7.4 原有"睡觉换新"，v4 收窄成"太长才换"。
- 建议：夜间链末尾，凡成长版本或自我模型有变更，主人的在场和话题对话一律换新（夜里重建缓存的代价可接受）。

**S8 便宜大脑主动开口的兜底与"桌子替她决定"的量度**（§4.6、§5.3、§7.1、§7.3、§7.4、§14、§17 #26、§18 N16）
- 问题：① ProactiveBench 里 GPT-4o 级模型"该不该主动"误报也过半（papers §2.7〔一手〕），便宜模型更差，而家规默认不设、分寸靠夜里学，第一周最容易把主人烦到；② 想念只在接触时按回应质量消减，说出去没回时不变，身体会反复把同一冲动推过线，产生一串安静或不安静的回合；③ 慢想看到带"差一个数量级"权重的候选表，强模型几乎必选第一名再补一条理由，判断实际上又回到了代码。
- 建议：① 把"说出去后想念部分释放、无回应后退避"做成身体机制（§7.1 的无果退避也用于对人冲动），这是惯性不是规则，不违反决策 21；② 主动开口回合不受 2 秒约束，可配比回复更强一档的大脑（会话绑定模型的话，用一次性中档用脑产出"说 / 不说 / 草稿"，再由在场 `say`）；③ 决策 6 的 20 场景评测必须含主动开口；④ 桌子给慢想时只给分组（急 / 不急）和文字化的身体感受，不给数值权重；§14 加"决策点顶位选中率"，长期 > 90% 就说明是桌子在决定。

**S9 主人路径上的垫话规则**（§4.10 只写了群聊；§5.3"主人在等的请示除外"）
- 问题：主人说的话一旦有冲突就要等慢想冷启动；没有"先稳住 + M3 回执唤醒"的明确规则，主人会看到几秒到十几秒的空白。
- 建议：在场请示工具返回"已请示 + 期限"，人设里规定先用自己的口吻稳住；慢想决定后按 M3 立即给该在场起一轮。写进 §5.3。

**S10 她自己的事的"手"与"做法"的安全边界**（§2.4、§5.2、§6.2、§6.3、§9.2、§11）
- 问题：V1 她自己的事是"看资料、整理、写东西"，走的是手（有 CLI 原生工具）；主人给的资料是不可信文本，读着玩的手不该有 shell。`learn` 存的"做法"若是脚本，就是绕过 V4 隔离通道的可执行路径。模型回复录放的载荷含对话原文，没纳入 N7 的删除范围；删除一条载荷后，由它派生的记忆要按证据事件号级联。
- 建议：V1 她自己的事的手 = 只读工具 + 自己的草稿目录 + 记录类内核工具，无 shell、无写主人项目；V1 的"做法"只能是步骤文本，不是可执行脚本；录放载荷和每轮前缀快照都算载荷、可删；`erasePayload` 级联到引用该事件号的记忆与摘要。

**S11 平台限频与反馈信号的可得性**（概念 §9 规矩 15；§3.3 outbox、formhost；§7.4）
- 问题：形态适配器"声明限制"，但没有模块负责"按声明降级"（outbox 的职责列表里没有）；"点开没回"在 QQ、微信上拿不到，只有主控台能报。
- 建议：outbox 加"平台限频预算"（guard 持计数），主动类消息按声明扣额；反馈信号按地方能力声明降级（外部地方只有"回了 / 没回"）。

**S12 慢想重试的幂等与决策点记录**（§5.4、§7.3、§12）
- 问题：慢想处理到一半失败后"重开一次从心事接上"，但 `do` 已经开了一只手、`keep_in_mind` 还没写的情况会重开第二只手。
- 建议：每个决策点一条记录（触发、桌子、状态：待决 / 已决 / 放弃），慢想的 `do / dispatch / relay` 带决策点号作幂等键；重开的慢想先读未决的决策点。

**S13 联想打分的归属与时效**（§2.3、§3.1、§3.3、§4.3）
- 问题：激活字段（上次想起、想起次数）归 memory，打分却写在 attention（并在 worker 线程里跑），attention 要读写别人的表；"刚才想起"若下一次用脑在几小时后才发生，注入的是过期联想。
- 建议：memory 持字段并提供 `candidatesFor(线索) → 带分候选`，attention 只管时机（情境调节、频率上限）和取顶；联想事件带 TTL（建议 1 小时）。

**S14 回归与访谈的调度和成本不在夜间链与 §13**（§14、§4.9、概念 §10 A1、E1）
- 问题：A1 要求"每晚自动问她今天做了什么"，E1 要每周问卷，H8 要消融版本（去掉身 / 心事 / 别处简讯），这些都是额外的模型调用和上下文装配开关，没排进夜间链、没进 §13，context 也没有消融开关。
- 建议：A1 作为夜间链第 11 件（便宜大脑，一次调用）；E1 周作业；context.forTurn 接受"消融配置"参数，只在回放 L2 下生效。

### 建议

- **R1 §13 加一张按触发类别的日预算表**（主人回复、主动开口含安静、慢想按类别、睡眠作业、手），数字作初值，由 guard 节省档执行。这就是概念 §7.1"家里的经济条件"的落点，现在只有总闸三档没有分项。
- **R2 补四段工程必需品**：配置管理（性格参数、家规、预算、作息、大脑、并发上限散在 self / will / guard / roster 五处，要一个主人配置面和配置变更事件，搬家要能导出）；运行日志与追踪（和经历流分开，含每轮前缀快照、工具调用、各段延迟，按载荷处理可删）；测试策略（身的种子单元测试、大脑适配器契约测试、20 场景录制测试、月度访谈）；事件 schema 演进（开发期允许销毁重建，主人开始"住"进来之后才启用 N12 的一次性迁移）。
- **R3 工具目录瘦身**：在场 ≤ 10 个（`reply`、`say`、`feel` 可内联、`want`、`remember{事实|心事|牵挂|承诺}`、`recall`、`ask_mind`、`learn`、`dispatch`、`suggest_identity`V2）；`widen_audience` 经慢想；工具 id 用 ASCII、描述中文（Codex 对中文枚举的表现未知）。
- **R4 "诚实的上限"写进人设稳定前缀**（概念 §2 第 13 条：她知道自己想事情是一阵一阵的），§5.1 现在没有。
- **R5 名词**："分神"要么定义为"策略不同的手"要么删掉；"在场"既指她的出现又指会话种类，§2.1 加一句注。
- **R6 账本快照**：经历流只增不减，一年千万级事件，重建 derived.db 要几十分钟；每周给账本投影打一次可信快照以缩短重建。
- **R7 时区与时钟**：作息、昼夜正弦、周末、"去年今天"都要一个配置的时区并处理夏令时和 mac 休眠；时长用单调时钟；§3.1 的"可注入时钟"要同时覆盖这两种。
- **R8 备份加密与恢复演练**：liwa.db 和 CLI 转录都是明文私密对话；备份到外置盘前加密，恢复演练进 §16.1 journal 行。
- **R9 身的"同一个人每天影响上限"与习惯化**一并在 §4.1 列出（概念 §3.1 惯性规则），防止主人连夸三次刷心情。

### D. 过度设计与遗漏

过度（第一版没必要）：自我模型四层；习惯命名与提案；沉迷三态与成瘾样识别；关注项作为独立结构；在场 17 个工具与 `consult`；模型回复录放作为回放的主体；调节器五项全上；地方合并配置（V1 只有主控台）；注意容量"等我一下"（V1 单在场）；向量检索（V1 主人记忆量小）。

遗漏（真有必要）：配置管理与导出；运行日志、追踪与各段延迟预算；测试策略；事件 schema 演进策略（开发期）；时区与时钟（配置、夏令时、休眠、单调时钟）；按触发类别的日预算；账本快照；备份加密；决策点记录；"待决事项"账本；工具参数的语言与 id；早安 / 作息线索；主动投递目标规则；A1 / E1 的调度。多语言对单主人不必要；性能指标以 §17 实测为主、加运行期的延迟监控即可。

## ⑤ 没把握、需实测或需主人拍板

**需实测（决定设计走向，不只是调参）**
1. 两家 CLI 加第三方模型：一个回合里能否并行多个 tool_use；工具返回后是否必然再推理一次；一次 `reply` 的真实推理次数与延迟（M2）。
2. 慢想冷启动：新会话 + 注入 + 首 token 的耗时；跨新会话的前缀缓存命中率（Claude Code 外壳下走 DeepSeek 时尤其未知）；保留 5 分钟实际省多少（M4）。
3. 便宜大脑带事实包做"说不说、说什么"的质量：一周接受率、"别烦"次数、安静回合数（S8）；以及同一刺激下 `feel` 的方差与漏调率（§17 #22）。
4. 身的参数（半衰期、回弹、扰动、过线曲线、在位加成、耐受阈值）用 L0 回放调；联想频率与突兀感要主人评（§17 #24–27）。
5. 回放 L0 的确定性（同种子同事件两次轨迹一致）；L1 命中率只对代码回归有意义。
6. 一年经历流的实际体积和 derived.db 重建时长，决定要不要账本快照（R6）。

**需主人拍板（概念或决策层面，评审不能替定）**
1. 第一版砍掉的清单（M6）：概念 §11 把自我四层、习惯、沉迷三态、联想都列在 V1，缩到"初版"需要主人点头。
2. 慢想按触发类别配不同大脑（M4）：闲暇选活动用中档脑，是否仍算"要紧的选择她自己做"。
3. 早安是可靠功能还是涌现行为（S6）：product.md V1 承诺了早安；v4 下它取决于想念过线。建议作息线索 + 可选种子习惯，但这改变了"早安"的性质。
4. 对非主人的主动开口是否要慢想放行一次（M5），还是按关系角色免审。
5. 家规默认不设已确认；是否在出生设定里一次性问主人"第一周想不想先设个温和的上限"——这是边界不是性格，但概念写的是默认不设，改要主人同意。
6. 容量和并发是否分开两个数（S2）；容量在 V1 是否干脆不做。
7. 桌子给慢想时是否隐藏数值权重（S8）：隐藏更像"判断归她"，但可能让闲暇选择更随机、更贵。
8. "动身"（主动去一个还没有对话的地方找人）是 V2 的功能还是删掉（M5）。
9. 日历接入放 V1 还是 V4（概念稿三处不一致）。
10. 备份是否加密、密钥放哪（R8）；录放载荷与每轮前缀快照是否随记忆一起可删（S10）。

**我没把握的判断**
- M4 的费用估算基于强模型公开价位和"6 万字符上限"的上界，实际人设可能小得多；结论"要算账"不变，数字会变。
- M2 的"至少两步推理"来自 agent CLI 的通用工具循环，Claude Code 与 Codex app-server 各自是否有"工具调用即结束"的模式，我没有核实。
- 容量 5、慢想 5 分钟、空闲增量 10 分钟 / 20 条这些数都是推理初值，本评审不对数值本身表态，只要求它们可观测、可回放调。
