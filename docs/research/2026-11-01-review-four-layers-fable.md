# four-layers.md 评审（Fable）

日期：2026-11-01。对象：`docs/architecture/four-layers.md`（草稿，2026-11-01）。任务：核实合理性、挑毛病，不复述设计。依据标记：〔一手〕我自己读过的文件或源码；〔二手〕转述；〔推理〕我推的。行号指评审时的文件版本。底座路径以 `liwa-dsh/` 为根（`dsh-base` 分支）。

## 总评

**这套设计立得住。** 四层的边界、"代码不读懂话"的分工表、按人切实例且共用账本、每个实例自带第三层、活的事件回到派它的实例，这几样在底座上都有对应物：地基的 `AgentRegistry` 就是一张 `Map<SessionId, Agent>`，每个 Agent 各自的 inbox 与 `idle / running` 驱动器，`followup / steer / inject / cancel({keepInbox})` 的语义和 §2.12 写的一致，预设可以按 Agent 绑定（`meta.agentPreset`），所以"多个常驻 Agent 在同一进程并行、共用账本"是现成能力，不是假设。没有发现 V1 范围内做不到的东西。

问题集中在三处，都是 V2 起才真正发作、但现在不补就会被当成已确认设计带下去的：

1. **主人实例跨平台合一，把 `overall.md` §11.2 已定的"外部渠道身份分级"抹掉了。** 工具集按"实例种类"裁，不按"触发消息来自哪种地方"裁；微信账号被盗就等于在主控台登录的主人：能 `dispatch` 任何活、`manage`、`commit`、经想事活花钱。这是对已确认安全决定的静默回退，而且 §8 没列。
2. **隐私边界有两处被交回了模型或绕开了结构。** `inner` 写入的事实带"谁能知道"——若由她填，就是模型在放宽受众（`overall.md` §5.8、决策 32 都规定受众只由代码造）；独处实例"召回全部"，而她自己的事默认受众公开，私密记忆经交接包流进公开受众的活。另有"群永远不作来源也不作去处"与已确认的 `product.md` §6.4 相反，也没列进 §8。
3. **删掉几个闸以后没有补上对应的"算术"。** 不应期删了，但"她选了留成心事"之后冲动不消退，下一分钟按概率又起一回合，`overall.md` §4.6 "p = 0.2 问 5 次就是 67%"的论证原样成立，主动开口的 20 次日预算会在半小时内被同一冲动耗尽；出站轻查删了，口头答应没 `commit` 只能等夜里补，验收 A3（承诺 100% 兑现）直接受影响。这两条不是推翻主人原则，是原则落地缺了一块身体机制。

另外一个贯穿的毛病：**R3 / R4 的落地机制写的是 `00-contracts.md` 的 `SessionConfig.limits` 与 `endTurnAfter`——那是第四层 `brain.provider` 的契约，而本稿说实例会话不经第四层、直接跑地基。** 地基的 agent-loop 没有任何每回合步数上限（已核实只有并行工具数 10），要靠 `agent/pre-step` 拒步和工具结果的 `concludesTurn` 来做；用量记账、令牌、换大脑回归在地基路径上也没有归属。§10 第 3 条提的"会话运行时抽象"是对的方向，但它现在是待议，而 R3 / R4 已经写成了已定规则。

## 八个方面逐条结论

1. **内部一致性**：逐节对照了 §0 三个例子、§1 表、§2.2 两张表、§2.9 工具表、§2.10 规则表、§2.17 场景表、§6、§8、§10。发现 7 处前后不一致（第 7、13、14、19、26、27、36 条），其中"没有默认表"三处说法不同（14）和"两分钟后暂停"无机制（7）最要紧。§10 的"已定 / 待拍板 / 待议"与 `handoff.md` 决策 42 对得上；但 R3 / R4 已写成已定规则，其机制却依赖待议的第 3 条（12）。
2. **与已确认文档的冲突**：§8 列出的改动核对过，范围大体对。**没列但冲突的**：`overall.md` §11.2 外部渠道身份分级（1）、`product.md` §6.4 群里群外同一个她（3）、`overall.md` §5.8 受众只由代码放宽（2）、`overall.md` §5.3 权限沿请示链（6）、决策 4 / 6 的措辞（16）、`overall.md` §2.1 话题对话（25）。**列了但低估幅度的**：`product.md` §3.1 默认表（14）、§7.1 前台优先（15）标"只改措辞"。决策 5、14、18、19、20、21、32 没有冲突。
3. **底座可行性**：到源码核了 12 处（见下节）。`followup / steer / inject / cancel({keepInbox})` 的语义与 §2.12 一致；多 Agent 同进程并行、各自 inbox、按 Agent 绑预设都是现成的；`subagent-claude-code / -codex / -acp` 确是一次性；`llm-pi-ai` 的三种协议与"OpenAI 不提供 ChatGPT 登录"属实。**与稿不符的**：地基没有每回合步数上限（12）；5 秒转后台是 Super-agent 配置不是地基默认（34）；`compaction-basic` 默认自动压缩会和换新打架（35）；`inject` 在 dispose 时会丢（20）。会话建与收：`ctx.agents.create({sessionId, meta: {agentPreset}, seed?})` / `AgentHandle.dispose()`，重建靠本体从账本拼前缀再 create，地基侧没有现成的"从账本重建"，要本体写。资源：每个 Agent 把会话事件日志持在内存（`core/session` "内存存储"），常驻实例靠换新封顶，是可控的。
4. **失败模式**：十二项里，账号冒用（1）、主人在群里（5）、回收时在途消息（20）、并发 `commit`（21）、串行饥饿（22、23）、跨实例泄露（2、4、18、19）、独处与主人争用 `manage`（10）、注意容量口径（13）、V2 成本上界（11）各有一条问题；同一人跨平台同时发消息（§2.6 "同一邮箱连发合并"，`reply` 目标取自事件）和多实例同时找主人（对象是主人的冲动只进主人实例，30 秒合批）查了没发现问题；回收重建后的前缀缓存（人设段逐字相同、在场说明放末尾）设计合理，能否跨实例命中标了待实测，没问题。
5. **"代码不读懂话"**：还在读内容的只剩群第二道门（已标待议）和"事实栏数字核对"（36）；反向的失控点有三：受众自报（2）、承诺用语无核对（9）、冲动选择后不消退导致代码的再触发节律决定结果（8）。后两条是删闸后缺身体算术，不是原则错。
6. **依据核查**：抽查 14 条〔一手〕。**属实**：Super-agent 额外名额与 `WorkerSlots`（到原型源码 `src/executor/dsh.ts` L166–171、`docs/003` L59 核过）；router 装 5 秒沙箱 bash（`cordis.patch.yml` L38–56）；DecisionBench 7.5–29.5%（arXiv 摘要核过）；Proactivity-Gym 30 人研究与 23 个配置（摘要核过，97.8 / 26.7 在正文）；Springdrift 三个症状（笔记 L242 一手 §3.4）；召回四条规则（OpenClaw）；KAME 垫话；InterruptBench；派出去的活不带人设（Hermes、麦麦、OpenClaw）；Kindroid / SillyTavern 资源闸。**张冠李戴或标错**：MIRROR 2.52 秒是回复延迟不是后台思考（30）；Kimi 15 步是 BrowseComp 实验设置（31）；30 词写成 30 字（32）；Letta / Hermes "换新后出现在所有地方"是推论标成一手（33）；5 秒转后台归到地基（34）；HiL-Bench "通过率"措辞（39）。没有发现编造的数字。

8. **第三、四层接口能否撑住第二层承诺**：`tasks.open({实例, 抄一份?})`、`tasks.send(订阅直通 | 主人直连)` → steer、`tasks.manage` 带"由哪个实例"、活事件 `followup` 派它的实例——形状够用；第四层的 `brain.provider` 契约（会话、回合、steer、中断、权限钩子、用量）覆盖干活与想事。**撑不住的两处**：想事活的决定档没按发起实例角色裁（6）；`conclude{要更正的实例}` 要求想事活知道实例清单，稿里没说代码把实例清单作为事实给它（一般，可并入 6）。想事活若用 Claude Code 外壳，决定类工具要经 MCP 暴露、带每会话令牌，`overall.md` §5.2 "MCP 只是接法之一"已覆盖。

## 对已定前提的保留意见

- **"硬限制只留家规与日预算，不应期不再是闸"**（前提第 5 条）：不反对删闸，但要补"她选择之后冲动消退"的身体算术（第 8 条）。证据：`overall.md` §4.6 的概率论证不依赖闸，依赖"没变的冲动会再过线"；`product.md` §3.5 ③ "做了计划的心事会平静下来"本来就是身体机制。不补的后果是主动开口日预算被同一冲动耗尽，之后主人实例对想念"失聪"到第二天。
- **"代码只做……机器核对"**（总原则）：边界要写清"机器核对"包不包括对她说的话做结构匹配（承诺用语、金额、数字与活号）。稿里一处删（出站轻查）一处留（事实栏核对），说明边界还没定（第 9、36 条）。
- **"每个实例 = 常驻实例会话 + 它自己的第三层"**：没有保留意见；但"主人一个常驻、跨平台合一"要加地方维度的权限分级（第 1 条），否则和已定的决策 25 M2 相撞。
