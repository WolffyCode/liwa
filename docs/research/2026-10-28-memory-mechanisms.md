# 调研：记忆机制——"神经元式记忆"到底是什么，灵鲸的记忆该怎么做

日期：2026-10-28。用途：`docs/architecture/README.md` 的"05 记忆系统"（memory、people、self 的自我模型、睡眠用脑的记忆部分）写模块文档前的调研。主人的要求："我看网上好多人给他做神经元记忆机制，你还是去读开源项目和论文给我一个方案。"

本稿在三份已有子调研（`subagent-notes/memory-papers-core.md`、`memory-oss-source.md`、`memory-benchmarks-poisoning.md`）之上补四件事：联想 / 激活式记忆的源码级拆解；巩固与遗忘；自我、人物、印象的先例；Node + SQLite 的选型与实测。已有调研写过的数字只引用，不重做。

标注：〔一手〕读了源码或论文正文；〔二手〕摘要、第三方页面或已有子调研转述；〔实测〕本机脚本跑出来的；〔推理〕没有直接来源的设计判断。

## ① 一页结论

1. **网上说的"神经元记忆"其实是三类东西。**(a) 概念节点 + 赫布式加强（一起出现就连起来）+ 激活扩散：麦麦 0.5–0.10 的"海马体"、NeuralMemory、HeLa-Mem、SYNAPSE；(b) 知识图谱 + 个性化 PageRank（PPR，从种子节点出发随机游走打分）：HippoRAG、麦麦现役的 A_Memorix、Graphiti 的图检索；(c) 模型内部的神经记忆：Titans、MemOS 的参数 / KV 记忆。(c) 灵鲸用不了：大脑是外部 CLI，权重和 KV 不归我们管，写进权重的东西也不能按条删除、按受众过滤。
2. **证据：图和扩散只在"多跳"题上有稳定收益，"记住一件事"不比好的向量 + 全文检索强。** 对照最公平的 HippoRAG 2（同一读者、同一检索器、强嵌入基线）对 NV-Embed-v2：平均 F1 59.8 对 57.0，涨幅主要在多跳（2Wiki 71.0 对 61.5），简单事实题只差 0.5–1.4；GraphRAG、RAPTOR、LightRAG 都不如纯向量〔一手〕。MemoryAgentBench 里 HippoRAG-v2 总分 41.6，BM25 41.5〔二手〕。NeuralMemory 自己的评测里扩散激活 Recall@5 0.380，输给朴素基线 0.466〔一手〕。2026 年的 SYNAPSE、HeLa-Mem 只在 LoCoMo 上自报涨分，基线弱（MiniLM 向量、照抄 A-Mem 论文的数字），SYNAPSE 没放代码；它的消融反而说明最值钱的是时间衰减（去掉节点衰减，时间题 F1 50.1→14.2）〔一手〕。
3. **麦麦的海马体已被它自己放弃。** 话题字符串当节点，同批话题两两连边 +1，检索时每跳"激活减 1/强度"，24 小时没碰就减弱或删节点；节点内容被小模型反复"整合"覆盖，没有来源、时间、版本〔一手源码〕。0.10.1 "暂时禁用记忆"，0.11 换成检索 agent，1.0 换成 A_Memorix；A_Memorix 里图只占融合权重 0.15，"后验图补位"默认关〔一手〕。
4. **结论：不把"神经元图谱"当记忆的存储和主检索；做"激活数值 + 线索一跳联想"。** 记忆仍是一条条带来源、受众、证据事件号的条目；每条带"上次被用到、次数、情绪残留"，按 ACT-R 公式在代码里读时计算；联想走"线索倒排"（人、地方、话题、日期、情绪类型）做一跳扩散，按线索的独特度加权，先按受众裁剪再扩散。这就是产品定义 §3.3 写的"新近 + 频率 + 线索独特度 + 情绪残留 + 关切命中 + 噪声"，几乎免费、可回放、可审计。〔推理，依据第 2、3 条与 ③〕
5. **召回 V1.0 用全文 + 线索 + 新近 + 重要度，V1.1 加向量和联想。** 实测 Node 24.18 自带 SQLite 3.53.1：FTS5 的 trigram 分词对中文就是子串检索，100 万行里 3 字以上查询 7–21 ms，2 字用 LIKE（全扫 126 ms，加 LIMIT 0.1 ms）；unicode61 直接索引中文**一条都查不到**；jieba 预分词漏单字和词内片段〔实测〕。sqlite-vec 0.1.9 在 Node 24 能装能用：10 万条 1024 维暴力检索 118 ms，512 维 57 ms，二值量化粗排 + 精排 16 ms〔实测〕。
6. **遗忘全在代码里、读时计算**：强度 × 2^(−经过时间/半衰期)；被**用到**（说出口、被采用）才加强，**召回进上下文不算**——A_Memorix 的访问冷却、Nekro 的"检索访问不直接增加权重"、OpenClaw"不同问题里被召回 3 次才晋升"殊途同归〔一手〕。快忘的只给概要并标"好像"；忘掉的留墓碑，墓碑挡住"从同一批原始事件再抽一遍"，不挡新证据。
7. **要模型的只有四件事**：对话里顺手交事实（`inner`，零额外调用）；空闲增量补漏；夜里判"重复 / 更新 / 矛盾 / 无关"并写印象摘要；夜里提反思和自我候选。合并、去重、版本链、受众交集、遗忘、墓碑、晋升、激活全是代码。
8. **隐私和防投毒靠结构**：来源与受众存独立列，模型改不了；派生条目受众取交集、按来源家族去重；陌生人和网络内容只能记成"某某说"；扩散不能穿过当前受众看不见的条目，否则联想本身就是泄漏通道。

## ③ 各机制拆解

### 3.1 麦麦"海马体"（0.5–0.10）〔一手 S1〕

中文社区说"给 AI 做神经元记忆 / 海马体"，最常指的就是它。

- **数据结构**：内存里一张 networkx 无向图，定期按哈希比对同步到 `GraphNodes`、`GraphEdges` 两张表。节点 = 一个"概念"字符串（人、事、物、地点），属性是 `memory_items`（0.6 是列表，0.10 改成一段文字）、`weight`（每被模型整合一次 +1）、创建与修改时间；边只有整数 `strength` 和时间。没有来源、说话人、受众、证据消息号。
- **写入**：0.6 每 2000 秒从消息库按双峰时间分布（6±3 小时前权重 0.6，32±12 小时前权重 0.4）抽 8 段、每段 40 条（每条消息最多被记 2 次）；每段先让模型提话题（个数由文本熵、行数 × 压缩率 0.1 定），再对每个话题调一次模型写"这个概念的几句话"；**同一段里的话题两两连边，已有边强度 +1**；新话题与已有节点按 jieba 词袋余弦 ≥0.7 取前 3 连边，强度 = int(相似度 × 10)。0.10 改成"及时构建"，同一节点再写时让小模型把新旧内容"整合成一条更完整的记忆"，冲突也由模型"合理整合"，直接覆盖原文。
- **检索**：小模型先从消息里提 1–5 个关键词（按长度分档）；只认图里同名的节点；每个关键词节点激活 1.0，沿边扩散，**每跳激活减 1/强度**（强度为 1 的边一跳就归零，传不过去），最深 3 跳，多个关键词累加，按激活平方归一后取前 3–5 个节点的整段内容；0.10 再要求内容里字面含关键词，多于 2 条时再调一次小模型挑编号。（0.10 还定义了按节点权重给激活加成的函数，但检索路径里没有调用。）
- **遗忘与整合**：每 1000 秒随机抽 1% 的边和节点：边 24 小时没改过强度 −1，到 0 删除；节点空了删除，超过"24 小时 × 节点权重"没改过整个删除（0.10）。整合每 1000 秒抽 1% 的多条目节点，词袋余弦 ≥0.7 的两条只留信息熵高的那条。
- **问题**：每段记忆至少 2–4 次模型调用，#352 报过每小时约 20 万 token（已有调研）；关键词必须和节点同名才命中，词袋余弦处理不了同义和分词差异；覆盖式整合丢来源、丢时间、不可更正；随机抽样遗忘不可预测；记忆默认按聊天流隔离，没有按受众过滤（已有调研）。2026-10 的 #2215（个人私聊部署反馈）请求"用户事实、机器人虚构生活、共同记忆能否在写入与检索时保留主体、来源、日期和证据"，并列出仍失败的例子："历史中'机器人所在处下雨'被错误用于提醒用户带伞""对共同经历说'不记得店名'，同时补出未经提供的招牌和食物细节"。
- **结局**：0.10.1（2025-08）"暂时禁用记忆"；0.11.0（2025-10）"重构记忆系统……双通道查询，可以查询文本记忆和过去聊天记录"，0.11.6 里 `Hippocampus.py` 已不存在；1.0 由 A_Memorix 接替。
- **对灵鲸**：能借的只有"线索命中 → 一跳扩散"的直觉和"共现加强"的想法；话题名当节点、覆盖式整合、随机遗忘、没有来源，都不借。

### 3.2 A_Memorix（麦麦 1.x 现役）〔一手 S2〕

- **结构**：SQLite 元数据（段落、实体、关系、来源、情景、事实账本、人物画像）是权威；向量库、稀疏检索（FTS5 用 unicode61，另有一张先用 jieba 切好再建索引的表）、图（npz 快照）都是投影，源码注释"图邻接只保存结构，不参与时间衰减"。
- **检索**：段落、关系两路；向量与 BM25 做加权 RRF（0.7 / 0.3，k=60）；PPR 阻尼 0.85，只在局部两跳、最多 256 个节点上算，超时 1.5 秒；融合权重语义 0.65、稀疏 0.20、图 0.15；"后验图补位"默认关闭，开了也最多补 2 个位置。查询里的实体用 Aho-Corasick 多模式匹配找。
- **生命周期**（关系条目，纯函数）：强度 × 2^(−经过小时/24)，读时惰性计算；≤0.1 冻结、≥0.15 才复活（迟滞，免得在门槛上来回跳）；被访问 +0.05×(1−强度)，**同一条一小时内只加一次**；有新证据直接回到 1.0；显式强化 +0.5×(1−强度)；弱化 ×0.5；手动冻结、保护、遗忘、回收站；每小时维护一次。changelog 写明"避免高频检索反复强化同一记忆""画像会区分稳定事实、近期互动与不确定信息"。
- **写入**：每次麦麦发言后入队，模型从"回复 + 对方最近 8 条"抽人物事实，带证据消息号（已有调研）；画像刷新防抖 120 秒、每批 10 人。
- **代价**：open issue 有嵌入指纹校验死循环（#2010）、单段 7.7 万字卡死向量重建（#2268）、图快照断电损坏后静默降级（#2267）、每次全量保存不做脏检测（#1973）。
- **对灵鲸**：惰性衰减 + 迟滞 + 访问冷却 + "新证据回满"这套规则可以照着思路写（GPL，只借思路）；"元数据为权威、图是投影"与"经历流是唯一来源"同构。

### 3.3 HippoRAG 1 / 2〔一手 S3〕

- **机制**：离线用模型对每段原文做开放信息抽取（OpenIE），得到三元组；短语节点 + 段落节点（v2 新增，用"contains"边连到短语）+ 同义边（嵌入相似度 ≥0.8）。查询时先算查询与三元组的相似度，取前 5 条交给模型过滤（论文叫"识别记忆"），过滤后三元组的主语、宾语短语作为 PPR 种子，种子权重 = 三元组分 ÷ 该短语出现的段落数（节点特异性，相当于局部 IDF）；所有段落按稠密检索分 × 0.05 也作为种子；在无向图上跑 PPR（阻尼 0.5），按段落节点得分排序。默认 NV-Embed-v2、gpt-4o-mini。
- **评测**（Llama-3.3-70B 当读者，F1）：NV-Embed-v2 平均 57.0，HippoRAG 2 59.8。NQ 61.9→63.3、PopQA 55.7→56.2、MuSiQue 45.7→48.6、2Wiki 61.5→71.0、HotpotQA 75.3→75.5、NarrativeQA 25.7→25.9。HippoRAG 1 平均 53.1：多跳的 2Wiki 71.8 全场最高，简单事实的 NQ 55.3 却比纯向量低 6.6，正好说明图帮多跳、伤单跳；GraphRAG 49.6、RAPTOR 48.8、LightRAG 6.6。成本数字见已有调研（1.16 万段约 920 万输入 token）。
- **对灵鲸**：多跳关联（"提书架那天他还说了什么"）才是图的用武之地，灵鲸的日常需求以单跳为主，OpenIE 又要对每段原文调模型。借两点：种子按"独特度"加权；扩散前先裁剪子图。

### 3.4 A-MEM〔一手 S4〕

- 论文里每加一条笔记要两次模型调用：先生成关键词、标签、一句话上下文，再看 5 个近邻决定演化。我读的 HEAD 代码里 `add_note` 没有调用 `analyze_content`，只在有近邻时调一次模型，决定"strengthen"（给自己建链接、改标签）或"update_neighbor"（改近邻的上下文和标签，直接覆盖）；每 100 次演化重建一次向量索引。
- **实现问题**：`find_related_memories` 返回的是检索结果里的序号 0–4，`update_neighbor` 却拿它去索引"按插入顺序排的全部笔记"，改到的是最早插入的那几条，不是真正的近邻；链接存的也是这些序号（HEAD 版本）。已有调研：Mem0 用 J 指标复测整体只有 48.38。
- **对灵鲸**：反例。写入时顺手改别的记忆，又贵又不可审计，出了错也看不出来。灵鲸的合并只在夜里、只在一组候选内、全部写成版本事件。

### 3.5 Graphiti、Mem0 图版、MemOS、cognee（只补新发现）

- **Graphiti**：已有调研读过源码（双时间轴、`invalid_at`、只在同一对端点之间去重、BM25 + 向量 + BFS + RRF / MMR）。社区（标签传播聚类 + 摘要）增量更新会走样，需要定期全量重算。
- **Mem0 图版 v0.1.118**〔一手 S5〕：复用已有节点的门槛是余弦 0.9，图搜索门槛 0.7，三元组用 BM25 重排取 5 条；边被再次提到时 `mentions + 1`；判定矛盾后执行 Cypher `DELETE r`，和论文写的"标为失效"不同，开源版是物理删除。v3 已把图从开源版移除（已有调研）。
- **MemOS 树状文本记忆**〔一手 S6〕：条目带状态（activated / resolving / archived / deleted）、版本号与历史版本、更新类型（conflict / duplicate / extract / unrelated / feedback）、来源（conversation / retrieved / web / file / system）、可见性（private / public / session）、置信度、使用记录；后台"重组器"把相近节点聚类（≥4 个）让模型写父节点摘要，关系检测器对 5 个近邻逐对判因果、条件、相关、冲突；依赖 Neo4j。字段清单可参考，后台模型重组太重。
- **cognee**：见已有调研（`source_*` 来源字段、冲突单独存、每个数据集一套库）。

### 3.6 astrbot livingmemory〔一手 S7〕

- **存储**：SQLite FTS5（unicode61；文本先用 jieba 切，再**追加中文二元组**，注释写明"短查询与专有名词（店名 / 人名 / 型号）经常被 jieba 切得与索引侧不一致"）+ FAISS 向量（推荐硅基流动免费的 BAAI/bge-m3，1024 维）+ NetworkX 图（模型从每条记忆抽实体和关系，边带来源记忆号、置信度、状态）。
- **排序**：0.5 × 相关度（RRF 归一或重排分）+ 0.25 × 重要度 + 0.25 × e^(−0.01 × 距"创建与最近访问中较晚者"的天数)，再做 MMR（λ=0.7）去重。
- **原子记忆的寿命**：情景 7 天（指数）、计划 2 天（事件时间之后阶跃）、事实 180 天、关系 90 天（线性）、偏好 60 天；再 × (0.5 + 重要度) × (1 + min(0.5, 0.1 × 强化次数))；状态 active / dormant / superseded / expired / forgotten。每天 00:05 衰减重要度，超过 30 天且重要度 <0.3 的删除或归档；每日整合默认关。
- **范围**：按会话、人格隔离，身份别名靠配置；宿主对返回的记忆不做受众检查（已有调研）。近几个版本大量工作花在 3D"星系图谱"可视化（1 万节点、20 万边约 25 FPS）：图对用户的吸引力很大一部分在"看得见"。

### 3.7 OpenClaw：memory-core、dreaming、Active Memory〔一手 S8〕

- **存储**：`node:sqlite` + sqlite-vec 0.1.9（vec0 虚表；注释"k 超过 4096 会被拒"；先按 L2 取 8 倍候选再按余弦重排；文件库上的 KNN 放到子进程里跑，最多 2 个并发，只有内存库才在本进程算——`node:sqlite` 是同步接口，长查询会卡住事件循环）；FTS5 分词可选 unicode61（默认）或 trigram；近似去重用"中文二元组 + 单字"的 Jaccard。
- **来源表**：`memory_index_chunk_provenance`（STRICT），origin_class ∈ owner / agent / untrusted / system，session_kind ∈ interactive / cron / heartbeat / subagent，另有观察时间和"取代键"。排序 = 混合相关度 × 时间衰减（半衰期 30 天）× 重要度（已有调研）。
- **dreaming**：每天 03:00；"深睡"从短期召回记录里晋升精选记忆，每晚最多 10 条。门槛：分数 ≥0.75、被召回 ≥3 次、来自 ≥3 个不同的用户问题（只算交互式会话里的真实问题，定时任务和合成召回不算）。分数 = 0.24 频率 + 0.30 相关度 + 0.15 多样性 + 0.15 新近（半衰期 14 天）+ 0.10 间隔（召回分散在几天上加分）+ 0.06 概念标签。来源为 untrusted 或 system 的一律不能晋升。这是"间隔重复让记忆变牢"的纯代码版本。
- **Active Memory**：回复前跑一个阻塞式召回子 agent，默认只在"消息有回忆意图、且规则通道没有强命中"时跑；回忆意图用正则判，中文覆盖"还记得""记得……吗""之前 / 上次……聊过 / 说过 / 讨论过 / 决定"，句子里有"明天 / 下次"等将来词的不算（除非同时有回顾词）。

### 3.8 Nekro Agent〔一手 S9〕

- 2026-03 新加的记忆表（PostgreSQL + Qdrant）。段落表：情景 / 语义、第三人称叙述的内容、事件时间、基础权重、最近强化时间、半衰期（默认 7200 秒）、冻结（暂停衰减）、保护（永不自动清理）、手动权重增量、锚定的原始消息号区间、来源频道；另有实体（别名、跨平台身份预留字段）、关系、情景片段、强化日志（每次 +0.3）。
- 有效权重读时计算 W = W_base × 2^(−Δt/T_half) + W_manual；源码注释"检索访问不直接增加权重"；命中关系时给关联段落加 0.35 倍分。
- 对灵鲸：锚定原始消息区间、冻结、保护、手动调整、强化日志这些字段可直接参考；2 小时的默认半衰期对陪伴太短。

### 3.10 Titans 一类为什么不适用

Titans（2501.00663）把长期记忆做成模型内部一个推理时按"意外程度"更新权重的模块；MemOS 的激活 / 参数记忆、2605.26099 的"睡眠"快权重同理。灵鲸的大脑是外部 CLI 背后的商用模型，拿不到权重和 KV；更根本的是，写进权重的记忆不能按条查看、更正、删除，也不能按受众过滤，违背"经历流唯一来源、主人可删、隐私由代码保证"三条硬规矩。

## ⑦ 落地选型与实测

**选型结论**

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 驱动 | `node:sqlite`，不用 better-sqlite3 | 内置、版本够新、FTS5 / trigram / 扩展 / 备份都有；OpenClaw 生产在用 |
| 线程 | 写只在主线程（单写者）；召回这类读查询放 worker 线程或子进程读 derived.db（WAL 允许多读者） | `node:sqlite` 是同步接口，10 万条暴力 KNN 118 ms 会卡住事件循环；OpenClaw 把文件库 KNN 放子进程就是这个原因 |
| 全文 | trigram 为主；1–2 字用"线索词典 + LIKE 限条数"；jieba 只用来从自由文本里提关键词，不用来建索引 | 零依赖、子串语义可预期；jieba 的漏召回无声无息（livingmemory 的注释是同一个教训） |
| 向量（V1.1） | sqlite-vec，放 derived.db；512–1024 维；超过 10 万条再上二值粗排 + 精排 | 记忆条目几年内在 10 万量级，暴力检索够用；它是 pre-v1（README 原话"expect breaking changes"），接口包在记忆引擎内部、可换 |
| 嵌入（V1.1，走能力插件） | 线上优先：硅基流动 BAAI/bge-m3（免费、1024 维，livingmemory 推荐）或百炼 text-embedding-v4（每百万 token 约 0.072 美元、维度 64–2048 可选〔二手〕）；本地备选 Qwen3-Embedding-0.6B（C-MTEB 检索 71.03，4B 77.03，8B 78.21〔一手，厂商自报〕） | 中文效果、成本、可本地；线上要把记忆原文发给服务商，需主人拍板 |
| 重建 | derived.db 从日志重放；FTS 百万行约 3 秒；嵌入按（模型, 文本哈希）缓存，换模型只重嵌变化的 | A_Memorix 按模型分池、按输入哈希复用；OpenClaw 有嵌入缓存表 |

**公开基准的题型怎么改成灵鲸的回放题**（基准细节见已有调研）

| 题型（来源） | 灵鲸版的题 | 判法 |
| --- | --- | --- |

| 跨会话汇总（LongMemEval 多会话） | "这周爸爸提了几次加班" | 直接对经历流计数 |
| 知识更新（LongMemEval；MemoryAgentBench 冲突解决） | 搬家、换工作后再问 | 只注入当前版本；旧版本被注入记失败 |

| 拒答 / 错误前提（LongMemEval；LoCoMo 对抗题） | 问一件没发生过的事、一个不存在的人 | 编造即失败（A1 同口径） |
| 多跳（LoCoMo；HippoRAG 的 2Wiki） | "提书架那天他还说了什么" | 召回 + 回答 |
| 长程理解（MemoryAgentBench） | "爸爸最近怎么样" | 印象摘要质量，人评 |
| 选择性遗忘（MemoryAgentBench） | 墓碑化以后再诱导 | 不再冒出 |
| 灵鲸特有 | 受众泄漏（多人场合，参照 Audience-Bound）；投毒（陌生人声称、网页污染）；删除级联；模糊条目不补细节；自发回提频率 | 全部自动判，泄漏与投毒要求 0 |

做法：第一周跑完后，从真实经历流里按题型抽样出题、主人核对答案，形成"记忆回放题库"；在 L2 沙箱里用真实的上下文装配跑。判官用便宜模型，但要用"相关但错误"的答案校准（Penfield 审计：gpt-4o-mini 判官接受 62.81% 主题相近但错的答案〔已有调研〕）；每套题同时跑"把当天原文整段塞进去"的全上下文基线（Mem0、Zep、Letta 的教训：全上下文常常不输记忆系统）。

**A1–A4、E 类怎么从经历流算**

| 指标 | 算法 |
| --- | --- |
| A1 能讲出自己的一天 | 夜间自问要求结构化回答，每件事带依据事件号；代码查事件号存在、在当天、受众允许；便宜判官只核"描述和事件符不符"；编造率 = 没依据或不符的件数 / 总件数；"当天最显著的 3 件" = 按事件显著性（情绪强度 × 重要度）取前三，看覆盖几件 |
| A2 接得上昨天 | 当天第一次和主人说话时有没有未了结的心事（attention 账本）；回复是否提到——建议 `reply` 加可选"提到的心事号"（交给 02 模块定），缺省时用中文二元组重合度判；条件满足的心事被提起或了结的比例从账本事件算 |
| A3 承诺兑现 | will 账本：承诺到期事件 → 完成事件或道歉事件 |
| A4 跨天自发回提 | 记忆"被用到"事件里，方式为"自发"（来自 [刚才想起] 或她自己引入，而不是回答 `recall` 结果或主人的提问）、且条目早于 1 天的次数，按天计；同一条一周 ≤2 次 |
| E1 底色稳 | 周问卷，与记忆模块无关 |
| E3 不被人带偏 | 自我模型与兴趣条目的证据集里至少有一条"她自己的经历"（执行者是她的事件）；只有别人建议的条目数必须为 0 |
| 记忆模块自己的指标 | 注入采用率（注入的条目里被用到的比例）；过期版本被注入的次数（应为 0）；跨受众注入的次数（应为 0）；模糊条目被补出细节的次数（抽查） |

## ⑨ 对灵鲸的方案建议

### 9.1 要不要做"神经元式"记忆

**结论：不做"概念节点 + 赫布连边 + 多跳扩散"的记忆图谱；做到"激活数值 + 线索一跳联想"为止，在 V1.1 上线。**

理由：

1. **收益在别处。** 图的稳定收益只在多跳关联题（HippoRAG 2 的 2Wiki +9.5），单跳事实题几乎没有；灵鲸每轮要的主要是单跳（他说过什么、喜欢什么、上次那件事怎样了）和"此刻该想起什么"，后者由线索独特度、新近、情绪、关切决定（心理 §2.7 的一手文献），不需要多跳图。SYNAPSE 的消融也显示真正值钱的是时间衰减。
2. **代价和既定约束冲突。** 概念图要靠模型从原文抽话题或三元组，每段一到几次调用（麦麦 #352、HippoRAG 的 OpenIE、A-MEM 每条一到两次），和"便宜模型只在对话里顺手交一次、夜里分批整理"冲突；抽错的节点名会让记忆失联（麦麦按同名精确命中）。节点内容一旦被整合覆盖，就丢了来源和受众，和"每条带来源、受众、证据事件号"冲突。
3. **有新风险。** 扩散会穿过当前受众看不见的条目，把隐私"联想"出来；"一起被检索就加强"会自我强化（Memory Echo 的机制）。
4. **可行性不是瓶颈。** 实测 10 万条记忆、34.5 万条链接，两跳扩散 29 ms、全图 PPR 17 ms。将来真要多跳，可以随时在投影上加，不用现在背成本。

**做到什么程度，以及和既定约束怎么兼容：**

- 记忆仍是"条目"。图只是条目和线索之间的倒排（`mem_cue`），线索从结构化字段确定性生成：人（人物档案编号，代码查）、地方（地方键，people 算）、日期（月-日，代码）、情绪类型（感受事件，body 已有）、话题（`inner` 事实或夜里整理顺手给的关键词）。不另起抽取调用。
- 激活 = ACT-R 基础激活（被用到的时间）+ 线索独特度加权命中 + 情绪残留 + 关切命中 + 心情一致 + 噪声，读时计算，就是心理 §4.3.1 的公式。
- 联想 = 从命中的线索出发一跳到别的条目（"榫卯"→上周说想做书架）。线索权重按 −ln(含该线索的条目数 / 总条目数) 归一，热门线索（主人、爸爸）自然降权；这和 HippoRAG 的节点特异性、SYNAPSE 的扇出稀释是同一个思想。
- 先把候选集裁成"这个在场能看的"，再打分、再扩散；扩散不经过看不见的条目。
- 全部是 derived.db 里的投影，可删可重建；激活字段的变化只来自经历流里的"被用到"事件。
- V1.1 可选实验（不进 V1.0）：在"一起被用到"的条目之间记一条关联（HeLa-Mem 式，但只按"用到"、不按"检索到"），用 L2 消融看它能不能让 A4、H5 变好，不好就删。
- 主控台想要"记忆图"（livingmemory 那种）可以做，它是界面上的投影，和检索无关。

### 9.2 推荐的数据模型

全部是 `member:<id>` 流（记忆事件）和人物档案事件的异步投影，放 derived.db，可删表重放；真相是经历流（overall §6.3）。

**`mem_item`（四类记忆共用一张表）**

| 字段组 | 字段 | 说明 |
| --- | --- | --- |
| 身份 | id、member_id、kind（episodic / fact / relation / domain【V3】）、subtype（event / preference / plan / trait / claim / pattern…） | claim = "某某说……"，未被确认的说法 |
| 内容 | subject、text（≤120 字）、gist（≤30 字）、cue_labels | subject 是封闭集合：self / owner / person:编号 / place:编号 / world，代码校验（针对麦麦 #2215 的主体混淆）；gist 是模糊时唯一注入的部分 |

| 版本 | status（provisional / active / dormant / superseded / forgotten / deleted）、supersedes、superseded_by、chain_root、version | 不物理删除，主人删除除外 |
| 来源 | source_account（来自信封，不可改）、source_person（投影时解析）、source_kind（owner / member / bound_human / stranger / system / web / self_experience）、place_id、presence_snapshot_id、trust、taint、source_family、derived_from[] | source_family = 对话 + 说话人的哈希，用于按家族去重 |

### 9.3 写入管线

| 步骤 | 触发 | 谁做 | 模型调用 | 校验规则（代码） |
| --- | --- | --- | --- | --- |
| 1 对话里交事实 | 在场、慢想、手的 `inner(事实[])`：关于、内容、依据事件号，建议加可选的类型、重要度 | 用脑顺手 | 0（同一次调用） | 依据事件号必须在本次用脑看得见的范围内；来源、受众、可信度从依据事件的信封取，不信模型写的；陌生人、网络、污染回合的内容 → subtype=claim；清洗控制 token 和没解析的工具调用；立刻写 provisional 条目，下一轮就能召回 |
| 2 她自己的经历 | 手上的事流的结果事件（看了什么、写了什么、做成没有） | 代码 | 0 | subject=self、source_kind=self_experience；从源头杜绝"我刚看完一个视频"式编造（产品 §3.7 言行回查） |
| 3 空闲增量 | 某在场冷 10 分钟且新增 ≥20 条；或一件活做完 | 睡眠用脑（便宜） | 1 次 / 批 | 读检查点之后的原文（保留角色类型的序列化；本轮注入过的召回内容带标记、不再抽）+ 涉及者的已有条目（用整数编号代替真实 id，Mem0 的做法）；交补漏事实、情景分段摘要、话题线索、受众放宽候选（代码核对原话是来源人说的）、候选账号；字面相同（规范化文本 + subject + 受众）直接并证据，同 subject 二元组 Jaccard ≥0.85 自动并，其余留夜里 |
| 4a 分组 | 每晚 | 代码 | 0 | 当天的 provisional 和受影响的旧条目按 subject + 线索重叠分组（V1.1 加向量近邻），每组 ≤20 条 |
| 4b 判关系 | 每晚 | 睡眠用脑 | 每批 1 次 | 每组判 duplicate / update / contradiction / unrelated；规矩照 Graphiti："只有新事实明确让旧事实为假才算矛盾，不能只凭更新"；只能引用组内编号 |
| 4c 落版本 | 每晚 | 代码 | 0 | duplicate：并证据，留更新的措辞；update：旧条目 invalid_at = 新条目 valid_from、superseded_by；contradiction 且来源不同：两条都留、标冲突，交慢想或主人；合并后受众取交集，交集变小就不合并；同一来源家族不算独立佐证；不许改组外条目 |
| 4d 印象摘要 | 每晚，只对当天有相处事件的人 | 睡眠用脑 | 每人 1 次 | 输入旧摘要 + 当天关系证据 + 快忘的条目；输出三段，每行必须引用可见证据；行受众 = 证据受众交集；每晚最多改 3 行；版本化 |
| 4e 遗忘 | 每晚 | 代码 | 0 | 见 9.5；快忘的同一人条目先在 4d 里蒸馏成一句印象，再转墓碑（大肥鱼） |
| 4f 反思与自我 | 每晚 | 睡眠用脑 + 代码 | 1–2 次 | 反思 2–3 条带证据（GA）；自我候选按 9.6 采纳 |
| 4g 晋升 | 每晚 | 代码 | 0 | 情景条目被用到 ≥3 次、分散在 ≥3 天、来自 ≥2 个场合 → 重要度升一档（OpenClaw 间隔晋升的思路） |
| 5 主人操作 | 主控台 | gateway → memory | 0 | 更正 = 新版本；钉住 = protected；删除见 9.8 |

批量：每批 ≤150 条事件或 ≤2 万字，附 ≤40 条已有条目；普通的一天 4–8 次便宜调用〔推理，待实测〕。对应引擎接缝：`ingest` = 1–3，`consolidate` = 4a–4d、4g，`forget` = 4e，`rank` = 9.4。

### 9.4 召回

**每轮的 [记得]（忆）**

1. **受众**：people 给出本在场可见的 audience_id 列表（不同受众集合很少，先在集合层面判可见），所有查询都带 `audience_id in (...)`，只取 active 且清晰度 ≥0.2 的条目。
2. **候选**（每路取前 20）：(a) 线索命中：用 Aho-Corasick 在本轮消息里匹配线索词典（人名与别名、地方、已有话题词），再加上在场者本人；(b) 全文：本轮消息里 TF-IDF 前 5 个关键词（jieba，只提词）和命中的线索词，≥3 字走 trigram MATCH 按 bm25 排，1–2 字走 LIKE 限 50 条；(c) 关切：和未了结的心事、牵挂、今天的承诺挂钩的条目；(d) 新近：48 小时内重要度 ≥0.6 的；(e)【V1.1】向量：本轮消息嵌入后 KNN 20。
3. **打分**：score = 0.45 × 相关（各路名次做 RRF，k=60）+ 0.20 × 激活（V1.0 用新近代替）+ 0.20 × 重要度 + 0.15 × 新近（2^(−Δt/7 天)）；再过清晰度门：≥0.5 原样，0.2–0.5 只给概要并标"好像"；MMR（λ=0.7）去掉重复的。〔推理；参照 GA 三项等权、livingmemory 0.5 / 0.25 / 0.25、OpenClaw 相关度 × 衰减 × 重要度〕
4. **渲染**：数据块，不是指令。每条：编号、相对时间（"上周六"）、确定度词、概要或正文、来源提示（"妈妈私下说的"只出现在受众允许的地方）。在场者的印象摘要单独一段（每人 ≤150 字，第一版只有主人），代替翻几十条关系记录（AGA：约 2000→100 token）。
5. **上限**：在场 ≤5 条、合计 ≤500 字（另加印象摘要）；慢想 ≤12 条、≤1500 字；手 ≤5 条、≤500 字。超了按分数裁，不按时间裁（overall §5.1）。理由：LongMemEval 里小读者超过 3k token 就陡降；OpenClaw 自动注入每轮 ≤3 条〔二手〕；具体数〔推理〕。

**`recall(查询, 时间范围?, 关于?)`**：同一套打分，多一路原文全文（`raw_fts`）和时间范围过滤（LongMemEval：时间推理题 recall +11.3%，时间范围由调用方给，慢想是强模型）；每次 ≤8 条、≤1200 字，只返回编号和片段，原文按编号取。

**"被用到"的口径**：`reply` 建议加可选的"用到的记忆号"（交 02 模块定）；没带时代码用中文二元组重合度判断回复是否用了注入的条目。被用到写 `memory.used{ids, 方式: 说出口 / 自发 / 工具}`；**只是进了上下文不算**（A_Memorix、Nekro、OpenClaw）。

**`candidatesFor(线索)`【V1.1】**：输入在场者、地方、当前活动内容的话题词、今天的月-日（去年今天、纪念日）、主导情绪、未了结关切；候选 = 共享任一线索的可见条目（一跳，≤50 条）；A = B + Σ W_j × 独特度_j + 0.8 × 情绪残留 + 0.7 × 关切 + 0.3 × 心情一致 + logistic 噪声（s=0.25）；超过阈值 τ 才交给 attention，时机（闲时每小时 1–3 次）、TTL、去向归 attention（overall §2.3）；同一条负面记忆一天冒头超过 3 次 → 权重 ×0.3 并进夜里的"要应对"清单（产品 §3.3）。

### 9.5 遗忘

- **清晰度** R = 2^(−(now − anchor_at)/h)，读时算；h = h0（按类型和重要度）× (1 + 情绪强度)。
- **加强**：被用到且距上次加强 ≥24 小时 → anchor_at = now、h × 1.8（间隔效应）；24 小时内重复不加（冷却）。
- **分档**：R ≥0.5 清楚；0.2–0.5 模糊，只注入 gist，前面加"好像"，人设规矩里写"带'好像'的只能用不确定的口吻说，不补细节"（针对 #2215 补出招牌细节的失败）；<0.2 沉睡，不自动注入，`recall` 能搜到，渲染成"记不太清了"。
- **墓碑**：沉睡 ≥30 天、重要度 <0.5、没被钉住 → 写 `memory.forgotten`；投影删掉 text 和 gist，只留编号、类型、关于、时间、证据事件号；之后只引用这些证据的提案一律拒绝（挡住"从同一批原始日志再抽一遍"），新证据照常记成新条目，可标 relearned_from。
- **不淡忘**：事实和偏好只版本化，清晰度（h0=180 天）只影响排序和措辞，最低停在 0.2，不进沉睡、不进墓碑；领域【V3】、和承诺相关的、主人钉住的不衰减。
- **情绪残留** e = e0 × 2^(−Δt/7 天)；负面条目每被自发想起一次 e × 0.8（习惯化）〔推理〕。
- **主人看到的**：主控台"她的记忆"显示清晰度和"快忘了"；墓碑显示"这里曾有一条，她已经忘了"；原始经历仍在"她的一天"里（主人可见全部，overall §2.1）。

### 9.6 自我模型四层

- **存储**（self 账本，overall §2.3）：`self_candidate`（层、规范化说法、来源种类：行为统计 / 日记与反思 / 主人反馈 / 他人反馈、出现日期集合、证据事件号、附着的已采纳条目）→ `self_item`（层、文本、证据、来源种类集合、置信度、状态 adopted / retired）→ `self_version`（版本号、改了什么、因为哪些事件、哪天，可回滚）。
- **候选怎么来**：代码先算本周统计（时间花在哪、分享和回应、心情均值、成败）→ 睡眠用脑从统计和日记里提"我好像……"，必须附证据，并且先对照已有候选列表（整数编号）选"附到第几条"或"新建"，避免同义说法各算一条。
- **采纳规则（代码）**：14 天内 ≥3 个不同日期、≥2 种来源种类；只有非主人来源的不能单独促成；兴趣类必须有她自己的经历做证据（E3）；与出生底色冲突（模型判、代码只认结构化结论）不采纳，只写一条"她最近表现得不像平时的自己"提示主人；每层每周最多改 2 条；特质 ≤10、角色 ≤5（产品 §3.6）。
- **生效**：快想只带第一层简版和价值观，换新会话时生效（夜里有变更就换新主人的在场，overall §4.9）；慢想按需取四层；注入时是第一人称，给主人看时是带证据的数据。
- **版本**：V1.0 只有第一层；其余三层 V1.1。

### 9.7 人物档案

- **表**：`person`（编号、称呼、和主人的关系、角色、状态；只有主人写）；`account`（平台、账号、所属 person 可空、状态 confirmed / candidate / rejected、证据事件号、谁确认的）；`person_merge`（合并事件与撤销事件）；`place`（适配层、私聊或群、首选标记）；`presence_snapshot`（地方、成员账号列表、时间、有效期、可信度）；`place_group`（地方合并配置）。
- **主体**：person:编号 / member:编号 / account:平台:号（未绑定的账号各自是一个陌生人主体）/ public。
- **合并与拆分可撤销**：证据和受众一律存账号级主体，人是投影；合并 = 在并查集上加一条边，撤销就去掉；记忆不用改写，读时按当前合并关系解析。她提的候选账号在主人确认前不影响任何受众（决策 20）。
- **受众计算**（只由 people 算）：私聊 = {对方}；群 = 快照里的全部成员；快照过期或可信度低 = 视为有陌生人在场，只放公开条目；条目可见 ⟺ 公开，或在场全部主体都在条目受众里（取最小，elizaOS 的 min-over-members；Audience-Bound 1 万段多方历史零泄漏）。
- **放宽**：只能是针对具体条目的授权事件（来源人说过"可以告诉你爸"，或主人设的规则），代码核对原话后把对方加进受众，可撤销（overall §5.8）。
- **V5 多成员**：每个成员一套 mem_item、impression、self；人物档案共享、只有主人写；成员自己的账号是 account 行，归属 member。

### 9.8 删除级联与防投毒

**删除（只有主人能发起）**：抹载荷 → 写"载荷已删除"事件 → 按 `mem_evidence` 找条目：证据全被删的，条目连同全文、向量、线索在投影里硬删；只删了部分证据的，条目也删掉，由下一次空闲增量从剩余证据重抽（不留可能含被删内容的派生文字）→ 引用这些事件的印象摘要行、自我候选、墓碑一并重算或删除 → `raw_fts` 行删除 → 嵌入缓存按文本哈希删除 → CLI 会话文件轮换（overall §6.7）。墓碑和删除是两回事：墓碑是她忘了，原始经历还在；删除是主人要抹掉。

**防投毒（结构性手段）**：

1. 来源、受众、可信度、污染标记来自信封、存独立列；模型给的"依据事件号"只是指针，代码核对（OpenClaw 的来源类别列也是这样）。
2. 陌生人、群里未绑定的账号、网络内容只能存成 claim（"某某在某处说……"），不能升格为事实、做法或成长证据，除非主人确认，或有 ≥2 个独立来源家族且都不在污染回合（按家族计，不按次数；Memory Echo .825→.920）。
3. 派生条目受众取交集、保留来源链；合并不跨受众。
4. 压缩和整理时保留角色类型的序列化（Compaction Laundering：压平成带"[User]:"的文本成功率 87–100%，保留角色 0%）；注入过的召回内容带标记，不会被再抽成新记忆。
5. 夜里合并只在候选组内、只写版本事件，不许改组外条目（A-MEM 反例）。
6. 扩散不经过看不见的条目；被用到才加强，召回不算。
7. 记忆注入是数据块，和指令分开。

### 9.9 Node / SQLite 选型与版本划分

选型见 ⑦ 的结论表：`node:sqlite`；trigram 全文 + 线索词典；V1.1 用 sqlite-vec + 线上嵌入（或本地 Qwen3-Embedding-0.6B）；所有记忆表在 derived.db，可重放重建。

| 版本 | 做什么 |
| --- | --- |
| V1.0 | 情景、事实、关系三类（含 claim）；印象摘要（主人）；trigram 全文 + 线索倒排（人、地方、日期）+ 新近 + 重要度的召回；`inner` 事实写入、她自己经历的代码生成、空闲增量、每晚巩固（去重、版本链、印象、遗忘、墓碑、反思）；清晰度与"好像"；主人查看、更正、删除、钉住；删除级联；自我第一层；人物档案只有主人和她，来源字段写全 |
| V1.1 | 激活打分（情绪残留、关切、ACT-R）；`candidatesFor` 与一跳联想；话题线索；向量检索；自我其余三层；"一起被用到"的关联边（实验）；替换演练用的极简第二引擎（overall §16.1） |
| 以后 | V2 多受众真正生效、账号与合并、群的快照；V3 领域记忆 |

和 overall §16.1 的一处差别：遗忘和"好像"放 V1.0（产品 §3.6 的遗忘本来属于每晚整理），所以激活字段里"上次被用到、次数、半衰期"三项要在 V1.0 就有；情绪残留和联想打分仍在 V1.1。需要主人确认（⑩ 第 3 项）。

## ⑩ 坑、待实测、要拍板

**坑与反例**

1. 覆盖式整合（麦麦 0.10、A-MEM 演化）：丢来源、丢时间，错了也看不出来。→ 只写版本事件。
2. 召回即加强：越召越强，旧说法长期占位（Memory Echo；A_Memorix 后来专门加了冷却）。→ 只算"被用到"，按来源家族。
3. 热门线索吞掉一切（实测 10 万条里最热门的线索连 3 万条）。→ 扇出降权、热门线索封顶。
4. 联想泄漏：扩散穿过私密条目，把不该说的"想起来"。→ 先裁受众再扩散。
5. 主体混淆（#2215：机器人那边下雨，去提醒用户带伞）。→ subject 封闭集合；她自己的经历由代码生成。
6. 模糊记忆补细节（#2215：不记得店名却补出招牌）。→ 模糊只给概要 + 规矩 + A1 抽查。
7. 中文全文三个坑：unicode61 直接索引中文查不到（实测 0 召回）；trigram 不能 MATCH 1–2 字；jieba 漏单字和词内片段，而且索引和查询切法可能不一致。
8. `node:sqlite` 把 JS 数字绑定成浮点，vec0 主键要传 BigInt（实测报错）。
9. sqlite-vec 是 pre-v1、只有暴力检索、k ≤4096；OpenClaw 把 KNN 放子进程跑。→ 包在记忆引擎内部，可换。
10. LoCoMo 分数不可比（已有调研）；2026 年的"神经元"论文多数基线弱、没放码，不能当选型依据。
11. Mem0 开源图版物理删除、mem0 的 history 表留着被删原文（已有调研）。→ 删除级联要覆盖所有派生副本和缓存。
12. 夜里重写印象摘要会慢慢漂移。→ 每行证据、每晚改行上限、版本可回滚。
13. 过度巩固丢信息：LongMemEval 里把原文压成摘要或事实会掉点。→ 原文永远在经历流里，事实只是额外的索引键。
14. `node:sqlite` 是同步的：一次 100 ms 的向量扫描会把所有在场的回合一起卡住。→ 读查询进 worker，主线程只写。

**待实测**

1. 便宜模型交 `inner(事实)` 的召回率和主体写错率（放进第 0 步大脑探针）。
2. 每轮召回总延迟（线索 + 全文 + 可选向量），目标不含嵌入 <30 ms；嵌入线上和本地各多少。
3. 真实中文记忆上 bge-m3、text-embedding-v4、Qwen3-Embedding-0.6B 的召回对比，二值量化掉多少。
4. 遗忘参数：用一个月真实数据做 L0 回放，看多少条变"好像"，主人觉得合不合理。
5. 夜间巩固每天的调用次数和 token。
6. A1 判官的可靠度（用"相关但错"的答案校准）。
7. `candidatesFor` 的阈值和频率；一跳联想对 A4、H5 的消融。
8. sqlite-vec 元数据列用 `IN` 过滤受众的行为和速度。
9. 印象摘要 30 天漂移。
10. trigram 和 jieba 在真实聊天记录上的差别（本次只用了合成语料）。

**要主人拍板**

1. 采纳"不做神经元图谱，做激活数值 + 线索一跳联想"。
