# 调研：论文与工程文章——整体架构的理论与实证依据

日期：2026-10-28。整体架构调研第 4 步。目的有两个：一是给整体架构找理论和实证依据；二是专门检验 handoff.md 的决策 11、12、13（顺带检验决策 6 里"主意识用便宜模型"这一条，因为 11、13 的可行性取决于它）。前三步（OpenClaw、Paseo、陪伴类系统）已经有的工程结论这里不重复，只在第 8 节做交叉印证。

标注约定：〔一手〕读了原文；〔二手〕通过别人的转述或工具摘要读到；〔推测〕是本文推论；〔未核实〕没读到原文。

## 0. 一页结论

**决策 11**：大体保持。"她是本体里的状态"和"主意识是唯一能做全局决定的位置"都有理论支撑：CoALA 主张记忆独立于 LLM、由代码持有；全局工作空间理论（GWT）主张一个容量有限的中心加上很多并行的专门过程。需要补两点：主人的私聊全部进主意识，主意识的大脑质量就直接决定了主人的体验；自主触发要先过代码闸再进主意识。

**决策 12**：结构保持，但要补"共享写"的规则。在场分身、干活分身互不共享上下文，确实会出现 Cognition 说的"各自做隐含决定、互相冲突"。冲突点不在说话风格，而在她的**共享状态**：承诺和日程、关于她自己和主人的事实陈述、关系变化、同一个工作区里的文件。修正办法：共享状态只经本体 API 单点写入，写入时做冲突检查；主意识的全局决定要"广播"给相关会话；派活从"传原话"改成"原话 + 交接信封"。

**决策 13**：①③④ 保持，① ② ④ 各补一条。
- ①：GWT 里决定"什么能进工作空间"的是两股力量：外围过程自己报的显著性（自下而上），加上工作空间当前的目标（自上而下）。决策 13 现在只有前一股（按规则上报）。要补一张主意识可以登记的"关注表"，还要补"广播"这一步：工作空间的内容要回到各个模块，否则 GWT 所说的连贯和协调就没有了。
- ②："按需拉取"对弱模型不可靠。MemGPT 用 GPT-3.5 时自我管理记忆的效果明显变差，而且模型常常翻几页就停。改成代码预取加模型拉取的混合方式。
- ④："睡觉时整理加换新会话"有依据：sleep-time compute、互补学习系统一类的离线巩固研究、Generative Agents 的反思。但这些研究说的是"空闲时"，不只是"夜里"。补两条：一是换新的触发条件改成"作息时间点 + 空闲"；二是白天空闲时也做增量整理。另外一个推论：夜间任务对延迟不敏感，正适合用更强的模型。

**便宜模型当主意识**：风险是实打实的。Cognition 2026 年的实验里，弱模型当主控时，"什么时候求助、问什么"恰恰是它做不好的地方，质量上限由主控决定。ToolOrchestra 发现，靠提示词让小模型当编排者有严重偏差，Qwen3-8B 73% 的情况都把活甩给 GPT-5。ProactiveBench 上小模型主动打扰的误报率更高。缓解办法：缩小主意识要做的判断；升级到强模型由代码决定，不让弱模型自己判断；加一个"请教"工具，把完整上下文分叉给强大脑。决策 6 建议在用 20 个左右真实场景实测之前，不要把主意识定成最便宜的一档。

## 2. 按主题的文献要点

只摘和灵鲸有关的主张。

### 2.1 认知架构：CoALA〔一手，P1〕

- **记忆和 LLM 分开**。LLM 本身无状态。agent 把信息组织成多个记忆模块：工作记忆，加上情景、语义、程序三类长期记忆（§4.1）。工作记忆不是模型的上下文，而是"跨 LLM 调用持续存在的数据结构"。每次调用时，LLM 的输入从工作记忆的一个子集合成（§4.1）。→ 对应决策 11："她"是本体里的状态，每个会话的上下文只是从中取出的一个子集。
- **动作空间分内外**（§4，图 5）：
  - 外部动作 = grounding（和环境、人、其他 agent 交互）。
  - 内部动作 = 检索（读长期记忆）、推理（更新工作记忆）、学习（写长期记忆）。
- **决策循环**（§4.6，图 4B）：每个循环先做规划（检索和推理，交替进行"提出、评估、选择"候选动作），再执行一个外部动作或学习动作，然后得到观察，进入下一轮。决策过程本身是"agent 代码里的 main 程序"，也就是说，循环由代码驱动，不由模型驱动。
- **写程序记忆最危险**（§4.1、§6）。写情景、语义记忆相对安全；改程序记忆（agent 自己的代码、规则、提示词）"容易引入 bug 或让 agent 绕过设计者的意图"。在动作空间里，学习动作（尤其是删改程序性内容）可能造成内部伤害，grounding 动作可能造成外部伤害（§6）。→ 对应成长和技能：人格变化和自写工具都属于程序性或自我模型的改动，应该走提案、审核和版本化。
- **动作空间越大，决策越难**。"取完成任务所需的最小动作空间可能更好"（§6）。
- **学习也是一种动作，可以推迟**。把学习留到交互结束时做，存进情景记忆之前先总结（§6、§7）。
- **内外的边界看"可控性和耦合度"**（§7）。别人能改的是外部环境，只有自己能写的才算内部记忆。〔推测〕按这个标准，CLI 自己的转录在灵鲸看来属于"外部"：本体控制不了它的格式和保留策略。这从理论上支持"操作日志才是真相"。
- **元推理**：LLM 调用又慢又贵，应该按规划的效用自适应分配计算，比如在几个决策子过程之间路由（§6）。这为"分层用模型"提供了依据。

### 2.2 全局工作空间理论（GWT）和它的计算化

**Goldstein & Kirk-Giannini〔一手，P2〕**

- **结构主张**：很多相对自治、处理特定任务的模块，加上一个所有模块都连着的全局工作空间。作者把这和"模块两两直接通信"的结构对比（§2）。
- **功能主张**（§2）分三部分：
  - 进入（uptake）：决定哪些模块信息能进工作空间。
  - 广播（broadcast）：把工作空间的内容发回各个模块。
  - 加工（processing）：在工作空间里整合信息。
- 模块并行处理，能力几乎无限；工作空间串行处理，容量有限。这个瓶颈迫使"进入"阶段必须有选择性注意（§2）。
- **谁决定进入**（§2.1）：
  - 各模块信号的激活强度不同，几个模块一起加强时激活更高；
  - 但仅靠激活不够，内容还要得到接收模块的正反馈才能留在工作空间；
  - 重复的信息会因习惯化而淡出；
  - 最终由注意控制，而且足够重要的信号能"突破"当前的专注（"Absorption does not protect us from high-priority signals"）。
- **自上而下与自下而上**（§4、§5.1）。Butlin 等要求两种注意都要有：自下而上是模块信号强度决定进入，自上而下是工作空间的当前状态决定接下来让什么进来。作者认为：分类功能需要自下而上；连贯、协调、纠错需要自上而下，加上工作空间内部的加工。
- **工作空间的四个用处**（§5.1）：
  - 分类：区分重要和不重要。
  - 连贯：把可能互相矛盾的表征整合成一个一致的叙事。
  - 协调：把一个处理器的输出提供给其他处理器，并通过自上而下的注意引导它们。
  - 纠错。
  - 作者还引用了 Dehaene 的话："机体必须行动，所以必须在多种可能中做出选择，收敛到单一的行动方案。"
- **容量有限不是意识的必要条件**（§5.2 思想实验）。〔推测〕对灵鲸来说，容量上限的理由来自工程（上下文退化、成本，见 2.4 节），不来自 GWT。
- **给语言 agent 的改造方案**（§7、§8）：
  - 把 Generative Agents 的单一记忆流拆成感知、信念、欲望与计划三个模块，加一个中心工作空间；
  - 设一个竞争函数：每次固定输出 50 条，其中 10 条是最显著的感知，另外 40 条按"重要度 + 相关度 + 新近度"排序；
  - 再设一个刷新函数：工作空间里的旧内容也要参与竞争，分数低于阈值的被替换。
- **作者的判断**：原版 Generative Agents 里所有信息都进记忆流，"没有通往它的瓶颈"，也说不上有并行模块（§6）。

**Conscious Turing Machine〔一手，P3〕**

- 短期记忆（STM）每个时刻**只存一个 chunk**（§1.2）。
- chunk = 〈来源地址、时间、gist、权重、强度、情绪〉。gist 是"简洁、压缩的多模态想法"。权重是**产生它的处理器自己**估计的"这条有多重要"（§1.2.2.1）。
- 竞争由 Up-Tree 上"小而快的电路"逐层完成（§1.3），不由 STM 决定。胜出者经 Down-Tree 广播给**所有**处理器（§1.2）。
- 处理器根据反馈，用 Sleeping Experts 算法修正自己给权重的方式：说对了就提升，说错了就降低（§1.5.1）。
- Links：两个处理器经常经由 STM 一问一答、对方认为有用，就会长出直接的连接，从"有意识的通信"变成"无意识的通信"，不再经过 STM（§1.2）。
- 外界输入经 Input maps 先送到长期记忆里的处理器，再去竞争 STM（§1.2）。

**LIDA〔二手，P4 经 MIRA §7 转述，Franklin 原文未读〕**

- 认知循环分三个阶段，各阶段内部的过程并行，只有"意识"和"动作选择"是串行的：
  - 感知与理解：感觉记忆 → 感知联想记忆 → 当前情境模型。
  - 注意：注意 codelet 在情境模型里挑内容，结成联盟去竞争，胜出的联盟被全局广播。
  - 动作与学习：各模块从意识内容中选取适合自己学习的部分；从程序记忆里选出候选行为；由动作选择模块选一个去执行。
- "学习发生在广播之后"是 LIDA 的标志性主张。〔未核实原文措辞〕检索摘要提到每秒约 5 个循环，同样未核实。

**近两年把 GWT 用在 LLM 多 agent 上的工作**

- **GWA〔一手，P5〕**：
  - 每个"认知 tick"分四步：感知与检索 → 生成与批评 → 元 agent 仲裁 → 更新与表达。
  - "Core Self"作为不变量，每个 tick 都注入，"以防长时间自主运行中的语义漂移"（§3.2）。
  - 设一个 Response 节点，把内部想法翻译成对外的话，且不暴露内部推理（§3.4）。
  - 工作记忆超过阈值 θ 时双路处理：经验写入长期记忆，同时用摘要覆盖工作记忆（§3.5）。
  - **没有任何实验**，只能当设计参考。
- **BIGMAS〔一手，P6〕**：
  - 专门 agent 只通过中心共享工作空间协作；
  - 每次写入都要校验（路径存在、动作类型匹配、内容非空），失败就不改动工作空间（§III-D2）；
  - 编排者路由占总 token 的 16.9%–25.2%，随任务复杂度增长（§IV-E）；
  - 只在 Game24 一类谜题上评测。

### 2.3 Generative Agents〔一手，P7〕

- **记忆流**是"agent 经验的完整记录"，每条带自然语言描述、创建时间和最近访问时间（§4.1）。
- **检索打分** = 新近度 + 重要度 + 相关度，三项权重都是 1（§4.1）：
  - 新近度按游戏小时指数衰减，系数 0.995；
  - 重要度在写入时让 LLM 打 1–10 分；
  - 相关度用向量余弦相似度。
- **反思**：最近事件的重要度累加超过 150 时触发，实际每天两三次。先从最近 100 条记录里提出 3 个高层问题，再检索证据，生成 5 条洞见，并**记下引用了哪几条记录**（§4.2）。反思可以基于以前的反思，形成一棵树。
- **计划**：自上而下递归分解：先排一天的 5–8 段，再分解到小时，再到 5–15 分钟（§4.3）。附录 A 说只提前生成高层计划，近期的细节"临时分解"。
- **反应**：每个时间步都把观察交给 LLM，问"要不要偏离原计划去反应"（§4.3.1）。也就是说，**每一步都调一次模型**。
- **消融实验**：完整架构比没有记忆、计划、反思的版本高出 8 个标准差。去掉反思就做不了需要综合经验的判断（§6.5）。
- **错误模式**（§6.5.2、§7.2）：
  - 检索不全，会出现"记得要在派对上讨论选举，却不确定派对是否存在"这种错误的笃定；
  - 会添油加醋；
  - **过度合作**：别人给的建议不合她的性格，Isabella 也很少拒绝，久而久之"别人的兴趣塑造了她的兴趣"。
- **成本**：25 个 agent 跑两个游戏日"花了几千美元的 token、用了好几天"（§8.2）。
- **伦理建议**：平台保留输入输出的审计日志（§8.3）；警惕"记忆攻击"，即用一段精心设计的对话让 agent 相信一件没发生过的事（§8.2）。

### 2.4 上下文是资源，本体是操作系统

**MemGPT〔一手，P8〕**

- **主上下文分三段**（§2.1）：
  - 只读的系统指令；
  - 固定大小、只能经函数改写的工作上下文（存用户和人设的关键事实）；
  - FIFO 消息队列，第一条是被挤出消息的递归摘要。
- **内存压力**（§2.2）：超过上下文的 70% 时插入"内存压力"警告，让模型自己把重要内容存走；到 100% 时挤出 50%，重做递归摘要。被挤出的消息永久留在 recall 存储里，可以检索。
- **事件触发推理**（§2.4）：用户消息、系统警告、用户交互（比如"用户刚登录"）、定时事件都算事件，定时事件让它能"不经提示自己跑"。函数调用带 `request_heartbeat=true` 就立刻接着推理（链式调用），不带就让出控制，等下一个外部事件。
- **效果**：深度记忆检索任务上，GPT-4 从 32.1% 提到 92.5%（表 2）。
- **对弱模型的警示**：
  - "MemGPT 用 GPT-3.5 时性能显著下降，因为它的函数调用能力有限"（§3.2.1）；
  - 嵌套键值任务上，GPT-3.5 和 GPT-4 Turbo 版也会"因为查得不够而在第 2 层开始掉"（§3.2.2）；
  - "MemGPT 经常在翻完检索结果之前就停止翻页"（§3.2.1）。

**AIOS〔一手，P9〕**

- 应用层和内核层分开，agent 不直接碰 LLM 和工具，只经系统调用（§2）。
- 所有队列集中在调度器（FIFO 或轮转）。每个 LLM 实例被封装成一个"核"，类似 CPU 核（§3.2–§3.3）。
- 上下文管理器做快照和恢复：闭源模型保存已解码的文本，开源模型保存 logits 搜索树（§3.4）。
- 内存超过 80% 时按 LRU-K 换出到存储（§3.5）。
- 访问管理器（§3.8）：按"权限组"管跨 agent 读写；对不可逆操作（删除、覆盖、改权限）强制用户确认。
- 有并发争用时，集中调度让吞吐最多提高 2.1 倍（§4.3）。
- 〔推测〕AIOS 的上下文切换针对的是 token 生成过程中途暂停，对 CLI 大脑没有直接意义；对应到灵鲸，是会话的 resume 和换新。

**Sleep-time compute〔一手，P10〕**

- 把"上下文 c"和"查询 q"分开。在 q 到来之前的空闲时间里，让模型对 c 做推断，重写成 c′；查询时用 c′ 代替 c（§3）。
- 数据：
  - 同样准确率下，查询时的计算量减少约 5 倍；
  - 加大空闲时的计算量，准确率还能再提高 13%（GSM）或 18%（AIME）（§5.1–§5.2）；
  - 同一个上下文有 10 个相关查询时，单次查询的平均成本降 2.5 倍（§5.3）。
- **查询越能从上下文预测，收益越大**（§5.4）。查询时预算高的情况下，纯查询时计算反而略好，作者推测预先计算的内容带来了干扰（§5.1）。
- 作者明确说"空闲时长可能从几秒到几天不等"，现实中是多轮交替进行的（§7）。也就是说，sleep-time 指的是**任何空闲时间**，不专指夜里。

**Auto-Dreamer〔一手，P11〕**

- 依据互补学习系统理论：海马快速编码单个情景，新皮层缓慢地提取跨情景的结构。按这个思路，把"每个会话的快速写入"和"跨会话的慢速巩固"分开。
- 巩固器把选中的一片记忆当作只读证据，可以回查**带出处链接的原始轨迹**，然后生成一组更紧凑的新条目替换原来那片。
- 每隔固定的 k 个会话运行一次（§5.2）。
- 效果：ScienceWorld 上比最强基线高 7 个百分点，记忆库小 12 倍；迁移到 ALFWorld 和 WebArena 仍然领先。
- 局限（附录 A）："写入时漏掉的信息，巩固器通常找不回来，除非原始轨迹让它显眼。"〔推测〕这支持灵鲸"日志是唯一来源、记忆是投影"：原始日志必须一直保留。

**SCM〔一手，P12〕**：有限工作记忆、重要度标签、NREM/REM 两段离线巩固、主动遗忘。只在 10 轮对话上做了测试，自称"research preview"，**证据弱**，只作旁证。

**Anthropic《Effective context engineering》〔E2，经工具转写〕**

- **上下文退化**（context rot）：token 越多，召回越差。上下文是"边际收益递减的有限资源"，每个 token 都在消耗"注意力预算"。n 个 token 就有 n² 个两两关系。性能是渐降的，不是断崖。
- **原则**：找到能产出期望行为的最小高信号 token 集合。
- 系统提示要"高度合适"：既不写成死板的 if-else，也不写成假定双方有共同背景的空话。工具集要最小、不重叠："如果人类工程师都说不清该用哪个工具，agent 也做不到。"
- **两种取上下文的方式**：
  - 即时检索：只保留轻量标识（路径、查询、链接），运行时再取；
  - 混合：Claude Code 把 CLAUDE.md 预先放进上下文，再用 glob 和 grep 即时取文件。
- **长任务的三种手段**：
  - 压缩：先保召回、再求精简；最轻量、最安全的做法是清掉旧的工具输出；
  - 结构化笔记：比如 NOTES.md，宝可梦的例子里，上下文重置后读自己的笔记接着玩；
  - 子 agent：每个子 agent 用几万 token，只回一份"通常 1000–2000 token"的浓缩摘要。
- **怎么选**：来回对话多的用压缩；有里程碑的迭代任务用笔记；能并行探索的研究用多 agent。

### 2.5 多 agent 与派活

**Anthropic 多 agent 研究系统〔E1，经工具转写〕**

- **分工**：主 agent 用 Opus 4，子 agent 用 Sonnet 4。比单 agent 的 Opus 4 高 90.2%（内部研究评测）。**主控用的是更强的模型。**
- **成本**：agent 约是普通聊天的 4 倍 token，多 agent 约是 15 倍。BrowseComp 上，三个因素解释了 95% 的表现差异，其中 token 用量一项解释 80%，另外两项是工具调用次数和模型选择；而且升级模型比把 token 预算翻倍收益更大。
- **派活要写清楚**："每个子 agent 需要一个目标、一种输出格式、用什么工具和信息源的指导、清晰的任务边界。"说得含糊，就会误解任务、重复搜索。
- **不适合多 agent 的场景**："需要所有 agent 共享同一上下文"或 agent 之间依赖很多的领域；大部分编程任务也不适合。
- **早期失败**：简单查询也派出 50 个子 agent；几个子 agent 做重复的工作；更新太多，互相干扰。
- **工程做法**：
  - 上下文超过 20 万 token 时，主 agent 把计划存进 Memory；
  - 子 agent 把产物写进外部存储，只回传轻量引用，避免"传话游戏"；
  - 目前子 agent 是同步执行的；
  - "agent 有状态，错误会累积"，出错时从出错处恢复而不是重来；
  - 部署新版本时，新旧版本并行、流量逐步切换（rainbow deployment）。

**Anthropic《Building effective agents》〔E3，经工具转写〕**

- 先找最简单的方案，只在能证明有改进时才加复杂度。
- 区分 workflow（预先写好的代码路径）和 agent（模型自己决定流程）。
- 路由模式：简单问题给 Haiku 一类的小模型，难题给 Sonnet。
- orchestrator-workers：适合事先预测不了子任务的情况。
- agent 必须有停止条件，比如最大迭代次数，还要在沙箱里测试并加护栏。
- 工具要做防错设计（poka-yoke）："改参数，让人更难犯错。"

**Cognition《Don't Build Multi-Agents》（2025）〔一手，E4〕**

- **原则 1**：共享上下文，而且要共享完整的 agent 轨迹，不只是单条消息。
- **原则 2**：动作里带着隐含的决定，决定冲突就出坏结果。
- **"只复制原始任务"不够**：真实系统是多轮的，主 agent 拆任务前调用过工具，"任何细节都可能影响对任务的理解"。
- Flappy Bird 的例子：两个子 agent 看不到对方在做什么，即使拿到同样的原始任务，做出来的风格也不一致。
- **Claude Code 的子 agent** 从不和主 agent 并行干活，通常只负责回答问题、不写代码，原因是缺上下文。子 agent 的好处是它的调查过程不留在主 agent 的历史里。
- **"edit apply"教训**：大模型写说明、小模型照着改文件，小模型常因说明里极小的歧义改错。

**Cognition《Multi-Agents: What's Actually Working》（2026-04）〔一手，E5〕**

- 原来的观察对"并行写入的群体"仍然成立。现在能用的是一类更窄的模式：**写入保持单线程，其他 agent 只贡献智力，不贡献动作。**
- **干净上下文的审查者**：编码 agent 和审查 agent 事先**不共享**上下文效果反而最好，原因之一是上下文退化。但编码 agent 要用自己的完整上下文过滤审查意见，否则会循环、越界、违背用户。
- **"Smart Friend"**：小模型当主控，在它认为棘手时调用大模型。
  - 难点："一个更笨的模型怎么知道自己到了极限？"
  - 缓解：至少调用一次；对特定情况硬性规定必须调用（比如合并冲突）；把主控的**完整上下文分叉**给大模型（"80/20 方案"）；鼓励主控问宽泛的问题。
  - 结果：**SWE-1.5 当主控不够格**，恰恰在"知道何时升级、知道问什么"上差距太大，"质量上限由主控决定"。两个前沿模型搭配时才真正有效。
- **管理者带子 Devin**：
  - "按小范围委派训练出来的管理者默认过度规定细节，当它缺少深入的代码库上下文时会适得其反"；
  - "agent 以为自己和子 agent 共享状态，其实没有"；
  - 子 agent 向管理者回报、再转给其他子 agent 的跨 agent 通信"默认不会发生"。
- 无结构的群体协商"大多是干扰"，实用的形态是"拆分、执行、汇总加管理"。

**Devin 管 Devin〔一手，E6〕**：每个子 Devin 在独立虚拟机里，干净上下文、单一焦点。协调者能给子会话发消息、看它的算力消耗、让它睡眠或终止、给自己定时提醒，还能读子会话的完整轨迹来改进下一次拆分。

**MAST〔一手，P17〕**

- 7 个开源多 agent 框架、1642 条轨迹，失败率 41%–86.7%。
- 14 种失败模式，分三类：系统设计问题、agent 之间失配、验证不足。
- 高频项：
  - 步骤重复 15.7%；
  - 不遵守任务要求 11.8%；
  - 不知道任务已经完成 12.4%；
  - 推理和动作不一致 13.2%；
  - 该问不问（带着错误假设继续做）6.8%；
  - 验证错误 9.1%。
- 作者判断：agent 之间失配不是统一消息格式（MCP、A2A）能解决的，需要 agent 能推断对方需要什么信息。
- 干预效果：把角色说明写清楚 +9.4%；加一步高层目标验证 +15.6%。

### 2.6 弱模型派活、强模型干活

- **RouteLLM〔一手，P18〕**：用偏好数据训练路由器，在 GPT-4 和 Mixtral 之间选。在保持质量的前提下，成本降 2 倍以上；MT Bench 上保持 95% 的 GPT-4 质量时省 3.66 倍。**路由器是训练出来的分类器，不是弱模型自己判断。**
- **FrugalGPT〔一手，P19〕**：LLM 级联。先让便宜模型答，再由一个**单独训练的打分函数**判断是否可靠，不可靠才升级。最多省 98% 成本。**是否升级同样不由弱模型自己决定。**
- **ToolOrchestra〔一手，P20〕**：
  - 用强化学习专门训练的 8B 编排者，HLE 上 37.1%，超过 GPT-5 的 35.1%，效率高 2.5 倍。
  - 试点研究（附录 A）：**直接用提示词让现成模型当编排者是脆的**。Qwen3-8B 当编排者时 73% 的情况交给 GPT-5；GPT-5 当编排者时 98% 交给 GPT-5 或 GPT-5-mini，不顾成本指令。
- **Advisor 策略〔E7，经工具转写〕**：
  - Sonnet 或 Haiku 当执行者，卡住时调用 Opus 当顾问。顾问读共享上下文，只给计划、纠正或"停"，不调工具、不对外输出，每次约 400–700 token。
  - Sonnet 加 Opus 顾问：SWE-bench Multilingual 提高 2.7 个百分点，单任务成本降 11.9%。
  - Haiku 加 Opus 顾问：BrowseComp 从 19.7% 到 41.2%，成本比 Sonnet 单独跑低 85%。
  - 用 `max_uses` 限制调用次数。这是厂商自己的数据。

### 2.7 主动性

**Inner Thoughts〔一手，P13〕**

- **"预测下一个说话人"不够用**（§3）：在"轮到谁说"有明确分配的场景（点名、提问）里，模型预测得好；在"谁都可以接话"的自选场景里，接近随机。原因是接不接话取决于不可见的内在动机。
- **8 个开口或不开口的启发**（§4.3.2），来自出声思维研究：相关性（77 次提及）、信息缺口（33）、平衡（33）、连贯（30）、动态（30）、预期影响（23）、原创性（16）、紧迫性（14）。
- **框架**（§5）分五步：触发（新消息、10 秒沉默）→ 检索（显著性超过 0.3 的记忆）→ 形成想法（快思考 + 慢思考）→ 评估（按 8 个维度给 1–5 分，先列支持和反对理由各两条，再按 logprob 加权）→ 参与。
  - 沉默越久，动机分越高（每步乘 1.02）。
  - 参与分三种情况：轮到别人时，只有超过打断阈值才插话；谁都能说时，要超过动机阈值；轮到自己时就说。
- **评估结果**：
  - 模拟评估：82% 的人偏好 Inner Thoughts。
  - 12 人的 Slack 用户研究：均衡的"积极贡献者"最受欢迎，阈值 3.59；只在很感兴趣时才说话的"选择性参与者"被 7 人评为最差，阈值 4.09，被嫌太被动；"话痨"评价两极。
- **局限**：阈值靠反复试错设定；想法会不相关或自相矛盾。**没有报告成本**。每条消息要调多次模型，还需要 logprob。〔推测〕CLI 大脑拿不到 logprob。

**ProactiveBench〔一手，P14〕**

- 目标：最大化"用户接受率"；不需要帮忙时保持沉默也算接受。
- 233 条真实事件的测试集上：GPT-4o-mini 误报率 64.73%，GPT-4o 51.85%，Claude-3.5-Sonnet 54.63%，LLaMA-3.1-8B 61.84%。**模型普遍爱帮倒忙**，"即使被要求只提供必要帮助"。
- 一次给 3 个候选能降低误报：GPT-4o 从 51.85% 降到 36.44%。加奖励模型反馈后误报降了，但召回大跌，模型"一收到反馈就闭嘴"。
- 这里用户是奖励模型模拟的。

**Need Help?〔一手，P15〕**

- 随机对照实验：主动建议让编程产出提高 12–18%。
- 时机由**代码定时器**决定：用户在打字或交互时不弹；空闲 5 秒后才弹；两次建议至少间隔 20 秒；运行报错时立刻给。
- 把建议频率调高的"持续建议"组，只有 47% 的人还偏好主动助手（另外两组是 90% 和 80%），抱怨"分心、烦人"。
- 参与者希望能自己选择开关和频率。

### 2.8 长对话人设漂移〔一手，P16〕

- LLaMA2-chat-70B 和 GPT-3.5 在 8 轮内就出现明显的指令漂移。原因和注意力对开头系统提示的衰减有关。
- **对话越长，agent 越会采纳对方的指令**（§3.3）。作者指出这可能被用来攻击。
- 每轮重复注入系统提示能缓解，但要付出一定的能力代价（§6）。
- 这是 2024 年的旧模型，新模型漂移的程度〔未核实〕。

### 3.5 检验结论汇总

- **保持**：11-1、11-2（补读取时机）、11-3（补广播）、11-4、11-5（补代码闸）、11-6、12-1、12-5、12-6（补"取原文"）、13-4、13-5（补"最近对话从日志取"）。
- **修正**（建议写进 handoff）：
  - **A 关注与广播**：决策 13 ② 补"自上而下的关注表"和"突破类别"；新增"决策广播"，主意识的全局决定写进她的状态，相关会话在下一轮收到提醒。
  - **B 共享写**：决策 12 补"共享写清单"：承诺和日程、关于她自己和主人的事实陈述、关系变化、对外答应的事、工作区文件。只经本体 API 写入，带冲突检查；这些类别属于"全局决定"，在场分身必须提请。
  - **C 原话 + 交接信封**：信封包括原话（按消息 ID 从日志取）、相关聊天片段、主意识至今的相关决定和理由、明确列出"你不知道的事"、汇报格式、边界和审核点、可以反问的通道。信封只描述流程，不改写需求，因此和决策 5"需求理解由分身完成"不冲突。
  - **D 代码预取 + 模型拉取**。
  - **E 睡觉 = 作息时间点且空闲**：白天做增量整理；夜间产出针对明天能预测的需要；夜间可以用更强的模型。
  - **F 主意识大脑不默认最便宜**：代码决定升级，加"请教"工具，先评测再定。
  - **H 在场分身两段门控**。

| ① 感知 | 形态插件（感知）、时钟、大脑适配器、日志 | 本体（不是会话） | CTM 的 Input maps；LIDA 的感知与理解；CoALA 的观察 |
| ② 进入工作空间 | 收件箱、门控、关注表 | 本体；在场分身和干活分身是"模块" | GWT 的进入与注意；CTM 的 Up-Tree 竞争；LIDA 的注意 codelet |
| ③ 决策 | 主意识会话、上下文组装器、检索 | 主意识（分身在自己范围内做局部决策） | CoALA §4.6 的规划阶段；GWT 的工作空间加工 |
| ④ 行动 | 内核工具（MCP）、准入、执行器 | 本体执行，会话只出决定 | CoALA 的 grounding；麦麦"MCP 只收决策"（第 3 步）；AIOS 的系统调用 |
| ⑤ 广播 | 她的状态、状态表、会话提醒 | 本体 → 相关的在场分身和干活分身 | GWT 的广播（连贯、协调）；Cognition 原则 1 和 2 |
| ⑥ 学习 | 后台任务（隐藏会话）、成长审核 | 后台会话（决策 4） | CoALA 的学习动作；GA 的反思；Auto-Dreamer；sleep-time compute |

〔推测〕这里和 LIDA 有一处差异：LIDA 主张学习发生在意识广播之后，灵鲸的记忆则从**全部**日志抽取，不只是主意识看到的部分。建议保持灵鲸的做法：分身的经历也是她的经历。但**人格成长**这种高风险的学习，应该像 LIDA 那样经过"进意识"这一步：形成提案，主人可见，下个会话才生效。

## 5. 主动性与成长触发的建议

### 5.1 文献里"什么时候开口、什么时候自己做事"的判定方法

| 方法 | 代表 | 成本或效果数据 | 对灵鲸 |
| --- | --- | --- | --- |
| 代码触发加定时器 | MemGPT 定时事件；Need Help（空闲 5 秒、间隔 20 秒、报错立刻给） | 频率调高后偏好从 90% 跌到 47% | **第一道闸**：作息、空闲、承诺到期、主人回来、模块有新观察（第 3 步 AIRI）；加冷却和每日上限 |
| 每步都问模型 | Generative Agents 的反应提示 | 25 个 agent 两天花几千美元 | 不用 |
| 内在动机打分 | Inner Thoughts：8 个维度，阈值，沉默加成，打断阈值 | 82% 偏好；均衡阈值最受欢迎；没报成本，需要 logprob | **第三道判断**：触发之后让模型按 8 个维度列出支持和反对理由，给 1–5 分，超过阈值才开口；阈值随主人反馈调 |
| 训练出来的预测器 | ProactiveBench 微调；奖励模型反馈 | 误报 50%–65%；一次给 3 个候选能降误报；奖励模型反馈让模型"闭嘴过头" | 不训练，但借两点：①目标是"主人接受率"，主人不需要时保持沉默也算对；②记录主人对每次主动的反应 |
| 预测下一个说话人 | Inner Thoughts §3 的基线 | 在自选场景里接近随机 | 群聊不能只靠它，见修正 H |
| 空闲时预先计算 | Sleep-time compute | 查询时省 5 倍；多查询摊薄省 2.5 倍；查询要能预测 | 空闲时预备早安内容、到期承诺、活的进度摘要 |

### 5.2 对灵鲸的建议

1. **把"开口找人"和"自己做事"分开**〔推测，综合 P14、P15〕。
   - 自己做事（逛、学、做工具，第四版）不打扰任何人，只受花钱总闸和作息约束。
   - 开口找主人要过三道闸：代码触发 → 频率和情境闸（每日主动上限、两次间隔、主人日历显示忙、主人最近几次没理就退避）→ 模型判断（允许安静返回）。
2. **计划要落在真实可执行的事上**。GA 证明计划对行为的长期连贯是必要的（没有计划，会在 12 点、12 点半、1 点各吃一次午饭）；麦麦删掉 LLM 编的日程，理由是幻觉（第 3 步）。两者并不矛盾：她的日程由承诺、主人日历、兴趣对应的适配器任务组成，模型只做排序和分解，不编一段叙事。
3. **反馈闭环**。主人对每次主动的反应（回复、点开、忽略、"别烦我"）写进日志。阈值和每日上限的调整做成可查的配置变更。这满足 Need Help 的"根据用户反馈调整时机"，也满足 product.md 的"事后可查"。
4. **群聊用两段门控**（修正 H）。阈值参考 Inner Thoughts：太高显得冷淡，太低像话痨，以"积极贡献者"为默认。
5. **成本控制靠"不触发就不起回合"**。各项文献的成本数据（GA 几千美元、多 agent 15 倍、麦麦每小时 20 万 token）都指向同一个结论：成本取决于起了多少次模型回合，不取决于单次回合写得多巧。

### 5.3 反思和成长在架构里的位置与触发条件

位置：全部属于 CoALA 的**学习动作**，由后台隐藏会话执行（决策 4），不在主意识的上下文里做。主意识只收到一条简短通知，比如"今晚整理出 3 条成长提案"。

| 学习层次 | 写到哪 | 触发条件 | 依据 |
| --- | --- | --- | --- |
| 情景 | 操作日志（本身就是） | 每个事件 | GA 记忆流；CoALA 情景记忆 |
| 事实和关系记忆 | 记忆投影 | 按条数或时间批量；会话换新前写回 | MemGPT 内存压力；第 3 步 eliza 按量反思 |
| 反思（高层洞见，带出处） | 记忆投影（反思也是记忆） | 重要度累计超过阈值（GA 是 150，约一天两三次）；或会话换新时；或每晚 | GA §4.2；Letta 按压缩事件触发（第 3 步） |
| 跨会话巩固（合并、去重、矛盾消解、遗忘） | 记忆投影的新版本，原始日志不动 | 每晚睡觉，或每 k 个会话 | Auto-Dreamer；互补学习系统理论 |
| 成长（人格枝叶） | 成长提案 → 审核 → 生效事件 | 只在夜间巩固时产生；要求跨多个会话、多种来源的重复证据；来源加权（主人高于群友）；生效在下一个会话 | CoALA：程序和自我模型的写入风险最高；GA §7.2 别人的兴趣塑造了她；P16 会采纳对方的指令；Letta"凭模式不凭单次事件"（第 3 步） |
| 技能和自写工具 | 技能库（带版本） | 干活完成**并且经过验证**（主人验收或测试通过）之后，作为候选 | CoALA §5：Voyager 只在任务成功后才把代码写进技能库 |

算法细节（重要度怎么打、提案格式、审核界面）留到"人格与成长"和"记忆系统"模块阶段。

## 6. 整体架构问题 A–J 的理论视角

- **A 进程模型与分层**：
  - AIOS 把 agent 和资源分到应用层和内核层，agent 只经系统调用拿 LLM、工具和存储；调度器集中管理队列；每个 LLM 实例算一个"核"。有争用时，集中调度让吞吐最多提高 2.1 倍。
  - 对灵鲸：本体是内核；会话是"进程"；CLI 大脑是"核"；能力插件和形态插件是"设备"。
  - 要有全局的会话并发上限和按模块的队列（第 2 步发现 Paseo 没有）。
  - CoALA："循环由代码驱动"，所以循环在本体里，不在任何一个 CLI 会话里。
- **B 核心对象与数据模型**：CoALA 给出最小的概念集合，分记忆、动作、决策三类：
  - 记忆：工作记忆、情景、语义、程序。对应到灵鲸：会话上下文 = 工作记忆；日志 = 情景的原始形态；事实和关系记忆 = 语义；人设、成长、技能、作息 = 程序和自我模型。
  - 动作：内部的检索、推理、学习，外部的 grounding。
  - 决策：决策循环。
  - CoALA §7 用"可控性"划分内外，CLI 的转录属于外部。
  - GWT 补上"通知 = 带权重的 gist"这个对象（CTM 的 chunk），字段建议：来源、时间、一两句话、类别、紧急度、受众、报告引用。
- **C 事件流**：
  - MemGPT：事件 = 用户消息 + 系统警告 + 用户交互（登录、上传）+ 定时事件；调用带 heartbeat 就链式推理，不带就让出。
  - GWT 和 CTM：先由外围打分，再机械竞争，最后广播。
  - Inner Thoughts 的触发：新消息、沉默 10 秒。
  - 对灵鲸：入口事件先写日志，再打标签，再门控或进收件箱；主意识回合结束后把决定广播出去（第 4 节①–⑤）。
- **D 唯一主意识加多个对话**：
  - GWT 和 CTM 都是"单一工作空间 + 很多并行模块"，明确反对两两通信的结构。
  - Anthropic、Cognition 2026、Devin 管 Devin 都收敛到"一个协调者加多个干净上下文的执行者"，写入保持单线程。
  - MAST：agent 之间失配大约占失败的三分之一，问题出在对方需要什么信息，不在消息格式。
  - BIGMAS：协调开销约占 17%–25% 的 token。
  - 结论：中心调度，不平级协商；中心要同时有上行（通知）和下行（广播）。
- **E 主动性与生活循环**：见第 5 节。理论共识是：触发由代码决定；模型只在触发之后判断说不说；空闲时预先计算；目标是接受率，而不是主动次数。
- **F 事实来源与持久化**：
  - GA 的记忆流是"完整记录"，反思带引用。
  - Auto-Dreamer：巩固依赖带出处的原始轨迹，"写入时漏掉的找不回来"。
  - CoALA 把学习当作有意识的写入动作。
  - GA 建议保留审计日志。
  - 这些都支持"只追加的日志是真相，记忆和人格是投影"，而且原始日志不能被巩固覆盖。
- **G 扩展边界**：
  - CoALA：grounding 过程和内部过程分开，动作空间取必要的最小。
  - E2 和 E3：工具最小、不重叠、做防错设计。
  - CTM：Input maps 和 Output maps 把外界编码转成内部 gist，核心不关心渠道。
  - AIOS 的 SDK 给不同框架做适配器，对应灵鲸的大脑适配器。
  - 结论：形态插件只做感知和行动的编码转换，不带认知（和第 3 步一致）。
- **H 多端连接与同步**：理论文献几乎不涉及。可借的只有 MemGPT 把"用户登录"当作事件，对应"主人回来了"这类触发（第 3 步 AIRI）。
- **I 安全与权限边界**：
  - CoALA：学习动作（尤其是改程序性内容）和 grounding 动作风险最高，要明确列出、必要时删减动作空间。
  - AIOS：跨 agent 读写按权限组管；不可逆操作要用户确认。
  - GA：记忆攻击。
  - P16：长对话会采纳对方的指令。
  - 对灵鲸：
    - product.md 定的"兜底靠可撤销，不靠审批"只覆盖**可撤销**的动作。发出去的消息、对外付款、删远端数据这类不可逆的外部动作，需要例外清单〔推测〕。
    - 非主人来源的内容不能直接改成长。
    - 在场分身的会话要能换新，限制长对话漂移。
- **J 出错与恢复**：
  - E1："agent 有状态、错误会累积"，所以从出错处恢复，配合重试和检查点；全量追踪；部署时新旧版本并行、流量逐步切换。
  - E3：要有停止条件。
  - MAST：步骤重复、提前结束、验证不足是高频失败；加一步高层目标验证 +15.6%。
  - 对灵鲸：
    - 每回合有步数和工具调用上限；
    - 干活分身"设计 → 审设计 → 执行 → 验收"里的验收算一层验证；
    - 本体升级时，正在运行的会话不能被打断，参考 rainbow deployment。

## 8. 坑与反例、待核实

### 8.1 坑与反例

1. **别把 GWT 当工程规范**。它是意识理论；Goldstein 等甚至认为容量有限不是意识的必要条件。灵鲸用它，只用它对"中心、模块、竞争、广播"的结构解释。容量上限的理由来自上下文退化和成本。
2. **GWT 多 agent 的新工作证据很弱**：GWA 没有实验；BIGMAS 只测了谜题；SCM 只测了 10 轮对话。能当设计参考，不能当效果依据。
3. **Generative Agents 的成本和年代**：GPT-3.5，25 个 agent 两天几千美元，每步都调模型。照抄它的循环不可行。它的"过度合作导致兴趣漂移"是成长设计的反例。
4. **"按需拉取"在弱模型上会失灵**（MemGPT），并带来"凭状态表编进度"的风险（GA 的错误笃定）。
5. **"传原话"不是银弹**（E4）。真正缺的是"你不知道什么"和"该问就问"（E5、MAST FM-2.2）。
6. **主动性：模型天生爱帮倒忙**（P14）；**频率一高就招人烦**（P15）。阈值太高又显得冷淡（P13 的选择性参与者被评为最差）。
7. **路由类论文不能直接拿来支持"弱模型派活"**。RouteLLM 的路由器和 FrugalGPT 的打分器都是**训练出来的独立组件**；ToolOrchestra 的小编排者是**专门用强化学习训练**的。靠提示词让现成小模型当编排者，正是 ToolOrchestra 证明有偏差的做法。
8. **Anthropic 的数据来自研究类任务，且主控是 Opus**。15 倍 token 的结论适用于"多 agent 并行研究"，不能直接推到灵鲸的"一个主意识加很多常驻会话"。灵鲸的成本主要由回合次数决定。
9. **夜间整理用便宜模型**会让巩固和成长提案质量偏低（Auto-Dreamer：学出来的巩固器比靠提示词的高 7–10 个百分点），而夜间恰恰是最不在乎延迟、可以用强模型的时候。
10. **人设漂移的数据来自 2024 年的旧模型**（LLaMA2、GPT-3.5），DeepSeek V4.1 Flash 和 Claude 系列的漂移程度要实测。

### 8.2 待核实

- **LIDA 原文没读到**（ccrg 和维基百科都因网络失败），只有 MIRA 的转述和检索摘要。"学习发生在广播之后"的原文措辞、循环频率都待核实。
- Butlin 等（2023，arXiv 2308.08708）的 B1–B4 只经 Goldstein 等的转述读到。
- Anthropic 的三篇文章（E1–E3）和 Advisor 博客（E7）是经 WebFetch 的摘要和关键句摘录读到的，不是逐字通读；数字和原句以原文为准。

### 8.3 待实测（都直接影响决策 6、11、13）

1. **主意识大脑小评测**：约 20 个真实场景，覆盖主人闲聊、听出一件活、汇报进度、主动关心、群里 @ 派活、承诺冲突。比较三种配置：DeepSeek V4.1 Flash 单独；Flash 加"请教"强大脑；中档模型单独。指标：派活判断准确率、主动拉取细节的比例、编造进度的比例、主动误报率、每回合成本。
