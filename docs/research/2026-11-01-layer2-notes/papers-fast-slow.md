## 1 Talker-Reasoner（Google DeepMind 2024）：分工、过时信念、何时等

### Takeaway
Talker（快、只负责对话）和 Reasoner（慢、负责多步推理、调工具、在世界里行动、产出结构化信念）只经共享记忆相连；Talker 默认用"最新已有的"信念、不等 Reasoner，代价是有时"抢答一个比用户问的更简单的问题"。等不等不是 Talker 自己判断难度，而是读 Reasoner 写进记忆的一个结构化字段（教练阶段 = planning 时等）。论文**只有定性案例，没有任何延迟、质量、成本数字**。

### Cited Findings
- 版本：arXiv 2410.08328 v1，2024-10-10，作者 Christakopoulou、Mourad、Matarić（Google DeepMind），CC BY 4.0。〔一手〕 — [arXiv](https://arxiv.org/abs/2410.08328)
- 分工：Talker 是"快而直觉"的 System 1，负责合成对话回复、感知世界、从用户拿观察和反馈、读记忆来"预热"回答；Reasoner 是"慢而审慎"的 System 2，负责多步推理与规划、调用工具、在世界里执行动作，并"由此产出新的 agent 状态"。〔一手〕 — [§摘要、§3.2](https://arxiv.org/abs/2410.08328)
- 两者主要经**记忆**交互：Reasoner 生成下一个信念状态和计划存进记忆；"Talker 任何时候需要信念，就从记忆取最新的一份"，因此"可能以延迟的世界视图运行"；Talker 的对话又被 Reasoner 处理，Talker 的"快速印象"成为 Reasoner 显式信念和计划的来源。〔一手〕 — [§3.2](https://arxiv.org/abs/2410.08328)
- 信念是 XML/JSON 的结构化语言对象，内容可含用户的目标、需求、情绪、动机、障碍；Reasoner 的动作空间是 reason、act、extract（抽取信念），"刻意建模世界/人"是它和普通 ReAct agent 的区别。〔一手〕 — [§3.1、§3.2.2](https://arxiv.org/abs/2410.08328)
- Talker 的回复条件为：最新用户话语 + 记忆里最新信念 + 交互历史；"它可能使用不是 Reasoner 最新的信念以保证快速交互，两个系统有时是解耦的"。〔一手〕 — [§3.2.1 式(1)(2)](https://arxiv.org/abs/2410.08328)
- 局限原话：Talker "以更过时的世界视图运行，有固有偏差，有时会回答比所问更简单的问题"，"对复杂问题求解和规划理解很少"；为此引入"让 Talker 等 Reasoner"的变量。〔一手〕 — [§1](https://arxiv.org/abs/2410.08328)
- 实例（睡眠教练）：Talker 与 Reasoner **都用 Gemini 1.5 Flash**；Talker 按三个教练阶段（理解、定目标、出计划）各有一套指令；Reasoner 是分层的：每轮先推断用户处于哪个阶段，再调用对应的三个"mini-Reasoner"之一，每个由不同组合的 CoT 提示 Gemini 1.5 Flash 加对应的抽取 schema 构成；信念 schema 由临床专家定，字段如睡眠困扰、目标、习惯、障碍、睡眠环境。〔一手〕 — [§4.2](https://arxiv.org/abs/2410.08328)
- **等不等的规则**："Talker 是否等 Reasoner 完成由信念决定——在 planning 教练阶段等，其他阶段不等。"示例里 planning 阶段 Talker 的输出是"copying Reasoner's response"，即原样转述 Reasoner 的计划。〔一手〕 — [§4.2、§4.3.1](https://arxiv.org/abs/2410.08328)
- 两种模式：①"Intuitive Talker"：理解阶段等 System 1 任务，用旧信念也能聊好；②"Snap judgement Talker"：用户要明确的多步计划或需要调工具取资源时，不等 Reasoner 就会"快速下判断"——例子是 Reasoner 抽取的信念还没把阶段更新为 planning、也没取资源，Talker 就自己给出了一份通用计划（示例对话第二轮）。〔一手〕 — [§4.3.1、§4.4](https://arxiv.org/abs/2410.08328)
- 作者列的未来工作："Talker 应自动判断是否需要 System 2"、"大部分时候低强度使用 Reasoner"、"多个 Reasoner 各写记忆的不同部分"——即**自动判断何时升级在本文中没有解决**。〔一手〕 — [§5](https://arxiv.org/abs/2410.08328)
- 论文没有代码链接、没有延迟测量、没有用户研究。〔一手，按全文检索〕 — [arXiv](https://arxiv.org/abs/2410.08328)

### Inferences
- 〔推理〕Talker-Reasoner 和灵鲸第二层几乎同构：前台不持有改世界的能力、状态在外部记忆、后台结果经记忆回来。差别在两处：①它的"等不等"由后台写的结构化阶段字段决定，不由前台临场判断；灵鲸 §2.3 末段留给总会话的那条"当场答还是想一想"恰好是 Talker-Reasoner 作者承认没解决的部分。②它在 planning 阶段让 Talker"原样转述"，灵鲸让总会话"按事实栏用自己口吻措辞"——后者更像人，但见 §3 DUMA 的"快脑吸收慢脑输入时出现事实不一致"。
- 〔推理〕"回答比所问更简单的问题"是便宜总会话最可能的失败形态：主人问"帮我想想下周怎么安排"，总会话给出一份泛泛的安排而不 `ponder`。对策可以学 Talker-Reasoner：让代码或一个结构化分类先打一个"阶段/意图"标签（如"要计划 / 要建议 / 涉及她的立场"），标签命中时前缀写"这件事 ponder"，而不是让模型自己意识到。

### Gaps
- 没找到官方代码，无法核对"等"在工程上如何实现（阻塞还是超时）。
- 没有任何定量结果；"解耦带来低延迟"只是论证，未测量。
- 未检索到 2025–2026 年直接以 Talker-Reasoner 为基线的定量后续（arXiv 元数据检索 `abs:"Talker-Reasoner"` 只返回原文；AgileThinker 在相关工作里把它归为"一方必须等另一方完成才能用其输出"的设计）。

## 2 PIANO（Altera，Project Sid 2024）：并发模块 + "认知控制器"瓶颈

### Takeaway
PIANO 让约 10 个模块并发、以不同速度读写共享的 Agent State；为防"嘴上说一套、手上做一套"，设一个**唯一负责高层决定**的认知控制器（CC），它只看经"瓶颈"筛过的信息，决定后**广播**给其他模块，尤其强烈约束说话模块。论文**没有给出瓶颈怎么选信息的算法**，也没有延迟数字；单 agent 结果只在 GPT-4o 上成立。

### Cited Findings
- 版本：arXiv 2411.00114 v1，2024-10-31，Altera.AL 技术报告。〔一手〕 — [arXiv](https://arxiv.org/abs/2411.00114)
- 并发原则："慢的心理过程（自我反思、规划）不应阻塞 agent 对周围即时威胁的反应"；单线程设计假设一次只做一件事、顺序设计假设所有模块同一时间尺度，"两个假设都不成立"；模块（LLM 的和非 LLM 的）如认知、规划、运动执行、说话并发运行，每个模块是"读写共享 Agent State 的无状态函数"；可按情境选择性启用（社交模块只在社交互动时用），速度不同（反射模块用小而快的非 LLM 网络，目标生成要在图上审慎推理）。〔一手〕 — [§2.1](https://arxiv.org/abs/2411.00114)
- 不连贯问题的例子：Abby 有两个独立 LLM 模块，一个管函数调用、一个管聊天；Bob 说"给我一把镐"，聊天模块答"Sure thing!"，函数调用却选了"explore"，Bob 就去用一把想象中的镐——"多个输出流的动作必须双向影响"，作者把这叫连贯性；不连贯"随独立输出模块数量指数增长"；"用一次 LLM 调用同时产出说话和动作"是简单解法，但输出种类多了（说话、视线、表情、肢体）不可扩展。〔一手〕 — [§1.3、§2.2](https://arxiv.org/abs/2411.00114)
- 认知控制器：唯一负责高层审慎决定的模块，决定再被下游翻译成各运动模块的输出；它"经一个瓶颈综合 Agent State 的信息"，瓶颈有两个作用：让 CC 只关注相关信息；"给系统设计者对信息流的显式控制"（例：让社交模块的信息总能通过瓶颈，就能做出很社交的 agent）；决定被广播给许多模块，"特别用于强烈约束与说话相关的模块，使言语与其他动作更连贯"；作者把这种"带瓶颈的决策者 + 广播"与意识理论（全局工作空间）挂钩。〔一手〕 — [§2.2](https://arxiv.org/abs/2411.00114)
- 核心模块（10 个并发中列出的 6 个）：记忆、动作觉察（比较预期结果与实际结果）、目标生成、社交觉察、说话、技能执行。〔一手〕 — [§2.3](https://arxiv.org/abs/2411.00114)
- 单 agent 结果：25 个 agent 玩 30 分钟平均获得 17 种物品，最好的 30–40 种；去掉动作觉察模块后物品进度下降；49 个 agent 跑 4 小时，全体物品数稳定饱和在约三分之一（全部约 1000 种）；"这一表现只有在最新的基础模型（GPT-4o）上才可能，旧模型不行"。基线架构 = 只保留技能执行、记忆、认知控制器。〔一手〕 — [§3.2、§8.1](https://arxiv.org/abs/2411.00114)
- 社交：有社交模块时，agent 能准确推断别人对自己的好感，观察者越多、互动越久越准；去掉社交模块后关系趋于中性；角色分化（农民、矿工、守卫等）只在有社交觉察时出现。〔一手〕 — [§4](https://arxiv.org/abs/2411.00114)
- 作者列的局限：没有视觉与空间推理；"缺乏稳健的内在驱动（生存、好奇、社群）"。〔一手〕 — [§7](https://arxiv.org/abs/2411.00114)
- 论文未说明瓶颈的选择规则、CC 的调用频率或各模块的具体延迟；正文与参考文献里只出现 LangChain、ell 的 GitHub 链接，没有 PIANO 自己的代码链接。〔一手，按全文检索〕 — [arXiv](https://arxiv.org/abs/2411.00114)

### Inferences
- 〔推理〕PIANO 的 CC 就是"每个人格一个协调者"的论据：凡是能对外说话、能对外行动的出口不止一个，就要有唯一的决定者，且它的决定必须约束说话。灵鲸比 PIANO 更严：第三层根本不对外说话（§1 层间规则），只有总会话说话，连贯性由结构保证。
- 〔推理〕但 PIANO 的 Abby 例子在灵鲸里有一个对应：总会话同一回合里 `reply("好，我开始改")` + `dispatch(...)`，如果 `dispatch` 被代码拒绝（名额满、权限不够），嘴上已经答应了。建议：`reply` 的"我开始了"类承诺只在 `dispatch` 返回活号之后发出（R4 要求回复在第一批工具调用里，二者要协调——比如 `dispatch` 同步返回成败，`reply` 放在同批但由 outbox 在 dispatch 失败时改写/拦截）。
- 〔推理〕PIANO 的"瓶颈给设计者显式控制信息流"对应灵鲸 §2.7 的"每轮前缀由代码拼"：进总会话的东西由代码决定，而不是让总会话自己去拉。这是 GWT 式设计在工程上最实用的一点。

### Gaps
- 没有找到 PIANO 的公开代码；"瓶颈"的具体实现、CC 多久跑一次、说话模块在 CC 没决定时能否自己说话，论文都没写。
- 没有延迟或成本数字；也没有"去掉 CC"的消融（基线只是去掉别的模块、保留 CC）。

## 3 SwiftSage、DPT-Agent 及其他 System-1/System-2 agent：切换判据与数字

### Takeaway
能跑出好结果的双系统 agent，切换判据几乎都是**外部可观察的信号**（卡住、动作非法、关键决定、异常、定时器、人发来消息），或是**训练出来的**路由器；"让快模型自己说我要升级"的只有 DUMA，且没有测升级准确率。慢系统的结论通常不以"一段话"交回快系统，而是变成快系统直接执行的东西（动作缓冲、改 FSM 的代码、信念字段）。

### Cited Findings
- **SwiftSage**（arXiv 2305.17390 v2，2023-12-06）：Swift = 用行为克隆离线训练的 T5-large（770M）；Sage = 提示 GPT-4，先用 Q1–Q5 做规划（找物品、拆子目标、跟踪进度、Q5"我是否犯了会妨碍下一子目标的错误、怎么改"），再把下一子目标落成一串动作（动作缓冲）。〔一手〕 — [§3](https://arxiv.org/abs/2305.17390)
- SwiftSage 切换判据（原文四条）：①卡住：连续 K=5 步零奖励；②非法：Swift 预测的下一个动作在当前环境无效；③关键：涉及关键决定，如给出实验最终答案；④意外：观察表明遇到异常。Sage 产出动作缓冲后逐个执行，**缓冲空了就退回 Swift**。〔一手〕 — [§3.4](https://arxiv.org/abs/2305.17390)
- SwiftSage 结果：ScienceWorld 30 类任务平均 84.7 分，SayCan 33.8、ReAct 36.4、Reflexion 45.3；每个动作消耗 token：SwiftSage 757，SayCan 1,856，ReAct 1,971，Reflexion 2,983；作者把省钱归因于"只在需要时调 LLM"和动作缓冲（一次 Sage 产出约 5 个动作）。Swift 单独用时，遇到异常（如炉子坏了）会重复无意义动作、泛化差。〔一手〕 — [§1、§3.2、§4](https://arxiv.org/abs/2305.17390)
- **DPT-Agent**（arXiv 2502.11882 v5，2025-05-28；上海交大）：System 1 = 有限状态机（FSM）+ code-as-policy 生成器；System 2 = 心智理论（ToM）模块 + 异步反思。System 2 输出关于人类搭档的信念和"行为准则"；code-as-policy 生成器把它们变成可执行代码，**改写 FSM 的逻辑**；"没有新输入时 FSM 继续自主产生宏动作，保证持续输出"。〔一手〕 — [§4](https://arxiv.org/abs/2502.11882)
- DPT-Agent 预实验（Overcooked 单人图，每个模型 20 局）：作为独立 System 1，<20B 的模型延迟低但得分效率接近零；用长 CoT 推理模型（DeepSeek-R1 系列、o3-mini）当 System 2，得分效率和总分比很多小模型还低；**所有 LLM agent 都不如纯 FSM agent**。〔一手〕 — [§3](https://arxiv.org/abs/2502.11882)
- DPT-Agent 真人实验：71 名大学生（有效 68），所有框架都用 GPT-4o-mini，基线也都加上 FSM System 1；DPT-Agent 在两张图上得分都最高；去掉 ToM 的版本也胜过 ReAct、Reflexion，作者据此认为"异步反思有效"；Map 2 上真人反而更偏好去掉 ToM 的版本（干活更多）。〔一手〕 — [§6.3、附录 I](https://arxiv.org/abs/2502.11882)
- DPT-Agent 代码里的触发：反思默认每 75 个时间步触发一次（`reflection_interval_n_timestep` 默认 75），System 1 的 LLM 部分（`urgent_response`）每 25 步或**收到人类消息时立即**触发；两个都是 asyncio 循环，用标志位保证同一时刻各自只有一个在跑。〔一手，代码 `llm_agent_run_dpt_exp1.py` 第 91–155、281–283、326–328 行，commit 967a621〕 — [GitHub sjtu-marl/DPT-Agent](https://github.com/sjtu-marl/DPT-Agent)
- **AgileThinker**（arXiv 2511.04898 v1，2025-11-07；SALT-NLP）：Real-Time Reasoning Gym 里环境按固定速率更新、不等 agent，没给动作就用默认动作；反应式 agent（限 token 预算）和规划式 agent（长推理）"都不够"；AgileThinker 两个线程并行：规划线程在冻结的状态上持续流式推理，反应线程在每个环境步的最后一段时间激活、**可以读取规划线程尚未完成的部分推理轨迹**，在环境更新期限内出动作。〔一手〕 — [§1、§3](https://arxiv.org/abs/2511.04898)
- AgileThinker 结果：随认知负荷和时间压力上升，持续优于单一范式；反应线程预算接近它"自然用量上界"时最好（Freeway 约 5k token，Snake、Overcooked 约 2k）；用 DeepSeek 官方 API 做真实时钟实验，token 数与耗时近乎线性，优势保持。失败例：规划 agent 还在对第 1 步的旧状态推理，跟着过时计划撞墙；反应线程知道最新状态，能纠正。局限：只能用 DeepSeek（需要可见推理轨迹）。〔一手〕 — [§4、§5、§9](https://arxiv.org/abs/2511.04898)；代码 [SALT-NLP/RealtimeGym](https://github.com/SALT-NLP/RealtimeGym)（未克隆）
- **DUMA**（arXiv 2310.18075 v4，2023-11-24）：快脑（Baichuan-13B-Chat SFT）是对外接口，每轮输出 `Invoke` 布尔值 + 回复；`Invoke` 为真时慢脑（ChatGLM2-6B，ReAct 式、可调工具）接管做推理、行动、观察，结果交回快脑由快脑生成对外回复——**升级由快模型自己根据"完整回复的复杂度"判断**。〔一手〕 — [§2](https://arxiv.org/abs/2310.18075)
- DUMA 的失败：快脑训练后"吸收慢脑输入时出现一致性偏差、编造事实"，靠两阶段 SFT（对话训练 + 事实性增强）缓解；评测只有房产领域的人工打分，作者自己说还缺"单独快脑、单独慢脑 vs 组合"的对比；**没有报告升级判断的准确率**。〔一手〕 — [§3.1.1、§5](https://arxiv.org/abs/2310.18075)
- **CogRouter**（arXiv 2602.12662 v1，2026-02-13）：按 ACT-R 设四级认知深度（从本能反应到战略规划），两阶段训练让 agent 每一步自选深度；核心假设是"合适的深度应使所得动作的置信最大"；Qwen2.5-7B 在 ALFWorld/ScienceWorld 达 82.3% 成功率，比 GPT-4o 高 40.3、比 o3 高 18.3、比 GRPO 高 14.0 个百分点，token 少 62%。〔一手，摘要〕 — [arXiv](https://arxiv.org/abs/2602.12662)

### Inferences
- 〔推理〕SwiftSage 的四条判据都能在灵鲸里找到代码可查的对应：卡住 ≈ 总会话连续几轮同一工具同一参数、或第三层"受阻"；非法 ≈ 工具调用被代码拒绝（如 `commit` 查到冲突）——此时不该让总会话再试，而应转 `ponder`；关键 ≈ R5"决定的分量"；意外 ≈ 第三层失败事件。"缓冲空了退回快系统" ≈ 想事活 `conclude` 后结论回到总会话。这支持 §2.3"规则要能被代码检查"。
- 〔推理〕DPT-Agent 的启发是"慢系统的产物改快系统的行为规则，而不是给快系统一段话让它再理解"。灵鲸的对应：想事活的决定写进账本（决策点、打算、心事），由代码在每轮前缀里呈现，总会话照着做；这比"结论作为一段话 followup 给总会话、由它复述"更稳。两条可以同时有：账本写入是权威，followup 只为让她"说出来"。
- 〔推理〕DPT-Agent 和 SwiftSage 都说明：便宜/小的前台单独做判断会很差（<20B 模型得分效率近零；Swift 遇异常就循环），双系统的收益来自把"什么时候升级"交给外部信号，而不是指望前台自知。
- 〔推理〕AgileThinker 的"前台读后台的半成品推理"对灵鲸意义有限：想事活的中间想法可能被推翻，前台引用它容易对主人说出后来要改口的话（见 §6 KAME）。可以借用的是"规划线程按旧状态推理会走偏"这一点——想事活必须收得到主人后来的改口（§6 评审第 5 条已提）。

### Gaps
- SwiftSage 的四条判据各自触发了多少次、各自贡献多少，正文没给（作者说细节在附录，本文未读附录 C）。
- DUMA 的升级准确率、升级比例、延迟均未报告。
- 没有找到任何在"陪伴/人格对话"场景测量"前台自判升级"准确率的双系统论文。

## 4 模型级联与路由：何时从便宜模型升级；自评升级可不可靠

### Takeaway
2025–2026 的证据一致：**模型口头报告的置信与对错的对齐度低**；前沿模型在"要不要求助"上的判断远差于它们在信息完整时的能力（HiL-Bench：完整信息 75–89% → 需要自己判断何时问时 4–24%）；零样本当路由器在一项 2026 评测里**等于瞎猜**。能用的升级要么靠独立训练/校准过的信号（打分器、置信 token、步级路由器），要么靠外部可观察条件。路由研究本身的评测口径互不可比。

### Cited Findings
- 旧笔记已核：RouteLLM 用偏好数据训练路由器（保持 95% GPT-4 质量时省 3.66 倍）；FrugalGPT 用单独训练的打分函数决定是否升级；ToolOrchestra 试点里靠提示词的 Qwen3-8B 编排者 73% 情况甩给 GPT-5；Cognition 2026：SWE-1.5 当主控输在"知道何时升级、知道问什么"。〔二手，转引自旧笔记 §2.5–§2.6〕 — [旧笔记](../2026-10-28-papers-architecture.md)；[RouteLLM](https://arxiv.org/abs/2406.18665)；[FrugalGPT](https://arxiv.org/abs/2305.05176)；[ToolOrchestra](https://arxiv.org/abs/2511.21689)
- 路由综述（arXiv 2603.04445 v3，2026-08-30）：把方法分为生成前路由、生成后路由（级联）、多阶段；级联"先用小模型，只在初始回答按质量估计不够时升级"。〔一手〕 — [§1、§7](https://arxiv.org/abs/2603.04445)
- 同一综述转述 Chuang 等（2025b）：模型自报置信分"一步口头化"（答案和数字置信一起出）与"两步口头化"（先答再单独问置信），"两者都一贯表现出报告的不确定性与预测正确性之间的低对齐"；但与其他机制结合时自验证可在级联里有效：AutoMix 用少样本自验证 + POMDP 路由器，Self-REF 用轻量微调的"置信 token"。〔二手，经综述转述 Chuang 等；AutoMix/Self-REF 的描述为综述一手〕 — [§5、§7](https://arxiv.org/abs/2603.04445)
- 综述的元结论：同一基准上的方法"很少共享指标、模型池或成本口径"，不能直接比较；大多数工作只研究一级路由而非多级级联。〔一手〕 — [§9、§11](https://arxiv.org/abs/2603.04445)
- Self-REF（arXiv 2410.13284 v3，2025-06-19）：给 LLM 加置信 token 并用基于错误的反馈微调；与口头置信和 token 概率相比，在下游路由与拒答上"显著更好"。〔一手，摘要；未读具体数字〕 — [arXiv](https://arxiv.org/abs/2410.13284)
- **HiL-Bench**（arXiv 2604.09408 v4，2026-05-04）：每个任务注入 3–5 个人工验证的"阻塞点"（缺信息、模糊、矛盾），只在逐步探索中暴露；agent 有 `ask_human()`；指标 Ask-F1 = 提问精确率与阻塞点召回率的调和平均。模型 GPT 5.4、GPT 5.3 Codex、Claude Opus 4.6、Gemini 3.1 Pro：完整信息下 pass@3 为 75–89%，**需要自己判断何时问时只有 4–24%**；分领域：完整信息 SQL 86–91%、SWE 64–88%，需判断时最好的模型 SQL 38%、SWE 12%；Ask-F1 平均 SQL 40.5%、SWE 37.4%；没有模型落在"判断良好"象限。〔一手〕 — [摘要、图 1、§4.2](https://arxiv.org/abs/2604.09408)
- HiL-Bench 失败模式（3,600+ 条轨迹）：①过度自信的错误信念、根本没发现缺口；②察觉到高度不确定却仍然出错；③宽泛、不精确的升级且不自我纠正；作者认为这是模型层面的缺陷而非任务特有；用 Ask-F1 塑形奖励做 RL，32B 模型的提问质量与通过率都提高，并跨领域迁移——"它学会的是识别无法自行消解的不确定性并据此行动"。〔一手〕 — [摘要、§4.3–§4.4](https://arxiv.org/abs/2604.09408)
- **Bayesian self-escalation**（arXiv 2608.24087 v1，2026-08-25）：区分三种委派时机——推理前（路由器选模型）、完成后（验证器打分后重试）、推理中（agent 自己意识到大概率失败就移交强模型）；把推理中委派形式化为最优停止，"能力后验"的充分统计量**从带标签的轨迹学习，而不是直接读原始熵**；核心结论："超额成本由该后验的校准程度控制：校准比更聪明的路由器更重要，'自信地错'是约束性的失败模式"；在一个 Qwen2.5-Coder 小/大模型级联上执行预注册协议，三条预测证实两条（含"同等成本下推理中升级的前沿优于事后路由"）。〔一手，摘要、§5.4〕 — [arXiv](https://arxiv.org/abs/2608.24087)
- **System-1 决策模型评测**（arXiv 2610.02267 v1，2026-10-01）：11 个 agent 框架决策点（选模型、选工具、检索相关性、注入检测等），7,283 个基础样例 + 6,640 个鲁棒性变体，对比开源 Laya 与托管 Jev：**两者在零样本模型路由上都不超过随机**（Jev 99.5% 都答"cheap"，Laya AUROC 0.48）；Laya 选项顺序一反转就改了 30.3% 的答案（路由里"cheap"比例从 58.5% 变成 82.3%，"它跟着位置走而不是内容"）；Laya 置信在 0.9 以上的回答里 26% 是错的（比较符号在 HTML 中丢失）。作者自审出的错误：漏算预筛成本（报告省 23.9%，实际 4.3%）、把门控准确率当端到端质量（58% vs 98%）、阈值在样本内定（目标 5% 漏检，留出集最多 17%）。〔一手〕 — [摘要、§5–§7](https://arxiv.org/abs/2610.02267)；数据与代码 [David-DL-Space/sys1-eval](https://github.com/David-DL-Space/sys1-eval)（未克隆）
- **R2V-Agent**（arXiv 2605.16604 v1，2026-05-15）："任务难度在轨迹中途变化——工具调用不稳、观察被截断、局部错误累积——使执行前路由很脆"；做法是步级、风险校准的 SLM→LLM 路由器（Brier 校准 + CVaR 约束），在 SLM 训练好之后用它的残余失败训练；TerminalBench 上以约一半于启发式路由器的强模型调用次数达到同等成功率。〔一手，摘要；具体百分比在公式中未能抽出〕 — [arXiv](https://arxiv.org/abs/2605.16604)
- Router-R1（arXiv 2506.09033 v3，2025-10-24）：路由器本身是 LLM，交替"think"与"route"动作、可多轮调用并聚合多个模型，用含成本项的规则奖励做 RL；只以价格、延迟、示例表现等描述符为条件，可泛化到未见过的模型。〔一手，摘要〕 — [arXiv](https://arxiv.org/abs/2506.09033)
- Springdrift 的工程做法：每条用户输入先分 Simple/Complex，Simple 走更快更便宜的模型（如 claude-haiku），Complex 走更强的（如 claude-opus）；分类用启发式（长度、关键词）+ 可选的一次 LLM 分类调用，10 秒超时。〔一手〕 — [附录 D.7](https://arxiv.org/abs/2604.04660)

### Inferences
- 〔推理〕对灵鲸 §2.3 是强支持：总会话（便宜模型）"自己判断这事重不重"恰恰是证据最差的一环；R2（没工具就只能派）和 R5（决定类工具只在想事活）把大部分升级变成了结构，不依赖它自评，这个方向对。
- 〔推理〕剩下的"当场答还是想一想"是 HiL-Bench 意义上的"选择性升级"，前沿模型也只有 37–40% 的 Ask-F1。灵鲸的缓解应是：①把判断尽量变成代码可算的信号（意图/阶段标签、提到的实体是否在账本里有未决事项、是否涉及她的立场）；②承认会判错，靠低代价纠正（主人追问时强制 `ponder`）；③记日志测量（当场答后被主人纠正的比例），而不是指望换更强模型解决。
- 〔推理〕"不要读原始熵/口头置信"对灵鲸的含义：不要让总会话输出"我对这个回答的把握是 X"再据此升级；若将来要学一个升级器，按 Bayesian self-escalation 和 R2V 的做法，用灵鲸自己积累的带标签轨迹（主人追问/纠正 = 负例）训练或校准。
- 〔推理〕System-1 评测的自审很有用：灵鲸 M4 评测若比较"总会话判 vs 想事活判"，要把预筛成本算进去、阈值在留出集上定，否则会高估省下的钱。

### Gaps
- 没有找到"人格对话 agent 自评升级"的专门测量；HiL-Bench 是编码与 SQL。
- Self-REF、R2V 的具体数字未抽出（HTML 里在公式中）。
- 2603.04445 转述的"口头置信低对齐"来自 Chuang 等 2025b，原文未读。

## 5 Sleep-time compute 与后台/预备计算：搬离对话路径的是什么、收益

### Takeaway
搬到对话路径之外的有四类：①对已知上下文预先推断（sleep-time compute）；②预测用户下一步需要并提前取证（ProAct、IdleSpec）；③反思与自我总结（DPT-Agent 异步反思、Lyfe 异步自我监控、MIRROR 回合间叙事重建）；④不紧急的主动工作推迟到"睡眠时"（Proactivity-Gym）。收益显著但有条件：**查询可预测才有效**；查询时预算很高时纯在线计算反而更好；人更愿意接受"睡眠时做好、明早再看"的主动帮助（97.8% vs 26.7%）。

### Cited Findings
- Sleep-time compute 复核（arXiv 2504.13171 v1，2025-04-17；Letta）：同等准确率下查询时计算减少约 5 倍（Stateful GSM-Symbolic、Stateful AIME）；加大睡眠时计算再提准确率最多 13%（GSM）和 18%（AIME）；同一上下文多个相关查询分摊后单查询平均成本降 2.5 倍；"用户查询的可预测性"与效果高度相关——与旧笔记一致。〔一手，复核摘要与 §5〕 — [arXiv](https://arxiv.org/abs/2504.13171)
- 补充旧笔记未写的 §6 agentic 案例：SWE-Features（至少改 3 个文件的 PR），睡眠时 agent 可先探索仓库；低查询时预算下睡眠时计算 F1 更高，**高预算下纯查询时计算更好**（精确率更高）；作者推测预先探索过更多文件的 agent 会改更多文件、精确率略低。§7：查询难预测或与上下文无关时，"更可取的是标准的查询时扩展"；现实交互是多轮交替的，不止两阶段。〔一手〕 — [§6–§7](https://arxiv.org/abs/2504.13171)
- **ProAct**（arXiv 2605.25971 v2，2026-05-26）：在交互之间的空闲时间里，用对话历史 + 持久记忆预测用户可能的下一步需要（Future-State Prediction），再按"价值门"决定是否去取证（Idle-Time Acquisition）：每个候选算价值分，过阈值才消耗检索/生成预算，低于阈值的保留待以后考虑；先查记忆覆盖度，够了就复用不再检索；交付时也有"价值感知的门"判断是否值得打扰。ProActEval（200 场景、40 领域）上相对被动基线：所需轮数 −14.8%、用户付出 −11.7%、幻觉率 −28.1%。〔一手，摘要、§1、§3.4〕 — [arXiv](https://arxiv.org/abs/2605.25971)
- IdleSpec（arXiv 2605.22154 v1，2026-05-21）：在等工具结果的空闲时间里迭代生成计划候选，结果回来后聚合指导下一步；GAIA 与 FRAMES 上 Gemini-2.5-Flash 平均准确率 55.6%，比不利用空闲时间的基线高 5.1%。〔一手，摘要〕 — [arXiv](https://arxiv.org/abs/2605.22154)
- DPT-Agent 的异步反思："与决策过程异步进行，实时响应由 System 1 负责，反思可以专注思考而不必担心决策延迟"；真人实验里去掉 ToM、只留异步反思的版本仍胜过同步的 ReAct 与 Reflexion。〔一手〕 — [§4.1.2、§6.3](https://arxiv.org/abs/2502.11882)
- Lyfe Agents（arXiv 2310.02172 v1，2023-10-03）的自我监控模块"与动作选择异步运行"，以较慢的时间尺度维护一份强调新颖与目标相关内容的叙事摘要；去掉它后 agent"经常忘记自己正在做的任务"。〔一手〕 — [§2.2、§4](https://arxiv.org/abs/2310.02172)
- **MIRROR**（arXiv 2506.00430 v3，2026-04-17；Arcarae）：Talker（快）立即回复，Thinker（慢：内心独白管理器在一次调用里生成目标、推理、记忆三条线程 + 认知控制器把它们重建成一份有界的第一人称叙事）在**回复发出之后**才开始处理；下一轮 Talker 用上一轮的叙事。多轮"注意力干扰下保持约束"的对话评测上，7 个模型平均相对提升 21%；只用认知控制器的"重建式综合"就让 7 个模型全部提升 5–20%；组合优于单独组件的有 6/7 个模型；收益集中在高注意负荷时。〔一手〕 — [摘要、§2、§4](https://arxiv.org/abs/2506.00430)
- MIRROR 延迟（400 个对话回合）：平均 2.52 秒，中位 2.16 秒，最短 0.74 秒，最长 13.24 秒，75% 在 3 秒内；只有 0.8% 的回合有活跃的后台线程。〔一手〕 — [附录 B.3](https://arxiv.org/abs/2506.00430)
- MIRROR 代码：`process_user_input` "永不等待后台线程"，加锁从洞见队列里取"已完成的最新一份"更新当前洞见，取不到就用旧的（可能为空）；每轮回复后深拷贝历史、起一个守护线程做后台思考，后台线程上限默认 3；重置会话时不等后台线程、直接清队列。Talker 的系统提示明确写"内部叙事是对**过去**交互的回顾，不针对当前消息"，"若当前问题转向新方向，优先直接回应，不要硬套过去的洞见"。〔一手，代码 `latency_tests/production_mirror.py` 第 17–260 行、`core/components/talker.py` 第 26–41 行，commit 78c6383〕 — [GitHub arcarae/MIRROR](https://github.com/arcarae/MIRROR)
- **Proactivity-Gym 人类研究**（arXiv 2609.37267 v1，2026-09-29；30 名熟悉 LLM 的学生与从业者，14 个场景）：同样正确的帮助，**与当前任务争资源时接受率 26.7%，安排在睡眠时做（即使第二天要修改）接受率 97.8%**；即便即时帮助只需 10 分钟审阅、不争资源也不影响期限，仍有 64.4% 的人选睡眠时。〔一手〕 — [§5.3](https://arxiv.org/abs/2609.37267)

### Inferences
- 〔推理〕灵鲸 §3.1 的"整理"和"想事"活、`overall.md` 已定的"空闲增量整理"都有直接依据；新增的一点是 Proactivity-Gym 的数据：**非紧急的主动帮助默认推迟到她空闲/主人睡觉时做，次日由总会话说**，比白天当场打扰更容易被接受。这可以写进 §2.4 的事实包规则："不紧急且主人在忙 → 留心事，明早说"。
- 〔推理〕MIRROR 给了一个和灵鲸很近的可选机制："回合间重建一份有界叙事，下一轮注入前缀"。灵鲸的每轮前缀目前由代码从账本拼；若要加一份"她对这段对话的理解"，应像 MIRROR 一样**事后、异步、有界、全量重建**（不是累加），并在提示里写明"这是对过去的回顾、当前话题转向时以当前为准"。代价是每轮多一次后台调用（MIRROR 用同一模型），是否值得要在 M4 评测里看。
- 〔推理〕sleep-time compute 的"可预测才有效"对夜间整理的产出有约束：早安要说的事、到期承诺、明天日程这类可预测的需要值得预先算；泛泛的"反思"收益不确定（旧笔记修正 E 已提）。

### Gaps
- 没有找到"后台计算对陪伴类 agent 用户满意度"的直接测量；Proactivity-Gym 是工作场景的情景评审，不是真实使用。
- MIRROR 的 21% 来自它自建的约束保持评测（作者说现有基准都不合适，附录表 9），外部效度未知。
- Letta sleep-time agent 的工程实现本轮没有重读（旧笔记说第 3 步已覆盖）。

## 6 异步/可打断 agent：工具跑着时前台能不能继续说话、打断怎么处理

### Takeaway
能：把"等结果"从生成过程里拿掉、结果以中断/事件的形式回来，端到端延迟降 1.3–5.4 倍。工程上收敛到"事件驱动状态机 + 单一真相账本 + 优先级队列"。但实测失败很集中：结果没回来就**先假设**结果、**最近的任务挤掉早先的任务**、用户中途改口后**继续按旧假设做**。在等后台结果期间就开始说内容（而不是垫话）会降质。

### Cited Findings
- **Ginart 等，Asynchronous Tool Usage for Real-Time Agents**（arXiv 2410.21620 v1，2024-10-28；Salesforce）：执行环境核心是"带优先级调度（优先队列）的事件驱动有限状态机"；派发器 = 派发 LM + 账本（ledger），"账本是派发 LM 上下文的唯一真相来源"，消息原子追加；事件来源：语音输入开始/结束说话、派发 LM 开始/结束生成、语音输出开始/结束播放、工具请求发出/结果返回。〔一手〕 — [§3、§3.1.3](https://arxiv.org/abs/2410.21620)
- 同上：FSM 四态 idle / listening / generating / emitting；每 5 秒入队一条"时间流逝"通知（时钟感知）；默认优先级"用户消息 −1、助手消息 1"（原文另说状态转移"应使用最小可能的优先级以立即处理"，据此数值越小越优先——这一解读是本人推断）；**同等优先级时，正在 generating 就打断，正在 emitting（已经在对外说）则不打断**；打断时环境要对账"已生成的 token"与"实际说出去的 token"（TTS 有延迟）。〔一手〕 — [§3.1.1、§3.1.3、§3.3.3](https://arxiv.org/abs/2410.21620)
- 同上，"并行思维进程"的 fork 与 spawn：fork 用父进程账本的副本初始化子进程，spawn 用全新账本 + 第一条说明；"fork 让子进程用更多上下文、更贵，也可能带进无关或干扰的消息，只应在子进程需要父进程完整视图时使用；**默认 spawn 大概更可取**"。〔一手〕 — [§3.1.2](https://arxiv.org/abs/2410.21620)
- 同上：前沿模型靠专门提示能一定程度异步工作，但"遇到乱序消息仍会糊涂"；作者微调了 Llama 3.1 与 GPT-4o；**结果只有语音通话录音的定性展示**；示例是"我马上为你准备行程"→ 用户插问天气 → 先答天气 → 行程准备好再给。〔一手〕 — [§1、Results](https://arxiv.org/abs/2410.21620)
- **AsyncLM**（arXiv 2412.07017 v1，2024-12-09）：函数调用不阻塞生成，执行器完成后向 LLM 的 token 流注入中断块；用 CML 标记语言（`[CALL] [INTR] [TRAP] [END] [HEAD]`）；正在生成函数调用时暂缓中断以免语法被打碎；LLM 需要等结果时发 `[TRAP]` 自陷；在 BFCL 上端到端任务完成延迟比同步函数调用降低 1.6–5.4 倍；Llama 3 微调，GPT-4o 用上下文提示模拟。〔一手〕 — [摘要、§1、§3](https://arxiv.org/abs/2412.07017)
- AsyncLM §6.6：中断也可用于用户输入——"找西雅图的酒店"之后马上补"靠近太空针塔"，或"其实改成周四"；他们在微调数据里随机注入多轮对话中的新任务来模拟用户中断，作者承认"不一定代表真实人机交互"。〔一手〕 — [§6.6](https://arxiv.org/abs/2412.07017)
- **Speculative Interaction Agents**（arXiv 2605.13360 v2，2026-05-14）：语音应用通常要求 <1 秒延迟；"异步 I/O"让推理-行动线程不必等用户或环境的额外信息；"推测式工具调用"在信息可能还不完整时先发调用；**只有只读工具可以推测执行**，有副作用的写工具要缓冲到确认后才执行（人工把工具分为安全/不安全，类比硬件的推测读写）；云端强模型开箱即用 1.3–1.7 倍加速、准确率小幅下降；3B 小模型经时钟式训练 1.6–2.2 倍。〔一手〕 — [摘要、§3](https://arxiv.org/abs/2605.13360)
- AsyncFC（arXiv 2605.15077 v2，2026-10-09）：纯执行层，用"符号 future"表示尚未返回的结果，不改模型、不微调；编码任务端到端 1.4 倍加速且准确率不变；作者认为 LLM 天然能对未决结果的 future 做推理。〔一手，摘要〕 — [arXiv](https://arxiv.org/abs/2605.15077)
- **AsyncTool**（arXiv 2605.27995 v3，2026-08-31）：多个任务同时进行、工具结果有延迟时性能明显下降；失败模式：①缺乏时间推理，依赖结果没回来就发下一个调用、**先假设结果**（例：没等返回就假定某公司股票代码是"ATGL"）；②倾向先做**最近给出的任务**，忽略早先的任务——小模型更常见，70B 级几乎没有，三任务比两任务多；③忘记进行中的任务，导致高"未完成"率；频繁切换本身不保证成功，关键是跟踪任务状态与依赖。〔一手〕 — [摘要、结果分析、附录错误示例](https://arxiv.org/abs/2605.27995)
- **InterruptBench**（arXiv 2604.00892 v1，2026-04-01）：把用户中途打断分三类——追加（加需求）、修改（改错误）、撤回（去掉某细节），基于 WebArena-Lite，默认在基线轨迹 60% 处注入；6 个主干模型都觉得难：追加类 Opus 约 50–55%、Sonnet 约 40–44%、Haiku 约 33–38%，开源 Qwen 约 26%、DeepSeek 30%、Mistral 23%；典型失败："带着过时假设继续做，没把环境状态与更新后的意图对齐，或给出与更新后目标不一致的答案"。〔一手〕 — [§2–§4、§6](https://arxiv.org/abs/2604.00892)
- **Retire**（arXiv 2610.01160 v1，2026-10-01；NVIDIA）：服务层把"修订"做成版本切换——请求拥有调度与显存资源，**执行版本拥有"发布输出或安装状态"的权限**；先撤销过时工作的权限，再认证可继承的已完成前缀；修订到接替请求首 token 的时间中位数快 17.1%；回放编码 agent 的真实打断序列"没有发出任何过时输出"。〔一手，摘要〕 — [arXiv](https://arxiv.org/abs/2610.01160)
- **KAME**（arXiv 2510.02327 v2，2026-05-25；Sakana AI）：前端语音到语音模型立即回应，同时把中间转写流给后端文本 LLM，后端回答作为"oracle"流实时注入前端；MT-Bench（语音合成子集）：Moshi 2.05，KAME（后端 GPT-4.1）6.43、（后端 Claude-opus-4.1）6.23，级联系统 Unmute（GPT-4.1）7.70、中位延迟 2.1 秒；KAME 中位延迟与 Moshi 相同（至少一半会话在问题说完前就开始回答）；换后端不需重训。〔一手〕 — [§2、§4、表 2](https://arxiv.org/abs/2510.02327)
- KAME 与级联系统的差距"主要不是后端能力而是早期回应的时机"：单独评测后端最后一次 oracle 文本平均 7.79；强制延迟回应的实验里分数随延迟上升；收到矛盾的 oracle 后 KAME 会**改口**，作者认为这在真实对话里自然，但产生冗余表达、拉低评分。〔一手〕 — [§4.2](https://arxiv.org/abs/2510.02327)
- 边想边听/边说：Asynchronous Reasoning（arXiv 2512.10931 v3，2026-05-13）免训练地让推理模型同时思考、聆听、输出，首个非思考 token 的时间从数分钟降到 5 秒；Chronological Thinking（arXiv 2510.05150 v3）让全双工语音模型在听的时候增量推理，用户一停就停止思考开口，"无额外延迟"；SyncLLM（arXiv 2409.15594 v1）把时间信息接入 Llama3-8b 使其与真实时钟同步，可容忍 240 ms 网络延迟。〔一手，摘要〕 — [AsyncReasoning](https://arxiv.org/abs/2512.10931)；[Chronological Thinking](https://arxiv.org/abs/2510.05150)；[SyncLLM](https://arxiv.org/abs/2409.15594)

### Inferences
- 〔推理〕灵鲸 §2.5 / R4 的设计（总会话没有 wait，结果以事件 followup 回来，低显著的 inject 不叫醒）与 Ginart 的"事件驱动 FSM + 账本唯一真相 + 优先级"同构；底座的 `followup / steer / inject / cancel` 对应 Ginart 的事件入队与优先级打断。可补的一条规则来自 Ginart："正在对外说（已投递）的不打断，正在生成的可打断"——灵鲸的 outbox 已投递的消息不能撤回，主人新消息到来时只 `cancel` 尚未投递的回合（§2.5 现在按"有无副作用"区分，已投递就是副作用，一致）。
- 〔推理〕AsyncTool 的三个失败对总会话是具体风险：①"结果没回来先假设"——总会话可能对主人说"改好了"而活其实还在跑；对策是每轮前缀的 [正在做] 带活的阶段，且"做完了"类话只在收到 `task.report{待验收}` 后说（outbox 可校验：提到活号且该活不在待验收/完成态时提醒改写）。②"最近的任务挤掉早先的"——合批时主人在等的、早到的事件要排前（§2.5 已有"主人在等 > 冲突与应对 > 其余"）。③"忘记进行中的任务"——Springdrift 去掉 sensorium 后同样出现（见 §9），[正在做] 必须每轮都在。
- 〔推理〕InterruptBench + Retire + AgileThinker 共同指向 §6 评审第 5 条：想事活/干活跑着时主人改口，要送进那件活；结论回来时要带"版本"（读到的最后消息号），**只有当前版本有权被说出去**——这正是 Retire 的"版本拥有发布权"。总会话发现结论之后又有新消息，就不照念（四层稿已提，论文支持）。
- 〔推理〕KAME 是"前台在后台结果到达前先开口"的量化反例：开口越早，内容越可能要改口。灵鲸的 `ponder` + 垫话（"我想想，等我一下"）是更干净的版本：前台先承诺的只是"我在想"，不是内容。不要让总会话对已经 ponder 的议题先给一版"初步看法"。
- 〔推理〕Ginart 的 fork/spawn 对应灵鲸交接包：干活默认 spawn（新会话 + 交接包），旧笔记修正 C 已定；"想事"如果需要她和主人刚才的完整语境，交接包里带"最近 N 轮原文"即可，相当于有限的 fork。

### Gaps
- Ginart 的端到端语音延迟数字在 HTML 公式里没抽出（"< … ms"）；论文无定量对比。
- 没有找到在多渠道文字聊天（非语音）场景下测量"异步前台"用户体验的论文。
- AsyncTool 各模型的具体分数本轮未抽。

## 7 主动型 agent：谁决定开口、误报、强模型或单独"想"一遍有没有用

### Takeaway
2026 年的新证据把"主动"拆成三件事：要不要做（能力）、什么时候做（时间分配）、做多深、要不要先问（信任/介入深度）。**更强的模型和更高的推理强度能提高"做得对"，但不能提高"介入深度合适"**（GPT 5.6-Sol 推理从无到 xhigh：任务分 50.0→58.9，信任指标持平）；人对一次介入深度不当的信任损失大于对正确行为的信任回升；LLM 评委几乎看不出介入不当。PARE 的"观察-执行"两段式与灵鲸第二/三层同构：观察方只有只读工具和"等/提议"两个动作，小模型的接受率显著更低、提议更早更多。

### Cited Findings
- ProactiveBench 数字复核（arXiv 2410.12361 v3，2024-12-03）：表中 GPT-4o-mini 误报 64.73%、GPT-4o 51.85%、Claude-3.5-Sonnet 54.63%，给 3 个候选时 GPT-4o 降到 36.44%——与旧笔记一致。〔一手，复核表 3/4〕 — [arXiv](https://arxiv.org/abs/2410.12361)
- Inner Thoughts（CHI 2025）的框架与数字见旧笔记 §2.7；2026-10 有一篇把它改成"对抗式 Inner Thoughts"用于狼人杀"随时发言"赛道的工作，认为一般对话的设计不适合利益冲突、信息不完全的环境（本轮未读数字）。〔一手，摘要〕 — [Adversarial Inner Thoughts](https://arxiv.org/abs/2610.32107)；[Inner Thoughts](https://arxiv.org/abs/2501.00383)
- **PARE**（arXiv 2604.00842 v1，2026-04-01）：观察-执行架构——**观察模式只有只读工具和两个控制动作：`wait` 继续观察，或 `send_message_to_user` 提议帮助**，用任一控制动作都结束本轮；用户接受后进入执行模式，执行方拥有场景内所有应用的完整 API，自主执行，只在完成或做不到时才发消息；用户拒绝就回到观察，不调用执行方。〔一手〕 — [§4](https://arxiv.org/abs/2604.00842)
- PARE-Bench（143 个任务，用户模拟器 GPT-5-mini，被要求"对接受很严格"；观察与执行用同一模型）结果（成功率 / 提议率 / 接受率）：Claude 4.5 Sonnet 42.0% / 12.8% / 78.2%；Gemini 3 Flash 42.1% / 19.1% / 67.1%；Gemini 3 Pro 35.1% / 16.5% / 71.2%；GPT-5 37.4% / 28.1% / 70.2%；Qwen 3 4B 18.5% / 20.5% / 63.7%；Llama 3.2 3B 10.0% / 23.0% / 58.4%；Gemma 3 4B 3.0% / 14.2% / 17.6%。一致性：Claude Success@4 60.8% → Success^4 18.2%，Llama 23.8% → 1.4%。〔一手〕 — [表 1、§6.1](https://arxiv.org/abs/2604.00842)
- PARE 分析：Qwen 接受率较高（63.7%）但成功率低（18.5%），"对小模型来说执行而非目标推断才是主要瓶颈"；小模型更常触发"再收集上下文"（Qwen 26.5%、Llama 29.1%），说明提议常常过早；收集上下文后被拒的转化率 Claude/GPT-5 为 3.7–4.6%，小模型 9–10%；作者设想的部署是"小的端侧模型持续观察 + 大模型执行"，**但没有评测这种不对称配置**。〔一手〕 — [§6、附录](https://arxiv.org/abs/2604.00842)
- **Proactivity-Gym / Foundations of Proactive Agents**（arXiv 2609.37267 v1，2026-09-29）：3T 原则——任务能力（TC）、时间分配（TA）、信任（TR）；设计空间五维：任务范围、预期时域、**激活触发（用户触发 / 事件触发 / agent 自己复查触发）**、**处理时机（交互时 / 睡眠时）**、**介入深度（自主执行到给建议待批）**。〔一手〕 — [§3–§4](https://arxiv.org/abs/2609.37267)
- Proactivity-Gym 评测：10 个多日场景（每个 7–10 个模拟日）× 3 种人设，9 个模型 × OpenClaw / Claude Code / Codex 三种 harness 共 23 种组合，主实验关闭推理；Claude Opus 5 任务分最高 65.1，但 TA 只有 51.7%、介入深度一致率 TR-D 52.4%；**其他模型 TA 都低于 20%，TR-D 39–51%**；GPT 5.6-Sol 推理强度从无到 xhigh，TC 50.0 → 58.9，**两个信任指标持平**；TC 与 TA、TR-D 相关性弱；LLM 评委给 Opus 5 的"可理解性"4.72、"技术能力"4.60，同时 TR-D 只有 52.4%，"LLM 评委对介入深度不当相当宽容"。〔一手〕 — [§5、附录 F](https://arxiv.org/abs/2609.37267)
- Proactivity-Gym 人类研究（30 人）：92.2% 的比较里选正确的结果；内容质量相同时 88.3% 选介入方式合主人意的；信任"失去比重建容易"：从合适到不当后信任降 1.86 分，反向只升 1.27 分；"合适-不当-合适"序列最后只恢复到 3.43（起点 4.43），尽管最后那次介入本身被评 4.71；参与者 P26："一次错误动作之后，agent 要长时间持续表现好才能挽回信任。"〔一手〕 — [§5.3](https://arxiv.org/abs/2609.37267)
- PPP / UserVille（arXiv 2511.02208 v2，2026-08-23）：把协作型 agent 拆成生产力、主动性、个性化，用任务结果、提问代价、偏好遵守三种奖励做多目标 RL；在 SWE-Bench 与 BrowseComp-Plus 上平均比 GPT-5 等强基线高 16.7 分，"问更有针对性的问题"。〔一手，摘要〕 — [arXiv](https://arxiv.org/abs/2511.02208)
- DiscussLLM（arXiv 2508.18167 v2，2026-05-14）：训练模型在不需要介入时输出一个特殊"沉默 token"；比较了端到端一体模型和"分类器 + 生成器"解耦的低延迟方案。〔一手，摘要；未读数字〕 — [arXiv](https://arxiv.org/abs/2508.18167)
- **POrchestra**（arXiv 2610.13485 v1，2026-10-09）——子 agent 对编排者的"主动"：子 agent 可在任何逻辑点暂停、向编排者请求调整其 harness，编排者修订或终止；三个长程基准上任务成功率相对最强基线平均 +9.1%；随机撤销工具权限的受控实验里主动反馈 92% 恢复、平均延迟 1.67 步；对照：轮询（每 5/10/20 步）越频繁恢复越好但成本更高、打断执行连续性，"只在结束/出错时触发"则发现不了没有显式报错的调整需求。〔一手〕 — [摘要、§3、§4](https://arxiv.org/abs/2610.13485)

### Inferences
- 〔推理〕对四层稿 §2.4（想念过线：A 总会话判 vs B 派想事活判）：Proactivity-Gym 的"推理强度提高 TC 但不提高 TR"和 ProactiveBench 的"强模型误报也过半"一起，支持 A 的论证——**多花钱换不来"该不该/该多深"的判断**；真正起作用的是代码闸、反馈、以及把非紧急的推迟到睡眠时（§5）。
- 〔推理〕但 PARE 显示模型档次对"接受率"不是没影响：同为观察者，Claude 4.5 Sonnet 78.2%，Qwen 3 4B 63.7%，Gemma 3 4B 17.6%。灵鲸总会话用的便宜模型（DeepSeek）不是 3–4B 级，但这提醒：M4 评测要把"主人接受率"按模型档测出来，而不是假设便宜模型够用。
- 〔推理〕PARE 的观察方工具集（只读 + wait/propose）几乎就是灵鲸总会话的工具集（`recall`/`look` 只读 + `say`/`dispatch`）；它的执行方"只在完成或做不到时发消息"对应灵鲸第三层"不对外说话、只经事件汇报"。PARE 把"提议率"当成越低越好的指标（太多提议惹人烦），灵鲸 M4 评测可以直接借用：主动开口率、接受率、"别烦"率三项一起看。
- 〔推理〕Proactivity-Gym 的"介入深度"对应灵鲸：同一件事，她是直接做、做好了告诉主人，还是先问。信任损失不对称意味着**默认宁可浅**（先说、先问），由主人的反馈逐步放宽（夜里进习惯）；这与 `overall.md` 请示三路的保守默认一致。LLM 评委看不出介入不当 → M4 评测不能用 LLM 评委替代主人反馈。
- 〔推理〕POrchestra 支持灵鲸 §3.2 的 `task.ask` / `task.report{受阻}` 可以在活的任何时刻发出，而不是只在结束时；也提示不要用"总会话定时轮询各活进度"代替（成本高且打断连续性）。

### Gaps
- 没有找到"陪伴型 agent 主动开口"在真实用户长期使用中的误报/接受率数据；PARE、Proactivity-Gym 都是模拟用户或情景评审。
- PARE 没测"小观察者 + 大执行者"的不对称配置——这正是灵鲸的配置。
- DiscussLLM、Adversarial Inner Thoughts 的数字本轮未读。

## 8 带全局协调者的认知架构：什么触发深思、什么走反射

### Takeaway
新增的几个实现（PIANO、Lyfe、MIRROR、Springdrift）都有一个"认知控制器/认知循环"做唯一的高层决定者，下面挂并行或下属模块；触发深思的条件普遍是**代码可判的**：时间/步数、重复检测、事件到达、重要度累计阈值；Lyfe 的数据显示"每步都让 LLM 重新选高层选项"不提升表现、只增加成本。

### Cited Findings
- 旧笔记已核：CoALA 主张决策循环由代码驱动、动作空间宜最小；GWT 的进入—广播—加工、自上而下与自下而上注意；Generative Agents 反思在近期事件重要度累计超过 150 时触发（实际每天两三次）、反应是每个时间步都问一次 LLM（成本高）。〔二手，转引自旧笔记 §2.1–§2.3〕 — [旧笔记](../2026-10-28-papers-architecture.md)；[CoALA](https://arxiv.org/abs/2309.02427)；[Generative Agents](https://arxiv.org/abs/2304.03442)
- **Lyfe Agents**：认知控制器（类比分层强化学习的 manager、前额叶）用一次 LLM 调用按 agent 的目标与内部状态选出一个"选项"（如"说话""用搜索引擎"）和子目标；选定后动作模块在该选项内逐步选具体动作，**直到终止条件满足；终止条件由快速的非 LLM 方法检查**，如基于时间的触发、对话里的重复检测（语义新颖度下降就退出对话）。〔一手〕 — [§2.1](https://arxiv.org/abs/2310.02172)
- Lyfe 消融：基础架构（每步同时选选项和动作）的 agent 退出对话的速度是 Lyfe 的 3 倍（"更善变"）；去掉选项-动作结构（每步都选选项）不提升表现但每步成本显著上升；去掉自我监控或"总结-遗忘"记忆则表现下降；整体成本比 Park 等（Generative Agents）低 10–100 倍。〔一手〕 — [§2.1、§4、摘要](https://arxiv.org/abs/2310.02172)
- PIANO：认知控制器经瓶颈读信息、决定后广播、强烈约束说话模块（详见本文 §2）。〔一手〕 — [§2.2](https://arxiv.org/abs/2411.00114)
- MIRROR：认知控制器把三条并行线程（目标、推理、记忆）综合成一份每轮**全量重建**的有界第一人称叙事（"重建而非累加"），作者把它对应到 GWT 的整合与情景记忆的重建；"重建式综合"单独就让 7 个模型都提升 5–20%（详见 §5）。〔一手〕 — [§2–§4](https://arxiv.org/abs/2506.00430)
- Springdrift 的认知循环是中心进程，接收运维者输入、调度器、邮件轮询，编排专家子 agent，管安全评估与输出（详见 §9）。〔一手〕 — [§2](https://arxiv.org/abs/2604.04660)

### Inferences
- 〔推理〕Lyfe 的"选项 + 非 LLM 终止条件"就是灵鲸第三层"自己的事"的形态（想事活 `do(活动, 理由, 终止条件)`，腻、累、到点由代码判），且有消融数据支持"不要每步都让模型重新决定做什么"；也支持四层稿 §2.11 第 10 行"再看一个"由代码在终止条件内掷硬币。
- 〔推理〕这些实现里"认知控制器"都**不是**最便宜的一环：Lyfe 的控制器、PIANO 的 CC 都在关键位置用 LLM，PIANO 明说只有 GPT-4o 能跑起来。灵鲸把总会话做成便宜模型，前提是它的决定被工具集和代码压窄（R1–R6）；这几篇论文没有直接证据说明"便宜控制器 + 窄职责"能行，也没有反证。

### Gaps
- 没有找到在这类架构里对"控制器用便宜模型 vs 强模型"做对比的消融。
- Lyfe 每 agent 每人类小时的美元成本数字在 HTML 公式中未能抽出（只有摘要里的 10–100 倍）。

## 9 2025–2026 的常驻/环境式/持久 agent 与协调前台

### Takeaway
最贴近灵鲸的是 Springdrift（2026-04）：一个常驻的"认知循环"跨终端、网页、邮件多渠道维持上下文，把活委派给有各自上下文与工具集的专家子 agent；**子 agent 不能直接找人，只能经返回值汇报**；每轮把一份结构化"自我状态"（sensorium）无需工具调用地注入上下文。证据只是单实例、单运维者 23 天的部署观察。

### Cited Findings
- 版本：arXiv 2604.04660 v1，2026-04-06；约 62,000 行 Gleam（运行在 Erlang/OTP 上），约 1,500 个测试；代码声称"发表后"放到 GitHub seamus-brady/springdrift。〔一手〕 — [arXiv](https://arxiv.org/abs/2604.04660)
- 架构：认知循环是中心 OTP actor，输入来自运维者（终端或网页 GUI）、调度器、邮件收件轮询；编排专家子 agent、管安全评估、产出输出；所有组件是受监督的 OTP 进程，经类型化通道通信（"认知循环不能向图书管理员发 ToolCall"在编译期就被挡住）。〔一手〕 — [§2、附录 E](https://arxiv.org/abs/2604.04660)
- 专家子 agent（每个有自己的消息历史、工具集、上下文窗口和 react 循环）：Planner（无工具，XML 输出，5 轮）、Project Manager（22 个规划工具，8 轮）、Researcher（网页 + 产物，8 轮）、Coder（沙箱 6 个工具，10 轮）、Writer（6 轮）、Comms（4 个邮件工具，6 轮）、Observer（18 个诊断工具，6 轮，临时）；委派深度上限默认 3。〔一手〕 — [§2.5 表 2](https://arxiv.org/abs/2604.04660)
- **子 agent 不能调用 `request_human_input`，只能经返回值汇报，"防止被委派的 agent 劫持与运维者的交互通道"**；子 agent 的 react 循环里有工具错误时，认知循环在结果前加警告让编排 LLM 知道结果可能不可靠；子 agent 健康状态推送到 sensorium，在下一个循环前就可见。〔一手〕 — [§2.5](https://arxiv.org/abs/2604.04660)
- sensorium："结构化、零延迟的运行状态特征向量，每个循环注入提示"；去掉它时 agent 每个循环开始都没有环境上下文——不知道时间、不能根据近期表现校准置信、看不到逾期作业、发现不了不健康的子 agent；实现它之前观察到："不论什么时间都是泛泛的问候"、"恢复会话时不提之前的工作"、"委派时不知道子 agent 的健康状况"。〔一手〕 — [§3、§3.4](https://arxiv.org/abs/2604.04660)
- 部署：单实例、单运维者 23 天（19 个运行日），agent 诊断了自己的基础设施 bug、给子 agent 的失败模式分类、跨邮件与网页渠道维持上下文；监督树自动处理了 714 次超时和多次崩溃，无需人工干预；作者明说这是"示例而非对照实验"。〔一手〕 — [摘要、§1、附录 E/F](https://arxiv.org/abs/2604.04660)
- 输入分 Simple/Complex 路由到 haiku/opus 一类模型（见 §4）。〔一手〕 — [附录 D.7](https://arxiv.org/abs/2604.04660)
- 其他"常驻"相关：PARE 的观察方持续监视用户动作与通知（§7）；Proactivity-Gym 用多日场景与模拟时钟评测常驻主动 agent（§7）；ProAct 用交互间空闲时间（§5）。〔一手〕 — [PARE](https://arxiv.org/abs/2604.00842)；[Proactivity-Gym](https://arxiv.org/abs/2609.37267)；[ProAct](https://arxiv.org/abs/2605.25971)

### Inferences
- 〔推理〕Springdrift 与灵鲸第二层的对应几乎逐条：认知循环 ≈ 总会话；专家子 agent ≈ 第三层的活；"子 agent 不能找人、只能经返回值汇报" ≈ "第三层永远不对外说话、只走事件"；sensorium ≈ 每轮前缀的 [状态]/[正在做]；监督树 ≈ procs 与看门狗；跨渠道上下文 ≈ V2 一个总会话管多个地方。它的"去掉 sensorium 后的三个症状"可以直接当灵鲸的回归测试：不同时间的问候是否不同、换新后是否提到之前的事、派活时是否知道手上活的状态。
- 〔推理〕Springdrift 的认知循环本身会按复杂度切到强模型（Opus），而灵鲸总会话固定便宜模型、重的思考派到第三层。两者在"前台遇到复杂问题时怎么办"上走了两条路：Springdrift 是"前台临时换脑"，灵鲸是"前台派出去"。灵鲸的路保持了"前台一直是同一个便宜会话、状态不分叉"，代价是多一次派活的往返；若 M4 评测显示 `ponder` 往返体验太慢，Springdrift 式"同一会话本回合换强模型"是一个可评估的备选（底座会话是否支持回合级换模型需另查）。

### Gaps
- Springdrift 代码"发表后"才放出，本轮未能核对实现；所有结论来自单人部署叙述。
- 未找到其他 2025–2026 年带"常驻协调前台 + 后台工人"并有定量评测的个人助理论文。

## 10 对灵鲸第二层的具体教训

### Takeaway
外部证据整体支持四层稿第二层的方向——前台不持改世界的工具、状态在外部账本、结果以事件回来、升级靠结构不靠自评——并指出四个要补的地方：①"当场答还是想一想"这最后一条模型判断是全部文献里证据最差的环节，要加代码侧信号和事后测量；②异步带来的三种典型错误（先假设结果、新挤旧、按旧假设继续）要用 [正在做] 常驻前缀和"版本化的结论"挡；③前台不要在后台结论到达前给内容，只给垫话；④非紧急的主动帮助默认推迟到睡眠时，介入深度默认宁浅。

### Cited Findings
- 交出去的判据在有效系统里都是外部/结构信号：Talker-Reasoner 用后台写的阶段字段（planning 时等）〔一手〕；SwiftSage 用卡住/非法/关键/意外四条〔一手〕；DPT-Agent 代码用定时器 + 人类消息〔一手〕；Lyfe 用非 LLM 终止条件〔一手〕；PARE 用模式状态机〔一手〕。 — [Talker-Reasoner](https://arxiv.org/abs/2410.08328)；[SwiftSage](https://arxiv.org/abs/2305.17390)；[DPT-Agent 代码](https://github.com/sjtu-marl/DPT-Agent)；[Lyfe](https://arxiv.org/abs/2310.02172)；[PARE](https://arxiv.org/abs/2604.00842)
- 自评升级不可靠：HiL-Bench 4–24% vs 75–89%〔一手〕；口头置信低对齐〔二手，经综述〕；零样本路由等于随机〔一手〕；校准是约束、"自信地错"是主失败模式〔一手〕。 — [HiL-Bench](https://arxiv.org/abs/2604.09408)；[路由综述](https://arxiv.org/abs/2603.04445)；[System-1 评测](https://arxiv.org/abs/2610.02267)；[Bayesian self-escalation](https://arxiv.org/abs/2608.24087)
- 前台用过时信念会"答一个更简单的问题"〔一手〕。 — [Talker-Reasoner §1](https://arxiv.org/abs/2410.08328)
- 异步失败模式：先假设结果、新任务挤掉旧任务、忘记进行中任务〔一手〕；用户改口后按旧假设继续〔一手〕；版本拥有发布权、无过时输出〔一手〕。 — [AsyncTool](https://arxiv.org/abs/2605.27995)；[InterruptBench](https://arxiv.org/abs/2604.00892)；[Retire](https://arxiv.org/abs/2610.01160)
- 前台提前开口的代价：KAME 6.43 vs 级联 7.70，差距来自时机，且会改口〔一手〕。 — [KAME](https://arxiv.org/abs/2510.02327)
- 慢的转述进快的会走样：DUMA 快脑吸收慢脑输入时事实不一致〔一手〕。 — [DUMA](https://arxiv.org/abs/2310.18075)
- 睡眠时帮助接受率 97.8% vs 争资源时 26.7%；信任失去比重建容易；推理强度不提高信任指标〔一手〕。 — [Proactivity-Gym](https://arxiv.org/abs/2609.37267)
- 子 agent 不能找人 + sensorium 每轮注入〔一手〕。 — [Springdrift](https://arxiv.org/abs/2604.04660)
- 子 agent 随时主动回报优于结束/出错触发与轮询〔一手〕。 — [POrchestra](https://arxiv.org/abs/2610.13485)

### Inferences
- 〔推理〕**保持**：R1（代码先判）、R2（没工具就只能派）、R5（决定类工具只在想事活）、R4（总会话没有 wait、结果以事件回来）、"第三层不对外说话"——这五条分别有 SwiftSage/DPT、PARE/Springdrift、Talker-Reasoner、Ginart/AsyncLM/MIRROR、Springdrift/PIANO 的正面证据，没有找到反证。
- 〔推理〕**补 1：给"当场答还是想一想"加代码侧信号**（对应 §2.3 末段）。学 Talker-Reasoner 的"阶段字段"：代码（或底座里不调大模型的轻分类）在起回合前给主人消息打标签——含"想想/安排/计划/建议/该不该/怎么看"、涉及她的立场或关系、引用了账本里未决的议题、或要跨三处以上账本——命中则每轮前缀写一句"这件事建议 `ponder`"。模型仍可不听，但从"自己意识到"变成"被提醒后决定"。依据：前沿模型自判求助的 Ask-F1 也只有约 40%（HiL-Bench）。
- 〔推理〕**补 2：测量而不是假设**。记两个指标：当场答后主人在 2 轮内追问/纠正的比例（"抢答简单版"的代理），`ponder` 后结论与当场答案差异不大的比例（"派多了"的代理）。M4 评测同时用这两个数调提示词或标签规则；不要用 LLM 评委打分（Proactivity-Gym：评委看不出介入不当）。
- 〔推理〕**补 3：异步三防**（对应 §2.5、§2.7、§6 第 5 条）：①[正在做] 每轮必在（Springdrift 去掉 sensorium 的症状、AsyncTool 的"忘记任务"）；②"做完了/改好了/我想好了"这类话只在对应事件到达后才允许说，outbox 按活号查状态（AsyncTool 的"先假设结果"）；③想事活与干活的结论带"读到的最后消息号"，晚于它有同议题新消息时不照念，改为"我刚想完，不过你后来说了 X，我再看看"（InterruptBench、Retire、AgileThinker 的过时计划）。
- 〔推理〕**补 4：`ponder` 之后只垫话不给内容**（对应 §2.3 `ponder` 的"建议答复"参数）。KAME 量化了"后台结论到之前就开口"的降质与改口；Ginart 的示范是"我马上准备"+ 先答别的快问题。`ponder` 的"建议答复"应限定为"我在想"类，不含对议题的初步结论。
- 〔推理〕**补 5：转述走样要挡**（对应 §2.2"结构化事实原样传、措辞她生成"）。DUMA 的教训是快脑转述慢脑结果会编造；灵鲸已有 `conclude{事实栏}` 与 outbox 校验 `relay` 事实栏的设计，应确保：事实栏里的数字、日期、人名在总会话的回复里一旦出现必须一致，否则拒绝并要求改写。
- 〔推理〕**补 6：主动开口默认推迟、默认宁浅**（对应 §2.4 方案 A 的事实包）。事实包里加"紧急度"：不紧急且主人在忙 → 留心事、到空闲或早上再说（Proactivity-Gym 97.8% vs 26.7%）；介入深度默认"先说/先问"，由主人反馈夜里放宽（信任不对称）。这些都是代码闸，不需要更强的模型；推理强度提高不改善信任指标，是 §2.4 选 A 的又一条依据。
- 〔推理〕**补 7：说的和做的要一致**（PIANO 的 Abby 例）。`reply` 里"我开始做了"与 `dispatch` 同回合时，若 `dispatch` 被代码拒绝，outbox 要拦下或改写那句承诺。
- 〔推理〕**可评估的备选**：MIRROR 式"回合后异步重建一份有界叙事、下一轮注入"可提升长对话里的约束保持（+21%，自建评测）；Springdrift 式"同一前台本回合临时换强模型"可作为 `ponder` 往返太慢时的备选。两者都会增加每轮成本，按 M4 评测结果决定，不默认上。
- 〔推理〕**一个被文献削弱的假设**：四层稿 §2.1 说"剩下的事是小模型做得了的"。PIANO（只有 GPT-4o 能跑）、DPT-Agent（<20B 前台得分效率近零）、PARE（3–4B 观察者接受率 17.6–63.7%）都提示前台模型太小会出问题；但它们的前台职责比灵鲸总会话宽。结论：便宜可以，**不要最小**——与旧笔记修正 F 一致。

### Gaps
- 所有教训都来自非陪伴场景（编码、游戏、网页、睡眠教练、房产客服）的迁移；没有一篇论文测过"一个人格、多渠道、长期常驻的便宜前台 + 强后台"整体的用户体验。
- 便宜前台在"当场答 vs 想一想"上的实际误判率只能靠灵鲸自己的 M4 评测得到。
